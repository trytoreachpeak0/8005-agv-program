## 0. 业务与接口约定

### 0.1 术语

- `LOT`：客户订单对应的母批次号。
- `SUBLOT`：母批次拆分后的生产批次，格式通常为 `xxxxxxx-x`，现场扫描的是 SUBLOT。
- `EQP`：MES 中的机台编号，业务上保证非空；为空时现场无法生产。
- `AREA`：MES 中记录的机台区域号，允许为空。正常情况下一个 EQP 只有一个有效 AREA；同一 EQP 查询出不同 AREA 时应上报 MES 数据异常。
- `站点`：RCS/RIOT 地图中的可导航点（RCS 地图 = RIOT 地图 = AGV 地图）。每个站点有字符串 `station_name` 和数字 `station_id` 两个标识；本系统配置文件和数据库统一使用 `station_name`，`station_id` 只在向 RCS/RIOT 发起派车调用的瞬间现查现用，不落盘。
- `任务类型`：本系统人为定义的运输业务类型，用于区分相同 SUBLOT 在不同阶段产生的运输任务。

### 0.2 五类运输任务

1. **装片完工 → 焊线/键合派工待送区**
   - 起点：MES 查询结果中 EQP/AREA 对应的装片机台站点。
   - 终点：固定的焊线/键合派工待送区站点。
2. **装片完工 → 烘箱间**
   - 起点：MES 查询结果中 EQP/AREA 对应的装片机台站点。
   - 终点：固定的烘箱间站点。
3. **焊线/键合完工 → 关卡区**
   - 起点：MES 查询结果中 EQP/AREA 对应的焊线或键合机台站点。
   - 终点：固定的人工质检关卡区站点。
4. **焊线/键合完工 → 三光区**
   - 起点：MES 查询结果中 EQP/AREA 对应的焊线或键合机台站点。
   - 终点：固定的三光机台区域站点。
5. **派工待送区 → 指定焊线/键合机台**
   - 起点：第 1 类任务的固定终点，即焊线/键合派工待送区站点。
   - 终点：MES 查询结果中 EQP/AREA 对应的指定焊线或键合机台站点。

MES 的 `STEP`、`入库`、`入站`、`完工`仅用于 IT 提供的 SQL 筛选，本系统按照上述任务类型解释查询结果，不依赖这些字段推导物理运输含义。

### 0.3 查询接入规则

1. SQL 返回列中的 `SUBLOT` 是 MES 数据库原字段 `lot`，仅将输出别名改为更准确的业务名称；SQL 内部的 `t.lot` 等原字段名保持不变。
2. 本系统运输任务的幂等键为 `任务类型 + SUBLOT`。MES 状态不变时，周期轮询会重复返回同一记录，本系统不得重复创建任务。
3. 同一 EQP、同一 AREA 产生的重复查询行允许归并；同一 EQP 查询出不同 AREA 时不得自动选取，应上报 MES 数据异常。
4. AREA 不符合“字母+两位数字-两位数字”编码格式，或反查不到对应站点时，保留候选记录并进入位置异常状态，不能直接下发 AGV。
5. MES 查询结果是当前状态快照。轮询采用固定延迟：每轮查询全部完成后等待 10 秒再启动下一轮，不允许查询重叠或堆积；仅在查询完整成功时累计消失次数。若同一记录连续 2 次未出现，且尚未开始装货，则自动取消本地任务、记录“MES记录已消失”并立即撤销相关取货路线；查询失败不累计，记录重新出现时计数归零。
6. 任务创建、取货、运输、送达、取消和异常状态均保存在本系统；当前阶段本系统不做任何 MES 回写。未来是否回写留作远期评估事项，评审前不得实现 MES 写操作。
7. 固定上线基线时间为 `2026-08-01 00:00:00`，用于排除上线前历史积压；不使用持续滚动的“最近 N 小时”窗口。上线后已接入的任务不会因等待时间过长而被过滤，应通过超时报警处理。
8. 正常情况下一个 SUBLOT 同一时刻只处于一个工序，因此只能命中一种任务类型。若同一 SUBLOT 在同一轮完整查询中命中多个任务类型，应作为阻断性异常转人工处理；送关卡和送三光绝对互斥。
9. 已取消任务再次出现在 MES 查询中时转人工确认，不自动恢复、不自动重新创建，也不允许人工创建正式 MES 任务。
10. 5 组查询应通过 `UNION ALL` 合并为一条 Oracle SQL，每个分支增加固定 `TASK_TYPE`，统一输出 `TASK_TYPE、SUBLOT、AREA、EQP、STEP、DATES`。单条 SQL 使用 Oracle 语句级一致性读，避免分开执行造成跨时刻“伪冲突”；不得使用会隐藏重复行的 `UNION`。正式SQL保存于`mes/sql/MES五类任务合并查询.sql`。
11. `DATES` 保证非空，表示本次运输需求产生时间，时区为北京时间 `UTC+8`。
12. EQP 和 AREA 编码精确匹配，仅去除首尾空格，不补零、不改变大小写；类似 `D4-06` 与 `D04-06` 的编码表示不同位置。
13. 异常骤降按任务类型独立保护：若该类型上一轮完整成功查询数量大于等于 10，本轮突然变为 0，则进入`PAUSED_ZERO_DROP`，暂停该类型的消失计数和取消处理并报警，其他类型不受影响。仅采用自动恢复：后续连续 2 轮该类型数量大于 0 时自动解除，不提供人工解除入口。阈值10作为可配置参数。
14. 任务首次创建后冻结其 EQP、AREA、DATES 和起终点信息。后续 MES 查询即使返回不同值，也不得更新已有任务；可另存观测值用于审计。
15. AREA 初始无法解析出站点的任务保持位置异常并报警，不因 MES 后续补全自动恢复，也不能人工生成正式MES任务。
16. 上线时间 `2026-08-01 00:00:00` 的过滤在应用层执行，不修改客户 IT 提供的原始 SQL。
17. AREA 到站点的解析使用两张表：表A（`station_id ↔ station_name`，从 RCS/RIOT 地图同步）、表B（`station_name → area_code[]`，由站点命名规则自动拆分派生，最多3个AREA，编码格式为字母+两位数字-两位数字，从01起无00）。任务只冻结保存 `station_name`；数字 `station_id` 只在向 RCS/RIOT 发起派车调用的瞬间现查现用，不落盘。

### 0.4 多仓位与花篮约定

- 一个 SUBLOT 对应一个或多个花篮，一个运输任务可包含多条花篮装载明细。
- AGV 允许混装不同任务类型的产品，也允许途中到多个站点取货；但每次取货必须校验当前站点与任务起点一致。例如在装片机台只能收取起点为该装片机台的产品。
- 花篮数量由 IT 提供的方式待定；若未来提供，按预计数量结束装载。若 IT 不提供，现场统一采用“重复扫码确认新增一篮”兜底：员工再次扫描同一 SUBLOT 并二次确认后分配新仓位，不提供独立的“新增一篮”按钮；由人工确认该 SUBLOT 装载完成。
- 不追踪实体花篮条码，只记录 SUBLOT、花篮序号和所占仓位。
- “开始装货”以该任务第一个仓门成功打开为边界。开始装货后，即使 MES 记录消失也保留任务，让用户完成取送。
- 装货和卸货时由系统自动打开仓门，用户关闭仓门即确认该仓位本次操作完成。
- AGV 仓位数量和规格均为车型配置，当前车型暂定 8 个仓位；后续车型可更多或更少，仓位也不保证等规格，程序不得写死。

### 0.5 调度与配置约定

- 第 5 类“派工待送区 → 指定焊线/键合机台”任务优先级最高。
- 任务持续 1～3 分钟无车辆响应时应提升优先级，具体阈值作为可配置参数。
- 允许为了顺路取货适当延迟当前配送，并支持在焊线/键合机台“送一批、取一批”。
- 若本地已有同一 SUBLOT 的上游任务正在送往派工待送区，而 MES 已产生第 5 类下游任务，则保留正在执行的上游任务，第 5 类任务等待上游在待送区卸货完成后再释放，不取消正在运行的任务。
- AREA 到站点的解析由 R-12 IT/软件维护人员和 R-13 AGV 运维/调度管理员维护；默认由 RCS/RIOT 地图同步与站点命名规则自动生成两张映射表（不要求开发前人工准备首版数据），命名不规范时补充显式覆盖记录，变更记录操作人、修改前后值、原因、时间和结果。
- 焊线/键合派工待送区、烘箱间、关卡区和三光区各自配置一个固定 `station_name`（字符串，不是数字 `station_id`），通过配置文件或数据库指定，可动态修改，不在程序中写死。

### 0.6 MES连接与监控约定

- MES 数据库为 Oracle，连接信息单独保存在 `mes/Oracle数据库连接信息.txt`，包含明文凭据，不得提交到公共仓库。
- 页面应显示每轮 MES 查询开始时间、完成时间、耗时、结果数量和执行状态，并允许人工调整轮询延迟；默认完成后等待 10 秒。
- 若单轮查询耗时超过轮询延迟，仍须等待本轮完成后再计时，不得并发启动或堆积下一轮。
- MES 查询超时时间默认 30 秒。查询超时、失败、结果不完整或连接中断时：不创建新任务、不累计消失次数、不批量取消任务并产生接口报警。
- MES 连接中断时，已经开始装货或已经取货的任务继续执行；尚未开始装货但已派车的任务暂停前往，等待 MES 恢复后重新确认。
- 每个任务的 MES 消失计数必须持久化。系统重启后的第一次完整查询用于建立恢复基线：可以创建新任务、重置重新出现任务的消失计数，但不累计缺失次数、不执行取消；从下一次完整查询开始恢复正常对账。
- 每个任务类型的最后正常非0数量、连续恢复次数和`PAUSED_ZERO_DROP`保护状态必须持久化。重启后第一次查询结果单独保存为恢复基线，不用0覆盖重启前的最后正常非0数量。第二次完整查询时：若重启前最后正常数量大于等于10且前两次均为0，则进入保护；若重启前已处于保护且前两次均大于0，则自动解除。
- 当前 MES 账号具有写权限，属于高危连接。应用只能执行预置的合并 SELECT，并使用 Oracle 只读事务；禁止通用 SQL 执行入口，任何非 SELECT 操作必须拒绝并报警，日志不得输出连接密码。
- 查询性能指标：正常目标不超过5秒，超过10秒产生慢查询警告，30秒硬超时；连续3轮失败产生高级报警。正式执行步骤和测试内容见`mes/sql/MES五类任务合并查询/MES五类任务合并查询测试计划.md`。
- 2026-07-13 正式实测已通过：单次合并约 3.28s；连续 10 轮全部成功，平均 3.13s，最大 4.37s；与原 5 组独立 SQL 行数一致。详细结果见`mes/sql/MES五类任务合并查询/output/`。

### 0.7 Mock任务约定

- 正式生产任务只能来自MES查询，不提供人工创建正式MES任务的入口。
- 开发和测试所需的人工任务属于Mock任务，必须设置`TASK_SOURCE = MOCK`并使用独立的`MOCK_TASK_ID`，不得占用或绕过正式MES任务的`任务类型 + SUBLOT`幂等键。
- Mock任务不参与MES出现/消失对账，不得因MES查询结果创建、取消或恢复。
- 生产环境默认禁用Mock任务；如现场联调必须启用，应使用专门权限并在界面显著标识。

## 1. 从MES获取装片完工送焊线键合的产品
### 1.1 sql内容
```sql
-- 从MES获取装片完工送焊线键合的产品
SELECT t.lot AS SUBLOT,
       tt.area AS AREA,
       t.eqp AS EQP,
       t.step AS STEP,
       wgdate AS DATES
FROM   (SELECT t.*,
               (SELECT Max(eqp)
                FROM   fw_wip_trans t1
                WHERE  t1.lot = t.lot
                       AND t1.dates = t.wgdate
                       AND t1.task = '完工') eqp
        FROM   (SELECT lot,
                       workorder,
                       step,
                       (SELECT Max(dates)
                        FROM   fw_wip_trans tt
                        WHERE  tt.lot = t.lot
                               AND task = '完工') wgdate
                FROM   v_fw_wip_sublot t
                WHERE  step IN ( '焊线', '键合' )
                       AND state <> '关闭'
                       AND task = '入库') t) t,
       fw_eqpres_eqpinformation tt
WHERE  t.eqp = tt.eqpno
       AND tt.step = '装片';
```

## 4. 从MES获取焊线和键合完工送三光的产品
### 4.1 sql内容
```sql
-- 从MES获取焊线和键合完工送三光的产品
SELECT 
       t.lot AS SUBLOT,
       tt.area AS AREA,
       t.eqp AS EQP,
       t.step AS STEP,
       t.wgdate AS DATES
FROM   (
        SELECT t.*,
               (
                SELECT Max(t1.eqp)
                FROM   fw_wip_trans t1
                WHERE  t1.lot = t.lot
                       AND t1.dates = t.wgdate
                       AND t1.task = '完工'
               ) eqp
        FROM   (
                SELECT lot,
                       workorder,
                       step,
                       (
                        SELECT Max(dates)
                        FROM   fw_wip_trans tt
                        WHERE  tt.lot = t.lot
                               AND tt.task = '完工'
                       ) wgdate
                FROM   v_fw_wip_sublot t
                WHERE  step IN ( '三光检验' )
                       AND state <> '关闭'
                       AND task = '完工'
               ) t
       ) t,
       fw_eqpres_eqpinformation tt
WHERE  t.eqp = tt.eqpno
       AND tt.step  in ( '焊线','键合');
```
