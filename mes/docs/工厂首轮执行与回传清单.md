# MES 工厂首轮执行与回传清单

本清单用于首次验证当前 `MES_TASK_UNION`、客户五分支基线、性能和 PACKAGE 覆盖。
本机不能连接 MES，因此“工厂通过”只能在完成回传导入后确认。

## 一、本机准备

- [ ] 运行结构检查：`python mes/tools/check_structure.py`
- [ ] 运行测试：`python -m unittest discover -s mes/tests -p "test_*.py"`
- [ ] 客户 IT 已批准数据库对象、执行窗口、30 秒超时、顺序执行和 10 轮性能测试。
- [ ] 准备不含密码的批准文件，例如：

```json
{
  "status": "approved",
  "reference": "<客户批准编号或记录链接>",
  "approved_by": "<批准人或角色>",
  "approved_at": "<ISO8601 时间>",
  "execution_window": "<批准执行窗口>",
  "scope": "MES_TASK_UNION、五客户基线、10轮顺序性能测试"
}
```

- [ ] 构建一次性实验 bundle：

```powershell
python mes/tools/mes_lab.py build-bundle `
  --queries-root mes/queries `
  --experiment mes/experiments/definitions/mes-task-union-validation/experiment.toml `
  --output mes/.dist/mes-task-union-validation
```

- [ ] 压缩 bundle 并记录压缩包 SHA-256；通过独立渠道把哈希提供给工厂执行人。
- [ ] 不把任何已填写的 `config.ini`、密码或 approval 之外的环境文件放入压缩包。

## 二、工厂机准备

- [ ] 校验压缩包 SHA-256 后解压，进入 bundle 根目录。
- [ ] 确认存在 `bundle-manifest.json`、`runner/`、`queries/`、`requirements.txt`。
- [ ] 使用 Python 3.11 或更高版本安装依赖：`python -m pip install -r requirements.txt`
- [ ] 把 `config.example.ini` 复制到 bundle 外，例如 `C:\private\mes-config.ini`。
- [ ] Oracle 11g 使用 `mode=thick`，配置 Instant Client；凭据仅写入本地配置。
- [ ] approval JSON 也放在 bundle 外，例如 `C:\private\approval.json`。
- [ ] 确认没有另一轮相同实验并发执行。

## 三、工厂执行

以下命令的 `--bundle .` 表示当前目录就是解压后的 bundle。

### 1. 单次 7 字段与质量检查

```powershell
python runner/mes_lab.py run-factory `
  --bundle . `
  --config C:\private\mes-config.ini `
  --approval-json @C:\private\approval.json `
  --output-root C:\transfer\mes-runs `
  --phase1
```

- [ ] run 状态为 completed。
- [ ] `reports/mes-task-union-quality.md` 已生成。
- [ ] 输出列恰为 `TASK_TYPE,SUBLOT,AREA,EQP,STEP,DATES,PACKAGE`。
- [ ] 质量报告 `硬失败：否`；若出现 `TASK_TYPE+SUBLOT 重复键`，记录冲突样例并反馈客户 IT，不得按归并处理。

### 2. 合并查询与客户五分支对比

```powershell
python runner/mes_lab.py run-factory `
  --bundle . `
  --config C:\private\mes-config.ini `
  --approval-json @C:\private\approval.json `
  --output-root C:\transfer\mes-runs `
  --compare-sources `
  CUSTOMER_BASELINE_DIE_TO_WIRE_STAGING `
  CUSTOMER_BASELINE_DIE_TO_OVEN `
  CUSTOMER_BASELINE_WIRE_TO_GATE `
  CUSTOMER_BASELINE_WIRE_TO_OPTICAL `
  CUSTOMER_BASELINE_STAGING_TO_WIRE
```

- [ ] `reports/customer-baseline-counts.csv` 已生成。
- [ ] 逐项记录时间差；实时变化与逻辑差异分开解释。

### 3. 10 轮顺序性能测试

```powershell
python runner/mes_lab.py run-factory `
  --bundle . `
  --config C:\private\mes-config.ini `
  --approval-json @C:\private\approval.json `
  --output-root C:\transfer\mes-runs `
  --query-id MES_TASK_UNION `
  --rounds 10 `
  --wait-seconds 10
```

- [ ] 不并发、不重叠；每轮完成后才等待 10 秒。
- [ ] 10 轮全部成功，平均不超过 5 秒，最大不超过 10 秒。
- [ ] 超时、告警或客户停止信号出现时立即停止，不扩大负载重试。

## 四、工厂回传

- [ ] 保留三个独立 `run-...` 目录，不能合并或改名复用。
- [ ] 每个目录含 `run-manifest.json`、`execution-log.md`、`results/` 和 `reports/`。
- [ ] 检查结果中无 `config.ini`、密码、完整连接字符串或参数值。
- [ ] 将原 bundle 和三个 run 目录一起回传；分别提供压缩包 SHA-256。

## 五、本机导入与反馈客户

对每个 run 分别执行：

```powershell
python mes/tools/mes_lab.py import-run `
  --bundle mes/.dist/mes-task-union-validation `
  --run-dir <回传的run目录> `
  --mes-root mes
```

- [ ] 已导入 `mes/evidence/runs/<run-id>/`，重复导入被拒绝。
- [ ] `mes/samples/mes-task-union/latest.csv`、`latest.md`、`latest.meta.json` 已刷新。
- [ ] `latest.meta.json` 包含 `sourceEvidence`、输出哈希和 PACKAGE 覆盖报告路径。
- [ ] 查看 `samples/mes-task-union/package-coverage/unmatched_packages.csv`。
- [ ] 把未匹配 PACKAGE、出现次数、任务类型分布和样例 SUBLOT 反馈客户补充容量。
- [ ] 不为近似字符串擅自继承容量；`TOLL-` 仅匹配 `TOLL-...`。
- [ ] 全量 PACKAGE 仍需按 `package-universe-discovery` 实验另行批准，活跃结果不能称全集。
