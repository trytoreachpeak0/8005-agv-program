# 工厂环境配置说明

## 原则

- 仓库只保存配置模板，不保存真实主机、端口、服务名、用户名、密码、令牌或完整连接字符串。
- 工厂环境使用本机 `config.ini` 或受控的密钥管理服务注入凭据；`config.ini` 必须保持在 `.gitignore` 中。
- runner、日志、manifest、evidence、samples 和传输包不得输出密码。
- 当前 MES 账号即使具有写权限，程序也必须使用只读事务并只允许执行查询目录中已登记的 SELECT。

## 配置占位符

本地配置应使用以下占位结构，实际值由客户 IT 通过安全渠道提供：

    [oracle]
    user = <ORACLE_USERNAME>
    password = <MES_PASSWORD_FROM_SECRET_STORE>
    dsn = <HOST>:<PORT>/<SERVICE_NAME>
    connect_timeout = 30
    call_timeout = 300000
    mode = thick
    instant_client_dir = <ORACLE_INSTANT_CLIENT_DIRECTORY>

不要把填入真实值后的文件复制到 evidence、samples 或工厂回传包。
Oracle 11g 必须使用 Thick 模式；Instant Client 目录也可通过
`ORACLE_CLIENT_LIB_DIR` 环境变量提供。

## 凭据处置与轮换

仓库历史中曾出现明文连接信息。客户 IT 应立即：

1. 停用或轮换已经暴露的密码。
2. 优先创建仅具有必要 SELECT 权限的专用账号，不继续使用可写账号。
3. 审计该账号自暴露以来的登录与写操作记录。
4. 确认开发机、聊天记录、邮件和共享盘中不存在额外副本。
5. 将后续凭据放入企业密钥管理系统，并规定轮换周期、责任人和吊销流程。

删除工作区中的明文文件不能清除 Git 历史；如该仓库曾被推送或共享，应由仓库管理员评估历史清理和下游克隆处置。

## 工厂回传

- 工厂只回传 runner 生成的证据包。
- 执行正式查询时，通过独立的批准 JSON 提供客户批准引用、执行窗口和范围；批准文件不得包含凭据。
- 回传前检查包内无 `config.ini`、环境变量转储、连接字符串和日志中的敏感值。
- 导入后按 [`../evidence/README.md`](../evidence/README.md) 校验 manifest 与哈希。
