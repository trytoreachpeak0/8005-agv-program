# 花篮没有独立身份，只追踪 SUBLOT 与仓位

同事初稿 §5.1 的装货输入只有 SUBLOT，没有逐篮扫码流程；项目现场的花篮本身也没有身份 ID。系统无法追踪具体花篮，不能根据装入顺序、仓位号或数组下标虚构花篮身份。

同一 SUBLOT 内的花篮作为 AnonymousBasket 处理。服务端保存物理仓位到 SUBLOT 的映射，并根据 OneBasketPerSlot 以 OCCUPIED 仓位数量核对 ExpectedBasketCount；不保存物理仓位到单篮 ID、序号或条码的映射。车载端只报告仓位占用事实，不解释产品身份。

目标仓位数组只表达完整集合，不表示花篮业务顺序。操作员无需逐篮扫描，可以随机选择已打开的目标仓位放入花篮；车载界面显示当前 SUBLOT、目标仓位和整批数量。全部目标仓位物理闭环后按 ADR-cross-0054 自动提交，StopClosureCommit 前仍可发起原仓位装货纠错。

**Status**: accepted

**Considered Options**:
- 按装入顺序自动生成花篮序号（拒绝：序号无法附着到实际花篮，取放后不可验证）
- 要求增加逐篮条码再实施身份追踪（拒绝：当前花篮没有身份 ID，项目不要求该能力）
- 只追踪 SUBLOT、仓位集合和数量，不追踪单个花篮（采纳）

**Consequences**:
- 服务端数据模型和接口不得出现必填 basketId。
- 审计可以回答某 SUBLOT 占用了哪些仓位、共有多少篮，但不能回答某个具体花篮的轨迹。
- 仓内光幕只能证明数量对应的仓位占用，不能证明放入产品确实属于当前 SUBLOT。
- 正确 SUBLOT 归属由已核验操作员的装货开始、目标仓位执行结果与业务审计共同承担；发现放错可在 StopClosureCommit 前执行追加审计的 LoadCorrection。
- 如果未来要求单篮追溯，必须新增物理标识和逐篮采集流程，属于新的业务协议版本。
- 初稿 §5、§17 和界面文案应使用“SUBLOT + 花篮数量”，不展示虚构的花篮编号。
