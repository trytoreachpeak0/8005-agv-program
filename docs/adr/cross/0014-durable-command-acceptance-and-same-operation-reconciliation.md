# 车载端持久化指令后才接受，超时沿用原仓位操作尝试编号对账

车载上位机只有在将完整仓位操作指令及其仓位操作尝试编号持久化到 OnboardExecutionJournal 后，才可回复 `OperationCommandAck.accepted=true`。服务端收到 ACK 前保持操作为等待接受并保留相关仓位；ACK 超时表示接受结果未知，服务端只能使用原仓位操作尝试编号重发相同指令或查询状态，不得生成新编号重试。车载端收到相同仓位操作尝试编号和相同内容时返回已有 ACK、进度或结果，不重新执行已发生的开门动作；相同编号携带不同内容时必须拒绝。只有明确收到 `accepted=false` 且确认没有启动 IO 动作后，服务端才可释放预留。

**Status**: accepted

**Considered Options**:
- 车载端先回接受 ACK、随后异步保存（拒绝：ACK 后崩溃会丢失已承诺执行的操作）
- ACK 超时后用新仓位操作尝试编号重试（拒绝：旧操作可能已执行，产生重复开门）
- 先持久化再接受，超时沿用原仓位操作尝试编号对账（采纳）

**Consequences**:
- `accepted=true` 表示车载端已经可靠记住操作，但不表示任何仓位已经完成。
- 服务端必须把“明确拒绝”与“ACK 未知”建模为不同状态，未知时不能释放仓位或启动替代操作。
- 仓位操作尝试编号的唯一性和防重复保存期限必须覆盖服务端可能重试和重连恢复的最长时间。
