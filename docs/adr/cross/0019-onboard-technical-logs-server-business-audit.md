# 车载端保存硬件技术日志，服务端保存业务审计

车载上位机保存 OnboardTechnicalLog，覆盖 Modbus 通信、DO/DI 变化、门锁与光幕判断、执行阶段、配置变更、重启恢复和本地异常；服务端保存 BusinessAuditRecord，覆盖操作员与 OperationSession、仓位操作尝试编号、任务与仓位业务关系、上下层命令和 ACK、可靠结果、调度动作与异常处置。车载端实时上报关键事件和错误摘要，但不持续上传每次 IO 轮询的全部原始数据；服务端排障时可按 AGV、时间和仓位操作尝试编号查询或拉取车载详细日志。两侧统一使用 AGV、操作、消息、配置和安全状态版本等关联标识。

**Status**: accepted

**Considered Options**:
- 所有车载原始日志持续集中上传服务端（拒绝：高频 IO 数据增加网络与存储负担，断线时仍会丢失现场证据）
- 只保留车载日志、不做服务端业务审计（拒绝：无法形成跨任务、人员和调度的权威追溯）
- 车载保留硬件细节，服务端保留业务审计并集中关键事件（采纳）

**Consequences**:
- 服务端日志不能替代车载原始技术证据，车载日志也不能作为服务端业务入账依据。
- 日志查询协议须支持按时间和关联标识拉取，而不要求把所有原始采样做成实时业务消息。
- 日志保留周期、容量上限和脱敏规则须分别配置并在部署验收前确定。
