# 车载上位机只持久化最小可恢复执行日志

> *2026-09-18：本文讲批量开锁（BatchUnlock）的部分拟由 [ADR-cross-0061](0061-one-slot-door-unlocked-at-a-time.md)（`proposed`）取代——业务仓位操作一次只开一扇仓门，按分组再按仓位号依次打开；随 `CP-0004` 批准生效，具体取代哪几句见该文 Consequences。其余正文不变。*

车载上位机持久化车载执行日志（OnboardExecutionJournal），只保存解释物理副作用和可靠恢复所需的最小因果上下文：当前仓位操作尝试编号、原指令摘要、装卸类型、目标仓位集合与逐仓/批量执行方式、关键执行阶段、当前开锁集合、逐仓进度与结果、当前 Sublot 引用、车载操作员上下文，以及尚未获得服务端确认应答（ACK）的进度和最终结果。完整运输任务、站点与路径、制造执行系统（MES）数据、Sublot 业务生命周期、仓位业务预留和调度计划仍只由服务端维护，车载上位机不得形成第二套业务任务数据库。

实时门锁、光幕、开锁输出回读和 IO 在线性在重启后重新读取，实时值才是车载物理事实；关机前观测最多作为预期物理检查点，不得覆盖实时 IO。车载程序按可唯一解释恢复（UniquelyExplainableRecovery）判定：日志阶段和实时 IO 只能导出一个安全结论、一个结果语义和一个合法下一步时，可以恢复已经开始的当前开锁集合；存在冲突、多种可能解释或任一相关状态为 `UNKNOWN` 时进入车辆待恢复态。若服务端暂未连接，仍只允许安全收尾已经开始的当前开锁集合，不得开始其它仓位。

**状态（Status）**: 已接受（accepted）

**考虑过的方案（Considered Options）**:
- 车载上位机完全无状态（拒绝：无法可靠处理重复命令、结果 ACK 丢失和进程重启）
- 在车载上位机复制完整任务与调度模型（拒绝：产生双主、离线分叉和复杂合并）
- 只持久化最小可恢复执行日志（采纳）

**影响（Consequences）**:
- 同一 `slotOperationAttemptId` 重发时，车载上位机必须返回已有进度或结果，不得重新执行已完成的开门动作。
- 开锁前必须先持久化“准备开锁”及完整目标集合，落盘成功后才允许发送单仓或批量开锁；逐仓完成和整个 Sublot 完成结果同样先落盘再上报。普通 IO 轮询不写日志。
- 脉冲 DO 在重启后已经自动复位属于可预期变化，不单独构成冲突；仍须结合当前执行阶段、锁 DI 和占用状态解释。
- 当前 Sublot 只有在全部目标仓位完成、结果上传并得到服务端确认后才算结束；此前不允许本地清除日志或切换工号。
- 日志清理必须晚于服务端确认结果及规定的重复命令防护期限；掉线暂停不设自动取消超时，维护人员也不能强制删除未结日志。
