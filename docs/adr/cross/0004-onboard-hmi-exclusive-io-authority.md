# 车载上位机独占 IO 控制与硬件安全裁决

> *2026-09-18：本文讲批量开锁（BatchUnlock）的部分拟由 [ADR-cross-0061](0061-one-slot-door-unlocked-at-a-time.md)（`proposed`）取代——业务仓位操作一次只开一扇仓门，按分组再按仓位号依次打开；随 `CP-0004` 批准生效，具体取代哪几句见该文 Consequences。其余正文不变。*

服务端只向车载上位机下发业务级仓位操作意图，包括仓位操作尝试编号、装卸类型、目标仓位集合及逐仓或批量执行方式；车载上位机是对应自动导引车（AGV）的唯一输入输出（IO）控制者，独占执行数字量输出（DO）脉冲与输出回读、数字量输入（DI）采样与稳定判断、门锁/光幕联锁以及逐仓或批量时序。服务端决定业务操作是否可以开始，车载上位机依据实时硬件状态独立决定该意图能否安全执行；服务端只能消费执行进度和安全状态，不得直连 IO、写入具体通道或绕过车载上位机强制开锁。

批量卸货采用批量开锁（BatchUnlock）：车载端先持久化完整目标集合并预检相关 IO 模块。同一模块内优先使用 Modbus `0x0F` 写多个线圈一次使能目标开锁 DO；跨模块时按模块分组并行发送，全部已计划分组发送完成后才进入统一反馈检查。跨设备不宣称物理绝对同时。任一模块通信失败时不得回滚已经打开的仓门，须逐仓显示成功、失败或未知并核验实时 DO/DI；成功仓位可以继续取空并关门，失败或未知仓位不得盲目重复开锁。

**状态（Status）**: 已接受（accepted）

**考虑过的方案（Considered Options）**:
- 服务端直接连接并控制每台 AGV 的 IO（拒绝：硬件安全依赖中央网络和服务可用性，且与车载实时执行状态产生双主）
- 服务端与车载上位机均可控制 IO（拒绝：无法建立唯一命令序列和可靠安全裁决）
- 服务端下发业务意图，车载上位机独占 IO 控制与硬件安全裁决（采纳）

**影响（Consequences）**:
- 既有需求中“本地服务器直接连接 IO 模块”的表述须按本决策修订，不能作为实现依据。
- IO 点位、脉冲和反馈等硬件细节不进入服务端业务命令；车载上位机应返回稳定的仓位执行结果和整车安全状态。
- 服务端授权不等于必然执行；车载上位机可以因 IO 离线、反馈失效、仓位实物状态不符或安全联锁失败而拒绝命令。
- 8005 项目的 8 个仓门位于同一 IO 模块，可用一次 `0x0F` 实现单模块批量开锁；其它项目若跨最多 4 个模块、52 个仓门，则只能实现按模块分组的逻辑批量开锁。
- 批量写请求成功只表示输出写入被模块接受；每扇仓门是否弹开仍必须依据各自锁 DI 判断，脉冲是否结束仍必须依据各自 DO 回读判断。
