# 业务仓位操作一次只开一扇仓门，按分组再按仓位号依次打开

用户 2026-09-18 按现场体感提出（[program#111](https://github.com/trytoreachpeak0/8005-agv-program/issues/111)）：装货时
两扇门同时开着，下面那扇碍事，操作员还可能顺手把它关上；卸货时另一扇门弹出来一点，要先把它推回去才能取当前仓的货。
取消清空与补偿清空同样是人从仓里取货。原决策要求批量开锁（ADR-cross-0035、0037 等），本 ADR 取代其中讲批量开锁的部分。
条文由 `CP-0004` 新增的 `REQ-0357` 与修订的 `REQ-0223`、`REQ-0353` 承载。

**一次只开一扇。**同一台车上，任一时刻最多一个仓位处于「开锁中」：从对它发出开锁脉冲（或发送结果不确定）起，到它闭环为止。
8005 没有门磁，系统看不到门是开是关，所以「开着」按系统能证明的事实定义。闭环有两种结局：

- 达到本操作的目标态：装货与纠错重放为 `OCCUPIED`，卸货、取消清空、补偿清空与故障货物受控取货为 `EMPTY`，同时锁传感器确认
  锁闭、开锁输出回读确认复位；
- 被判为 `UNKNOWN`。

因此当前开锁集合（ActiveUnlockSet）恒为零个或一个仓位。约束以整车为界：同车不同 SUBLOT 的物理操作本来就串行
（ADR-cross-0046），本条再收紧到任一时刻至多一扇。

**下一扇什么时候开。**前一仓达到目标态后，按顺序打开下一仓；仍须满足原有的开锁前条件：授权有效、车辆安全事实允许开锁、
没有断联。已处于目标态的仓位跳过不开（例如取消清空时已经 `EMPTY` 的仓位）。ExpectedSlotOccupancyClosureLoop 的自动重开
只重开当前这一仓，天然满足本条。

**前一仓进入 `UNKNOWN` 时停下。**后面的仓不开，整个操作暂停，按 ADR-cross-0058 决策 2 转人工恢复；对账后沿用原
SlotOperationAttemptId，从下一个未完成的仓按同一顺序继续，未开的仓如实报 `NOT_STARTED`。`UNKNOWN` 就是锁闭反馈无效或开锁
输出无法确认复位：那扇门关没关证明不了，再开下一扇就可能两扇同开。

**顺序：先分组，再仓位号。**同一仓位操作指令的目标集合内，先开 FRONT 分组，后开 REAR 分组（`SlotPosition`，ADR-cross-0059），
组内按仓位号从小到大。一条机台需求不跨组，所以大多数指令只涉及一组；跨组的只有公共站点的操作与跨 Sublot 的 `UnloadBatch`。

这个顺序与协议的关系要写清楚。`SlotOperationCommand.slots` 在协议 `v2.0.0` 里必须升序（`x-sortedAscending`），车载端也拒绝
非升序的数组。8005 当前的整车仓位模板把 1～4 号编为 FRONT、5～8 号编为 REAR，于是「先 FRONT 后 REAR、组内升序」**恰好等于**
仓位号升序，车载端按数组顺序执行即可，不改协议。**这个等价依赖模板的编号方式**：FRONT 编在 REAR 之前、各组内连续编号。
模板一旦改成交错编号（例如前后交替），升序就不再等于本规则，那时要么调整模板编号，要么改协议让数组顺序可以表达分组顺序，
二者择一，不能让车载端自行重排。

**适用与例外。**适用于凡由系统发开锁脉冲、引导人放取货的业务仓位操作：装货、卸货、取消清空、补偿清空、装货纠错重放、故障
货物受控取货（`REQ-0240`）、断联与重启后的当前开锁集合安全收尾，以及操作员在会话内的手工重开（`REQ-0223`）。纠错不是例外。

两处不适用：

- **维护开门模式**（`REQ-0226`，用户 2026-09-18 定为例外）：「一次进入可重复开关多个合格仓位」保持原样，可以同时开多扇。例外只
  覆盖维护开门模式本身。现有条文规定了维护开门期间阻止新仓位作业（`REQ-0229`），但没有规定「另一个仓位的业务操作尚未收敛时
  能否进入维护开门模式」，列为 `CP-0004` 第六节的待定问题，本 ADR 不自行决定。
- **强制机械取出**（`REQ-0241`）：由有资质的人应急机械开锁，系统此时停止发送开锁 DO，本条约束不到。

**取消授权到达时正在装的那扇门。**它就是当时唯一开着的门。先让它收尾（按 ADR-cross-0046 可以直接以 `EMPTY` 收尾，或进入
`UNKNOWN` 停下），它仍留在当前开锁集合里直到闭环；然后才按顺序逐个打开已装货的仓位。

**不变的部分。**

- 服务端一次冻结完整目标集合，一次分配与预留，`SlotOperationCommand.slots` 仍表达完整集合（ADR-cross-0035 的这一半不变）；
- 逐仓结果与证据，某仓失败不抹掉其它仓的结果；
- 开锁前先持久化完整目标集合，每次开锁前先持久化当前开锁集合（ADR-cross-0006）；
- 锁反馈未按期变化或输出未复位时不自动重复开锁；
- 业务提交粒度：装货整批自动提交（ADR-cross-0036、0054），8005 卸货逐仓清空业务状态（ADR-cross-0037）；
- 站点保护与离站条件。

**Status**: proposed（随 `CP-0004` 批准转为 accepted）

**Considered Options**:

- 维持批量开锁（拒绝：用户按现场体感否决，另一扇开着的门会碍事，还可能被误关）
- 依次发开锁脉冲、然后并发等各仓闭环（拒绝：各仓脉冲发完后多扇门仍同时开着，只是「逐个发脉冲」，不是一次一扇）
- 前一仓 `UNKNOWN` 时跳过它继续开后面的仓（拒绝：那扇门关没关证明不了，继续开就可能两扇同开；用户选停下转人工）
- 维护开门模式也一次一扇（拒绝：用户定维护模式例外，维护时由管理员自己掌握开几扇）
- 顺序只按仓位号、不提分组（拒绝：用户要求先分侧；在当前模板下两者等价，但写成「先分组」才能在模板变化时看出协议要改）
- 业务仓位操作一次一扇，服务端冻结完整集合，按分组再按仓位号依次打开，`UNKNOWN` 停下转人工（采纳）

**Consequences**:

- **取代的部分**，其余正文不变：
  - ADR-cross-0035：「车载端批量开锁」「同一模块优先用 Modbus `0x0F`、跨模块并行发送」「数组顺序不构成物理执行次序」
    「操作员可以按任意顺序放取、关门」「执行日志在批量写前持久化模块分组」。数组顺序现在就是开门顺序；
  - ADR-cross-0037：「下发给车载端批量开锁」「一次 `0x0F` 写多个线圈」「全部分组发送完成后统一检查反馈；操作员可以任意顺序
    取货和关门」「批量开锁允许物理部分成功……成功仓位继续取空」。部分成功仍按仓如实上报，但出错的仓之后的仓不再打开；
  - ADR-cross-0004：「批量卸货采用批量开锁」一段，以及后果中「一次 `0x0F` 实现单模块批量开锁」；
  - ADR-cross-0046、0052：取消清空「形成批量开锁集合一次性打开」及其多线圈写、跨模块分组语义，改为按本条逐个打开；
  - ADR-cross-0003：「装货与卸货都可能批量打开多个仓位」「当前开锁集合不是固定单仓」；当前开锁集合至多一个仓位；
  - ADR-cross-0006：「发送单仓或批量开锁」中的「批量」；
  - ADR-cross-0036：「一次分配……并批量开锁」中的「批量开锁」；「批量执行方式」读作逐个执行；
  - ADR-cross-0040：「批量开锁后的各仓位独立触发该闭环」，改为各仓依次触发。
- **协议不改。**`activeUnlockSlots` 单元素合法，`NOT_STARTED` 覆盖未开的仓，向量不要求同时开。两处措辞留到下一次破坏性发布：
  `CapabilitySnapshot.supportsBatchUnlock` 在本决策下恒为 `false`；`FP-IS-04` 的 scope 名 `DESTINATION_BATCH_UNLOAD`。
  `RecoveryStateReport.activeUnlockSlots` 按本决策读作「当前开着、尚未闭环的那一个仓位」。
- **站点耗时变长。**操作员不能再并行放取。站点离站等待期限（ADR-cross-0055）、ADR-cross-0058 的期限与 `REQ-0203` 的阈值投运前
  按实测重新标定。
- **卸货的一仓故障会挡住后面的仓**，直到人工恢复。这是停下转人工的代价，用户已接受。
- **实现（2026-09-18 核查，v2 车载端 `w2g/fp-v2-impl`）**：装货、卸货与清空、纠错、故障交接执行器都已是开一个、等闭环、再开下一个，
  前一仓 `UNKNOWN` 时停下并把后面的仓报 `NOT_STARTED`。唯一的违反出在装货途中取消：被中止的装货留下的开门与清空循环打开的
  仓可能同时开着，当前开锁集合还会丢掉前者。缺陷与改法记在 program#111 的评论里，由实现票修复。服务端不依赖批量开锁。
- **HMI 提示**改为逐仓「请在 N 号仓放入／取出并关门」。

**为什么新写一篇而不是逐篇回写。**批量开锁分散在九篇 ADR 里，每篇讲的是别的决定（断联收尾、IO 独占、恢复日志、取消流程），
批量开锁只是其中的执行方式。逐篇回写要改九处正文，而且每处都得重述一次规则，改漏一处就留下两种口径。新写一篇把规则集中在一处，
九篇各加一行指针指向这里，读旧 ADR 的人第一行就知道哪部分已被取代。
