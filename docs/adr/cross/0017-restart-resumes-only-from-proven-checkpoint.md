# 车载重启后只从可证明检查点恢复原操作

车载程序重启后先加载车载执行日志（OnboardExecutionJournal），再重新读取实时门锁、光幕、开锁输出回读和 IO 在线性；实时 IO 是当前物理事实，关机前观测只作为比较依据。只有日志阶段与实时 IO 能导出唯一安全结论、唯一逐仓结果语义和唯一合法下一步，且重连后能与服务端操作事实共同形成可证明恢复点（ProvenRecoveryCheckpoint）时，服务端才可明确授权后续仓位继续；不得从头重做或重新打开已完成仓位。若未结操作曾因锁 DI 等硬件故障进入 VehicleRecoveryRequired，即使重启后信号恢复，也必须先取得 HardwareRecoveryConfirmation，不能仅凭可证明检查点自动续行。

若重启发生在开锁命令已发但反馈未知的阶段，车载端不得再次发送开锁输出，而应按实时物理状态执行当前开锁集合安全收尾（SafelyFinishActiveUnlockSet）。服务端暂未连接时也允许完成该集合，但不得扩大集合或开始后续仓位。日志缺失、损坏、状态为 `UNKNOWN`、存在多个可能解释或与任一事实冲突时，操作保持阻断并转人工对账。

**Status**: accepted

**Considered Options**:
- 重启后从操作开头自动重做（拒绝：会重复产生不可逆开门和装卸副作用）
- 所有重启一律转人工（拒绝：已有可靠日志和一致物理事实时没有必要放弃自动恢复）
- 从可证明检查点经服务端授权恢复，无法证明时转人工（采纳）

**Consequences**:
- 车载启动完成不等于业务可继续；恢复前 StationOperationGuard 保持有效。
- 恢复协议必须传递原仓位操作尝试编号、逐仓进度、当前阶段和实时 IO 摘要。
- 开锁准备阶段必须在产生 DO 副作用前落盘；否则“日志显示未开锁、实时锁 DI 显示未锁”无法唯一解释。
- 脉冲模式下 DO 在重启前后自动复位属于预期硬件行为，不能脱离锁 DI、占用状态和执行阶段单独判为异常。
- 人工对账只能确认或修复事实，不能删除原操作与恢复历史。
