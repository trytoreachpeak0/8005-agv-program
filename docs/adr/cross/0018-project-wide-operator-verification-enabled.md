# 装卸身份核验分别采用项目级策略，8005 装货启用、卸货关闭

操作员身份核验按装货和卸货分别定义项目级策略，不按 AGV、站点或单次操作配置，也不允许现场临时切换。8005 项目装货身份核验启用：车载上位机采集工牌或工号，服务端调用 MES 核验身份与岗位权限；核验成功前不得提交新的 Sublot。8005 项目卸货身份核验关闭：服务端根据当前站点和在车业务状态自动识别可卸仓位并下发批量卸货，不要求输入工号，也不得虚构操作员身份。

车载端持久化车载操作员上下文（OnboardOperatorContext）。同一到站期间可以连续处理多个 Sublot，新 Sublot 默认沿用当前已核验工号；只有不存在活动或待服务端确认的 Sublot 时，用户才能主动更换工号，新工号必须重新经服务端校验。同一 Sublot 从首次开锁到全部结果上传并得到服务端确认期间不得换人。掉线和车载重启保留工号及当前 Sublot 绑定，不重复验证；只有用户主动离站后才清除工号。

**Status**: accepted

**Considered Options**:
- 只使用一个装卸共用开关（拒绝：8005 装货需要追溯操作员，而自动批量卸货不需要输入工号）
- 按 AGV、站点或单次操作分别启停（拒绝：同一项目产生不一致的操作规则和绕过路径）
- 车载端本地决定是否核验（拒绝：现场可绕过服务端权限与审计）
- 装货与卸货分别采用项目级策略，8005 装货启用、卸货关闭（采纳）

**Consequences**:
- 装货流程须在提交 Sublot 前取得有效工号；工号输入与 Sublot 提交使用不同消息和状态。
- 卸货流程不得引用“必须已有操作员会话”的前置条件；策略关闭时业务审计记录策略版本和“未要求操作员”，而不是伪造人员。
- 操作会话（OperationSession）覆盖一次到站和多个 Sublot，但操作员绑定以 Sublot 为不可切换边界，不再以整次到站首次开门为锁定边界。
- 服务端与车载端对策略版本认知不一致时，不得开始新的站点操作。
- 其它项目可在后续版本改变两个项目级策略，但第一版不提供按站点或按任务覆盖。
