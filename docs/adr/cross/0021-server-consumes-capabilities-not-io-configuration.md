# 服务端只消费仓位能力，不读取 IO 配置

原始 IO 配置完全归车载上位机，服务端不读取或保存 IO 模块地址、DO/DI 通道、寄存器、信号极性、脉冲参数或映射文件。车载端只向服务端提供 OnboardCapabilitySnapshot，包括仓位数量、物理仓位号、逐仓 SlotOperability、抽象不可用原因、能力版本和观测时间；服务端据此在 OperationCommitPoint 前完成业务仓位分配检查。配置维护完成后，车载端只上报 IO 配置版本/指纹与完整能力快照供服务端重新投运核对，不提交原始配置或逐仓拟议差异，原始配置始终不出车载端。

**Status**: accepted

**Considered Options**:
- 服务端读取完整 IO 配置并保存只读副本（拒绝：泄漏硬件实现细节且无业务用途）
- 服务端严格只知道仓位总数（拒绝：无法在不可撤回指令发出前排除不可操作仓位）
- 服务端消费最小仓位能力快照，不读取 IO 配置（采纳）

**Consequences**:
- 服务端业务代码只能使用物理仓位号和抽象可操作性，不能依赖任何 IO 通道或设备型号。
- 车载端拒绝不可操作仓位仍是最终安全防线，但服务端须使用最新有效能力快照尽量在发指令前排除它们。
- 能力快照缺失、过期或版本不明时，服务端不得向该车提交新的仓位操作。
