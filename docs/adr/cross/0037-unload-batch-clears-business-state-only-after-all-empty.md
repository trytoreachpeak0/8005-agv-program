# 8005 卸货跨 Sublot 批量开锁，按仓位独立清空业务状态

> *2026-09-18：本文讲批量开锁（BatchUnlock）的部分由 [ADR-cross-0061](0061-one-slot-door-unlocked-at-a-time.md) 取代——业务仓位操作一次只开一扇仓门，按分组再按仓位号依次打开；已随 `CP-0004` 批准生效（2026-09-18，需求基线 `v1.4.0`），具体取代哪几句见该文 Consequences。其余正文不变。*

卸货操作员核验和卸货 Sublot 完整性分别是项目级策略。8005 项目两者均关闭：卸货不输入 Sublot、不输入工号；服务端根据当前站点、任务目标和在车仓位业务状态自动识别本站全部可卸仓位，允许目标集合跨多个 Sublot，并通过一个卸货批次（UnloadBatch）下发给车载端批量开锁。

车载端在产生输出前持久化完整目标集合和模块分组。8005 的 8 个仓门位于同一 IO 模块，优先使用一次 Modbus `0x0F` 写多个线圈；其它项目跨模块时按模块并行批量写。全部已计划分组发送完成后才统一检查反馈；操作员可以任意顺序取货和关门。

每个仓位达到 `EMPTY + 锁闭 + 开锁输出已复位` 后形成可靠逐仓结果；服务端可以立即清空该仓位与 Sublot 的业务关联，不等待同一 Sublot 或本次卸货批次的其它仓位完成。已经清空的仓位不得因其它仓位失败而回滚为有货。车辆仍受站点操作保护约束，所有目标仓位完成或经服务端明确异常处置前不得离站。

批量开锁允许物理部分成功：成功仓位继续取空和关门，失败或状态未知仓位保持待处理，不得盲目重复开锁。通信恢复或故障排除后沿用原仓位操作尝试编号从可证明恢复点继续；已经取出的产品不要求放回，也不存在反向补偿。

**Status**: accepted

**Considered Options**:
- 每个 Sublot 全部取空后才整体清空（拒绝：8005 要求本站全部可卸仓位一次全开并减少操作）
- 中途失败时把已取出产品放回以恢复原状（拒绝：不符合现场卸货流程，也扩大人工错误风险）
- 跨 Sublot 批量开锁，逐仓物理完成后独立清空业务状态；异常仓位单独恢复（采纳）

**Consequences**:
- 8005 不使用 ProvisionalUnloadState 延迟已完成仓位清空；其它项目若将卸货 Sublot 完整性策略设为开启，须另行启用整批提交语义。
- 一个 Sublot 可以在业务上出现“部分仓位已在本站交付、其它仓位仍待处理”的可追溯状态，这是当前项目明确接受的结果。
- 卸货失败不会进入 LoadCompensationRecovery；排障后继续原操作。
- OperationResult 既是逐仓物理事实，也是逐仓业务清空的提交依据；整个 UnloadBatch 结束只决定车辆何时可以结束本站卸货保护。
