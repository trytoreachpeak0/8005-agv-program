# 仓内光幕作为仓位有货与空仓的物理证据

> *2026-09-18：「操作员可以在反复无法达到预期时暂停并呼叫设备维护」一句的具体形态见 [ADR-cross-0062](0062-server-side-slot-fault-declaration-enters-recovery.md)（`proposed`）——车载端等待过久时上报超时，由管理员在服务端依据现场事实判为 `UNKNOWN` 后进入恢复；随 `CP-0005` 批准生效。其余正文不变。*

> *2026-09-18：本文讲批量开锁（BatchUnlock）的部分拟由 [ADR-cross-0061](0061-one-slot-door-unlocked-at-a-time.md)（`proposed`）取代——业务仓位操作一次只开一扇仓门，按分组再按仓位号依次打开；随 `CP-0004` 批准生效，具体取代哪几句见该文 Consequences。其余正文不变。*

同事初稿 §4.2 为每个仓位配置光幕 DI，§8 将光幕纳入逐仓操作序列。项目实际光幕安装在仓位内部，能够检测产品是否留在仓内，而不只是检测门口临时遮挡。因此车载端以仓内光幕及其数据有效性形成 SlotOccupancyState：

- 光幕在线、数据有效且稳定遮挡：`OCCUPIED`。
- 光幕在线、数据有效且稳定无遮挡：`EMPTY`。
- 光幕故障、IO 通信离线、数据无效或状态无法稳定确认：`UNKNOWN`。

装货仓位只有在 OCCUPIED、锁传感器有效反馈确认仓门锁闭且开锁输出回读确认为复位后才算物理完成；正常卸货与 LoadCompensationRecovery 只有在 EMPTY、锁传感器有效反馈确认仓门锁闭且开锁输出回读确认为复位后才算物理完成。当前硬件没有独立的门关闭传感器，不另设“门已关闭”完成条件。UNKNOWN 必须阻断完成判定和后续业务提交，不允许用操作员确认覆盖。

所有正常与补偿性仓位操作统一执行 ExpectedSlotOccupancyClosureLoop。锁传感器给出有效锁闭反馈后，车载端读取稳定的 SlotOccupancyState：装货与 LoadCorrection 重放预期 OCCUPIED，卸货、LoadCompensationRecovery 和 LoadTaskCancellation 清空预期 EMPTY。若读到明确相反状态，当前仓位不记为完成，车载端自动再次输出开锁脉冲使仓门弹开，并提示操作员重新放入或取出；关闭后重复核对，直到达到预期状态，不设置“超过若干次便强制通过”的上限。批量开锁后的各仓位独立触发该闭环，已经达到预期并安全锁闭的仓位不因其它仓位不符而重新打开。

SlotOccupancyState 为 UNKNOWN、锁闭反馈无效或开锁输出无法确认复位时，不执行自动重开循环，而是暂停当前操作并进入恢复；软件不得把传感器故障当成“放错/漏取”。

操作员可以在反复无法达到预期时暂停并呼叫设备维护，但暂停不形成成功结果，也不解除 StationOperationGuard 或 SublotReservation。硬件反馈恢复有效后仍不得自行续行；取得 HardwareRecoveryConfirmation 并由服务端明确授权后，才继续原仓位目标态闭环。只有对应业务明确允许的清空并取消等出口才能改变原操作目标。

操作员负责实际放入或取出产品，不需要额外点击“已装入/已清空”作为物理证明。所有进入系统的花篮必须满足 DetectableLoadConstraint，客户不得放入尺寸过小、姿态无法可靠遮挡光幕或不属于任务的物品。

当前若光幕只有单一状态 DI、无法自诊断“信号卡死为无遮挡”，该类不可检测故障作为已知剩余风险，由设备维护、定期检查和客户产品约束承担；软件不能把无法观测的故障宣称为已检测。

**Status**: accepted

**Considered Options**:
- 只用操作员按钮确认有货或空仓（拒绝：已有仓内检测能力，且人工确认更容易误操作）
- 将光幕只用于门口防夹，不参与占用判断（拒绝：不符合实际安装位置和用途）
- 使用有效仓内光幕形成三态占用证据，故障或无效时进入 UNKNOWN（采纳）

**Consequences**:
- IO 适配层必须把原始 DI 极性和有效性归一化为 SlotOccupancyState，业务流程不得直接解释原始电平。
- 初稿 §8 应明确装货需要 OCCUPIED、卸货和补偿需要 EMPTY，而不仅描述光幕触发过程。
- 装货、纠错、卸货、补偿和取消共用仓位目标态闭环；明确相反状态自动重新弹锁，UNKNOWN 则暂停恢复。
- 目标态闭环没有可强制放行的重试次数上限；人工暂停只用于求助维护，不改变业务结果或离站保护。
- SlotOccupancyState 属于 SlotPhysicalState，由车载端负责；服务端只接收可靠结果和抽象状态。
- 光幕只能证明仓位有货或空仓，不能计数；产品数量约束由 ADR-cross-0041 的 OneBasketPerSlot 保证。
- 项目验收与操作规程必须写明 DetectableLoadConstraint，并用允许的最小花篮和最不利放置姿态验证遮挡。
- 光幕或 IO 无效时不能通过人工点击强行提交，只能排障恢复或进入人工维护流程。
