# 装货整批成功才提交，硬件故障暂停等待人工处置

> *2026-09-18：本文讲批量开锁（BatchUnlock）的部分由 [ADR-cross-0061](0061-one-slot-door-unlocked-at-a-time.md) 取代——业务仓位操作一次只开一扇仓门，按分组再按仓位号依次打开；已随 `CP-0004` 批准生效（2026-09-18，需求基线 `v1.4.0`），具体取代哪几句见该文 Consequences。其余正文不变。*

同事初稿 §5.1 所称“总任务码”实际就是操作员输入的 Sublot。服务端根据 Sublot 解析唯一任务和不可修改的 ExpectedBasketCount，一次分配数量相等的完整仓位集合并批量开锁，同时保留逐仓结果。业务上一个任务只对应一个 Sublot，一个 Sublot 包含 1～N 个待存放花篮；因此整个任务是一个 LoadBatch，逐仓结果只是物理过程，不能形成逐仓正式业务提交。

服务端在 OperationCommitPoint 前必须按 ADR-cross-0041 确认花篮数量与完整目标仓位数量相等，冻结任务、子批号、产品数量、目标仓位集合和批量执行方式，并一次性预留全部目标仓位。无法容纳整批产品时不得发送 SlotOperationCommand，车载端不得打开任何仓位。

执行期间，服务端根据可靠逐仓 OperationResult 维护 ProvisionalLoadState，但不把已完成仓位逐仓正式提交为已存入。全部目标仓位均按 ADR-cross-0040 由仓内光幕确认 OCCUPIED、由锁传感器确认仓门锁闭且开锁输出回读确认为复位，且安全状态有效后，服务端按 ADR-cross-0054 在一个业务事务中自动提交子批号、整批产品和全部目标仓位的 SlotBusinessState。

任一目标仓位发生开锁、机构、通信或关键反馈故障时，尤其锁 DI 失效导致无法证明仓门是否锁闭时，车载端必须停止发送尚未发出的模块分组，并且不得分配替代仓位、不得发出任何新增或续行开锁指令。已经随原批量命令打开或结果未知的仓位保留逐仓事实；服务端继续保持原目标仓位集合、ProvisionalLoadState、全部预留和 StationOperationGuard，车辆不得离站。

硬件故障不自动把 LoadBatch 转为 LoadCompensationRequired，也不自动要求清空该 SUBLOT 已经放入的全部花篮。系统进入 VehicleRecoveryRequired 并等待人工检查和明确处置；人工决定之前，既不得继续装货，也不得自动重开已装仓位执行整批清空。

故障修复后，只有通信、锁 DI、光幕和开锁输出回读等相关实时物理状态重新有效且可唯一解释，并取得 HardwareRecoveryConfirmation，服务端才可明确授权在原目标仓位、原 LoadBatch、原 SlotOperationAttemptId 上继续。HardwareRecoveryConfirmation 只能由 R-11 设备/电气维护人员或被显式授予等效维护权限的人员以个人身份提交；普通生产操作员不能代确认，系统必须审计确认人、时间、车辆、仓位和故障原因。信号恢复或确认提交本身均不得自动续行，不创建新尝试，也不得改分仓位。若不再继续而要整批清空，则必须先由 R-09 班组长或被显式授予等效生产管理权限的人员作出 LoadCompensationDecision，再由服务端授权进入 ADR-cross-0039 的 LoadCompensationRecovery；R-11 的硬件恢复确认不包含该业务决定。

**Status**: accepted

**Considered Options**:
- 每个仓位成功后立即正式入账（拒绝：会产生一个子批号只存入部分花篮的业务状态）
- 首个失败后自动换成其它空闲仓位继续（拒绝：锁 DI 等硬件反馈可能已经失效，无法证明原仓门状态，扩大开门范围不安全）
- 任一硬件失败都自动要求整批清空（拒绝：在故障原因和仓门状态尚不明确时继续开门清空，同样会扩大风险）
- 全部成功后整批提交；硬件失败保持现场、预留与逐仓事实，停止新增开门并等待人工决定（采纳）

**Consequences**:
- ADR-cross-0013 中原先“逐仓结果分别业务入账”的结论被本 ADR 取代；逐仓结果继续作为物理证据。
- LoadBatch 的全有或全无约束最终业务提交，不代表硬件故障发生时必须立即或自动执行整批物理清空。
- 服务端必须区分目标仓位预留、ProvisionalLoadState 和正式已存入三种业务阶段。
- 全部仓位物理成功即形成 LoadBatch 自动提交边界；StopClosureCommit 前仍允许按 ADR-cross-0054 对原仓位执行追加审计的 LoadCorrection。
- 故障发生后不得改分仓位；原目标仓位、已完成结果和状态不确定结果必须完整保留。
- 物理信号恢复和人工确认缺一不可；两者满足后仍须由服务端明确授权，车载端不能自行恢复。
- 硬件恢复确认属于 R-11 或等效维护权限，不属于普通生产操作权限；确认必须绑定个人身份并形成可追溯审计记录。
- 故障后的整批清空决定属于 R-09 或等效生产管理权限；R-11 只确认设备状态，普通生产操作员只能申请。兼任者必须同时具备两项独立权限，不能以一项权限代替另一项。
- 取得 LoadCompensationDecision 后，车载恢复引导必须覆盖已完成仓位和状态不确定仓位，不能只处理明确失败仓位。
- 补偿结果也必须可靠、可去重并关联原 SlotOperationAttemptId，便于重启和断线恢复。
- 初稿 §17 应保留逐仓明细，但将正式装货结果定义为整批成功或整批补偿完成。
