# 发车后安全许可失效必须自动介入车辆移动

服务端通过 PreDepartureSafetyCheck 后一旦向 RIOT 提交车辆移动请求，车载上位机若发现 DepartureSafe 由 true 变为 false，必须立即发送 DepartureSafetyRevoked；服务端收到后不得只告警或等待人工，必须自动阻止尚未执行的移动或停止已经开始的移动。车载上位机仍不直接调用 RIOT，具体采用暂停、取消或急停由后续分级策略决定，但“自动介入”本身不可省略。

**Status**: accepted

**Considered Options**:
- 仅记录告警并等待现场人员处理（拒绝：车辆可能在仓位机构不安全时继续移动）
- 车载上位机直接调用 RIOT 停车（拒绝：破坏服务端对移动任务和调度的唯一控制）
- 车载端撤销安全许可并高优先级上报，服务端自动介入 RIOT 移动（采纳）

**Consequences**:
- 上下层协议须提供独立、可靠且可去重的安全许可失效事件，不能依赖普通进度消息或最终结果。
- 服务端必须把安全许可与已提交的 RIOT 移动关联，直到明确知道该移动未执行、已停止或已完成。
- 停车命令的风险分级、确认条件和失败升级路径须另行确定。
