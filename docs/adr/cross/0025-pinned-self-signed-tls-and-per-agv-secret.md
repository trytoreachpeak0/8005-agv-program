# 使用固定信任的自签名 TLS 证书与每车共享密钥

厂内没有可用 CA，项目也不建设企业级证书体系；车载—服务端 TCP 长连接使用服务端自签名 TLS 证书，车载端固定信任该证书或公钥，并在加密连接内使用与 `agvId` 绑定的独立共享密钥验证 VehicleCredential。第一版不采用双向 TLS，不为每台车签发客户端证书；IP 白名单仅作可选附加限制。证书或公钥固定值与车辆密钥通过部署配置提供，密钥不进入仓库和普通日志。

**Status**: accepted

**Considered Options**:
- 厂区内网直接使用明文 TCP 且只校验 `agvId`（拒绝：无法阻止连接冒充和消息窃听）
- 建设私有 CA 并使用双向 TLS（拒绝：当前项目规模与安全要求不足以承担证书体系运维）
- 固定信任自签名服务端证书，连接内使用每车独立共享密钥（采纳）

**Consequences**:
- 服务端证书更换必须同步更新车载端固定信任值，否则车辆无法连接。
- 共享密钥可先使用受文件 ACL 保护的部署配置保存，不要求第一版引入独立密钥管理系统。
- TLS 与认证失败不得降级到明文或匿名连接。
