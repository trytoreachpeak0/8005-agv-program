# 仓位身份稳定，IO 配置只在整车配置维护态换版

仓位身份（SlotIdentity）固定为 `AGV 标识 + 物理仓位号`，不随数字量输出/数字量输入（DO/DI）映射、配置版本或仓位可操作性（SlotOperability）改变；配置缺失或硬件不可用只能把仓位标记为未配置或不可操作，不能让服务端删除仓位或释放其业务内容。仓位模型和 IO 配置在正常运行期均视为冻结，不提供运行中热变更、逐仓差异提交或服务端在线审批 IO 映射。

仓位模型及其面、位置和跨度由服务端维护权威版本；因车载人机界面（HMI）必须按真实位置显示仓门，车载上位机须持久化服务端面向本车生成的版本化车载仓位布局快照（OnboardSlotLayoutSnapshot），并用物理仓位号将它与本地仓位 IO 绑定（SlotIoBinding）关联。当前一仓一门，仓门不建立独立身份；当前生效 IO 配置必须以物理仓位号为键表达逐仓开锁输出、锁闭反馈和仓内光幕映射，不能只保存无仓位归属的 DO/DI 通道列表。

需要修改仓位布局，或者修改 IO 模块/通道、信号极性、脉冲参数等映射细节时，必须先在线请求服务端进入车辆配置维护态（VehicleConfigurationMaintenance）。服务端只在确认整车没有活动仓位操作、业务内容或预留后，才持久化该状态并阻断新任务和移动。进入维护态后，车载端本地编辑、校验和激活期间允许服务端临时断线；但断线状态不能自行进入维护态。

激活前，车载端必须按当前有效配置确认全部仓位的仓位占用状态（SlotOccupancyState）均为 `EMPTY` 且数据有效、全部仓门由锁传感器确认锁闭、全部开锁输出回读确认为复位；任一仓位有货、状态为 `UNKNOWN` 或两侧事实不一致都禁止激活。维护人员在车载端本地校验、实际 IO 验证并原子激活候选配置，失败时继续使用上一版；激活完成后再次核验整车空仓和机构安全。车载端重新连接并上报仓位模型版本、布局校验值、IO 配置版本与指纹以及完整车载能力快照（OnboardCapabilitySnapshot）；服务端核对仓位集合、能力和物理/业务状态后，由人员明确重新投运，车辆才能再次取得业务就绪。

**状态（Status）**: 已接受（accepted）

**考虑过的方案（Considered Options）**:
- 每次变更都提交逐仓能力差异，由服务端在线审批后激活（拒绝：配置极少变化，不值得长期维护专用双端审批协议和状态机）
- 正常运行中允许车载端直接热加载配置（拒绝：可能在业务占用或活动操作期间改变实际硬件控制关系）
- 正常运行期冻结配置，整车进入配置维护态后由车载端本地换版，完整对账后重新投运（采纳）

**影响（Consequences）**:
- 配置快照必须表达固定物理仓位及其配置/可操作状态，缺少某仓位不能解释为该仓位不存在。
- 服务端是仓位布局模型的权威来源，车载端保存只读车载仓位布局快照（OnboardSlotLayoutSnapshot），供 HMI 在重启或暂时断联后继续按真实位置显示；该本地快照不得独立编辑成另一套仓位模型。
- 当前生效 IO 配置中的每项仓位 IO 绑定（SlotIoBinding）必须引用车载仓位布局快照（OnboardSlotLayoutSnapshot）中已有的物理仓位号；布局存在但 IO 绑定缺失时，该仓位仍保留在 HMI 原位置并标记为未配置或不可操作。IO 绑定引用未知仓位或布局版本/校验值不匹配时，整组配置不得激活，车辆不得因此取得业务就绪。
- 服务端不保存 IO 配置副本或逐仓配置差异，只保存换版后的版本/指纹、车载能力快照（OnboardCapabilitySnapshot）和重新投运审计；原始 DO/DI 映射始终只在车载端。
- IO 配置换版会停用整车而不是只锁住受影响仓位，这是用低频维护窗口换取更简单交互和更小实现面的明确取舍。
- 即使只改变 HMI 上仓位所属面、位置或跨度，也必须在车辆配置维护态下载并激活新的车载仓位布局快照，不允许运行中热更新。
- 增减仓位、修改物理仓位号或改变仓位模型结构须发布新的仓位模型版本，并按同样的整车空仓、维护和重新投运边界处理。
- 车载端根据 IO 映射、在线性和安全条件形成仓位可操作性（SlotOperability）；服务端人工启用/禁用属于独立的仓位管理可用性（SlotAdministrativeAvailability）。最终只有两者都允许的仓位才可使用，人工启用不能覆盖硬件故障。
- 人工禁用未被活动 Sublot 占用的仓位时立即生效；仓位已分配给活动 Sublot 时进入待禁用（Disable Pending），允许该 Sublot 按既有承诺完成并在服务端确认结束后生效，同时禁止新 Sublot 再分配。硬件不可操作不采用延迟规则，必须立即阻断尚未开始的开锁。
- 本系统不支持有货状态下修改 IO 配置，也不为该场景设计自动或人工例外分支；任一仓位有业务内容、物理占用或状态未知时都必须拒绝激活。
- 若仓位因故障、配置损坏或绕过流程而意外不可用，服务端须保留其仓位业务状态（SlotBusinessState），阻断该车的新任务和离站；如仓内有货，必须先执行受控人工清空和两侧对账，满足整车无货条件后才能恢复或更换映射。
