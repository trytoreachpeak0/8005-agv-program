# 急停锁住即视为停稳，人员在服务端确认后由服务端解除

2026-09-15 agv02 上三次急停，每次 RIoT 回查读到 `emergencyState=CAN_RECOVER` 时车都已停住；但订单仍在执行时锁住的车
持续报 `MT_RUNNING` 加 `speed=0`，停在两站之间时站点号为 0、位置未知，产品的组合停稳证明（`REQ-0247`）永远不成立，
服务端解不开自己的急停，现场在 RIoT 里手动解锁又会被当成意外恢复立即重触发（`REQ-0248`）。本条决定锁住之后怎么判停、
怎么解除。条文见需求变更提案 [`CP-0003`](../../../requirements/change-proposals/CP-0003.md)，问题见
[control-server#63](https://github.com/trytoreachpeak0/8005-agv-control-server/issues/63)。

**锁住即停稳。**急停状态经回查确认为 `CAN_RECOVER` 或 `CAN_NOT_RECOVER`，就视为车辆已停稳，不再另读运动状态、速度或
位置；急停状态回到 `OK` 后不再适用。它只对急停成立：订单 HELD 或单次查询仍不证明停稳，决定要不要发急停时仍用组合证据。
用户的理由是「急停一定会停稳啊，这个不需要再去读了啊」。

**解除有两条路径。**既有的自动解除保留：本车自己触发、`CAN_RECOVER`、原因消除、安全条件通过，其中停稳按上一段。
新增人工确认：服务端已登录且有车辆查看权限的人员选中车辆，确认原因已消除、车上无货、全部仓门已关闭并记下身份，服务端
自己调用 `cancelEmergency`、回查 `OK`，并结束本次急停，所以这次解除不算意外恢复、不重触发。它适用于自动触发、车载端请求、
服务端人员请求三种来源。车载端不能确认，不要第二人确认。**该车仍有未终结的订单时不得解除，须先取消订单**：锁住时订单
仍在执行，一解除 RIoT 就可能让车接着开，而确认的人可能就在车旁。`CAN_NOT_RECOVER` 仍禁止解除，转 RIoT 人员。解除只结束
急停，不恢复派车资格、不解除故障阻断。

**Status**: accepted（2026-09-15 随 `CP-0003` 批准由 proposed 转）

**Considered Options**:
- 锁住后仍按 `REQ-0247` 的完整组合证据判停，两站之间的位置改用 `getVehicleInfo.precisePosition` 的坐标补上（拒绝：用户认为急停一定停稳，不需要再读）
- 选项 a：闩锁确认 ＋ 车辆在线且读数新鲜 ＋ 车速连续 1～2 秒为 0（拒绝：同上。提出它是为防车离线时闩锁读数过时——agv02 2026-09-14 断联期间报过 `CAN_NOT_RECOVER`——以及锁住初期车仍在减速）
- 不改判停规则，只加人工确认解除（未采纳：用户同时定了锁住即停稳；只加人工路径时，锁住的车在两站之间仍证不出停稳，自动解除与以停稳为前提的处置照样走不通）
- 允许车载端确认恢复（拒绝：恢复从严；车载端请求急停无需登录、不留身份）
- 人工确认要第二人（拒绝：与 `REQ-0253` 不重新引入双角色批准的口径一致）

**Consequences**:
- **接受两处风险**：车离线时闩锁读数可能过时；锁住初期车可能仍在减速（2026-09-15 第二次运行读到 `CAN_RECOVER` 与车速归零相差约 0.06 秒）。现场出现反例时经新的变更提案重开，不在实现里自行加读。
- 基线里凡以停稳为前提的条目（`REQ-0225`、`0234`、`0240`、`0245`、`0251`、`0261` 等）连带生效，锁住的车满足「已停稳」。
- **ADR-cross-0011 不改**：它说的「不能仅凭命令接口返回成功认定已停止」针对命令受理，本条认的是回查到的急停状态。
- 人员确认「仓门已关闭」只用于解除急停，不是移动所需的锁闭证明（`REQ-0244`）。
- 人工确认路径要求订单已终结，所以订单不能原地续跑；要续跑走 `REQ-0239` 修复续行。「已终结或已 HELD 均可」未采纳：HELD 订单解除急停后是否保持暂停没有实测。
- 以停稳为前提的条目连带放宽，用户 2026-09-15 确认接受。
- `docs/riot-call-allowlist.md` 第 1.5 节「解除前车载端必须确认」须跟改，`8005-agv-control-server` 钉着该文档 SHA-256 的架构测试同步更新。
- 本条是接上任何能让行驶中的车急停的触发（`REQ-0249` 请求、白名单 1.5 节的仓门触发、`REQ-0232` 所列症状）以及生产切到 v2（program#61）的前置。
