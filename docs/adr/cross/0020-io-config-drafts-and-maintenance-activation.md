# IO 配置草稿可离线编辑，只能在整车配置维护态激活

第一版不提供 IO 配置编辑界面或应用内维护权限，配置由软件人员直接维护文件；尚未激活的候选文件视为 IO 配置草稿（IoConfigDraft）。服务端断线时允许编辑、保存并执行格式、必填、通道冲突与范围等本地静态校验，但文件修改不得自动热加载、替换当前生效配置、控制真实 IO 或改变仓位可操作性（SlotOperability）。

激活候选配置前，服务端必须确认整车没有活动仓位操作、业务内容或预留，并已经将整车持久化置为车辆配置维护态（VehicleConfigurationMaintenance），阻断新任务和移动；车载端必须确认全部仓位的仓位占用状态（SlotOccupancyState）均为 `EMPTY` 且数据有效、仓门锁闭且开锁输出已复位。任一仓位有货、状态为 `UNKNOWN` 或两侧事实不一致都禁止激活。维护人员显式重新加载或在受控维护窗口重启程序后，车载端检查草稿基准版本、仓位布局兼容性，完成实际 IO 验证并原子激活；任何检查或验证失败都继续使用上一版配置，激活完成后还须再次核验整车空仓和机构安全。进入维护态后，本地换版不要求服务端保持在线，也不再提交逐仓拟议差异；激活完成后须重新连接，上报版本/指纹和完整车载能力快照（OnboardCapabilitySnapshot），经服务端完整对账和人员明确重新投运后才能恢复业务。

**状态（Status）**: 已接受（accepted）

**考虑过的方案（Considered Options）**:
- 服务端断线时完全禁止编辑（拒绝：无运行副作用的维护准备工作没有必要被网络阻塞）
- 每次候选变更都在线提交逐仓差异并等待服务端审批（拒绝：低频配置维护不值得引入专用双端审批协议）
- 正常运行期允许车载端离线直接激活（拒绝：可能在服务端仍有业务内容或活动操作时改变硬件控制关系）
- 草稿可离线编辑，整车进入配置维护态后本地激活并重新投运（采纳）

**影响（Consequences）**:
- 候选配置文件与当前生效配置必须有明确版本或状态区分，禁止把“文件保存成功”解释为“已经生效”。
- 第一版不实现配置编辑 UI 和应用内维护账号；文件访问由操作系统权限与软件部署流程管理。
- 不监视文件变化自动热生效；显式重新加载和维护重启都必须经过相同的维护态、本地验证和重新投运检查。
- 草稿编辑、本地校验、实际 IO 验证和激活结果写入车载技术日志（OnboardTechnicalLog）；服务端记录进入/退出维护态、最终版本/指纹、能力对账和重新投运结果为业务审计记录（BusinessAuditRecord）。
- 草稿可以长期保留，但每次激活前须基于当前生效版本重新检查是否已经过时。
- 配置换版期间整车不可接新任务或移动；不实现逐仓配置审批，也不以连接恢复自动结束维护态。
- 本系统不支持有货状态下修改 IO 配置；业务无货和物理 `EMPTY` 是所有配置激活共同且不可绕过的前置条件。
