# 实时进度只作遥测，可靠结果保留逐仓物理事实

车载上位机发送的 `OperationProgress` 只用于服务端侧监控界面的实时展示和诊断，不直接修改 SlotBusinessState；车载端界面直接展示本地执行状态，不依赖消息经服务端返回。服务端可靠、可去重并需要 ACK 的 `OperationResult` 必须保留每个仓位的实际完成、失败或未开始事实，用于物理追踪、恢复和审计，但逐仓物理成功不再自动等于逐仓业务提交。

服务端持久化逐仓结果后才回复 ACK，车载端在收到 ACK 前持续保留并可按原标识重发结果。装货的正式业务提交遵守 ADR-cross-0036：整个 LoadBatch 全部成功后一次提交；硬件或关键反馈故障时保持逐仓事实、停止新增开门并等待人工处置，不自动进入 LoadCompensationRecovery。8005 卸货遵守 ADR-cross-0037：项目关闭卸货 Sublot 完整性，逐仓达到 `EMPTY + 锁闭 + 开锁输出已复位` 后独立清空业务状态。

**Status**: accepted

**Considered Options**:
- 每条实时进度直接修改服务端业务状态（拒绝：进度不逐条 ACK，丢失或乱序会污染业务事实）
- 丢弃逐仓结果，只记录整批结论（拒绝：无法恢复已经发生的物理副作用）
- 进度只作遥测，可靠结果保留逐仓物理事实，具体业务提交由操作类型决定（采纳）

**Consequences**:
- 服务端监控界面必须区分“实时执行进度”和“已持久化业务结果”，不能把进度显示成已入账。
- `OperationResult` 必须携带所有目标仓位的完成、失败或未开始状态，并支持同一消息幂等重放。
- 车载上位机须先把逐仓完成事实写入 OnboardExecutionJournal，再生成或补报最终结果。
- 装货界面必须区分 ProvisionalLoadState 与整批正式存入，不能把前几个仓位的物理成功显示成子批号已部分入库。
- 8005 不使用 ProvisionalUnloadState 延迟业务清空；卸货界面须逐仓区分物理完成、服务端已持久化清空和仍待处理。即使某仓已清空，在整次到站操作保护解除前也不得自行开始新的装货。
