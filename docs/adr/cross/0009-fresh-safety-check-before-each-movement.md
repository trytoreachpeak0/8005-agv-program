# 每次请求车辆移动前必须取得实时安全核验

`OperationResult.departureSafe` 只描述生成该结果时的仓位机构安全快照，不能作为稍后发车的凭证。服务端每次准备向 RIOT 请求车辆移动前，必须向车载上位机发起 PreDepartureSafetyCheck；车载端基于当前 IO 重新计算 DepartureSafe，并返回唯一检查标识、观测时间、单调递增的安全状态版本以及仓门锁闭状态、开锁输出回读和 IO 有效性摘要。服务端只能在结果为 true、连接仍有效、安全状态版本未被后续变化取代且处于约定短有效窗口内时发车；任一条件不满足即状态不明，必须阻断。

**Status**: accepted

**Considered Options**:
- 直接复用最近一次 `OperationResult.departureSafe`（拒绝：它可能在真正发车时已经过期）
- 只依赖周期心跳中的安全位（拒绝：周期和业务发车没有明确因果关联）
- 每次发车前主动核验，并用状态版本和短有效窗口限制复用（采纳）

**Consequences**:
- 上下层协议须增加独立的发车前安全核验请求/响应，不能只在最终结果中携带 `departureSafe`。
- 车载端安全状态发生任何相关变化时必须推进版本并通知服务端，使尚未使用的旧核验立即失效。
- 有效窗口的具体时长须结合网络延迟与 RIOT 下单时序验证后配置，不在本 ADR 中写死。
