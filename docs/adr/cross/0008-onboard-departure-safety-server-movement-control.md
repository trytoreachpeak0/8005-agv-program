# 车载端给出离站安全许可，服务端控制车辆移动

车载上位机依据全部仓门均由锁传感器有效反馈确认为锁闭、全部开锁输出回读确认为复位、IO 在线且反馈有效、当前仓位操作结束和无致命硬件故障等本车事实计算并上报 DepartureSafe；该判定只是发车的必要安全前提，不代表车载端控制车辆。服务端或调度是唯一离站决策与 RIOT 移动请求发起方，只能在最新且有效的 DepartureSafe 为 true 时请求移动；判定为 false、缺失、过期或车载端失联时均按状态不明即阻断，不得发车。车载上位机不直接调用 RIOT，也不自行决定离站。

**Status**: accepted

**Considered Options**:
- 车载上位机在仓位操作完成后直接调用 RIOT 发车（拒绝：车载端不拥有站点、运输任务和调度上下文）
- 服务端独立判断仓位安全并直接发车（拒绝：服务端不拥有实时 IO 物理事实）
- 车载端提供离站安全许可，服务端结合业务与调度条件控制移动（采纳）

**Consequences**:
- `departureSafe=true` 不等于批次业务成功，也不能绕过服务端的任务、站点、车辆和调度检查。
- 服务端不得把历史安全结果无限期复用；具体的新鲜度与重新核验协议须在通信契约中明确。
- 仓位机构安全状态与车辆移动状态必须分别可观测，任何一侧不明确都不能启动新的移动。
