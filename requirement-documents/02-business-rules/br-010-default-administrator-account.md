# BR-010 内置默认管理员账号

## Rule Statement 规则内容

### 1. 账号存在性与唯一性

1. 系统必须始终存在且仅存在一个登录名固定为 `admin` 的内置默认管理员账号；该账号由系统在部署/初始化阶段自动创建，不通过 [[uc-030-maintain-user-account|UC-030]] 的"新建账号"入口创建，也不计入该 UC 触发条件所覆盖的人工创建场景。
2. 该账号不属于 [[uc-030-maintain-user-account|UC-030]] 停用、重新启用、资料修改及 [[uc-032-assign-user-roles|UC-032]] 角色撤销覆盖的常规对象：任何试图对该账号执行改名、停用、删除，或撤销其内置角色的请求，系统必须直接拒绝。
3. 本内置账号及其绑定的内置"超级管理员"角色（见第 3 节）是系统保证"始终存在可用管理员"的唯一机制：经确认，[[uc-030-maintain-user-account|UC-030]]（停用账号）、[[uc-031-maintain-role-and-permission|UC-031]]（停用角色）、[[uc-032-assign-user-roles|UC-032]]（撤销角色）均不再单独核验"是否会移除系统内最后一个可用管理员/权限管理员"——因为无论普通管理账号或自定义角色如何被停用、撤销，内置账号与内置角色始终存在且不受影响，不需要每次操作时都重复判断。

### 2. 初始密码与强制修改

1. 该账号在系统部署/初始化时被赋予一个初始默认密码；该密码的具体明文值属于部署/初始化配置项，不在需求文档、设计文档或任何非受控文档中以明文记录。
2. 该账号携带"待强制修改密码"标记，初始化后默认为真。
3. 只要该标记为真，该账号登录成功后，系统必须在允许访问任何其他管理功能之前，强制要求先完成密码修改；新密码必须满足 [[br-011-account-and-password-format|BR-011]] 定义的密码格式规则，且不得与当前默认密码相同。
4. 修改成功后，系统清除"待强制修改密码"标记，该账号后续按普通登录流程处理（会话建立细节见 [[uc-033-login-and-session-management|UC-033]]，本规则不重复定义）。
5. 该标记后续是否可在非首次场景下被重新置位（如怀疑密码泄露后的强制重置）及具体触发方式，属于 TBD，需在相关 UC 补充后再引用本规则。

### 3. 权限范围与角色建模

1. 该账号绑定一个系统内置的"超级管理员"角色；该角色的权限集合定义为系统当前及未来全部权限的全集，由系统在新增权限点时自动同步纳入，不需要逐项手动维护清单——区别于 [[uc-031-maintain-role-and-permission|UC-031]] 中普通角色"按具体权限项组合"的建模方式。
2. 该内置角色本身不可通过 [[uc-031-maintain-role-and-permission|UC-031]] 编辑权限组成、停用或删除；不可通过 [[uc-032-assign-user-roles|UC-032]] 从该账号撤销，也不得授予给其他账号——该角色与该内置账号一一绑定，不作为可复用角色分配给别的本地账号。

### 4. 审计

1. 该内置账号的登录成功/失败、密码修改，以及任何被本规则拒绝的改名、停用、删除或角色撤销尝试，均须按 [[uc-034-query-and-export-audit-logs|UC-034]] 的审计要求正常记录，不因该账号的特殊性而降低可追溯性或允许静默拒绝。

## Rationale 制定原因

- 提供一个不依赖任何具体人员维护的最终兜底登录入口，避免因误操作或配置失误导致系统彻底无人可登录管理配置端、必须停机或联系厂商才能恢复的极端场景。
- 相比于在 [[uc-030-maintain-user-account|UC-030]]、[[uc-031-maintain-role-and-permission|UC-031]]、[[uc-032-assign-user-roles|UC-032]] 中各自维护一套"是否为最后一个可用管理员/权限管理员"的动态判断逻辑，改为"系统内置一个不可停用、不可撤销的超级管理员账号与角色"这一静态、唯一的事实性保证，逻辑更简单，也避免了多个 UC 各自实现同类校验时可能出现的遗漏或并发场景下的竞态问题（如同时停用/撤销多个账号或角色时如何正确判断"最后一个"）。
- 强制首次登录改密码是为了消除可预测默认凭据长期暴露的安全风险，属于常见的默认账号安全基线要求。
- 采用"内置超级管理员角色 + 权限全集自动继承"而不是具体权限清单，是为了避免每次 [[uc-031-maintain-role-and-permission|UC-031]] 新增权限点时都要额外维护这个内置角色，降低遗漏风险。

## Source 来源

2026-07-14 需求确认（与用户澄清问答）：

- 内置账号为永久存在、不可停用/改名/删除的兜底账号。
- 初始密码首次登录强制要求修改；具体默认密码明文不写入需求文档。
- 权限范围建模为内置"超级管理员"角色，自动继承当前及未来全部权限。
- 经进一步确认：既然该内置账号/角色始终存在且不可撤销，[[uc-030-maintain-user-account|UC-030]]、[[uc-031-maintain-role-and-permission|UC-031]]、[[uc-032-assign-user-roles|UC-032]] 中原有的"最后一个可用管理员/权限管理员"判断规则不再需要，已从对应用例中移除（原 UC-030 EA3.2.1、UC-031 EA3.3.1、UC-032 EA3.1.1 及相关前后置条件）。

## Related Use Cases 关联用例

- [[uc-030-maintain-user-account|UC-030]]：本规则约束该 UC 的账号创建、修改、停用、重新启用流程不适用于该内置账号；UC-030 需能识别并标注该内置账号，对其改名/停用/删除请求按本规则直接拒绝。
- [[uc-031-maintain-role-and-permission|UC-031]]：需定义并维护本规则第 3 节所述的内置"超级管理员"角色，保证其权限集合始终等于系统全集，且该角色本身不可编辑、停用或删除。
- [[uc-032-assign-user-roles|UC-032]]：本规则约束该内置角色不可通过该 UC 从内置账号撤销，也不可授予其他账号。
- [[uc-033-login-and-session-management|UC-033]]：该账号登录成功后，若"待强制修改密码"标记为真，需先完成密码修改才能继续使用管理功能；具体登录流程本身仍遵循该 UC。
- [[uc-034-query-and-export-audit-logs|UC-034]]：查询该内置账号的登录、密码修改及被拒绝操作审计记录。
