# BR-005 Workflow Template Versioning 流程模板版本与快照规则

## Rule Statement 规则内容

### 1. 模板状态

流程模板版本仅允许以下状态：

- `Draft`：草稿。允许具有维护权限的人员编辑和校验，不得参与运行时匹配或创建流程实例。
- `Published`：已发布。内容不可变，可以按 [[br-004-workflow-template-matching|BR-004]] 参与新实例匹配。
- `Retired`：已停用。内容仍不可变，不再参与新实例匹配；已有任务和流程实例继续引用其历史快照。

允许的状态转换只有：

```text
Draft -> Published -> Retired
```

不允许将 `Published` 或 `Retired` 退回 `Draft`，不允许重新启用原 `Retired` 版本。需要恢复或修改时必须从历史版本复制生成新的 `Draft`，经校验后发布为新版本。

### 2. 发布与不可变版本

1. 每次发布必须生成新的、不可变的模板版本，至少包含稳定的 `templateId`、单调递增的 `version`、全局唯一 `templateVersionId`、模板内容、匹配条件、步骤定义、发布时间、发布人和内容校验值。
2. 发布必须基于一个校验通过的 `Draft`。模板结构、步骤参数、匹配条件、安全步骤、外部事件及重试策略任一无效时，整次发布失败，不得产生部分可用版本。
3. `Published` 后，匹配条件、步骤顺序、步骤参数、跳过条件、重试参数、安全标记及名称说明均不得原地修改。
4. 修订已发布模板时，应复制生成新的 `Draft`；发布后得到下一个版本，旧版本保持原内容和原状态。
5. 版本号不得重用；发布失败也不得覆盖另一个已经成功发布的版本。

### 3. 任务、流程实例与快照绑定

任务或流程实例创建时，系统必须绑定当时唯一匹配的 `Published` 模板版本，并保存足以独立重放和审计的不可变快照。快照至少包括：

- `templateId`、`templateVersionId`、版本号和内容校验值。
- 匹配条件及本次匹配输入、匹配结果或授权覆盖记录。
- 有序步骤、步骤类型、参数、跳过条件、重试上限、等待事件与超时策略。
- 强制安全步骤标记及当时引用的步骤目录版本。
- 创建时间、创建来源和绑定主体（任务 ID、流程实例 ID）。

具体绑定时点遵循：

1. 创建业务任务时已经具备完整匹配上下文的，应在任务创建事务中完成匹配并绑定模板快照；匹配或快照持久化失败时，任务不得进入可执行状态。
2. 业务任务创建时尚不具备完整上下文的，应保持“等待模板匹配”阻断状态；在创建流程实例前补齐并冻结上下文，再完成唯一匹配和快照绑定。
3. 流程实例从已绑定任务创建时，必须复制并校验任务所绑定的同一模板版本快照，不得重新匹配到更新版本。
4. 独立创建的流程实例必须在其创建事务中完成匹配和快照绑定。

任务/流程实例一旦绑定快照，后续模板发布、停用、重命名或目录调整均不得改变该快照。运行时执行快照，不动态读取模板当前内容。

### 4. 新版本影响范围

- 新发布版本只允许影响其发布时间/生效时间之后创建且尚未绑定模板的任务或流程实例。
- 已存在并已绑定的任务、流程实例、暂停实例、等待外部事件实例、重试中实例和异常恢复实例继续执行原快照。
- 不允许批量把历史实例静默迁移到新版本。
- 若确需迁移未开始执行的实例，必须作为独立的受控能力另行定义审批、兼容性校验和审计规则；在该能力明确前一律禁止迁移。
- 停用版本只阻止后续新匹配，不得中断或改写引用该版本的历史实例。

### 5. 发布、停用与二次认证

发布 `Draft` 或将 `Published` 置为 `Retired` 均属于高风险操作，必须：

1. 由具有相应权限的个人账号发起。
2. 在提交前再次刷卡或认证，二次认证必须与当前操作人一致并在限定有效期内使用。
3. 填写变更/停用原因，并展示模板、版本、匹配范围、步骤差异和潜在影响。
4. 以原子事务完成版本生成或状态转换；任何校验、持久化或审计写入失败时，保持原状态。
5. 审计操作人、角色、认证时间、操作类型、原因、变更前后内容/状态、执行结果和失败原因。

停用前应展示仍引用该版本的任务和流程实例数量，但这些历史引用不得阻止停用，也不得因停用而失效。

### 6. 历史保留与删除限制

- `Published`、`Retired` 版本以及曾被任务、流程实例或审计记录引用的 `Draft` 不得物理删除。
- 历史版本、快照、发布/停用记录和审计记录必须保持可查询、可校验。
- 对未发布且从未被引用的误建 `Draft`，如需清理也只能逻辑作废并保留最小审计记录，不得通过数据库脚本绕过保留规则。
- 管理界面的“删除”不得对模板历史执行物理删除；如提供操作，只能表达“作废草稿”或“停用已发布版本”。
- 备份、归档和数据保留策略不得破坏任务到模板版本、流程实例到快照的追溯关系。

## Fail-closed 规则

模板状态未知、版本内容与校验值不一致、快照不完整、引用版本不存在、二次认证失败或审计记录无法可靠写入时，相关发布、停用、匹配或实例创建操作必须拒绝。已经运行的实例若无法验证其快照完整性，应暂停在安全状态并告警，不得改用最新模板继续执行。

## Rationale 制定原因

流程模板会直接决定认证、扫码、硬件控制和移动步骤。发布版本不可变、实例绑定快照以及新版本仅影响后续实例，可以避免运行中的流程因配置变化而改变，并确保历史任务能够准确解释“当时执行了哪一版流程”。

## Source 来源

2026-07-13 流程模板需求确认：

- 模板状态为 `Draft`、`Published`、`Retired`。
- 发布生成不可变版本，任务/流程实例创建时绑定快照。
- 新版本只影响之后创建的实例。
- 发布和停用需要二次认证，历史记录不得物理删除。
