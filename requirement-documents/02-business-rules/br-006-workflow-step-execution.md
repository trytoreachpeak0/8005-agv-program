# BR-006 Workflow Step Execution 流程步骤执行规则

## Rule Statement 规则内容

### 1. 支持的流程结构

流程模板只支持以下四种控制能力：

1. **顺序执行**：步骤按模板快照中的固定顺序一次推进一个。
2. **条件跳过**：在到达步骤时，根据快照中预先声明的只读条件决定执行或跳过。
3. **步骤重试**：步骤失败后按预先声明的有限次数和退避策略重试同一步骤。
4. **等待外部事件**：步骤进入等待状态，接收预先声明、可关联且可去重的 MES、RCS/RIOT、IO 或人工事件；必须配置超时及超时后的阻断/异常处理。

明确不支持：

- 并行步骤、并行网关或并发分支。
- 循环、回跳、递归、动态重复步骤或无限重试。
- 任意条件分支、运行时选择任意下一节点或跳转到任意步骤。
- 管理员编写脚本、表达式代码、SQL 或任意 API 调用。
- 运行时插入、删除、重排步骤或修改已绑定快照。

条件跳过只决定“执行当前步骤”或“跳过当前步骤”，之后均进入固定的下一顺序步骤；不得借条件跳过实现多路分支。模板发布时必须证明步骤图为单一有向无环顺序链，否则拒绝发布。

### 2. 步骤执行状态与原子边界

单个步骤至少使用以下状态：

```text
Pending -> Running -> Succeeded
                   -> WaitingExternal -> Running
                   -> RetryWaiting -> Running
                   -> Failed
Pending -> Skipped
```

每次只允许一个步骤处于 `Running`。只有当前步骤持久化为 `Succeeded` 或允许的 `Skipped` 后，才可创建/激活下一个步骤。步骤状态、业务副作用结果和审计写入必须采用可恢复的一致性边界；进程崩溃后不得仅凭内存判断步骤是否完成。

流程实例终态至少区分 `Completed`、`Failed`、`ExceptionTerminated`；非终态至少区分 `Pending`、`Running`、`WaitingExternal`、`RetryWaiting`、`Suspended`。实际代码名称可调整，但语义不得合并到业务任务状态。

### 3. 幂等要求

每个步骤类型必须定义幂等语义。每次执行至少携带：

```text
workflowInstanceId + stepInstanceId + attemptNo + idempotencyKey
```

规则如下：

1. 同一步骤因超时、进程重启、消息重复或网络结果未知而再次调用时，必须使用稳定的 `idempotencyKey` 查询/复用已确认结果，不能重复产生副作用。
2. `attemptNo` 用于审计实际尝试次数，不得替代稳定幂等键。
3. 外部系统支持幂等键时必须传递；不支持时，应在本地通过请求记录、外部业务标识和结果对账阻止盲目重复。
4. 对开锁、关门确认、RCS 下发、MES 回写等副作用步骤，结果未知时不得直接认定成功，也不得无条件重发；应先查询状态或进入人工确认。
5. 外部事件必须按事件 ID 或可证明唯一的业务键去重，并核验实例、步骤、对象和当前等待状态。

### 4. 输入、输出与审计

每次步骤尝试必须记录：

- 流程实例、模板版本/快照校验值、步骤实例、步骤类型和顺序号。
- 输入快照及其来源；敏感字段应脱敏或使用安全引用，不得把凭据写入日志。
- 条件跳过的条件定义、参与判断的值和判断结果。
- 幂等键、尝试次数、开始/结束时间、执行主体。
- 输出或外部响应摘要、标准化结果、错误码和错误信息。
- 状态迁移、重试决定、等待事件、超时结果和下一步骤。

审计记录必须追加写入并可关联业务任务、AGV、仓位、SUBLOT、外部请求/事件 ID。输入、输出或审计无法可靠持久化时，不得把步骤标记为成功。

### 5. 重试规则

- 只有 [[workflow-step-catalog|步骤目录]] 明确标记“可重试”的步骤才允许配置重试。
- 重试次数必须是有限非负整数，并配置固定或受限指数退避；不得配置无限重试。
- 参数校验失败、权限失败、安全联锁失败、业务冲突和明确的永久错误不得自动重试。
- 对可能已产生副作用但结果未知的步骤，必须先对账；无法对账时转 `Failed`/`Suspended` 并告警。
- 重试耗尽后步骤进入 `Failed`，流程不得自动越过失败步骤。

### 6. 条件跳过与强制安全步骤

1. 只有步骤目录标记“可跳过”的步骤才能配置条件跳过。
2. 跳过条件只能使用开发预置的字段、比较运算和枚举，不得执行脚本、SQL、网络调用或读取未冻结的任意数据。
3. 条件求值结果必须是明确的 `true` 或 `false`；字段缺失、类型错误、读取失败或结果未知时采用 fail-closed，不得按“可跳过”处理。
4. 步骤目录标记为“强制安全步骤”的步骤禁止跳过，即使管理员配置了跳过条件、上游输出声称已满足或手动覆盖模板匹配，也必须执行并取得明确成功结果。
5. 光幕、仓门、门锁、移动安全联锁、身份/权限校验等强制安全结论不得从历史成功结果长期复用；必须按步骤定义在相应危险动作前读取当前有效状态。

### 7. 等待外部事件

- 等待步骤必须声明事件类型、关联键、允许来源、数据校验、去重键、超时和超时处理。
- 仅当前流程实例的当前等待步骤可以消费匹配事件；早到事件按预置策略安全暂存或拒绝，迟到事件只记录审计，不得推进已结束/已离开步骤的流程。
- 事件来源无法认证、关联键不一致、内容不完整或顺序异常时不得推进。
- 超时只能进入预置的重试、告警、等待人工或异常结束步骤，不得动态跳往任意节点。

### 8. Fail-closed

以下任一情况发生时，当前步骤不得标记成功，流程不得推进：

- 步骤类型未知、参数无效、模板快照损坏或与校验值不一致。
- 输入缺失、条件结果未知、输出无法验证或审计无法写入。
- 外部调用超时且结果未知、事件无法关联、幂等状态无法确定。
- 安全状态未知、联锁失败、仓门/光幕状态异常或认证/权限失败。
- 系统恢复后无法确定崩溃前步骤是否已产生副作用。

系统应保持或恢复到可证明安全的状态，记录异常并告警；不得默认成功、默认跳过、推进下一步骤或直接改变业务任务为完成。

### 9. 流程实例状态与业务任务状态分离

流程实例状态描述“模板步骤执行到了哪里”，业务任务状态描述“物料搬运业务处于哪个阶段”。二者必须分开存储、分别校验和审计：

- 流程 `Completed` 只表示当前流程快照的全部步骤已完成，不自动等于业务任务 `COMPLETED`；只有目录中明确的业务状态转换步骤成功后，业务任务才能按其状态机变化。
- 流程 `Failed`、`Suspended`、`WaitingExternal` 或 `RetryWaiting` 不得直接把业务任务改成同名状态；业务任务可保持原状态并附加流程异常/等待原因。
- 业务任务被取消、异常关闭或完成时，必须通过预置的协调规则安全终止或收敛关联流程，不能只修改一张状态表。
- 一个业务任务可关联多个阶段性流程实例，但每个实例都必须有独立状态、快照和审计；同一业务动作不得因多个实例重复执行。

## Rationale 制定原因

受限的顺序流程足以覆盖当前 MES 接入、派车、移动、人工装卸、硬件联锁和异常处理，同时显著降低并行、循环和任意脚本带来的不可预测性。步骤幂等、完整审计和 fail-closed 能在网络超时、重复消息或进程重启时避免重复下发、误开锁和错误推进。

## Source 来源

2026-07-13 流程执行需求确认：

- 仅支持顺序、条件跳过、步骤重试和等待外部事件。
- 不支持并行、循环或任意分支。
- 步骤必须幂等，输入输出可审计，异常时 fail-closed。
- 强制安全步骤禁止跳过，流程实例状态与业务任务状态必须分离。
