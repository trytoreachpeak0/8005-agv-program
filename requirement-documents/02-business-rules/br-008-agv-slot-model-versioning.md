# BR-008 AGV Slot Model Versioning 多仓位AGV模型版本与绑定规则

## Rule Statement 规则内容

### 1. 模型版本状态

多仓位 AGV 模型（型号）的每个版本仅允许以下状态：

- `Draft`：草稿。允许具有维护权限的人员编辑面、仓位定义和规格，不得被 [[uc-019-register-agv-from-rcs|UC-019]] 选用于接入新 AGV。
- `Published`：已发布。面、仓位定义（编号、所属面、位置、跨格、规格）内容不可变，可以被 UC-019 选用于接入新 AGV。
- `Retired`：已停用。内容仍不可变，不再允许被 UC-019 选用于接入新 AGV；已绑定该版本的历史 AGV 及其仓位实例继续有效，不受影响。

允许的状态转换只有：

```text
Draft -> Published -> Retired
```

不允许将 `Published` 或 `Retired` 退回 `Draft`，不允许重新启用原 `Retired` 版本。需要修改型号定义时，必须从历史版本复制生成新的 `Draft`，校验通过后发布为下一个版本号。

### 2. 发布与不可变版本

1. 每次发布必须生成新的、不可变的模型版本，至少包含稳定的 `modelId`（型号）、单调递增的 `version`、全局唯一的 `modelVersionId`、面列表（`faceId`、名称、列数、行数）、仓位定义列表（仓位编号、所属面、起始行/列、`rowSpan`/`columnSpan`、规格：尺寸与最大载重）、发布时间、发布人和内容校验值。
2. 发布必须基于一个校验通过的 `Draft`：面标识与仓位编号唯一、行列与跨格均为正整数、仓位矩形不越界、同一面内任意两个仓位矩形不重叠、每个仓位规格字段完整；任一校验失败则整次发布失败，不得产生部分可用版本（校验规则与 `slots-simulator` [[dr-009-slot-layout-model|DR-009]]/`FR-011` 一致）。
3. `Published` 后，面列表、仓位编号、位置、跨格及规格均不得原地修改。
4. 修订已发布型号时，应复制生成新的 `Draft`；发布后得到下一个版本，旧版本保持原内容和原状态。
5. 版本号不得重用；发布失败也不得覆盖另一个已经成功发布的版本。

### 3. AGV 接入时的快照绑定与不可更换

1. 管理员通过 UC-019 接入 AGV 时，必须从任一型号的 `Published` 版本中选择一个，系统在同一事务中据此生成该 AGV 的仓位实例记录（仓位编号、所属面、位置、规格），并保存所绑定的 `modelId`、`modelVersionId`、版本号和内容校验值快照。型号选择与车型（AGV 底座）无强制关联——同一型号可安装于不同车型，系统不按车型过滤可选型号列表。
2. AGV 一旦完成接入并绑定某个模型版本，**不允许更换**该 AGV 绑定的型号或版本，也不允许在 [[uc-020-maintain-agv-dispatch-profile|UC-020]] 中修改已生成的仓位编号、位置或规格；确需更换型号时，必须先按 [[uc-021-archive-agv|UC-021]] 归档该 AGV，再以正确型号版本重新执行 UC-019 接入（视为一台新的本地档案）。
3. 该约束比 [[br-005-workflow-template-versioning|BR-005]] 中"未开始执行的实例可另行定义受控迁移能力"更严格：本规则当前不为已接入 AGV 保留任何迁移到新模型版本的路径。

### 4. 新版本影响范围

- 新发布版本只允许影响其发布时间之后、尚未接入的 AGV 通过 UC-019 新接入时的可选范围。
- 已接入并已绑定模型版本快照的 AGV 及其仓位实例，继续使用原快照，不因型号后续发布新版本而改变。
- 不允许批量把已接入 AGV 的仓位记录静默迁移到新版本。
- 停用（`Retired`）版本只阻止后续新接入选用，不得中断或改写已引用该版本的历史 AGV 及仓位实例。

### 5. 发布、停用与二次认证

发布 `Draft` 或将 `Published` 置为 `Retired` 均属于高风险操作，必须：

1. 由具有相应权限的个人账号发起。
2. 在提交前再次刷卡或认证，二次认证必须与当前操作人一致并在限定有效期内使用。
3. 填写变更/停用原因，并展示型号、版本、面与仓位定义差异及潜在影响。
4. 以原子事务完成版本生成或状态转换；任何校验、持久化或审计写入失败时，保持原状态。
5. 审计操作人、角色、认证时间、操作类型、原因、变更前后内容/状态、执行结果和失败原因。

停用前应展示仍引用该版本的 AGV 数量，但这些历史引用不得阻止停用，也不得因停用而失效。

### 6. 历史保留与删除限制

- `Published`、`Retired` 版本以及曾被任一 AGV 引用的 `Draft` 不得物理删除。
- 历史版本、快照、发布/停用记录和审计记录必须保持可查询、可校验。
- 对未发布且从未被引用的误建 `Draft`，如需清理也只能逻辑作废并保留最小审计记录。
- 管理界面的"删除"不得对模型历史执行物理删除；如提供操作，只能表达"作废草稿"或"停用已发布版本"。

## Fail-closed 规则

模型版本状态未知、内容与校验值不一致、快照不完整、引用版本不存在、二次认证失败或审计记录无法可靠写入时，相关发布、停用或 AGV 接入操作必须拒绝。AGV 接入事务中若仓位实例生成失败，整次接入必须回滚，不得产生"AGV 档案已建但仓位缺失"的中间状态。

## Rationale 制定原因

多仓位 AGV 模型的面、仓位数量、位置与规格直接决定后续仓位启停（[[uc-014-enable-disable-slot|UC-014]]）、IO 点位映射（[[uc-018-io-point-mapping-verification-test|UC-018]]）、装卸业务（UC-001/005/010）以及任务分配的仓位能力核验（[[br-002-agv-allocation-eligibility|BR-002]] 第 9 条）。若型号定义可以随时原地修改，会导致已在运行的 AGV 仓位编号、位置或规格与现场实际、已下发任务或历史记录不一致。采用"发布不可变版本 + 接入时绑定快照 + 不允许换型号"的设计，可以保证一台 AGV 从接入起，其仓位结构在整个生命周期内保持确定、可追溯，需要变更结构时通过"归档旧档案、以新版本重新接入"这一明确路径处理，不产生隐式漂移。

## Source 来源

2026-07-13 需求确认：

- 用户提出"接入 AGV 时未定义多仓位类型"的问题，需要一个专门维护多仓位 AGV 模型的功能，接入时可选择该模型。
- 模型内容范围确认为：仓位数量、仓位规格、仓位位置，做法参照 `slots-simulator` 对仓位（面 + 位置 + 跨格 + 规格）的定义方式。
- 确认选择模型后系统自动生成对应仓位实例记录。
- 确认 AGV 接入后不允许更换已绑定的型号/版本。
- 确认型号支持多版本：修改只能发布新版本，旧版本不变——做法与 [[br-005-workflow-template-versioning|BR-005]] 流程模板版本一致。
- 确认车型（AGV 底座）与多仓位 AGV 模型是两个独立概念，不做一一绑定：车型可能变化，多仓位模型也可能变化，但同一模型通常可以通用安装在不同车型的 AGV 底座上。
- 确认面/仓位数量无需设置上限。
- 确认型号维护操作角色以 IT/软件维护人员（R-12）为主，AGV 运维/调度管理员（R-13）可协同确认现场仓位规格。
