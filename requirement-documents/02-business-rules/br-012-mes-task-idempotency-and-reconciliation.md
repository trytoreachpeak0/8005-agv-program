# BR-012 MES Task Idempotency and Reconciliation MES任务幂等与轮询对账规则

## Rule Statement 规则内容

### 1. 幂等键与任务来源

1. 正式运输任务的业务幂等键为：`任务类型（TASK_TYPE / moveType）+ SUBLOT`。不得仅用 `SUBLOT + STEP` 去重。
2. 正式生产任务只能由 MES 合并查询产生，不提供人工创建正式 MES 任务的入口。
3. 开发与测试用的人工任务属于 Mock 任务：使用独立 `MOCK_TASK_ID` 与 `TASK_SOURCE = MOCK`，不占用正式幂等键，不参与 MES 出现/消失对账；生产环境默认禁用，联调启用须专门权限并显著标识。

### 2. 查询与轮询

1. 5 类任务通过带固定 `TASK_TYPE` 的 `UNION ALL` 合并为一条 Oracle SQL；只有整条合并查询完整成功后，才能用于判断任务出现或消失。不得使用会隐藏重复行的 `UNION`。
2. 轮询采用固定延迟：本轮查询全部完成后等待默认 10 秒再开始下一轮；不得并发启动、重叠或堆积查询。查询超时默认 30 秒。
3. 查询超时、失败、结果不完整或连接中断时：不创建新任务、不累计消失次数、不执行批量取消，并产生接口报警。
4. 性能目标：正常不超过 5 秒；超过 10 秒慢查询警告；30 秒硬超时；连续 3 轮失败产生高级报警。
5. 上线基线时间为 `2026-08-01 00:00:00`（应用层过滤，不修改客户 SQL）；该时间以前的记录不创建 AGV 任务。不得用持续滚动的“最近 N 小时”作为唯一过滤条件。

### 3. 字段校验、归并与冻结

1. EQP 业务上必须非空；为空则阻断性 MES 数据异常。AREA 允许为空，但为空或无法按 [[br-003-area-station-mapping|BR-003]] 解析站点时，任务进入位置异常（LOCATION_ERROR），不得下发 AGV。
2. EQP/AREA 仅去首尾空格，不补零、不改大小写；`D4-06` 与 `D04-06` 视为不同位置。
3. 同一 `任务类型 + SUBLOT`、同一 EQP、同一 AREA 的重复行归并为一个候选任务。同一 EQP 出现不同 AREA、或同一 SUBLOT 在同一轮完整查询中命中多个任务类型，均为阻断性异常，不得自动挑选；关卡与三光互斥。
4. 任务首次创建时冻结 EQP、AREA、DATES 及起终点（含冻结的 `station_name`）。后续快照只判断“仍存在/已消失”，不得用 MES 新值更新已有任务业务字段；位置异常任务不因 MES 后续补全而自动恢复。

### 4. 消失对账与装货边界

1. 仅在对应类型完整成功查询时累计消失；对仍存在的本地任务更新 `mes_last_seen_at` 并将消失计数归零。
2. 同一记录连续 2 次成功查询未出现，且任务尚未开始装货时：自动取消、记录“MES记录已消失”，并立即撤销相关取货停靠点与路线。
3. “开始装货”以该任务第一个仓门成功打开为边界。进入装货后，即使 MES 记录消失也保留整个任务，由现场完成装货与送货。
4. 已转 GONE 的业务键若再次出现在查询中：MesIngest 保留旧 GONE 实例、分配新的本地 DemandId 投影并产生对账告警；不在接入层阻断，也不查询调度侧抑制。该新实例不表示 MES 形成了新的搬运需求。
5. 调度消费 MesIngest 投影时，若 TransportDemandKey 命中本地取消的永久抑制，则不得创建或恢复业务任务、不得派车；该抑制不改变 MesIngest 的投影行为。同键候选在现场人工搬运并于 MES 扫码过站前持续可见属于正常现象。
6. 消失计数必须持久化，系统重启不得清零。

### 5. 异常骤降保护（PAUSED_ZERO_DROP）

1. 按任务类型独立判断：若某类型上一轮完整成功查询数量 ≥ 10（阈值可配置），本轮突然变为 0，则进入 `PAUSED_ZERO_DROP`：暂停该类型的消失计数与取消处理并报警；其他类型不受影响。
2. 仅自动恢复：该类型连续 2 轮完整成功查询数量 > 0 时自动解除；不提供人工解除入口。
3. 每类型最后正常非 0 数量、连续恢复次数与保护状态必须持久化。

### 6. 系统重启恢复基线

1. 重启后第一次完整合并查询只建立恢复快照：可创建新任务、对重新出现的已有任务归零消失计数；未出现的已有任务本次不累计消失、不取消。
2. 第一次查询的每类型数量单独保存为恢复基线；数量为 0 时不得覆盖重启前持久化的最后正常非 0 数量。
3. 从第二次完整成功查询起恢复正常对账（含 `PAUSED_ZERO_DROP` 进入/解除判定）。

### 7. MES 连接中断与只读安全

1. MES 连接中断时：已开始装货或已取货任务继续按本地状态执行；尚未开始装货但已派车的任务暂停前往，待连接恢复与下一轮完整快照确认。
2. 当前阶段本系统只读查询 MES，不做任何回写；评审确认前禁止实现 MES 写操作。
3. MES 任务查询链路必须使用只读事务且只能执行预置 SELECT；禁止通用 SQL 入口；非 SELECT 必须拒绝并报警；日志不得输出数据库密码。

## Rationale 制定原因

MES 返回的是会重复、会消失的当前状态快照，且人工搬运与 AGV 长期并存。必须以稳定幂等键与完整快照对账，才能在取货前及时撤销失效任务，又在装货后不以 MES 消失误取消在途物料；异常骤降保护与重启基线用于避免误批量取消。
