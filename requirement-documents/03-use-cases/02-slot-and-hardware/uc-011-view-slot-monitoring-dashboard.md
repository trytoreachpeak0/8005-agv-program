# UC-011 查看仓位监控看板

## 描述

班组长/生产管理者（车间主任）可以查看权限范围内各多仓位 AGV 的仓位总览：每个仓位的物理占用、锁闭/未锁、IO 有效性、管理可用性和业务关联。现场没有独立门磁；看板不得把锁 DI 为“未锁”伪装成精确门板位置，也不得用 DO 复位推断仓门已经关闭。本 UC 是纯只读查询，不触发仓位或任务状态变更。

> 本 UC 与 UC-001/UC-005/UC-010 的分工边界：那几个 UC 是"操作员在具体一次到站期间，针对具体仓位执行装载/取出动作"的业务流程，会真正改变仓位与任务状态；本 UC 只是把这些状态变化实时展示出来，供管理角色随时查看全局情况，本身不改变任何数据。

## 触发条件

班组长/生产管理者主动打开仓位监控看板界面；或该界面已打开时，达到预设的自动刷新周期。

## 前置条件

**系统与接口**

1. 本地服务器与数据库运行正常，可读取各多仓位 AGV 仓位/任务的最新状态记录。

**人员与权限**

2. 该角色（班组长/生产管理者）具备查看仓位监控看板的权限。The actor (shift leader / production manager)

> 本 UC 不核验具体某个仓位/任务的业务合法性（如该任务是否属于本次派车范围），这些核验由各自触发状态变更的业务 UC（如 UC-001 第 1.2 步）负责；本 UC 只负责如实展示当前记录。

## 后置条件

**任务与数据**

1. 看板界面展示的各仓位状态（空闲/已占用/异常锁定）、仓门开关状态、（若已占用）关联子批号与搬运任务信息（任务号、目标/交货站点、任务当前状态），与本地数据库当前记录一致。
2. 本 UC 本身不改变任何仓位、任务的状态数据；仓位/任务状态的变更由其他业务 UC（如 [[uc-001-load-completed-lot-into-slot|UC-001]]、[[uc-005-retrieve-mis-stored-product-from-slot|UC-005]]、[[uc-006-cancel-transport-task-upon-arrival|UC-006]]、[[uc-010-unload-completed-lot-at-destination-station|UC-010]]）触发。

## 假设

1. 看板展示的仓门开关状态、光幕检测结果等硬件相关数据，由 IO 模块采集后同步至本地数据库，本 UC 只读取该已有记录，不重复触发硬件读取指令，也不核验硬件采集本身是否准确——该核验属于各业务 UC 在开门/关门步骤中的核验范围（如 UC-001 第 2.1/4.1 步）。
2. 看板默认展示该角色权限范围内可见的全部 AGV/站点仓位；具体权限粒度（如是否可按车间/产线过滤）TBD 待补充。

## 正常流程

### 11.0

1. 班组长/生产管理者打开仓位监控看板界面
2. 系统读取本地数据库中各多仓位 AGV 全部仓位的最新状态记录，在看板上按 AGV/仓位号列出：
   2.1 仓位状态（空闲/已占用/异常锁定）
   2.2 锁闭状态和反馈有效性；没有独立门状态 DI
   2.3 若该仓位状态为"已占用"，同时展示关联的子批号及其搬运任务信息（任务号、目标/交货站点、任务当前状态）
3. 系统按预设周期（具体周期 TBD）自动刷新看板数据，或支持该角色手动刷新
   3.1 系统核验本次刷新读取本地数据库/服务是否正常（见 Exception Flow E3.1）
4. 该角色可（视 UI 设计支持情况）按 AGV、站点或仓位状态进行筛选/排序，聚焦关注的仓位子集

## 备选流程

不存在需要区分的备选流程：无论该角色关注的是单台 AGV 还是全部 AGV，看板均按 Normal Flow 相同的"读取→展示→刷新"逻辑处理，第 4 步的筛选/排序只是同一份数据的不同呈现方式，不构成触发方式或步骤不同的分支路径。

## 异常流程

以下异常以 `E<步骤号>` 编号，与 Normal Flow 中触发该异常的具体步骤一一对应：

* E3.1 看板刷新时数据读取异常

### E3.1 看板刷新时数据读取异常

1. 系统按第 3 步定时/手动刷新看板数据
2. 系统读取本地数据库/服务时发生异常（如数据库连接中断、服务无响应）
3. 系统在看板上提示"数据刷新失败，请稍后重试"，并保留上一次成功读取到的数据，同时标注该数据的最后刷新时间，避免与最新真实状态混淆
4. 系统持续尝试重新读取；IT/软件维护人员（R-12）介入排查并修复数据库/服务异常后，看板恢复正常刷新

## 备注

* 本 UC 是用户在讨论 [[uc-001-load-completed-lot-into-slot|UC-001]]、[[uc-005-retrieve-mis-stored-product-from-slot|UC-005]] 等装卸场景时提出的新需求整理而来：用户提出"操作员在存取产品时，可能需要看仓位状态（有物无物、门开或门未开、产品的批号和对应的任务信息等）"。经进一步确认，该需求对应的是一个**独立的"仓位监控看板"页面**，可由班组长/生产管理者在任意时刻主动打开查看全局仓位状态，与某次具体的装载（UC-001）/取出纠错（UC-005）/终点站取出（UC-010）操作无关，因此拆分为独立的只读查询类 UC，而不是重复插入到那几个业务 UC 的正文中。
* 本 UC 是纯只读查询：不改变任何仓位/任务状态，Postcondition 只描述展示内容与数据一致性要求，不涉及状态迁移；这点与会引起状态变化的 UC-001/UC-005/UC-006/UC-010 等业务 UC 不同，因此本 UC 不强行套用"状态改变"式的 Postcondition 写法。
* 经与用户确认：本 UC 的 Actor 是班组长（R-09）/生产管理者（R-10），不是执行具体装卸动作的生产/终点站操作员（R-01~R-08）；后者在装卸过程中若需要查看仓位状态，属于其执行 UC-001/UC-005/UC-010 时界面上自然呈现的辅助信息，不在本 UC 范围内重复定义。
* 待补充（TBD）：具体展示字段的最终清单、看板 UI 布局、自动刷新周期、可见范围（是否需要按车间/产线过滤）等细节，需要后续进一步与用户确认。
* 看板中展示的"异常锁定"仓位状态，其产生与解除逻辑分别由 [[uc-001-load-completed-lot-into-slot|UC-001]]（Exception Flow E2.1/E2.2）、[[uc-005-retrieve-mis-stored-product-from-slot|UC-005]]（Exception Flow E3.1/E3.2）、[[uc-010-unload-completed-lot-at-destination-station|UC-010]]（Exception Flow E2.1/E2.2）各自的异常流程定义和维护，本 UC 只负责如实展示该状态，不负责判定或解除。

## 关联用例

* [[uc-001-load-completed-lot-into-slot|UC-001]]：本 UC 展示的"已占用"仓位及其批号/任务信息，部分来源于该 UC 装载完成后记录的仓位-子批号映射关系；该 UC 的 Exception Flow（E2.1/E2.2）产生的"异常锁定"状态也会体现在本看板中。
* [[uc-005-retrieve-mis-stored-product-from-slot|UC-005]]：该 UC 取出纠错、仓位回滚为"空闲"的过程，会实时体现在本看板的仓位状态变化中；该 UC 的 Exception Flow（E3.1/E3.2）产生的"异常锁定"状态同样会展示在本看板中。
* [[uc-006-cancel-transport-task-upon-arrival|UC-006]]：任务被取消后的状态变化，会体现在本看板展示的任务状态字段中。
* [[uc-010-unload-completed-lot-at-destination-station|UC-010]]：该 UC 在终点站取出产品、仓位恢复"空闲"的过程，以及其 Exception Flow（E2.1/E2.2）产生的"异常锁定"状态，均会体现在本看板中。
