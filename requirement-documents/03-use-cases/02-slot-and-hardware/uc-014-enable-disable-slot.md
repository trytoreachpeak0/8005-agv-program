# UC-014 启用/禁用仓位

## 描述

操作人员在服务端选择一个或多个仓位，修改仓位管理可用性（SlotAdministrativeAvailability）。人工禁用是业务管理动作，只阻止新的 Sublot 使用该仓位，不改变仓位身份、不清除业务内容，也不覆盖车载端依据 IO 和硬件状态形成的仓位可操作性（SlotOperability）。

仓位没有活动操作、预留或业务内容时，禁用立即生效。仓位已被活动 Sublot 使用、已预留或载有产品时，进入待禁用（Disable Pending）：既有 Sublot 和必要卸货继续完成，但不得再分配给新的 Sublot；相关业务经服务端确认结束后自动转为已禁用。人工启用只恢复管理许可，若车载端仍判定硬件不可操作，仓位仍不能使用。

车载 HMI 必须在仓门真实物理位置显示“可用、待禁用或已禁用”，不得通过隐藏仓位表达禁用。

## 前置条件

1. 操作人员具备仓位管理权限。
2. 服务端能读取仓位业务状态、活动 Sublot 和最新车载能力快照。

## 正常流程

1. 操作人员选择一个或多个仓位并点击“禁用”或“启用”。
2. 服务端逐仓核验并独立处理：
   - 禁用且无活动/预留/内容：立即置为已禁用。
   - 禁用且存在活动/预留/内容：置为待禁用，阻止新分配，既有业务继续。
   - 启用：清除已禁用或待禁用管理标记，但不改变车载仓位可操作性。
3. 服务端可靠同步管理可用性到车载端，HMI 在原物理位置更新显示。
4. 待禁用仓位的既有 Sublot 或业务内容经服务端确认结束后，自动转为已禁用。
5. 服务端记录操作人、仓位、原状态、新状态、原因和时间。

## 异常流程

- 服务端与车载端尚未对账管理状态时，不得把该仓位用于新的 Sublot。
- 人工点击启用但车载端报告 IO 故障时，管理状态可恢复为可用，最终有效使用状态仍为“不可操作”，并显示硬件原因。
- 禁用请求到达时开锁已经开始，不中断当前开锁集合安全收尾。

## 备注

- 正常服务端应避免对正在执行 Sublot 的仓位发起禁用；待禁用是竞态与异常保护。
- 真正硬件故障由车载仓位可操作性立即生效，不使用待禁用延迟。
- 维护开门仍通过车载端控制 IO，服务端不能绕过车载安全联锁直接写通道。
