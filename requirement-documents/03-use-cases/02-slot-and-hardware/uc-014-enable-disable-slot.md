# UC-014 启用/禁用仓位

## 描述

操作人员在系统的仓位列表中选中一个或多个仓位（可对单个仓位单独操作，也可在同一批量请求中选择多个仓位一起处理），点击"禁用"或"启用"按钮。禁用后，该仓位不会再被 [[uc-001-load-completed-lot-into-slot|UC-001]] 分配用于装载新的完工产品，即无法在正常业务流程中被打开/关闭仓门用于存取物料；本 UC 仅允许对当前"空闲（Idle）"状态的仓位执行禁用，若目标仓位当前"已占用（Occupied）"或"异常锁定"，直接拒绝该仓位的禁用请求，不采用过渡状态设计。"启用"则是相反操作，将已禁用的仓位恢复为可正常分配使用的"空闲"状态。设备/维护人员仍可通过独立的维护界面对仓门进行开关操作（如设备检修、故障排查），该能力不受本 UC 维护的禁用状态限制，具体流程细节不在本 UC 范围内（见 Assumption 第 3 条）。

> 本 UC 与 [[uc-013-enable-disable-agv|UC-013]]"启用/禁用 AGV"是同一类"本地调度开关"设计模式在不同粒度上的应用——UC-013 作用于整台 AGV，本 UC 作用于单个仓位；两者的差异在于"目标对象当前有未完成的工作时如何处理"：UC-013 允许对有任务的 AGV 禁用，先进入"禁用待生效"过渡状态；本 UC 则直接拒绝对"已占用"仓位的禁用请求，不设置过渡状态（详见 Notes 中与用户确认的设计决策）。

## 触发条件

操作人员在仓位列表中选中一个或多个仓位，点击"禁用"或"启用"按钮。

## 前置条件

**系统与接口**

1. 本地服务器可读取各仓位当前状态（空闲/已占用/异常锁定/已禁用）。

**任务与数据**

2. 点击"禁用"时，目标仓位当前状态为"空闲（Idle）"（见 Exception Flow E3.1）。
3. 点击"启用"时，目标仓位当前状态为"已禁用（Disabled）"（见 Exception Flow E4.1）。

**人员与权限**

4. 操作人员具备禁用/启用仓位的操作权限（具体角色待定，见 Notes）。

## 后置条件

**任务与数据**

1. 点击"禁用"且目标仓位当前为"空闲"：该仓位状态变为"已禁用（Disabled）"，不再出现在 [[uc-001-load-completed-lot-into-slot|UC-001]] 分配空闲仓位时的可选范围内。
2. 点击"启用"且目标仓位当前为"已禁用"：该仓位状态恢复为"空闲（Idle）"，清除禁用标记，重新可被 UC-001 分配使用。
3. 若本次为批量请求（选中多个仓位），系统对每个仓位分别核验并处理：核验通过的仓位按上述第 1/2 条完成状态迁移，未通过核验的仓位被跳过、不受影响，其余仓位的处理结果也不受影响。
4. 本次操作（操作人、涉及仓位清单及各自处理结果：成功/跳过及原因、操作类型：禁用/启用、时间戳）被记录到本地数据库，用于追溯。This operation (operator, the list of involved slots with each one's result — success or skipped with reason —, operation type: disable/enable, timestamp)

## 假设

1. 本 UC 的"禁用"是纯本地系统层面的调度开关，只影响该仓位是否可被 [[uc-001-load-completed-lot-into-slot|UC-001]] 分配用于装载新任务，不涉及对仓位电子锁/光幕等硬件的禁用操作，也不联动 RIOT；与 [[uc-013-enable-disable-agv|UC-013]] 对"本地纯调度开关"的定位一致。
2. 因本 UC 仅允许对"空闲"仓位执行禁用（已占用仓位直接拒绝，见 Precondition 第 2 条、Exception Flow E3.1），"已禁用"状态的仓位必然是空的，不存在"已禁用但仓位内仍有产品"的情况；因此 [[uc-005-retrieve-mis-stored-product-from-slot|UC-005]]、[[uc-010-unload-completed-lot-at-destination-station|UC-010]] 这两个操作"已占用"仓位的 UC，不会遇到"目标仓位已被禁用"的场景，不需要为此新增核验逻辑。
3. 设备/维护人员可以通过一个独立于本 UC 的维护界面，对任意仓位（无论其当前是"空闲""已占用"还是"已禁用"）执行开关仓门操作，用于设备检修、故障排查等场景；该操作不受本 UC 维护的"已禁用"状态限制，也不会触发 UC-001/UC-005/UC-010 等业务流程中的核验逻辑（如光幕核验、任务归属核验）。该维护开关门能力的具体流程已由 [[uc-015-slot-door-unlock-open-test|UC-015]] 落地实现（用于仓门开锁/开启的硬件功能测试），本 UC 不再重复描述。

## 正常流程

### 14.0

1. 操作人员在仓位列表中选中一个或多个仓位
2. 操作人员点击"禁用"或"启用"按钮
3. 若点击"禁用"：
   3.1 系统对每个被选中的仓位分别核验其当前状态是否为"空闲（Idle）"（见 Exception Flow E3.1）
   3.2 对核验通过的仓位，系统将其状态置为"已禁用（Disabled）"；对未通过核验的仓位跳过，不做改变，不影响其余仓位的处理
4. 若点击"启用"：
   4.1 系统对每个被选中的仓位分别核验其当前状态是否为"已禁用（Disabled）"（见 Exception Flow E4.1）
   4.2 对核验通过的仓位，系统将其状态恢复为"空闲（Idle）"，清除禁用标记；对未通过核验的仓位跳过，不做改变，不影响其余仓位的处理
5. 系统记录本次操作（操作人、涉及仓位清单及各自处理结果、操作类型：禁用/启用、时间戳）
6. 系统在界面上汇总展示本次操作结果（成功处理的仓位数量、被跳过的仓位及各自原因）

## 备选流程

不存在需要区分的备选流程：无论操作人员选中的是单个仓位还是多个仓位，系统均按 Normal Flow 相同的"逐一核验 → 逐一处理 → 汇总结果"逻辑处理，单个仓位操作只是批量大小为 1 的特例，不构成触发方式或步骤不同的分支路径（写法参照 [[uc-011-view-slot-monitoring-dashboard|UC-011]]、[[uc-004-slot-door-safety-interlock|UC-004]] 中"不需要额外区分备选流程"的处理方式）。

## 异常流程

以下每条异常均以 `E<步骤号>` 编号，与 Normal Flow 中触发该异常的具体步骤一一对应：

* E3.1 被选中的仓位当前并非"空闲"状态（已占用/异常锁定），点击"禁用"
* E4.1 被选中的仓位当前并非"已禁用"状态，点击"启用"

### E3.1 被选中的仓位当前并非"空闲"状态，点击"禁用"

1. 操作人员选中的仓位中，某个仓位当前状态为"已占用（Occupied）"或"异常锁定"
2. 系统按第 3.1 步核验，发现该仓位不满足"空闲"条件
3. 系统跳过该仓位的禁用操作，在结果提示中标注该仓位"禁用失败：当前非空闲状态"；本次请求中其余满足条件的仓位不受影响，仍按计划继续禁用
4. 操作人员核对提示：若该仓位确需禁用，需等待其恢复"空闲"（如通过 [[uc-005-retrieve-mis-stored-product-from-slot|UC-005]] 取出产品、或 [[uc-010-unload-completed-lot-at-destination-station|UC-010]] 完成取料后仓位释放）后重新发起禁用请求；若为"异常锁定"状态，需联系设备/电气维护人员（R-11）先排除异常

### E4.1 被选中的仓位当前并非"已禁用"状态，点击"启用"

1. 操作人员对某个当前并非"已禁用"状态的仓位点击"启用"按钮
2. 系统按第 4.1 步核验，发现该仓位当前并非"已禁用"状态
3. 系统跳过该仓位的启用操作，在结果提示中标注该仓位"无需启用：当前并非禁用状态"；本次请求中其余满足条件的仓位不受影响，仍按计划继续启用
4. 操作人员核对该仓位当前状态，确认是否操作了正确的目标仓位

## 备注

* 本 UC 是用户提出的新场景："人员禁用和启用仓位……禁用仓位后，这个仓位就没法在执行任务的时候存取物料了（打开仓门和关上仓门），但是维护人员还是可以通过自己的界面打开和关闭仓门"。经与用户确认以下设计决策后独立成 UC：
  1. 禁用/启用操作既支持对单个仓位单独操作，也支持在同一批量请求中选择多个仓位一起处理（见 Normal Flow）。
  2. 仅允许对当前"空闲"的仓位执行禁用；若仓位当前"已占用"，直接拒绝该仓位的禁用请求（见 Exception Flow E3.1），不采用 [[uc-013-enable-disable-agv|UC-013]] 中 AGV"禁用待生效"的过渡状态设计——即本 UC 不存在"仓位有产品但仍被标记为待禁用"的中间态。
  3. "维护人员通过自己界面开关仓门"这一能力，本 UC 只在 Assumption 第 3 条中说明其不受禁用状态影响；具体的维护开关门流程已由 [[uc-015-slot-door-unlock-open-test|UC-015]] 补充落地，本 UC 不再重复描述。
* 禁用/启用仓位的操作角色本次不做确定，先留 TBD；该角色与"维护开关门"所涉及的角色是否为同一人也待定，两者不一定相同（例如禁用/启用可能是班组长或生产管理者的调度决策，而维护开关门可能是设备/电气维护人员 R-11 的现场操作）。
* 待补充（TBD）事项：
  1. 禁用/启用仓位的操作角色（`primary_actor`）最终确定。
  2. 已禁用仓位是否需要在 [[uc-011-view-slot-monitoring-dashboard|UC-011]] 监控看板中单独展示状态标识，及展示方式。
  3. 批量操作时是否有数量上限、是否支持跨 AGV 批量选择（本 UC 当前未限定选中仓位是否必须属于同一台 AGV）。
