# UC-018 点位映射表核对测试

## 描述

维护人员对系统中配置的"仓位—DO/DI 点位映射表"逐个仓位进行双向核对：方向一，系统按配置向某仓位下发开锁 DO 指令，维护人员现场目视确认实际发生反应（弹开）的是哪个物理仓位，核对其是否与配置中该 DO 点位对应的仓位编号一致；方向二，维护人员现场手动触发某个物理仓位的传感器（如遮挡光幕或开合仓门），在软件侧核对系统读取到 DI 变化的是哪个仓位编号，核对其是否与该物理仓位配置中的编号一致。两个方向均核对通过，才判定该仓位的 IO 映射配置正确。

> 本 UC 验证的是配置层面的"点位—物理位置"对应关系是否正确，与 [[uc-015-slot-door-unlock-open-test|UC-015]]、[[uc-016-slot-light-curtain-function-test|UC-016]]、[[uc-017-slot-door-state-detection-test|UC-017]] 验证"某个仓位的硬件本身是否正常工作"是不同维度的问题：若映射配置本身是错的，即使被误指向的那个仓位硬件完全正常，那三个 UC 的测试结果也会被误判到错误的仓位上；因此本 UC 是那三者能够正确工作的更底层前提，通常应先于它们进行（尤其在设备安装/改线后）。

## 触发条件

设备安装/改线/新增仓位后，或怀疑现有映射配置有误时，维护人员发起 IO 点位映射核对。

## 前置条件

**系统与接口**

1. 本地服务器与 IO 模块之间通信正常，可正常下发 DO 指令并读取 DI 状态。
2. 系统中已存在一份仓位—DO/DI 点位映射配置（待核对的对象本身）。

**任务与数据**

3. 建议本次核对涉及的仓位提前通过 [[uc-014-enable-disable-slot|UC-014]] 标记为"已禁用"，避免核对期间被业务流程意外分配使用（非强制，处理方式同 UC-015/016/017）。

**人员与权限**

4. 维护人员具备查看 IO 映射配置、下发测试指令的权限（具体角色待定，见 Notes）。

## 后置条件

**任务与数据**

1. 若某仓位两个方向均核对通过：该仓位的 IO 映射配置被确认正确。
2. 若某仓位任一方向核对不通过：该仓位被标记为"映射异常"，暂停对该仓位的业务分配，直至配置被修正并重新核对通过（见 Exception Flow E3.1/E4.1）。
3. 本次核对结果（维护人员、涉及仓位清单及各自核对结果：通过/映射异常、时间戳）被记录到本地数据库，用于追溯。This verification result (engineer, the list of involved slots with each one's result — pass or mapping error —, timestamp)

## 假设

1. 本 UC 假定"仓位—DO/DI 点位映射表"是系统中已存在的一份配置数据（无论以何种形式存储），本 UC 只负责核对其正确性，不负责该配置最初如何生成/录入，也不提供批量自动生成映射的能力。仓位实例本身（编号、位置、规格）的存在，来自 [[uc-038-maintain-agv-slot-model|UC-038]] 型号版本在 AGV 接入（UC-019）时的自动生成，但仓位到具体 DO/DI 点位的映射关系仍需另行配置，不由 UC-038/UC-019 一并生成。
2. 方向一（DO→观察物理仓位）依赖维护人员现场目视判断"是哪个仓位有反应"，方向二（触发物理仓位→读取软件 DI）依赖维护人员准确记住/确认自己触发的是哪个物理仓位；两个方向都依赖人工判断的准确性，系统本身无法独立交叉验证。Direction one (DO → observe physical slot) relies on the engineer's on-site visual judgment of which slot reacted; direction two (trigger physical slot → read software DI)

## 正常流程

### 18.0

1. 维护人员在维护界面中选择待核对的仓位（可逐个选择，也可按 AGV 批量选择多个仓位依次核对）
2. 对该仓位执行方向一核对：
   2.1 系统按当前配置向该仓位下发开锁 DO 指令
   2.2 维护人员现场目视确认实际发生反应（弹开）的是哪个物理仓位
   2.3 维护人员核对第 2.2 步确认的物理仓位编号是否与配置中该 DO 点位对应的仓位编号一致（见 Exception Flow E2.3）
3. 对该仓位执行方向二核对：
   3.1 维护人员现场手动触发某个物理仓位的传感器（如遮挡光幕或开合仓门）
   3.2 维护人员在软件侧查看系统读取到本次 DI 变化对应的仓位编号
   3.3 维护人员核对第 3.2 步系统显示的仓位编号是否与第 3.1 步实际触发的物理仓位一致（见 Exception Flow E3.3）
4. 该仓位两个方向均核对通过后，系统记录该仓位映射核对结果为"通过"
5. 若本次选中了多个仓位，对下一个仓位重复第 2~4 步，直至全部选中仓位核对完毕
6. 系统汇总记录本次核对结果（维护人员、涉及仓位清单及各自结果、时间戳）

## 备选流程

不存在需要区分的备选流程：无论本次核对的是单个仓位还是多个仓位，均按 Normal Flow 相同的"方向一→方向二→记录"步骤逐一执行，单个仓位只是批量的特例，写法参照 [[uc-014-enable-disable-slot|UC-014]] 对单个/批量操作的处理方式。

## 异常流程

以下每条异常均以 `E<步骤号>` 编号，与 Normal Flow 中触发该异常的具体步骤一一对应：

* E2.3 方向一核对不通过：DO 触发反应的物理仓位与配置不一致
* E3.3 方向二核对不通过：软件读取到的 DI 变化仓位编号与实际触发的物理仓位不一致

### E2.3 方向一核对不通过

1. 系统按第 2.1 步向配置中指向该仓位的 DO 点位下发开锁指令
2. 维护人员按第 2.3 步核对，发现实际发生反应（弹开）的物理仓位，与配置中该 DO 点位对应的仓位编号不一致（例如系统认为下发的是"仓位 3"的指令，但实际是"仓位 5"的门弹开）
3. 判定该仓位（按物理位置计）的 DO 映射配置错误，系统将涉及的仓位标记为"映射异常"，暂停对其业务分配，记录本次核对结果
4. 维护人员联系 IT/软件维护人员（R-12）或自行核实并修正该物理仓位的 DO 点位映射配置（或检查、修正实际接线），修正后重新发起本测试，直至该仓位方向一核对通过

### E3.3 方向二核对不通过

1. 维护人员按第 3.1 步手动触发某个物理仓位的传感器
2. 维护人员按第 3.3 步核对，发现软件侧显示的 DI 变化仓位编号，与自己实际触发的物理仓位不一致
3. 判定该物理仓位的 DI 映射配置错误，系统将涉及的仓位标记为"映射异常"，暂停对其业务分配，记录本次核对结果
4. 维护人员联系 IT/软件维护人员（R-12）或自行核实并修正该物理仓位的 DI 点位映射配置（或检查、修正实际接线），修正后重新发起本测试，直至该仓位方向二核对通过

## 备注

* 本 UC 是用户提出的新场景"测试 IO 点位映射表是否设置正确"，经与用户确认，核对需要双向进行（DO→物理位置、物理位置→DI），因此 Normal Flow 按方向一/方向二两步分别描述，而不是单向核对。
* 本 UC 与 [[uc-015-slot-door-unlock-open-test|UC-015]]、[[uc-016-slot-light-curtain-function-test|UC-016]]、[[uc-017-slot-door-state-detection-test|UC-017]] 的关系：那三者验证的是"某个仓位的硬件本身是否正常工作"，前提是 IO 映射本身正确；本 UC 验证的是映射配置本身，属于更底层的前提条件，建议在设备安装/改线后先执行本 UC，再执行那三者。
* 维护角色本次不做最终确定，先留 TBD，推测候选为 R-11 设备/电气维护人员；映射配置的修正可能需要 IT/软件维护人员（R-12）介入，两者是否为同一次操作中的同一人待后续确认。
* 待补充（TBD）事项：
  1. 维护操作角色（`primary_actor`）最终确定，以及映射配置修正具体由 R-11 还是 R-12 执行、或两者协作完成。
  2. 映射配置数据本身的存储形式、查看/编辑界面细节，本 UC 暂不展开。
  3. 是否需要提供一种"批量自动核对"手段（如系统依次自动下发全部仓位的 DO 并要求维护人员逐一确认，而非维护人员手动逐个发起），当前 Normal Flow 按维护人员逐个手动核对描述，如需自动化辅助待后续补充。
