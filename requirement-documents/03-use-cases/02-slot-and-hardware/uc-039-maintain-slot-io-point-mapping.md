# UC-039 维护仓位—IO点位映射配置

## 描述

IT/软件维护人员（R-12，必要时 R-11 现场协同）为某个仓位实例（见 [[uc-038-maintain-agv-slot-model|UC-038]]、[[uc-019-register-agv-from-rcs|UC-019]] 生成的仓位实例）录入或调整其对应的 DO/DI 点位映射：至少包括开锁输出点位（DO，对应 [[uc-015-slot-door-unlock-open-test|UC-015]] 测试的开锁指令）、门状态输入点位（DI，对应 [[uc-017-slot-door-state-detection-test|UC-017]] 测试的门状态反馈）、光幕状态输入点位（DI，对应 [[uc-016-slot-light-curtain-function-test|UC-016]] 测试的光幕遮挡状态）。本 UC 是这三个硬件功能测试 UC、以及 [[uc-018-io-point-mapping-verification-test|UC-018]] 核对测试的更底层前提：先有配置数据本身，后续才能测试其"是否正确""是否工作正常"。

> 本 UC 与 [[uc-018-io-point-mapping-verification-test|UC-018]] 的分工边界：本 UC 负责"配置数据的创建、修改、删除"，UC-018 负责"核对已有配置数据是否与物理点位实际对应正确"；两者不重复，但存在明显的先后依赖——没有本 UC 先建立映射配置，UC-018 无从核对。

## 触发条件

出现以下任一情况：

1. [[uc-019-register-agv-from-rcs|UC-019]] 接入新 AGV、生成新的仓位实例后，需要为这些新仓位逐一录入 IO 点位映射（TBD：是否要求接入当天即完成录入，或允许仓位暂时处于"未配置映射"状态但不可用，见 Notes）。
2. 设备安装、改线、更换 IO 模块或调整点位分配后，需要修改现有仓位的映射。
3. [[uc-018-io-point-mapping-verification-test|UC-018]] 核对不通过、判定某仓位"映射异常"后，需要修正对应的映射配置（见 UC-018 Exception Flow E2.3/E3.3）。
4. 需要删除已下线/报废仓位对应的映射配置。

## 前置条件

**系统与接口**

1. 本地服务器与目标 IO 模块之间通信正常，可用于后续下发测试指令核实（本 UC 本身只保存配置，不强制要求配置时 IO 模块必须在线，具体是否要求在线校验见 Exception Flow）。

**任务与数据**

2. 目标仓位实例已存在（来自 [[uc-038-maintain-agv-slot-model|UC-038]] 型号版本在 [[uc-019-register-agv-from-rcs|UC-019]] 接入时自动生成），本 UC 不创建仓位实例本身，只维护其到 IO 点位的映射。

**人员与权限**

3. 操作人员具备维护 IO 点位映射配置的权限（见 [[stakeholders-and-user-classes|干系人与用户角色清单]] R-12；R-11 是否需要独立的系统操作权限、还是仅现场协同，TBD 见 Notes）。

## 后置条件

**任务与数据**

1. 目标仓位的 IO 点位映射配置（DO 开锁点位、DI 门状态点位、DI 光幕点位，以及各点位所属 IO 模块/通道标识）被创建、修改或删除，保存到本地数据库。
2. 新建或修改后的映射配置默认处于"待核对"状态，需经 [[uc-018-io-point-mapping-verification-test|UC-018]] 核对通过后才能变为"已验证"，验证前该仓位是否可被业务分配，TBD 见 Notes。
3. 本次配置变更（操作人、仓位、变更前后的点位内容、时间戳、原因）被记录到本地数据库，用于追溯。

## 假设

1. 本 UC 假定每个仓位与其 DO/DI 点位之间是一对多的静态配置关系（一个仓位可能同时对应开锁 DO、门状态 DI、光幕 DI 三类点位），不涉及运行时动态改变某仓位使用哪个点位；运行时如需临时更换点位（如硬件故障后接线调整到备用通道），仍需回到本 UC 修改配置后重新走 UC-018 核对。
2. 本 UC 不校验录入的点位标识在 IO 模块侧是否真实存在、是否已被其他仓位占用——点位是否配置正确、是否与实际物理位置一致，由 [[uc-018-io-point-mapping-verification-test|UC-018]] 的双向核对来验证，不在本 UC 的核验范围内（本 UC 只做格式/唯一性等静态校验，见 Exception Flow）。

## 正常流程

### 39.0

1. 操作人员进入 IO 点位映射维护界面，选择目标仓位实例（可按 AGV/仓位编号查找）
2. 操作人员为该仓位录入或修改点位信息：开锁 DO 点位（IO 模块标识 + 通道号）、门状态 DI 点位、光幕 DI 点位
3. 系统校验（见 Exception Flow）：
   3.1 同一 IO 模块的同一通道号，是否已被本仓位或其他仓位的其他点位类型重复占用
   3.2 必填点位（至少开锁 DO、门状态 DI）是否均已填写
4. 操作人员确认保存
5. 系统将该仓位映射配置状态置为"待核对"，记录变更内容、操作人、时间戳
6. 操作人员或维护人员前往 [[uc-018-io-point-mapping-verification-test|UC-018]] 对该仓位发起核对测试

## 备选流程

### A2.1 批量导入多个仓位的映射配置

1. 操作人员选择批量导入方式（如按 AGV 一次性导入其全部仓位的映射），而非逐个仓位手动录入
2. 系统按 Normal Flow 第 3 步同样的规则逐条校验导入内容，对校验不通过的条目单独提示，不影响其他条目正常保存
3. 其余步骤与 Normal Flow 一致

> 是否需要支持批量导入、导入文件格式，TBD 待补充，见 Notes。

## 异常流程

以下每条异常均以 `E<步骤号>` 编号，与 Normal Flow 中触发该异常的具体步骤（或子步骤）一一对应：

* E3.1 点位通道重复占用
* E3.2 必填点位缺失

### E3.1 点位通道重复占用

1. 操作人员保存的配置中，某 IO 模块的某通道号已被本仓位其他点位类型或另一仓位占用
2. 系统拒绝保存，提示冲突的具体 IO 模块、通道号及已占用该通道的仓位/点位类型
3. 操作人员核实并修正点位分配后重新保存

### E3.2 必填点位缺失

1. 操作人员保存的配置中，开锁 DO 点位或门状态 DI 点位未填写
2. 系统拒绝保存，提示缺失的具体点位类型
3. 操作人员补充完整后重新保存

## 备注

* 本 UC 是为填补需求缺口而新增：[[uc-018-io-point-mapping-verification-test|UC-018]] 的 Assumption 第 1 条明确写明"本 UC 假定仓位—DO/DI 点位映射表是系统中已存在的一份配置数据……不负责该配置最初如何生成/录入"，此前 03-use-cases 目录下没有任何 UC 覆盖"这份配置数据本身如何创建/维护"，导致设备安装、新接入 AGV 等场景下第一次录入映射时无据可依，形成流程闭环缺口；本 UC 用于补齐这一环节。
* 待补充（TBD）事项：
  1. 仓位在映射配置"待核对"状态下（尚未经 UC-018 核对通过）能否被业务流程正常分配使用，还是必须先核对通过才可用；本 UC 暂按"待核对"状态保存但不强制阻断业务分配来描述，具体是否需要强制阻断待与用户确认。
  2. 操作角色最终确定：R-12 是否为唯一可操作本 UC 的角色，R-11 是否需要独立的系统操作权限（而非仅现场口头协同确认物理点位/接线），还是两者共用一个账号协作完成（参照 [[stakeholders-and-user-classes|干系人清单]] R-11/R-12/R-13 兼任说明）。
  3. 是否需要批量导入能力及具体文件格式（见 Alternative Flow A2.1）。
  4. 高风险变更（如修改已被业务频繁使用的仓位映射）是否需要二次认证，参照 [[uc-038-maintain-agv-slot-model|UC-038]]、[[uc-024-maintain-area-station-mapping|UC-024]] 等其他配置类 UC 的二次认证做法，本 UC 暂未加入，待用户确认后统一。

## 关联用例

* [[uc-038-maintain-agv-slot-model|UC-038]]：本 UC 维护的仓位实例来源于该 UC 定义的型号版本在 [[uc-019-register-agv-from-rcs|UC-019]] 接入时自动生成；本 UC 不涉及仓位数量、位置、规格本身的定义。
* [[uc-019-register-agv-from-rcs|UC-019]]：新接入 AGV、生成新仓位实例后，本 UC 是紧接着需要执行的下一步（否则新仓位无法通过硬件功能测试或业务分配）。
* [[uc-018-io-point-mapping-verification-test|UC-018]]：本 UC 创建/修改的映射配置，需经该 UC 的双向核对验证其正确性；该 UC 核对不通过后判定"映射异常"，需要回到本 UC 修正配置。
* [[uc-015-slot-door-unlock-open-test|UC-015]]、[[uc-016-slot-light-curtain-function-test|UC-016]]、[[uc-017-slot-door-state-detection-test|UC-017]]：三者测试的硬件功能均依赖本 UC 先配置好正确的点位映射，否则测试结果可能被误判到错误的物理仓位（与 UC-018 的说明一致）。
* [[uc-014-enable-disable-slot|UC-014]]：仓位映射配置变更期间，建议配合该 UC 将目标仓位标记为"已禁用"，避免变更过程中被业务流程意外分配使用。
