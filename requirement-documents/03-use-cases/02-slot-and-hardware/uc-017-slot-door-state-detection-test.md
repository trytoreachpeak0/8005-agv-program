# UC-017 锁状态反馈与仓门闩合识别测试

## 描述

现场没有独立门磁或门位 DI。系统通过电子锁的锁状态 DI 判断锁舌是否闩合：有效开锁脉冲应使锁舌释放、弹簧自动弹开仓门且锁 DI 变为“未锁”；脉冲 DO 自动复位后，锁 DI 仍保持“未锁”；维护人员实际关门并使锁舌重新闩合后，锁 DI 才变为“锁闭”。

本 UC 验证开锁、自动弹门、关门闩合与锁 DI 的对应关系。维护人员目视确认仓门是否弹开或关严，系统读取锁 DI；不得把 DO=0 当作仓门已经关闭，也不得虚构独立门状态点位。

## 触发条件

维护人员需要验证某仓位的电子锁反馈和仓门闩合识别是否正常。

## 前置条件

1. 车辆已经按 ADR-CROSS-0007 进入车辆配置维护态，整车无货且全部仓位初始锁闭。
2. 车载上位机与 IO 模块通信正常，可读取目标仓位锁状态 DI 和开锁 DO 回读。
3. 目标仓位已停止新的业务分配。

## 后置条件

1. 测试正常时，系统记录开锁后“未锁”、DO 复位后仍“未锁”、关门闩合后“锁闭”的结果。
2. 任一步骤失败时，目标仓位标记为测试未通过和硬件不可操作，暂停新的业务分配。
3. 记录维护人员、仓位号、各阶段 DO/DI 读数、目视结果、时间戳和最终结论。

## 正常流程

### 17.0

1. 维护人员选择目标仓位，确认初始锁 DI 为“锁闭”。
2. 车载上位机按 [[uc-015-slot-door-unlock-open-test|UC-015]] 发出一次开锁脉冲。
3. 维护人员确认弹簧已自动弹开仓门；系统确认锁 DI 变为“未锁”。
4. 系统等待脉冲 DO 自动复位，确认 DO 已复位且锁 DI 仍为“未锁”。
5. 维护人员关闭仓门并确认锁舌已经闩合。
6. 系统确认锁 DI 变回“锁闭”，记录测试通过。

## 异常流程

### E3.1 开锁后仓门未弹开或锁 DI 未变为未锁

1. 系统停止后续自动动作，不盲目重复开锁。
2. 记录目视结果、DO 回读和锁 DI，标记该仓位测试未通过和硬件不可操作。
3. 维护人员排查弹簧机构、锁舌、电磁铁、接线或反馈信号后重新测试。

### E4.1 开锁 DO 未自动复位

1. 系统报告 IO 输出故障，不允许执行关门闩合测试。
2. 目标仓位保持不可操作，等待维护人员处理。

### E6.1 关门后锁 DI 未变为锁闭

1. 系统判定仓门尚未可靠闩合或锁反馈异常，不允许把车辆视为仓门安全。
2. 维护人员重新关门；仍失败时标记测试未通过并排查机构、接线或反馈信号。

## 备注

- 锁 DI 为“锁闭”可以证明仓门已关并闩合；锁 DI 为“未锁”只能证明没有闩合。正常机构中开锁后弹簧会自动弹门，维护测试仍通过目视确认实际弹门结果。
- 本 UC 不测试光幕遮挡，光幕测试见 [[uc-016-slot-light-curtain-function-test|UC-016]]。
- IO 映射正确性见 [[uc-018-io-point-mapping-verification-test|UC-018]]。
