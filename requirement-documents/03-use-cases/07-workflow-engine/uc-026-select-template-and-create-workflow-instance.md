# UC-026 选择模板并创建流程实例

## 描述

本地服务器在 MES 入口接收并标准化候选数据，冻结模板匹配所需的业务上下文，按 [[br-004-workflow-template-matching|BR-004]] 从有效 `Published` 版本中选择唯一模板，并在原子事务中创建流程实例和 [[br-005-workflow-template-versioning|BR-005]] 规定的不可变模板版本快照。

无匹配、多匹配、关键输入不完整或快照持久化失败时一律 fail-closed，不启动步骤、不下发外部写操作。具有专项权限的 R-12/R-13 可在二次认证并填写原因后，对单个异常实例手动选择一个安全有效的已发布版本；该覆盖不修改模板规则。

## 触发条件

出现以下任一情况：

1. MES 入口收到一条待处理候选数据，并已完成原始接收。
2. 已存在业务任务补齐并冻结了完整匹配上下文，等待创建流程实例。
3. “无匹配”或“多匹配”实例收到授权人工覆盖请求。

## 前置条件

1. 候选数据已通过来源认证，并具有稳定的候选、MES 事务或业务幂等标识。
2. 系统可以读取当前有效的 AREA—站点映射、步骤目录和已发布模板版本。
3. 用于匹配的 `moveType`、`taskSource`、`materialType`、起终点及站点类型可以被标准化和冻结；缺失情况在流程中显式校验。
4. 模板匹配、流程实例、快照和审计存储可参与可恢复的一致性事务。

## 后置条件

1. 唯一匹配成功时，创建一个流程实例，并绑定当时模板版本、步骤目录版本和内容校验值的不可变快照。
2. 匹配输入、候选版本、优先级向量、选择结果、覆盖记录和创建结果可审计。
3. 无匹配、多匹配或输入异常时，候选/任务保持明确的“模板匹配异常/等待授权处理”状态，不执行危险动作或外部写入。
4. 后续模板发布、停用或修改不改变已创建实例的快照。

## 假设

1. MES 原子查询、业务字段校验和去重规则仍由 [[uc-007-sync-transport-task-from-mes|UC-007]] 负责；本 UC 从可识别的候选数据进入流程编排边界开始。
2. AREA—站点解释由 [[uc-024-maintain-area-station-mapping|UC-024]] 和 [[br-003-area-station-mapping|BR-003]] 定义，本 UC 只消费并冻结解析结果。
3. 手动覆盖只解决单实例模板选择，不允许编辑模板、补造未知业务值或绕过安全步骤。

## 正常流程

### 26.0

1. 本地服务器接收 MES 候选数据及其来源、事务标识和接收时间。
2. 系统把入口字段标准化为预置类型和枚举，形成候选快照：
   2.1 保留原始值摘要、标准化值、转换规则版本和字段来源。
   2.2 不把空值、未知枚举、读取失败或转换失败解释为 `ANY`。
3. 系统按 BR-003 解析并冻结起点、终点的 station_name 及其命中的 area_code；解析失败或冲突时进入位置异常，不进入后续匹配步骤。
4. 系统冻结 BR-004 所需的 `moveType`、`taskSource`、`materialType`、起终点站点及站点类型等匹配输入。
5. 系统从当前已生效且未停用的 `Published` 模板版本中建立候选集合，并排除未知步骤、结构无效或目录不兼容的版本。
6. 系统按 BR-004 的优先级向量逐项比较，不使用模板名称、创建时间、主键、版本号或配置顺序消除并列。
7. 系统确认最高优先级候选恰好一个。
8. 系统校验所选模板版本的状态、内容校验值、步骤目录版本及 [[br-006-workflow-step-execution|BR-006]] 结构。
9. 系统在同一事务中：
   9.1 创建唯一流程实例和有序步骤实例。
   9.2 保存不可变模板版本快照、匹配输入和选择证据。
   9.3 关联候选数据、业务任务及适用的 MES 标识。
   9.4 将流程实例置为 `Pending`，但不在本 UC 中执行步骤。
10. 系统写入创建审计，并触发 [[uc-027-execute-workflow-steps|UC-027]]。

## 备选流程

### A7.1 授权手动覆盖匹配结果

1. 系统已将“无匹配”或“多匹配”结果保持为阻断状态。
2. 具有“流程模板匹配覆盖”专项权限的 R-12/R-13 查看原匹配输入、候选列表、优先级向量及异常原因。
3. 操作人员从当前仍有效、结构有效且步骤已知的 `Published` 版本中选择一个版本，填写非空、可追溯的覆盖原因。
4. 操作人员使用个人账号再次刷卡或认证。
5. 系统确认所选模板不能绕过 BR-006 的强制安全步骤和步骤目录限制。
6. 系统仅针对当前候选/任务执行第 8～10 步，并把原结果、所选版本、原因、操作人、角色、认证时间和关联告警写入审计。

### A1.1 从已绑定业务任务创建实例

1. 业务任务已在创建事务中完成唯一匹配并绑定模板快照。
2. 系统校验任务快照完整性，复制同一版本快照创建流程实例。
3. 系统不得因出现新模板版本而重新匹配。

## 异常流程

以下异常与 Normal/Alternative Flow 的对应步骤关联：

- E2.1 候选标准化失败。
- 或站点解析失败。
- E7.1 无匹配。
- E7.2 多匹配。
- E8.1 模板或目录完整性校验失败。
- E9.1 实例、快照或审计持久化失败。
- EA4.1 手动覆盖认证或授权失败。
- EA5.1 手动覆盖版本不安全或已失效。

### E2.1 候选标准化失败

1. 关键字段缺失、类型错误、枚举未知或原始值相互冲突。
2. 系统记录原始值摘要及标准错误码，进入“模板匹配异常”，不得猜测、默认补齐或继续匹配。

或站点解析失败

1. AREA 为空、映射缺失/停用/异常，或站点类型无法确定。
2. 系统按 BR-003 记录位置异常，不得用 `ANY` 或其他站点代替。

### E7.1 无匹配

1. 候选集合为空。
2. 系统保存匹配输入和排除原因，将候选/任务置于“无匹配/等待授权处理”。
3. 系统不创建可执行实例，不开锁、不派车、不调用外部写接口。

### E7.2 多匹配

1. 最高优先级存在两个或以上候选。
2. 系统记录所有并列版本及优先级向量，不自动任选一个。
3. 候选/任务进入“多匹配/等待授权处理”，仅可转 A7.1 或等待模板配置修正。

### E8.1 模板或目录完整性校验失败

1. 版本状态变化、校验值不一致、快照字段不完整、步骤未知或目录不兼容。
2. 系统拒绝实例创建并告警，不改用最新版本或其他候选继续执行。

### E9.1 实例、快照或审计持久化失败

1. 流程实例、步骤实例、不可变快照、关联关系或审计任一写入失败。
2. 系统回滚本次创建，不留下可执行的部分实例；幂等重试时先检查既有事务结果。

### EA4.1 手动覆盖认证或授权失败

1. 操作人员无专项权限、二次认证失败/超时、身份不一致或原因无效。
2. 系统拒绝覆盖，保持原阻断状态并记录失败审计。

### EA5.1 手动覆盖版本不安全或已失效

1. 所选版本已 `Retired`、结构无效、含未知步骤或会绕过强制安全约束。
2. 系统拒绝覆盖；若不存在安全有效的已发布版本，实例继续阻断。

## 备注

- 本 UC 合并“唯一模板选择”和“创建不可变快照实例”，保证两者之间不存在模板被替换的时间窗口。
- UC-007 的候选获取、业务校验和去重不在此重复定义；本 UC 只补充进入流程引擎前的标准化、匹配和快照边界。
- 手动覆盖不修改 BR-004 排序规则，也不影响其他候选、任务或实例。
