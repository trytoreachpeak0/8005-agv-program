# UC-027 执行流程步骤

## 描述

流程引擎依据流程实例绑定的不可变模板快照和 [[br-006-workflow-step-execution|BR-006]]，一次推进一个 [[workflow-step-catalog|预置步骤]]。步骤通过受控适配器复用 [[uc-007-sync-transport-task-from-mes|UC-007]]、[[uc-024-maintain-area-station-mapping|UC-024]]、[[uc-023-allocate-transport-tasks-to-agv|UC-023]]、[[uc-008-dispatch-move-order-to-riot|UC-008]]、[[uc-009-monitor-move-order-until-arrival|UC-009]]、[[uc-001-load-completed-lot-into-slot|UC-001]]、[[uc-010-unload-completed-lot-at-destination-station|UC-010]]、[[uc-002-confirm-task-completion|UC-002]] 等原子业务能力，不在本 UC 重复定义其业务规则。

引擎支持固定顺序、受限条件跳过、有限重试和等待外部事件，记录每次步骤尝试的输入输出。流程实例状态描述编排进度，业务任务状态只能由预置业务状态转换步骤按既有状态机改变，二者不得合并或互相默认映射。

## 触发条件

出现以下任一情况：

1. UC-026 成功创建状态为 `Pending` 的流程实例。
2. 当前步骤成功、允许跳过或达到下一次重试时间。
3. 当前等待步骤收到可认证、可关联且未重复的外部事件。
4. 系统重启后恢复一个可证明状态一致的非终态实例。

## 前置条件

1. 流程实例及其模板版本快照完整，内容校验值和步骤目录版本可验证。
2. 当前步骤是快照顺序链中唯一可运行的步骤，不存在另一个 `Running` 步骤。
3. 步骤类型存在于 [[workflow-step-catalog|预置流程步骤目录]]，参数符合 Schema，适配器已注册。
4. 流程状态、步骤状态、幂等记录和审计存储可用。

## 后置条件

1. 当前步骤被持久化为 `Succeeded`、允许的 `Skipped`、`WaitingExternal`、`RetryWaiting` 或 `Failed`。
2. 只有当前步骤成功或允许跳过后，下一顺序步骤才被激活。
3. 所有步骤成功/允许跳过后，流程实例为 `Completed`；该状态不自动把业务任务置为完成。
4. 每次尝试的输入、输出、幂等键、事件、错误、状态迁移和关联业务对象可审计。

## 假设

1. 原子用例负责各自领域内的校验、状态和副作用；流程引擎只按目录契约调用。
2. 模板快照不会在运行时插入、删除、重排步骤或切换到新版本。
3. 同一业务动作的幂等标识可跨进程重启和重复消息稳定复用。

## 正常流程

### 27.0

1. 引擎加载流程实例、不可变模板快照、当前步骤及最后持久化状态。
2. 系统校验快照内容、步骤目录版本、步骤类型、参数和唯一当前步骤。
3. 系统取得当前步骤所需的冻结输入及受控实时状态，生成或复用稳定的 `idempotencyKey`。
4. 若步骤配置了条件跳过，系统使用快照声明的预置字段、比较符和枚举求值：
   4.1 结果为 `true` 且目录允许跳过时，将步骤记为 `Skipped`。
   4.2 结果为 `false` 时继续执行当前步骤。
5. 系统将步骤置为 `Running`，记录尝试号、开始时间、输入快照及来源。
6. 系统通过步骤目录绑定的受控适配器调用对应能力，例如：
   6.1 MES 接收、校验、去重或建单能力（UC-007）。
   6.2 AREA—站点解析能力（UC-024）。
   6.3 任务范围与 AGV 选择能力（UC-023）。
   6.4 RCS/RIOT 下发和状态监控能力（UC-008、UC-009）。
   6.5 人员认证、扫码、装取料、仓门/光幕/联锁与确认能力（UC-001、UC-010、UC-002 及其关联安全用例）。
7. 系统取得标准化输出或进入预置外部事件等待。
8. 对同步完成的步骤，系统验证输出、副作用结果和幂等状态。
9. 系统在可恢复的一致性边界内保存输出摘要、外部标识、步骤状态和审计：
   9.1 成功时置为 `Succeeded`。
   9.2 等待事件时置为 `WaitingExternal`，流程实例同步显示等待原因和截止时间。
10. 当前步骤成功或允许跳过后，系统激活快照中的下一顺序步骤并重复第 2～9 步。
11. 最后一个步骤成功或允许跳过后，系统将流程实例置为 `Completed`，保留业务任务自身的独立状态。

## 备选流程

### A4.1 条件跳过当前步骤

1. 当前步骤被目录标记为可跳过，且预置条件明确求值为 `true`。
2. 系统记录条件定义、输入值和结果，将步骤置为 `Skipped`。
3. 系统按固定顺序进入下一步骤，不允许跳到任意节点。

### A7.1 等待外部事件

1. 当前步骤声明预置事件类型、来源、关联键、去重键和超时。
2. 系统持久化 `WaitingExternal` 状态并暂停推进。
3. 收到事件后，系统认证来源，核验实例、步骤、对象、顺序和去重键。
4. 事件有效时，步骤恢复为 `Running`，按第 8～10 步处理。

### A8.1 可恢复错误自动重试

1. 步骤目录允许重试，错误被分类为可恢复，且尚未达到快照中的有限重试上限。
2. 系统按固定或受限指数退避将步骤置为 `RetryWaiting`。
3. 到期后复用稳定幂等键并增加 `attemptNo`，重新执行当前步骤。
4. 详细异常处置遵循 [[uc-028-handle-workflow-step-exception|UC-028]]。

### A1.1 崩溃后恢复

1. 引擎根据持久化步骤状态、幂等记录及外部对账结果恢复实例。
2. 已确认成功的步骤不重复产生副作用；结果未知的步骤不被默认成功或盲目重发。
3. 无法证明一致状态时转入 UC-028。

## 异常流程

以下异常与 Normal/Alternative Flow 的对应步骤关联：

- E2.1 快照、步骤类型或参数无效。
- E3.1 输入、幂等状态或实时安全状态未知。
- E4.1 条件求值失败或强制步骤被配置跳过。
- E7.1 外部事件无效、重复、迟到或超时。
- E8.1 外部调用失败或结果未知。
- E9.1 输出、状态或审计写入失败。
- E11.1 流程状态与业务任务状态被错误联动。

### E2.1 快照、步骤类型或参数无效

1. 内容校验值不一致、步骤未知、目录不兼容或参数超出 Schema。
2. 系统暂停实例并告警，不动态读取最新模板替代。

### E3.1 输入、幂等状态或实时安全状态未知

1. 必要输入缺失、幂等记录不确定，或仓门、光幕、站点、身份等关键状态未知。
2. 当前步骤不得成功，系统保持安全状态并转 UC-028。

### E4.1 条件求值失败或强制步骤被配置跳过

1. 条件字段缺失、类型错误或结果不是明确布尔值，或目标步骤不可跳过。
2. 系统 fail-closed，不记为 `Skipped`，阻断流程并告警。

### E7.1 外部事件无效、重复、迟到或超时

1. 事件来源未认证、关联键不一致、内容不完整、顺序异常或已被消费。
2. 系统不推进步骤；重复/迟到事件仅记录审计。
3. 等待超时后只进入快照预置的重试、告警、等待人工或异常结束处理。

### E8.1 外部调用失败或结果未知

1. 永久错误直接进入 `Failed`；可恢复错误按 A8.1 处理。
2. 可能已产生副作用但结果未知时，系统先按幂等键和外部业务标识对账，不盲目重发。
3. 无法对账时暂停并转 UC-028。

### E9.1 输出、状态或审计写入失败

1. 输出无法验证，或步骤状态与审计不能可靠持久化。
2. 系统不得把步骤标记成功或推进下一步骤；恢复时依据一致性记录重新判定。

### E11.1 流程状态与业务任务状态被错误联动

1. 系统检测到仅因流程 `Completed`/`Failed` 等状态而直接改写业务任务状态的请求。
2. 系统拒绝该请求；业务任务只能由步骤目录中明确的业务动作及既有状态机转换。

## 备注

- 本 UC 是编排用例，不取代被调用的原子 UC；原子 UC 的业务校验、安全联锁和外部契约继续有效。
- 每次执行至少记录 `workflowInstanceId + stepInstanceId + attemptNo + idempotencyKey`。
- 流程 `WaitingExternal`、`RetryWaiting`、`Failed` 或 `Completed` 与业务任务状态是两个独立维度。
