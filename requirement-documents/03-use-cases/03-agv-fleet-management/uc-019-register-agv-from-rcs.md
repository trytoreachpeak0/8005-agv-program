# UC-019 从 RCS 接入 AGV

## 描述

AGV 运维/调度管理员从 RCS/RIOT 已存在的车辆列表中选择一台尚未接入本系统的 AGV，建立本地车辆档案并补充任务分配所需配置。本操作不在 RCS/RIOT 中创建车辆，也不直接连接 AGV。

配置过程中，管理员需独立于车型，另行为该 AGV 选择一个[[uc-038-maintain-agv-slot-model|多仓位 AGV 模型]]的已发布（`Published`）版本；系统据此自动生成该 AGV 的仓位实例记录（仓位编号、所属面、位置、规格），管理员不再手工逐个填写仓位数量/规格/载重。车型与多仓位 AGV 模型是两个独立概念，不做一一绑定或联动过滤——同一模型可安装于不同车型的 AGV 底座上通用。模型版本一旦绑定，即成为该 AGV 档案的一部分快照，具体不可变、不可更换规则见 [[br-008-agv-slot-model-versioning|BR-008]]。

新接入车辆默认处于“已禁用（Disabled）”状态；配置和现场检查完成后，由管理员通过 [[uc-013-enable-disable-agv|UC-013]] 手动启用。

## 触发条件

管理员需要将一台已在 RCS/RIOT 注册的 AGV 纳入本系统管理和任务分配。

## 前置条件

1. RCS/RIOT 接口在线，且本系统有权限查询车辆列表和基础状态。
2. 目标 AGV 已在 RCS/RIOT 中存在。
3. 管理员具有 AGV 接入权限。
4. 拟为该 AGV 选用的多仓位 AGV 模型存在至少一个 `Published` 版本（该模型与车型无强制关联，见 [[uc-038-maintain-agv-slot-model|UC-038]]、[[br-008-agv-slot-model-versioning|BR-008]]）。

## 后置条件

1. 本地新增唯一 AGV 档案，并保存 RCS/RIOT 车辆 ID 映射。
2. 保存本地名称、车型、服务区域、最低接单电量、调度权重和维护备注，以及绑定的多仓位 AGV 模型型号、版本号和内容校验值快照。
3. 系统按绑定的模型版本快照自动生成该 AGV 的仓位实例记录（仓位编号、所属面、位置、规格）；该绑定后续不可更换（见 BR-008 第 3 条）。
4. 新 AGV 状态为“已禁用”，不会参与 [[uc-023-allocate-transport-tasks-to-agv|UC-023]]。
5. 接入操作及配置内容被记录到审计日志。

## 假设

1. RCS/RIOT 是可接入车辆及其外部车辆 ID 的来源。
2. 本系统只维护本地业务档案，不负责在 RCS/RIOT 中创建、删除或修改 AGV 本体配置。
3. 由模型版本生成的仓位实例描述本系统可使用的业务仓位（编号、位置、规格），不替代 IO 点位映射配置——后者仍由 [[uc-018-io-point-mapping-verification-test|UC-018]] 针对具体仓位实例单独维护。

## 正常流程

### 19.0

1. 管理员打开“新增 AGV”界面。
2. 系统查询 RCS/RIOT 车辆列表，并标识已接入和未接入车辆。
3. 管理员选择一台未接入车辆。
4. 系统读取并展示 RCS/RIOT 车辆 ID、在线状态及可获得的基础信息。
5. 管理员填写或确认本地名称、车型、服务区域、最低接单电量、调度权重和维护备注。
6. 管理员独立选择一个多仓位 AGV 模型及其已发布（`Published`）版本（与第 5 步选择的车型无强制关联）。
   6.1 系统校验所选版本确实处于 `Published` 状态（见 Exception Flow E6.1）。
7. 系统校验车辆 ID 唯一性及必填配置完整性。
8. 管理员确认保存。
9. 系统在同一事务中创建本地 AGV 档案、绑定所选模型版本快照、按该快照生成对应仓位实例记录，将 AGV 置为“已禁用”，并记录审计日志。
10. 系统提示管理员完成检查后通过 [[uc-013-enable-disable-agv|UC-013]] 启用车辆。

## 备选流程

### A2.1 刷新 RCS/RIOT 车辆列表

1. 管理员发现目标车辆未显示，手动刷新列表。
2. 系统重新查询 RCS/RIOT；若目标车辆仍不存在，管理员联系 RCS/RIOT 管理人员先完成外部车辆注册。

## 异常流程

查询失败

1. 系统无法取得完整车辆列表。
2. 系统不允许凭空手工创建 RCS 车辆 ID，提示接口异常并记录日志。

### E6.1 所选模型版本不可用

1. 管理员按第 6 步选择某个模型版本，系统核验发现该版本当前处于 `Draft` 或 `Retired` 状态，而非 `Published`。
2. 系统拒绝保存，提示"该型号版本不可用于接入"，引导管理员改选其他 `Published` 版本，或联系型号维护人员通过 [[uc-038-maintain-agv-slot-model|UC-038]] 发布新版本。

### E7.1 车辆已接入

1. 系统发现目标 RCS/RIOT 车辆 ID 已存在于未归档或已归档的本地档案。
2. 系统拒绝重复创建，并引导管理员查看现有档案；已归档车辆的恢复方式 TBD。

### E7.2 配置不完整或不合法

1. 必填配置缺失，或车型、电量阈值、权重等值不合法，或未选择任何模型版本。
2. 系统拒绝保存并逐项提示修正。

## 备注

- 车辆 ID 是跨系统映射的唯一标识，不允许重复。
- “接入”与“启用”分开，避免配置不完整的车辆立即参与自动分配。
- 已归档车辆是否允许恢复，以及恢复后是否沿用原档案，TBD。
- 经与用户确认新增：本 UC 不再手工填写仓位数量/规格/载重，而是从 [[uc-038-maintain-agv-slot-model|UC-038]] 维护的多仓位 AGV 模型中选择一个已发布版本，由系统自动生成仓位实例；该绑定接入后不可更换，需要更换型号必须先归档、再重新接入，具体规则见 [[br-008-agv-slot-model-versioning|BR-008]]。
- 经与用户确认：车型（AGV 底座）可能发生变化，多仓位模型也可能发生变化，但两者通常是解耦的——同一个多仓位模型可以通用安装在不同车型的 AGV 底座上；因此本 UC 第 5、6 步分别独立选择车型与多仓位模型版本，不做互相过滤或一致性校验。

## 关联用例

- [[uc-038-maintain-agv-slot-model|UC-038]]：提供本 UC 可选用的已发布模型版本，本 UC 消费该版本生成仓位实例并绑定快照。
- [[uc-020-maintain-agv-dispatch-profile|UC-020]]：维护本 UC 创建的本地业务配置（车型、服务区域、电量阈值等），但不能修改本 UC 绑定的型号/版本或其生成的仓位结构。
- [[uc-013-enable-disable-agv|UC-013]]：完成检查后启用新接入车辆。
- [[uc-021-archive-agv|UC-021]]：不再使用时归档本地档案；需要更换型号时也需先归档再重新接入。
- [[uc-022-view-agv-fleet-and-availability|UC-022]]：查看接入结果及可分配状态。
- [[uc-023-allocate-transport-tasks-to-agv|UC-023]]：仅已启用且满足条件的车辆参与分配。
