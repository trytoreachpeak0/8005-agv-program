# UC-025 维护流程模板

## 描述

R-12 或 R-13 从 [[workflow-step-catalog|预置流程步骤目录]] 选择步骤，维护流程模板的匹配条件、固定顺序、条件跳过、超时和有限重试策略，并发布或停用模板版本。管理员只能配置步骤公开的受限参数，不能编写脚本、表达式、SQL，不能配置任意 API，也不能创建并行、循环、回跳或动态分支。

模板草稿、已发布版本和停用版本按 [[br-005-workflow-template-versioning|BR-005]] 管理；发布和停用必须二次认证。运行时模板匹配和实例执行分别由 [[uc-026-select-template-and-create-workflow-instance|UC-026]]、[[uc-027-execute-workflow-steps|UC-027]] 负责，本 UC 不执行具体业务步骤。

## 触发条件

出现以下任一情况：

1. 新搬运业务需要建立流程模板。
2. 现有已发布模板的匹配范围、步骤或参数需要修订。
3. 已发布模板不再允许用于新流程实例。
4. 维护人员需要查看、复制或校验历史版本。

## 前置条件

1. 操作人员使用个人账号登录，并具有流程模板查看或维护权限。
2. 系统可以读取当前有效的 [[workflow-step-catalog|预置流程步骤目录]] 及其版本。
3. 新增或修订操作基于 `Draft`；`Published`、`Retired` 内容不可原地修改。
4. 发布或停用前，模板、步骤目录、审计和二次认证服务均可用。

## 后置条件

1. 草稿保存后，匹配条件、步骤顺序、受限参数、跳过条件、超时和重试策略形成可继续校验的 `Draft`。
2. 发布成功后，系统按 BR-005 生成新的不可变 `Published` 版本；新版本只影响之后创建且尚未绑定模板的实例。
3. 停用成功后，目标版本变为 `Retired`，不再参与新匹配，但历史实例继续执行原快照。
4. 操作人、模板与版本、变更前后内容、原因、认证时间、目录版本、校验结果和执行结果被审计。

## 假设

1. 步骤实现及目录扩展由开发人员通过受控软件发布完成，不属于本 UC。
2. 一个模板是单一有向无环顺序链；条件仅决定当前步骤执行或跳过。
3. 模板维护不迁移、不改写已绑定的业务任务或流程实例快照。

## 正常流程

### 25.0

1. R-12/R-13 进入流程模板维护页面，查看 `Draft`、`Published`、`Retired` 版本及引用情况。
2. 操作人员新建草稿，或从历史版本复制生成新的 `Draft`。
3. 操作人员按 [[br-004-workflow-template-matching|BR-004]] 配置 `moveType`、`taskSource`、`materialType`、起终点站点及站点类型等匹配条件；通配项必须显式选择 `ANY`。
4. 操作人员从 [[workflow-step-catalog|预置流程步骤目录]] 选择步骤并排列为固定顺序。
5. 操作人员仅在目录允许时配置：
   5.1 使用预置字段、运算符和枚举的条件跳过。
   5.2 有限重试次数及固定或受限指数退避。
   5.3 外部事件类型、关联键、允许来源、超时和预置超时处理。
   5.4 步骤 Schema 公开的其他受限参数和配置引用。
6. 系统按 [[br-006-workflow-step-execution|BR-006]] 校验步骤类型、参数、单顺序链、强制安全步骤、可跳过性、可重试性、等待事件和幂等要求。
7. 系统按 BR-004 检查匹配条件完整性及与当前已发布模板的潜在冲突。
8. 操作人员填写发布原因，系统展示版本差异、匹配范围、步骤、安全约束及潜在影响。
9. 操作人员再次刷卡或认证。
10. 系统按 [[br-005-workflow-template-versioning|BR-005]] 原子生成新的不可变 `Published` 版本、内容校验值和审计记录。

## 备选流程

### A2.1 保存草稿但暂不发布

1. 操作人员完成部分配置并选择保存。
2. 系统校验字段格式后保存为 `Draft`，同时展示尚未满足的发布条件。
3. 草稿不参与 UC-026 的运行时匹配。

### A1.1 停用已发布版本

1. 操作人员选择一个 `Published` 版本并填写非空停用原因。
2. 系统展示仍引用该版本的任务和流程实例数量，明确历史引用不会被修改或终止。
3. 操作人员再次刷卡或认证。
4. 系统原子地将该版本置为 `Retired` 并写入审计；该版本不再参与新实例匹配。

### A2.2 从历史版本复制修订

1. 操作人员选择 `Published` 或 `Retired` 历史版本。
2. 系统复制内容生成新的 `Draft`，保留来源版本关联。
3. 操作人员按 Normal Flow 修改、校验并发布；原历史版本保持不变。

## 异常流程

以下异常与 Normal/Alternative Flow 中的对应步骤关联：

- E3.1 匹配条件无效或冲突。
- E4.1 步骤类型未知或目录版本不兼容。
- E5.1 配置包含禁止能力或越权参数。
- E6.1 模板结构或安全校验失败。
- E9.1 二次认证失败。
- E10.1 发布、停用或审计事务失败。

### E3.1 匹配条件无效或冲突

1. 关键匹配维度为空、未知值被当作 `ANY`，或配置可能产生无法唯一消除的并列候选。
2. 系统拒绝发布，指出冲突条件和候选版本；草稿可保留供修正。

### E4.1 步骤类型未知或目录版本不兼容

1. 草稿引用不存在、已禁止或与当前目录不兼容的步骤类型。
2. 系统拒绝发布，不允许用通用步骤、脚本或任意接口替代。

### E5.1 配置包含禁止能力或越权参数

1. 系统发现脚本、表达式代码、SQL、任意 URL/API、并行、循环、回跳、无限重试或超出 Schema 的参数。
2. 系统拒绝保存或发布，记录违规字段和操作人。

### E6.1 模板结构或安全校验失败

1. 步骤链不是固定顺序，强制安全步骤缺失/被配置跳过，或重试、等待、幂等约束不成立。
2. 系统 fail-closed，拒绝发布且不产生部分可用版本。

### E9.1 二次认证失败

1. 再次认证失败、超时、身份与当前操作人不一致或权限不足。
2. 系统不发布、不停用，保留原状态并记录失败审计。

### E10.1 发布、停用或审计事务失败

1. 版本持久化、状态转换、内容校验值或审计任一写入失败。
2. 系统回滚整个操作，不产生新版本或部分状态变更，并提示稍后重试。

## 备注

- 模板页面不提供“通用 API 调用”“执行代码”“任意数据库操作”等步骤。
- 和 `Retired` 不可物理删除或退回 `Draft`；版本号不得重用。
- 条件跳过不是任意分支，有限重试不是循环；模板任何配置都不能绕过步骤目录的安全边界。
