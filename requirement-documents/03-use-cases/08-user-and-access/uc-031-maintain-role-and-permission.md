# UC-031 维护角色与权限

## 描述

具有角色权限管理权限的 R-12 创建、修改、复制、启用或停用自定义角色，并从系统预置权限目录中为角色配置权限。权限目录中的权限项由系统功能定义，管理员可以组合权限形成角色，但不能创建系统无法识别的权限代码或修改权限的运行语义。

R-01～R-15 是业务参与者清单，可作为角色设计依据，但不限制系统只能存在这些角色。系统通过受保护权限和职责分离校验等规则，避免角色变更导致越权。

## 触发条件

1. 新职责需要创建角色及其权限组合。
2. 业务或维护职责变化，需要调整已有角色权限。
3. 角色不再允许分配给新用户，需要停用。
4. R-12 需要查询角色、权限及用户引用关系。

## 前置条件

1. R-12 已通过 [[uc-033-login-and-session-management|UC-033]] 登录，并具有角色与权限维护权限。
2. 系统预置权限目录可读取，权限项具有唯一代码、名称、功能域、风险级别和状态。
3. 用户、角色、授权和审计服务可用。
4. 系统能够识别受保护权限及不允许组合的职责冲突。

## 后置条件

1. 新角色具有唯一标识、唯一名称、明确状态和有效权限集合。
2. 角色修改成功后，其生效权限按原子变更结果更新；历史审计保留变更前后集合。
3. 停用角色不再允许新分配；对现有用户的影响按确认结果一致处理。
4. 角色、权限集合、影响用户、原因、操作人、时间和执行结果被完整审计。

## 假设

1. 权限项随系统功能通过受控软件发布新增、修改语义或退役，不由页面任意创建。
2. 权限采用允许式授权；未授予即无权，不支持通过隐藏菜单替代服务端鉴权。
3. 现场操作员工牌的岗位权限由 MES 返回，不在本 UC 的本地角色中维护。
4. 系统内置一个不可编辑、不可停用的"超级管理员"角色（见 [[br-010-default-administrator-account|BR-010]]），始终拥有系统全部权限；本 UC 停用自定义角色时不需要核验是否会导致系统失去权限管理员，具体见 备注。

## 正常流程

### 31.0

1. R-12 进入角色与权限管理页面。
2. 系统展示角色列表、状态、权限摘要、引用用户数及权限目录。
3. R-12 新建角色，填写唯一名称、说明和适用职责。
4. R-12 从预置权限目录选择查看、操作、维护、授权、导出等权限项。
5. 系统按功能依赖、风险级别、受保护权限和职责分离规则校验权限组合。
6. 系统展示角色权限清单、高风险权限和潜在影响。
7. R-12 填写创建原因并确认。
8. 系统原子地保存角色与权限关系，并记录操作人、原因、权限集合和校验结果。

## 备选流程

### A3.1 修改已有角色

1. R-12 选择启用中的角色并编辑名称、说明或权限集合。
2. 系统展示权限增减差异、引用用户及变更后的生效权限影响。
3. 对高风险权限增加或移除，系统要求 R-12 再次确认变更范围和原因。
4. 系统重新校验后原子保存；受影响用户在后续请求中使用新权限，现有敏感操作须重新鉴权。

### A3.2 复制角色

1. R-12 选择一个角色作为来源。
2. 系统复制其说明和当前有效权限集合，生成未保存的新角色草稿。
3. R-12 设置新的唯一名称并按 Normal Flow 校验、确认和保存；来源角色不变。

### A3.3 停用角色

1. R-12 选择角色并填写非空停用原因。
2. 系统展示引用该角色的用户及其停用后剩余权限。
3. R-12 选择先完成用户授权调整，或确认同时撤销该角色对现有用户的生效授权。
4. 系统原子停用角色并记录影响范围。

## 异常流程

以下异常与 Normal/Alternative Flow 中的对应步骤关联：

- E3.1 角色名称重复或字段无效。
- E4.1 权限项未知、已退役或不可分配。
- E5.1 权限依赖或职责分离校验失败。
- EA3.1.1 并发修改导致角色版本冲突。
- E8.1 角色、授权影响或审计事务失败。

### E3.1 角色名称重复或字段无效

1. 角色名称已被使用、格式无效或与系统保留名称冲突。
2. 系统拒绝保存并提示修正，不创建部分角色记录。

### E4.1 权限项未知、已退役或不可分配

1. 所选权限不存在、已停止用于新配置，或仅供系统内部使用。
2. 系统拒绝加入角色，并显示允许选择的权限范围。

### E5.1 权限依赖或职责分离校验失败

1. 权限缺少必要依赖，或组合违反预置职责分离规则。
2. 系统拒绝保存并列出冲突；不得通过客户端参数或直接请求绕过。

### EA3.1.1 并发修改导致角色版本冲突

1. 编辑期间角色已被其他管理员修改。
2. 系统拒绝覆盖，展示最新版本并要求重新比较后提交。

### E8.1 角色、授权影响或审计事务失败

1. 角色、角色权限、受影响授权或审计任一写入失败。
2. 系统回滚整个操作，保持原角色及用户权限不变。

## 备注

- 自定义的是“角色及其权限组合”，不是权限代码和鉴权逻辑；后者由系统功能受控提供。
- 角色不物理删除，避免历史审计无法解释当时授权来源。
- 菜单可见性仅用于界面呈现，所有受保护操作仍须由服务端按当前生效权限校验。
- 经确认：本 UC 停用角色时不再核验"是否会导致系统失去权限管理员"（原 EA3.3.1 已删除），因为 [[br-010-default-administrator-account|BR-010]] 定义的内置"超级管理员"角色始终存在、不可被停用或从其账号撤销，系统天然不会因停用任何自定义角色而失去权限管理能力。
