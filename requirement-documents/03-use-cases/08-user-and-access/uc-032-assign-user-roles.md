# UC-032 为用户分配角色

## 描述

具有用户授权管理权限的 R-12 为 AGV 管理配置端本地账号授予或撤销一个或多个启用角色。系统根据全部角色的权限并集计算用户生效权限，同时执行授权范围、职责分离、目标账号状态和最后管理员保护校验。

本 UC 仅处理本地管理账号授权。现场操作员在放料、收料、取消订单等场景刷工牌后，由 MES 返回人员身份和岗位权限，不要求也不允许先在本 UC 中绑定本地账号或角色。

## 触发条件

1. 新建本地账号需要获得工作所需角色。
2. 人员调岗或兼任，需要增加或移除角色。
3. 人员离岗或临时取消职责，需要撤销授权。
4. 角色权限发生变化，需要查看用户最终生效权限及来源。

## 前置条件

1. R-12 已通过 [[uc-033-login-to-management-console|UC-033]] 登录，并具有用户授权管理权限。
2. 目标用户由 [[uc-030-maintain-user-account|UC-030]] 创建且存在。
3. 待授予角色由 [[uc-031-maintain-role-and-permission|UC-031]] 创建并处于启用状态。
4. 系统可读取操作者可授予范围、职责分离规则和审计服务状态。

## 后置条件

1. 授权成功后，目标用户的角色集合和各项生效权限来源可查询。
2. 撤销成功后，相关权限在后续请求中失效；活动敏感操作必须重新鉴权。
3. 系统始终保留至少一个启用且可登录的用户与权限管理员账号。
4. 操作人、目标用户、角色增减、权限差异、原因、时间和结果被审计。

## 假设

1. 用户可以兼任多个角色，生效权限为所有启用角色中允许权限的并集。
2. 本系统不提供用户级隐式权限；每项本地权限均可追溯到具体角色。
3. 角色变更不改写历史审计中当时的用户、角色和权限快照。

## 正常流程

### 32.0

1. R-12 进入用户授权页面并选择目标本地账号。
2. 系统展示目标账号状态、当前角色、生效权限及每项权限来源。
3. R-12 选择一个或多个启用角色准备授予。
4. 系统验证操作者具有用户授权管理权限，且不得授予超出其可管理范围的受保护角色或权限。
5. 系统计算授权后的角色集合、权限并集和职责冲突。
6. 系统展示新增角色、新增权限、高风险权限及影响摘要。
7. R-12 填写非空授权原因并确认。
8. 系统原子保存用户角色关系，刷新目标用户的生效权限并写入审计。

## 备选流程

### A3.1 撤销一个或多个角色

1. R-12 选择目标用户当前拥有的一个或多个角色。
2. 系统计算撤销后的剩余角色、失效权限和仍由其他角色保留的权限。
3. 系统检查目标用户是否为最后一个可用权限管理员，并展示活动会话影响。
4. R-12 填写撤销原因并确认。
5. 系统原子撤销角色；后续请求按新权限校验，高风险页面和操作令牌立即失效。

### A3.2 查看权限来源但不修改

1. R-12 查看目标用户的角色和生效权限。
2. 系统对每项权限标明来源角色、角色状态和风险级别。
3. 用户未提交角色增减，系统不修改授权；查看行为按安全策略记录。

### A3.3 为停用账号预配置角色

1. R-12 选择已停用但计划恢复的本地账号。
2. 系统允许配置角色，但明确标记“账号停用，权限当前不生效”。
3. 账号只有按 UC-030 重新启用并通过 UC-033 登录后，角色权限才可用于请求鉴权。

## 异常流程

以下异常与 Normal/Alternative Flow 中的对应步骤关联：

- E1.1 目标用户不存在或不可管理。
- E3.1 角色不存在、已停用或不可授予。
- E4.1 操作者尝试越权授权。
- E5.1 授权后产生职责冲突。
- EA3.1.1 撤销将移除最后一个权限管理员。
- E8.1 授权或审计事务失败。

### E1.1 目标用户不存在或不可管理

1. 目标用户已不存在、状态已变化，或超出操作者管理范围。
2. 系统拒绝操作，不泄露无权查看的账号资料。

### E3.1 角色不存在、已停用或不可授予

1. 待授予角色在提交时已停用、被替换或标记为不可分配。
2. 系统拒绝本次授权并要求刷新角色列表。

### E4.1 操作者尝试越权授权

1. R-12 不具备授权管理权限，或尝试授予其无权管理的受保护角色/权限。
2. 系统拒绝整个请求并记录安全审计，不允许拆分后部分成功。

### E5.1 授权后产生职责冲突

1. 新角色与目标用户已有角色违反预置职责分离规则。
2. 系统拒绝授权并列出冲突角色和权限；本 UC 不提供绕过入口。

### EA3.1.1 撤销将移除最后一个权限管理员

1. 撤销后系统将不存在启用、可登录且具备用户与权限管理能力的账号。
2. 系统拒绝撤销，要求先为另一可用账号建立替代授权。

### E8.1 授权或审计事务失败

1. 用户角色关系、生效权限刷新或审计任一处理失败。
2. 系统回滚整个授权变更，继续使用提交前的完整权限集合。

## 备注

- 多角色兼任不要求用户切换角色；每次请求按该用户当前全部启用角色计算权限。
- 同一权限由多个角色提供时，撤销其中一个角色不会移除仍由其他角色提供的权限。
- 高风险业务操作仍须遵守其原用例中的二次认证和安全前提，拥有角色不能绕过这些要求。
