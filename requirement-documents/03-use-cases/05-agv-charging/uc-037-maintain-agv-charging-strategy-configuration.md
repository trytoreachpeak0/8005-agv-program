# UC-037 维护 AGV 充电策略配置

## 描述

AGV 运维/调度管理员为每台多仓位 AGV（或按车型/分组）维护充电策略配置，包括：该车可使用的充电桩候选集合、触发自动充电的电量阈值（低电量阈值）、以及充电完成/可离开的电量阈值（充满阈值）。

本 UC 只负责"配置"本身：候选充电桩的选择范围、阈值数值的录入与校验、保存与审计。具体"系统何时检测到某车电量到达触发阈值、如何从候选集合中选出一个空闲充电桩、多车竞争同一批充电桩时如何排队"等运行时行为，由 [[br-007-charging-pile-allocation-and-queueing|BR-007]] 统一定义规则，供本 UC 之外的执行流程（如 [[uc-012-manually-dispatch-agv-to-charge|UC-012]] 及未来的自动低电量回充执行 UC，见 Notes）遵守；本 UC 不重复定义该算法本身。

## 触发条件

管理员需要新增、修改某台 AGV（或某个车型/分组）的充电策略配置，或在充电桩布局调整、新车接入后需要补充配置。

## 前置条件

**系统与接口**

1. RIOT 接口在线可用，且本系统已能取得 RIOT 当前地图站点列表（含站点类型标记，用于识别哪些站点是"充电桩"）。

**任务与数据**

2. 目标 AGV 已通过 [[uc-019-register-agv-from-rcs|UC-019]] 接入且未归档。
3. 候选充电桩必须来自 RIOT 当前同步的地图站点列表中类型为"充电桩"的站点，不允许管理员手工录入任意站点编号（做法与 [[uc-024-maintain-area-station-mapping|UC-024]] 对站点来源的约束一致）。

**人员与权限**

4. 管理员具备充电策略维护权限。

> 与 [[uc-020-maintain-agv-dispatch-profile|UC-020]] 不同，本 UC 修改的是"该车什么时候该去充电、去哪些充电桩"，不直接影响任务分配所需的仓门/安全状态，因此不强制要求目标车辆处于"已禁用"状态才能保存；是否需要该前提，TBD 待与用户确认（见 Notes）。

## 后置条件

**任务与数据**

1. 该 AGV（或分组）的候选充电桩集合、触发充电阈值、充电完成阈值被保存，供 [[br-007-charging-pile-allocation-and-queueing|BR-007]] 后续选桩/排队决策及 [[uc-012-manually-dispatch-agv-to-charge|UC-012]] 引用。
2. 修改只影响保存后新发生的充电请求/排队决策，不影响已经在物理充电中的车辆。
3. 操作人、目标 AGV/分组、修改前后值及时间戳被记录到审计日志。

## 假设

1. 充电桩本身是 RIOT 地图站点的一种特殊类型，其列表、有效性及当前占用/空闲状态均由 RIOT 同步提供；本 UC 不维护充电桩本身的主数据（如坐标、供电参数），只从已同步的"充电桩"类型站点中选择候选集合。
2. 一台 AGV 可以配置多个候选充电桩（服务范围内可能不止一个），实际每次充电具体分到哪一个，由 [[br-007-charging-pile-allocation-and-queueing|BR-007]] 在运行时决定，不在本 UC 中固定为唯一绑定。
3. "触发充电阈值"与 [[uc-020-maintain-agv-dispatch-profile|UC-020]] 已有的"最低接单电量阈值"是两个独立的配置项，语义不同：前者回答"这台车该不该去充电"，后者回答"这台车该不该继续接新的搬运任务"；两者数值可以相同，也可以不同，具体数值关系 TBD。

## 正常流程

### 37.0

1. 管理员进入充电策略配置页面，选择目标 AGV（或车型/分组）
2. 系统展示当前配置（候选充电桩、触发阈值、完成阈值）及最近修改记录
   2.1 系统同步 RIOT 当前地图站点列表，标记其中类型为"充电桩"的站点及其有效状态（见 Exception Flow E2.1）
3. 管理员从已同步且有效的"充电桩"类型站点中勾选候选充电桩集合
4. 管理员录入触发充电阈值（低电量）与充电完成阈值（充满）
   4.1 系统校验触发阈值必须小于完成阈值（见 Exception Flow E4.1）
   4.2 系统校验候选充电桩集合不能为空（见 Exception Flow E4.2）
   4.3 系统校验阈值数值在合法范围内（见 Exception Flow E4.3）
5. 系统展示修改前后差异，管理员确认保存
6. 系统保存新配置，记录审计日志

## 备选流程

不存在需要区分的备选流程：无论按单台 AGV 还是按车型/分组维护，均按 Normal Flow 相同的选桩范围、阈值录入、校验和保存步骤处理。

## 异常流程

以下每条异常均以 `E<步骤号>` 编号，与 Normal Flow 中触发该异常的具体步骤（或子步骤）一一对应：

* E2.1 RIOT 站点同步失败，无法确认充电桩列表
* E4.1 触发阈值不小于完成阈值
* E4.2 候选充电桩集合为空
* E4.3 阈值数值超出合法范围

### E2.1 RIOT 站点同步失败

1. 系统按第 2.1 步同步 RIOT 地图站点列表，发现通信异常、超时或结果不完整
2. 系统采用 fail-closed：允许只读查看已有配置，禁止新增、修改候选充电桩集合
3. 系统显示最后一次成功同步时间，并记录接口异常
4. IT/软件维护人员（R-12）或管理员排查并修复 RIOT 接口/网络异常后，管理员重新进入本 UC 进行配置

### E4.1 触发阈值不小于完成阈值

1. 管理员按第 4 步录入触发充电阈值和完成阈值，触发阈值大于或等于完成阈值
2. 系统提示"触发充电阈值必须小于完成阈值"，拒绝保存
3. 管理员修正数值后重新提交

### E4.2 候选充电桩集合为空

1. 管理员未勾选任何候选充电桩即尝试保存
2. 系统提示"候选充电桩集合不能为空"，拒绝保存
3. 管理员至少选择一个候选充电桩后重新提交

### E4.3 阈值数值超出合法范围

1. 管理员录入的阈值数值超出系统允许的合法范围（如负数、超过满电量）
2. 系统提示具体的合法范围要求，拒绝保存
3. 管理员修正数值后重新提交

## 备注

* 本 UC 是用户提出的新场景："配置充电策略——每个车去哪个充电桩充电、到多少电就充电、充到多少就离开、以及 m 台车共享 n 个充电桩（m>n）时如何处理"，经与用户确认后拆分为：本 UC（配置本身）与 [[br-007-charging-pile-allocation-and-queueing|BR-007]]（选桩算法与 m>n 排队/抢占规则），拆分方式与 [[uc-023-allocate-transport-tasks-to-agv|UC-023]] / [[br-002-agv-allocation-eligibility|BR-002]] 的分工一致。
* 经与用户确认：充电桩的具体选择责任在本系统，不是 RIOT 自主决定（RIOT 只负责移动执行）；这一澄清也同步修正了 [[uc-012-manually-dispatch-agv-to-charge|UC-012]] 中原先"由 RIOT 自主规划选桩"的假设。
* 经与用户确认：m 台车竞争 n 个充电桩时采用"电量优先"策略——电量更低的车辆优先获得空闲充电桩，可以打断排队顺序，但不能打断正在物理充电中的车辆；具体算法细节见 [[br-007-charging-pile-allocation-and-queueing|BR-007]]。
* 本 UC 只覆盖"配置"，不覆盖"系统检测到 AGV 电量到达触发阈值后自动创建充电任务、监控直至完成阈值、释放充电桩"的执行流程：该执行流程与 vision-and-scope.md 主要特性清单中提到的"低电量自动回充"、以及 [[uc-012-manually-dispatch-agv-to-charge|UC-012]] Assumption 第 3 条中提到但尚未建 UC 覆盖的场景是同一件事，留待后续单独建执行类 UC 覆盖，本 UC 先把它依赖的阈值与候选充电桩配置落地。
* 待补充（TBD）事项：
  1. 保存配置前是否要求目标车辆已禁用（类比 [[uc-020-maintain-agv-dispatch-profile|UC-020]]），待与用户确认。
  2. "触发充电阈值"与 UC-020"最低接单电量阈值"之间是否存在数值约束关系（如触发充电阈值应低于最低接单电量阈值），待与用户确认。
  3. 候选充电桩集合是按单台 AGV 维护，还是也支持按车型/分组批量维护，界面细节待补充。
