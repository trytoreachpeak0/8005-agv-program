# UC-045 从 RIOT 同步地图路网

## 描述

本地服务器从 RCS/RIOT 只读同步当前地图的**站点（节点）**与**可通行路径（边/路段）**，在本地形成带版本与同步时间戳的路网快照，供 [[br-015-path-cost-and-dispatch-ranking|BR-015]] 计算最短路径成本，并被 [[uc-023-allocate-transport-tasks-to-agv|UC-023]] 在派车排序时消费。

本 UC 只负责路网数据的获取、校验、落库与过期标记，不负责 AREA 映射维护（见 [[uc-024-maintain-area-station-mapping|UC-024]]），不负责向 RIOT 下发移动任务或改写 RIOT 地图。站点列表（表 A）可与 UC-024 共用同一同步源；本 UC 额外要求同步站点之间的可通行连接关系。

## 触发条件

满足以下任一条件：

1. 到达配置的定时同步周期。
2. 系统检测到 RIOT 侧地图版本/变更信号（具体检测方式 TBD）。
3. [[uc-023-allocate-transport-tasks-to-agv|UC-023]] 本轮需要启用路径成本因子，但本地路网缺失或已超过允许过期阈值。
4. AGV 运维/调度管理员（R-13）在管理配置端手动触发「刷新地图路网」。

## 前置条件

1. RCS/RIOT 接口在线，且本系统有权限查询地图站点及路径/拓扑数据（接口形态与字段 TBD，须在对接时确认）。
2. 手动触发时，操作人员具有地图/调度相关配置或运维权限。

## 后置条件

1. 同步成功后，本地存在一份有效的路网快照：至少包含站点节点集合、可通行边集合、同步时间戳，以及可用于追溯的地图/快照版本标识（版本字段来源 TBD）。
2. 快照中的站点须能与 RIOT 当前地图站点标识对齐；无法对齐的节点/边不得进入「有效可计算」集合，并记录原因。
3. 同步失败时：保留上一份有效快照（若有），将当前同步标记为失败并记录错误；不删除历史可用快照，除非另有清理策略（TBD）。
4. 每次同步尝试（成功/失败）、耗时、节点/边数量、操作人（若手动）被记录。

## 假设

1. RIOT 提供可读的地图站点与路径/拓扑数据；本系统不在 RIOT 中创建、修改或删除地图元素。
2. RIOT 在仅指定目的地时通常按最短（或等价最优）路径行驶，因此本地基于该路网计算的最短路径成本可作为派车权衡估计；真实导航仍由 RIOT 执行（见 [[br-015-path-cost-and-dispatch-ranking|BR-015]]、[[uc-008-dispatch-move-order-to-riot|UC-008]]）。
3. 本 UC 不同步交通管制实时占用、临时封路等动态交管状态；若后续需要把动态拥堵纳入成本，须另立规则，不在本 UC 范围。
4. 管理员不能手工录入任意边或伪造路网；只能触发从 RIOT 重新同步。

## 正常流程

### 45.0

1. 系统因定时、变更检测、分配前过期检查或管理员手动刷新进入本 UC。
2. 系统向 RCS/RIOT 查询当前地图站点列表与可通行路径/拓扑数据。
3. 系统校验返回数据完整性（节点、边端点存在性、自环/重复边处理策略 TBD）：
   3.1 核验关键字段齐全且边的两端均能映射到本次返回的站点集合（见 Exception Flow E3.1）。
4. 系统在同一事务中写入或替换本地路网快照，更新同步时间戳与版本标识，标记为「有效」。
5. 系统记录同步成功审计（节点数、边数、版本、时间戳、触发来源）。
6. 若本轮由 UC-023 触发，将「路网已刷新」结果返回给分配流程，供 BR-015 计算路径成本。

## 备选流程

### A1.1 管理员手动刷新

1. R-13 在管理配置端选择「刷新地图路网」并确认。
2. 系统按 Normal Flow 第 2～5 步执行同步。
3. 界面展示同步结果（成功则显示版本/时间戳/规模；失败则显示原因且不覆盖上一份有效快照的「有效」标记，除非整库无任何有效快照）。

### A4.1 与表 A 站点同步合并执行

1. 若实现上与 [[uc-024-maintain-area-station-mapping|UC-024]] 的表 A 同步共用同一次 RIOT 拉取，系统可在一次调用中同时更新站点主数据与路网边数据。
2. AREA 解析、显式覆盖仍只由 UC-024 / [[br-003-area-station-mapping|BR-003]] 处理；本备选不改变该分工。

## 异常流程

### E2.1 RIOT 通信失败或超时

1. 系统按第 2 步请求路网数据时通信异常、超时或鉴权失败。
2. 系统不写入残缺快照，保留上一份有效快照（若有），记录失败原因。
3. 按 [[br-015-path-cost-and-dispatch-ranking|BR-015]] 第 4 节：后续分配可继续但不得把本轮失败伪装成「已按最新 RIOT 路网计算」；达到告警条件时通知 R-12/R-13。

### E3.1 返回数据不完整或不可用

1. 系统按第 3.1 步核验，发现节点/边缺失、端点无法对齐、或关键字段为空。
2. 系统拒绝将本轮结果标为「有效可计算」快照，记录具体校验失败项。
3. 保留上一份有效快照；若无任何有效快照，标记路网不可用，供 BR-015 降级策略使用。

## 备注

- 本 UC 填补「派车要用最短路径成本、但此前只有站点列表同步、没有路径/拓扑同步」的缺口。
- RIOT 地图/路径接口的具体 API、字段名、是否含单向边/限速/边权，对接前均为 TBD；确认前实现不得假设不存在的字段。
- 路网快照的允许过期阈值、定时周期，TBD（可配置）。
