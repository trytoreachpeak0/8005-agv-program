# UC-036 查询与实时查看系统技术日志

## 描述

具有系统技术日志查看权限的 R-11、R-12、R-13 或 R-15，按组件、严重级别、时间范围或关键字查询历史技术日志，或订阅实时日志流持续监看系统运行状况，用于设备通信、应用服务、接口调用和网络连通性问题的排查。日志覆盖 IO 模块通信、仓门/光幕信号、AGV/RCS/RIOT 交互、应用服务异常、数据库及 MES/RIOT 接口调用等技术细节，字段颗粒度精确到毫秒，包含错误码、请求/响应摘要、重试次数和诊断上下文。

本 UC 与 [[uc-034-query-and-export-audit-logs|UC-034]] 的区别：UC-034 面向安全/合规审计，严格脱敏并限制敏感报文；本 UC 面向技术排障，按角色对应的组件范围展示更完整的原始诊断信息（如接口报文摘要、错误堆栈概要），但仍须遵守权限范围与脱敏规则，不展示凭据类明文。本 UC 与 UC-034、[[uc-035-query-material-handling-history|UC-035]] 共享同一日志查询入口的不同视图。

## 触发条件

1. 设备、应用服务或接口出现异常，需要排查根因。
2. 运维人员需要持续监看某组件的实时运行状态。
3. 用户从告警、流程实例（[[uc-029-view-workflow-instance-progress|UC-029]]）、异常处置（[[uc-028-handle-workflow-step-exception|UC-028]]）或物料存取事件（UC-035）跳转到关联技术日志。
4. 定期巡检或联调期间查看接口调用与网络连通性记录。

## 前置条件

1. 用户已登录，并具有对应技术日志组件范围的查看权限；权限范围由 [[uc-031-maintain-role-and-permission|UC-031]]/[[uc-032-assign-user-roles|UC-032]] 配置，可覆盖设备层、应用层、接口层或全部。
2. 目标组件的历史日志或实时日志流服务可用。
3. 查询条件或订阅范围（组件、严重级别、时间范围、关键字、追踪标识）格式有效。
4. 建立实时流订阅时，系统与前端之间的推送通道可用。

## 后置条件

1. 历史查询返回按条件筛选、按时间排序的日志条目，包含时间戳、组件、级别、事件、错误码和诊断上下文。
2. 实时订阅建立后，新产生的匹配日志条目持续推送到用户界面，直到用户取消订阅或会话结束。
3. 查询、订阅和取消订阅行为被记录；日志本身不可通过本 UC 修改或删除。
4. 敏感凭据、密钥等即使在技术日志中仍被脱敏或隐藏，不展示明文。

## 假设

1. 各组件（IO 模块、应用服务、接口适配层等）已按其运行规范产生结构化日志并写入统一日志存储/流。
2. 实时流的推送延迟、缓冲及断线重连策略由部署侧技术方案确定，本 UC 只描述用户可见的订阅行为。
3. 日志保留期限、归档和存储容量策略与 UC-034/UC-035 共享同一整体日志治理策略。

## 正常流程

### 36.0

1. 用户进入系统技术日志页面（日志查询入口下的"系统日志"视图）。
2. 系统按用户权限展示可查询的组件范围（设备/应用/接口/网络等）。
3. 用户设置查询条件：组件、严重级别、时间范围、关键字或追踪标识（如幂等键、请求 ID、AGV/仓位/任务编号）。
4. 系统校验条件格式与用户组件权限范围。
5. 系统返回匹配的日志条目列表，按时间排序，显示时间戳、组件、级别、事件摘要。
6. 用户打开一条日志详情。
7. 系统展示该条目的完整诊断信息：错误码、请求/响应摘要、重试次数、关联追踪标识，并对凭据等敏感字段脱敏。
8. 系统记录本次查询与查看行为。

## 备选流程

### A1.1 订阅实时日志流

1. 用户在日志页面选择"实时查看"，设置组件、级别或关键字过滤条件。
2. 系统校验用户权限范围后建立推送订阅。
3. 系统持续将匹配的新日志条目推送到用户界面，用户可暂停/继续或调整过滤条件。
4. 用户取消订阅或离开页面时，系统释放推送通道并记录订阅起止时间。

### A3.1 从关联对象反查

1. 用户从告警、流程实例、异常处置或物料存取事件详情进入"查看技术日志"入口。
2. 系统预填组件范围及关联追踪标识，进入历史查询或实时订阅。
3. 用户按需补充条件后继续 Normal Flow 第 4～8 步或 Alternative Flow A1.1。

## 异常流程

以下异常与 Normal/Alternative Flow 中的对应步骤关联：

- E2.1 用户无权访问目标组件日志。
- E4.1 查询条件无效或范围过大。
- E5.1 日志数据不完整或存储暂不可达。
- E7.1 敏感字段无法可靠脱敏。
- EA1.1.1 订阅权限不足或推送通道建立失败。
- EA1.1.2 实时推送中断。

### E2.1 用户无权访问目标组件日志

1. 用户缺少目标组件的查看权限，或请求超出其组件范围。
2. 系统拒绝请求，不泄露该组件日志是否存在，并记录安全审计。

### E4.1 查询条件无效或范围过大

1. 时间范围超过预置上限、条件格式错误，或组合造成不可接受的资源消耗。
2. 系统拒绝查询并提示缩小范围或修正字段，不返回不受控全量数据。

### E5.1 日志数据不完整或存储暂不可达

1. 部分日志源、索引或存储无法读取。
2. 系统明确标记"数据不完整/暂不可用"及受影响范围和最后可用时间，不把无返回解释为未发生操作。

### E7.1 敏感字段无法可靠脱敏

1. 某类日志无法确认敏感字段边界或脱敏处理失败。
2. 系统隐藏该字段或拒绝展示详情，记录处理失败；不得回退为原文展示。

### EA1.1.1 订阅权限不足或推送通道建立失败

1. 用户无实时查看权限，或推送通道初始化失败。
2. 系统拒绝建立订阅并提示原因，不返回部分订阅状态。

### EA1.1.2 实时推送中断

1. 网络中断、服务重启或推送通道异常导致流中断。
2. 系统提示"实时连接已中断"，标注最后收到日志的时间，并按预置策略尝试自动重连；重连前不得静默丢弃期间日志而不提示用户。

## 备注

- 本 UC 覆盖设备通信、应用服务、接口调用及网络连通性等技术组件产生的日志；具体组件清单和权限粒度由部署侧结合 UC-031/UC-032 持续调整，本 UC 不固定枚举。
- 实时订阅是历史查询的补充能力，两者共享同一权限模型和脱敏规则，不因"实时"降低数据保护要求。
- 本 UC 与 UC-034、UC-035 共享统一日志查询入口的不同视图，底层各自维护对应的日志/事件存储，不强制合并为单一数据模型。

## 关联用例

异常处置的重试、告警和人工决定可关联本 UC 的技术日志做进一步根因诊断。
流程实例执行产生的外部调用和步骤日志，可跳转本 UC 查看更完整的技术细节。
定义并授予本 UC 按组件范围划分的查看/订阅权限。
共享同一日志查询入口，服务不同用户群体和用途（安全审计 vs 技术排障）。
物料存取历史查询发现的异常，可跳转本 UC 排查设备/系统层根因。
