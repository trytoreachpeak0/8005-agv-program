# UC-010 终点站取出产品存料

## 描述

多仓位 AGV 到达终点站后，系统自动找出 AGV 上所有“已占用”且其关联任务目标（交货）站点与当前站点一致的仓位，直接批量打开这些仓门。卸货不输入 Sublot，因为标有 Sublot 的单据也随货放在仓位内；8005 项目也不要求输入工号。目标集合可以跨多个 Sublot，操作员按任意顺序取走产品并关闭仓门。

> 本 UC 与 [[uc-001-load-completed-lot-into-slot|UC-001]] 是方向相反的一对：UC-001 是起点站"扫码装入仓位"，本 UC 是终点站"系统自动开仓、取出存料"，两者共享同一批次产品、同一次 AGV 行程，但触发站点、Actor、系统核验方式均不同（详见 Related Use Cases）。

## 触发条件

多仓位AGV到达某站点（见 [[uc-003-agv-arrives-at-designated-station|UC-003]]），且该AGV上存在至少一个"已占用"仓位，其关联任务的目标（交货）站点与当前站点一致

## 前置条件

**系统与接口**

1. IO 模块通信正常，可正常对目标仓位执行开锁及门状态/光幕读取操作

**设备与硬件**

2. 目标仓位仓门在本 UC 开始前均处于关闭状态

**任务与数据**

3. 当前停靠作业清单中至少存在一个待卸项目：AGV 上对应仓位为“已占用”，其关联任务目标站点与当前站点一致，且任务状态为“进行中（Executing）”

**人员与权限**

4. 服务端与车载端对项目级卸货策略版本认知一致；8005 项目的卸货操作员核验和卸货 Sublot 完整性均为关闭。

> 与 [[uc-001-load-completed-lot-into-slot|UC-001]] 不同，本 UC 不需要核验"该任务是否属于本次派车范围"（对应 [[br-001-dispatch-task-range|BR-001]]）：任务此时已经装载在AGV上、正跟车运行，其目标站点在装载时已经确定，不存在"扫错、扫到不属于本次派车范围的子批号"的问题，因此本 UC 的仓位识别可以完全由系统自动完成，不需要操作员扫码核验。

## 后置条件

**设备与硬件**

1. 目标仓位电子锁在仓门关闭后恢复锁闭状态
2. 光幕检测确认仓门已关闭且仓位内确实已清空，与系统记录一致

**任务与数据**

3. 目标仓位状态由"已占用"变为"空闲"，仓位-子批号映射关系被清除
4. 本次取出操作（项目策略、子批次、仓位号、站点、时间戳，以及策略开启时的操作员）被记录到服务端，用于后续追溯
5. 每个仓位达到 `EMPTY + 锁闭 + 开锁输出已复位` 后独立清空该仓位业务状态；本站全部待卸仓位完成后，纯卸货站直接结束停靠，装卸混合站若仍可继续装货则进入 StationDepartureWaiting

## 假设

1. 操作员从仓位取出产品后，会将其正确存放到该站点预期的现场位置（如烘烤炉、氮气柜、机台等），系统不核验产品取出后的实际去向是否正确。
2. 任务的目标站点（即最终应在哪个站点被取出）最迟在任务下发/装载上AGV时已被正确确定并记录，本 UC 不核验该目标站点本身的判定过程是否正确。

## 正常流程

### 10.0

1. AGV到站后（见 [[uc-003-agv-arrives-at-designated-station|UC-003]]），系统自动识别该AGV上所有"目标站点=当前站点"且状态为"已占用"的仓位，并作为待卸项目列入 CurrentStopWorklistSnapshot；复合停靠时与本站待装项目同时显示
2. 系统自动批量打开这些仓位的仓门（不需要输入 Sublot；8005 不需要输入工号）
   2.0 系统按 [[uc-004-slot-door-safety-interlock|UC-004]] Flow A 核验该 AGV 当前是否处于移动状态，只有核验通过（未在移动）才允许下发开锁指令，否则拒绝本次开门（见该 UC Exception Flow EA1.1）
   2.1 8005 的 8 个仓门位于同一 IO 模块，车载端优先使用一次 Modbus `0x0F` 写多个线圈；跨模块项目按模块分组并行发送
   2.2 全部已计划分组发送完成后，系统分别核验各仓门是否正常打开（见 Exception Flow E2.1）
3. 操作员按任意顺序从所有已打开仓位取出产品，存放到该站点现场位置
4. 操作员按任意顺序关闭仓门；系统逐仓确认 `EMPTY + 锁闭 + 开锁输出已复位`
   4.1 每个完成仓位立即清除仓位—Sublot 业务关联，不等待同一 Sublot 或其它目标仓位
   4.2 若光幕仍检测到产品残留，系统自动再次弹开该仓门并转 [[uc-044-reopen-slot-after-incomplete-retrieval|UC-044]] 继续目标态闭环（见 Exception Flow E4.1）
5. 某仓开锁失败、通信失败或状态未知不回滚其它已打开仓位；操作员先处理成功仓位，异常仓位保持待恢复
6. 本站所有待取料仓位均完成后，服务端自动完成卸货任务；纯卸货站直接结束，装卸混合站按是否仍可继续装货进入 StationDepartureWaiting

## 备选流程

第一版没有按站点或单次操作覆盖策略的分支。其它项目以后可以在项目级开启卸货身份核验或 Sublot 完整性，但 8005 固定按 Normal Flow 执行；若本次到站同时还有装货任务，装货部分由 [[uc-001-load-completed-lot-into-slot|UC-001]] 处理。

## 异常流程

以下每条异常均以 `E<步骤号>` 编号，与 Normal Flow 中触发该异常的具体步骤（或子步骤）一一对应：

* E2.1 仓门开锁失败（电子锁/机械故障）
* E2.2 打开仓门后发现仓位内实际无产品，或产品与系统记录不符
* E4.1 关门后光幕检测仓位内仍有产品残留，转 [[uc-044-reopen-slot-after-incomplete-retrieval|UC-044]] 处理

### E2.1 仓门开锁失败

1. 系统在 Normal Flow 第 2 步下发目标仓位开锁指令
2. 系统按第 2.1 步核验仓门状态，发现该仓位仓门未能在规定时间内正常打开
3. 系统提示该仓位开锁异常，将该仓位标记为"异常锁定"，暂停对该仓位的后续操作
4. 系统提示终点站操作员联系设备/电气维护人员（R-11）处理；已经成功打开的其它仓位继续取货和关门，不回滚
5. 设备/电气维护人员排查并修复电子锁/机械故障后，解除该仓位的"异常锁定"状态，操作员重新尝试取出

### E2.2 打开仓门后发现仓位内实际无产品，或产品与系统记录不符

1. 系统打开系统记录中为"已占用"状态的目标仓位
2. 操作员按第 2.2 步核验，发现该仓位内实际没有产品，或存放的产品与系统记录的子批号不符
3. 操作员上报该仓位状态异常，暂停从该仓位取出
4. 系统将该仓位标记为"异常锁定"，暂停对该仓位的后续操作，等待核实该仓位实际情况与系统记录不一致的原因（如 [[uc-001-load-completed-lot-into-slot|UC-001]] 装载环节记录有误、途中产品遗失等）；该AGV上其他待取料仓位不受影响
5. 核实并处理完毕（更正系统记录或按异常流程处理该批次）后，方可解除该仓位的"异常锁定"

### E4.1 关门后光幕检测仓位内仍有产品残留

1. 操作员关闭仓位仓门
2. 系统按第 4.1 步通过光幕检测该仓位，发现该仓位内仍检测到产品残留
3. 系统自动再次弹开该仓门并转 [[uc-044-reopen-slot-after-incomplete-retrieval|UC-044]] 处理：操作员取出残留产品后再次关闭，直至光幕确认已清空为止，具体流程见该 UC，本 UC 不重复描述
4. UC-044 处理完毕、仓位恢复"空闲"后，流程返回本 UC 继续（若本次到站还有其他待取料仓位，回到第 2～4 步逐个处理）

## 备注

* 本 UC 是从 `user case.md` 中原始记录的场景（如"装片完工送烘烤：R-01 → R-02""氮气柜送焊线/键合机台：R-03 → R-06/R-07"）拆分出来的：这些场景此前只有起点站"装载"部分被写成 [[uc-001-load-completed-lot-into-slot|UC-001]]，终点站"取出存料"部分一直没有独立成文，因此新增本 UC 补齐。
* 经与用户确认：卸货既不输入 Sublot，也不读取随货单据；系统直接根据“仓位已占用 + 关联任务目标站点=当前站点”识别全部可卸仓位。
* 8005 项目的卸货身份核验和 Sublot 完整性均关闭；策略为项目级，不允许现场或站点临时切换。
* “批量开锁”指同模块优先一次 `0x0F` 写多个线圈，跨模块按模块分组并行发送；全部发送完成后统一检查反馈，避免逐仓发命令期间操作员已关闭先开仓门造成误判。
* 2026-07-31 已确认：8005 卸货逐仓物理闭环后独立清空业务状态，本站全部待卸完成后不再等待统一“确认完成”。纯卸货站直接结束；装卸混合站只有完成卸货后才可能进入装货离站等待。
* 2026-07-14 已确认：当前阶段不做 MES 回写；任务完成状态保存在本系统（见 [[br-012-mes-task-idempotency-and-reconciliation|BR-012]]）。原“是否回传 MES”TBD 关闭。
* 待补充事项（TBD）：

  2. 是否存在"该站点是取料站点，但操作员发现此次不需要收这批货"的取消场景（类比 [[uc-006-cancel-transport-task-upon-arrival|UC-006]]）？初步判断该场景发生概率低（产品已经在AGV上、通常是必然要交付的），暂标注 TBD，不深入展开。
