## 1. 测试目标

验证模拟器：

1. 对主系统表现为符合硬件规格的 Modbus TCP Slave。
2. 仓位动作、镜像、故障和 reset 行为确定且可重复。
3. WPF 与 Headless Host 使用相同核心逻辑。
4. FR-001～FR-015 都有至少一个可执行测试证据。

## 2. 测试范围

### 2.1 范围内

- 配置加载、校验和热重载
- 仓位状态与非法迁移
- Modbus 功能码、地址、权限和异常码
- HTTP API
- 多模块、多实例
- 故障注入/清除
- Pulse 计时、并发和 reset
- WPF 基础交互
- Headless 生命周期和可观测性

### 2.2 范围外

- 主系统任务、站点、MES、RIOT 业务正确性
- AGV 移动仿真
- 客户演示级 UI 视觉验收
- 正式 CI 流水线搭建

## 6. 核心测试场景

### 6.1 正常装载

- Given：仓位锁定、门关闭、光幕无遮挡。
- When：Modbus 写开锁 DO 自动弹门，随后 API 放料、关门。
- Then：锁 DI 正确、光幕 DI 有遮挡、占用立即为已占用。

### 6.2 非法迁移

- Given：仓位门仍关闭。
- When：API 请求放料。
- Then：返回 409 和稳定错误码，全部状态不变。

### 6.3 Pulse 重触发

- Given：Pulse=500ms。
- When：写 ON，300ms 后再次写 ON。
- Then：第二次写入后仍保持完整 500ms，随后归零。

### 6.4 批量写原子性

- Given：批量范围中包含非法或只读地址。
- When：执行 `0x0F` 或 `0x10`。
- Then：整批失败，不发生部分写入。

### 6.5 reset 隔离

- Given：存在故障、运行中的脉冲、DI 延迟和非默认寄存器。
- When：完整 reset。
- Then：全部恢复规定默认值；等待旧任务原期限后也不再回写。

### 6.6 配置热重载失败

- Given：磁盘和运行态为配置 A。
- When：候选配置 B 因端口占用无法预检。
- Then：磁盘和运行态均保持 A。

### 6.7 仓位矩形跨格布局

合法布局至少覆盖：

- 省略 `rowSpan`/`columnSpan` 时按 `1×1` 兼容旧配置。
- `1×N` 跨列、`N×1` 跨行和 `N×M` 跨行列。
- 仓位矩形的下边界、右边界刚好贴合所属面的最后一行/列。
- 两个仓位仅相邻、不共享基础格时允许加载。
- WPF 对每个跨格仓位只渲染一个状态卡片，并填满整个合并矩形。

非法布局至少覆盖：

- `rowSpan` 或 `columnSpan` 为零、负数或非整数。
- 起始坐标合法，但跨格后的下边界或右边界越界。
- 两个仓位起始坐标不同，但跨格区域发生部分重叠。
- 一个仓位矩形完全包含另一个仓位。

所有非法配置在启动时必须拒绝；热重载时必须保持磁盘配置和运行布局为上一有效版本，并返回两个冲突仓位、字段路径及相交范围。

## 7. 协议测试矩阵

每个功能码至少覆盖：

- 最小合法地址
- 最大合法地址
- 单个值
- 最大合法数量
- 地址越界
- 跨读写权限边界
- 非法值
- 多客户端并发

## 8. 故障测试矩阵

| 故障 | 注入 | 观察 | 清除 | reset |
| --- | --- | --- | --- | --- |
| 锁 DI 脱钩 | API | DO 与 DI 不一致 | 按当前 DO 重建 | 清除 |
| 光幕 DI 脱钩 | API | 实际遮挡与 DI 不一致 | 按实际遮挡重建 | 清除 |
| 模块断连 | API | 客户端连接断开 | 恢复监听 | 清除 |
| 模块不响应 | API | 连接保留但请求超时 | 恢复响应 | 清除 |

## 9. 非功能测试

- 逐步增加模块、仓位和连接，记录内存、线程、句柄和响应时间。
- 定义测试机器配置。

## 10. 通过标准

- 所有 P0/P1 FR 的自动化测试通过。
- 无未解释的随机失败。
- 协议非法输入不会导致进程崩溃或部分提交。

- 每个失败都能通过结构化日志定位。
