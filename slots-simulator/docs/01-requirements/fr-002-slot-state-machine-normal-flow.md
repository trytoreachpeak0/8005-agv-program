# FR-002 仓位状态机与正常流程

## Description 需求描述

每个仓位维护锁状态（锁定/解锁）、门状态（开/关）和光幕检测（有遮挡/无遮挡），并支持“开锁并由弹簧自动弹门→放料→关门”以及“开锁并由弹簧自动弹门→取出→关门”的状态迁移。统一术语为“开锁、关门、放料、取出”。

“开锁指令”DO 与“锁状态”DI 是两个独立硬件事实。主系统写 DO=1 触发电磁铁拉下锁舌；正常情况下弹簧随即把仓门弹开，锁状态 DI 变为“未锁”。脉冲模式下 DO 在脉宽结束后由 IO 模块自动复位为 0，但仓门仍然打开、锁状态 DI 仍保持“未锁”；只有操作员实际关闭仓门并使锁舌重新闩合后，锁状态 DI 才变回“锁闭”。因此不得用 DO=0 推断仓门已经锁闭。

"门状态"不对应独立 Modbus 点位。现场没有门磁/门位传感器；主系统只把有效锁 DI 的“锁闭”作为仓门已关并闩合的证明。模拟器仍维护内部门状态，用于表现弹簧自动弹门以及约束“放料/取出→关门”的动作合法性，但不对外暴露独立门 DI。

"占用状态"不作为独立字段存储，也不对应独立寄存器，始终由光幕 DI 推导：有遮挡即"已占用"，无遮挡即"空闲"。控制 API 的"放料"使实际遮挡成立并更新光幕 DI，"取出"清除实际遮挡并更新光幕 DI；占用变化在动作生效时发生，不要求先关门。故障注入导致光幕 DI 延迟或不跟随时，占用状态同样只按当时可读的光幕 DI 推导，不以模拟器内部的实际遮挡纠正。

开锁不属于控制 API 动作，只能由主系统写 Modbus DO 发起；正常开锁成功时模拟器自动把内部门状态置为“开”并把锁 DI 置为“未锁”，无需控制 API 再执行一次“开门”。控制 API 主要模拟人工“关门、放料、取出”；放料或取出前必须已开门，关门只有在开锁输出已复位且锁舌可以重新闩合时才使锁 DI 变为“锁闭”。任何非法状态迁移均须拒绝并保持请求前状态。

同一仓位的 Modbus 写入、控制 API 动作、自动脉冲复位和故障注入事件按到达顺序串行处理；不同仓位的事件可并行处理，且不得因共享全局状态相互阻塞或串扰。

**边界说明**：主系统的业务态（如异常锁定、已禁用等，参见根目录 [UC-014 启用/禁用仓位](../../../requirement-documents/03-use-cases/uc-014-enable-disable-slot.md)）完全由主系统根据锁状态 DI、光幕 DI 等硬件状态自行判定和维护；模拟器不感知这些业务态，也不提供"禁用仓位"等业务能力。

## Acceptance Criteria 验收标准

- 主系统通过 Modbus 将开锁 DO 写为 1 后，正常情况下仓门由弹簧自动弹开且锁状态 DI 变为“未锁”；脉冲自动复位 DO=0 后，门和锁 DI 仍保持打开/未锁。
- 对已打开的空仓执行放料时光幕 DI 立即变为“有遮挡”；对已占用仓位执行取出时光幕 DI 立即变为“无遮挡”，无需等待关门。
- 控制 API 执行关门且 DO 已复位时，内部门状态变为“关”并使锁 DI 变为“锁闭”。
- 控制 API 不提供开锁动作；所有开锁均由主系统写 Modbus DO 发起。
- 门关闭时放料或取出等非法迁移被拒绝并给出明确原因，请求前后的全部状态一致。
- 同一仓位事件严格串行，不同仓位事件可并行且互不串扰。

## Verification 验证方式

- **TC-FR-002-001（预留）**：Given 仓位锁闭、门关闭且光幕无遮挡；When 主系统写开锁 DO=1 且脉冲随后自动复位；Then 门自动打开、锁 DI 保持未锁，DO=0 不会令锁 DI 自动恢复锁闭。
- **TC-FR-002-002（预留）**：Given 已占用仓位已弹开；When API 执行取出并在 DO 复位后关门；Then 光幕 DI 变为无遮挡，关门后锁 DI 变为锁闭。
- **TC-FR-002-003（预留）**：Given 注入开锁/弹门失败；When 主系统写开锁 DO=1；Then DO 按脉冲复位，但门仍关闭且锁 DI 保持锁闭。
- **TC-FR-002-004（预留）**：Given 两个仓位同时接收动作且其中一个仓位连续接收多个事件；When 并发执行；Then 单仓位事件按到达顺序完成，不同仓位可并行且状态互不串扰。
