# FR-007 WPF 可视化面板

## Description 需求描述

提供图形界面，展示每个仓位当前的锁/门/光幕状态和由光幕 DI 实时推导的占用状态，并提供关门、放料、取出、批量设置光幕遮挡、一键全空闲及故障注入/清除入口，复用 [[fr-006-automation-control-api|FR-006]]。界面不提供开锁或开门入口；开锁只允许通过 Modbus DO，成功后弹簧自动弹门。

面板按 [[fr-011-configurable-slot-layout|FR-011]] 定义的版面布局渲染（分面统一基础网格，非从上到下的单列列表）。仓位可以按 `rowSpan`/`columnSpan` 连续跨越多个基础格，但无论跨格数量多少都只显示一个状态卡片并填满对应矩形区域；各面并排同时展示，不提供切换视图。

WPF 首期即提供完整配置编辑能力，覆盖仓位布局（含起始行列和跨行/跨列）、仓位与模块/通道映射、IO 模块监听地址/端口、寄存器模板及其可配置默认值等模拟器配置。编辑时实时校验必填项、类型、范围、跨格越界、任意覆盖区域重叠、映射重复、模板引用和端口冲突。保存采用原子事务：先在临时配置上完成静态校验和热重载预检，只有全部组件可切换时，才原子持久化 JSON 并切换 WPF、控制 API、状态机及全部 Modbus 模块；任一步失败都同时保留原磁盘配置和原运行态，并显示明确错误，不要求重启进程。

## Acceptance Criteria 验收标准

- 界面上能一眼看出每个仓位当前的锁、门、光幕及由光幕 DI 推导的占用状态，不维护第二份占用值。
- 布局严格按配置文件中的面、左上角行列、`rowSpan` 与 `columnSpan` 渲染，不是硬编码的单列列表；省略 span 时按 `1×1` 显示。
- 跨格仓位必须是连续矩形，并以一个状态卡片填满合并区域；界面不得把同一仓位拆成多个重复卡片。
- 手动操作与控制 API 一致，统一为关门、放料、取出、批量光幕、一键全空闲及故障注入/清除；不存在开锁或开门按钮。
- 面板本身不持有业务逻辑，只是控制 API 的可视化客户端。
- 可在 WPF 中编辑并保存完整模拟器配置为 JSON，字段能力不低于直接编辑配置文件。
- 配置编辑过程中可设置仓位的跨行数和跨列数，并实时显示字段级及跨字段校验结果；span 非正整数、跨格越界或任意覆盖区域重叠时禁止保存。
- 保存成功后所有配置立即热重载；新增、删除或修改仓位/模块、布局、起始坐标、span、映射、端口、模板默认值均无需重启即可生效。持久化与运行态切换必须是同一原子事务，不允许磁盘配置与运行态使用不同版本。
- 配置没有固定的模块数或仓位数上限；校验只依据硬件模板通道容量、监听端口可用性、映射完整性及当前机器资源约束给出结果。
- 不要求视觉美观度，仅供内部开发自测使用。

## Verification 验证方式

- **TC-FR-007-001（待建立）**：Given 已加载含多个分面的仓位配置；When 通过 Modbus 开锁并在 WPF 执行关门、放料、取出和光幕批量设置；Then 布局与配置一致、状态实时更新、占用与光幕 DI 一致，且界面中不存在开锁或开门入口。
- **TC-FR-007-002（待建立）**：Given 配置编辑器已打开；When 输入重复映射、无效模板引用或冲突端口；Then 对应字段立即显示校验错误且保存被禁止。
- **TC-FR-007-003（待建立）**：Given 模拟器正以配置 A 运行并保持 API/Modbus 连接；When 在 WPF 将布局、模块、映射和模板默认值修改为有效配置 B 并保存；Then 生成可再次加载的 JSON，所有组件立即按 B 工作且无需重启。
- **TC-FR-007-004（待建立）**：Given 磁盘配置和运行态均为配置 A；When 尝试保存一个通过静态校验但热重载预检因端口占用而失败的配置 B；Then WPF 显示明确错误，磁盘配置和运行态均继续完整使用配置 A。
- **TC-FR-007-005（待建立）**：Given 硬件模板和机器资源允许配置超过常见数量的模块与仓位；When 编辑、保存并热重载该配置；Then 系统不因固定数量上限拒绝，只在模板、端口、映射或资源约束不满足时报告错误。
- **TC-FR-007-006（待建立）**：Given 一个面同时包含 `1×1`、跨行、跨列和跨行列仓位；When WPF 加载布局并修改其中一个仓位的 span；Then 每个仓位只显示一个卡片且尺寸符合占用矩形，合法修改立即热重载，重叠或越界修改在保存前被明确阻止。
