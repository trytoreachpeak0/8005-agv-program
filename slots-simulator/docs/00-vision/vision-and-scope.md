# slots-simulator 愿景与范围

## 1. 背景 Background

多仓位 AGV 的仓位硬件（电子锁、光幕）在真实环境下开关门、放取产品都依赖人工操作。如果每次开发联调或回归测试都要人到现场手动操作，效率很低，也无法纳入自动化回归。通用的 Modbus Poll/Slave 一类工具虽然能模拟寄存器读写，但：

1. 不直观——只能看寄存器数值，看不出"仓位""锁""门""光幕"这些业务概念；
2. 没有可编程的状态迁移和时序能力，模拟不出"开门→放料→关门"这类带业务语义的流程，也做不了异常场景（如开门后发现异物、关门后残留检测不通过）的自动化重放。

`slots-simulator` 就是为解决这两个问题而建的仓位硬件模拟器。

## 2. 目的 Purpose

1. **对被测系统协议层透明**：模拟真实 IO 模块的 Modbus TCP 行为，被测系统（服务器/工控机的 IO 对接代码）连接模拟器和连接真实硬件不需要改代码。
2. **可视化直观**：提供图形界面，把锁状态、门状态、光幕/物体检测状态用"仓位"的形式展示出来，而不是裸寄存器数值。
3. **自动化测试能力**：提供独立于 Modbus 协议之外的 HTTP/JSON 控制 API，让测试脚本驱动“关门、放料、取出、故障注入/清除”等人工或环境动作。开锁必须由被测主系统通过 Modbus 写 DO 发出，成功后模拟弹簧自动弹门；控制 API 不提供开锁或开门入口。

## 3. 范围 In Scope

1. **只模拟仓位 IO 这一层硬件行为**：电子锁（开锁指令 DO、锁状态 DI）、光幕（DI）。不模拟 AGV 本体的移动状态、不对接/模拟 RIOT，也不模拟 MES。
   > 经确认：本项目没有"仓门开启时检测 AGV 是否移动"的硬件联锁（对应根目录 [UC-004](../../../requirement-documents/03-use-cases/uc-004-slot-door-safety-interlock.md) 描述的安全联锁），该逻辑（如果存在）属于主系统软件层的判断逻辑，不是仓位硬件本身的行为，因此不在本模拟器职责范围内，也不需要模拟器提供"AGV 是否移动"这个状态量。详见 [[dr-002-simulation-scope|DR-002]]。
2. **仓位数量可配置**：不写死仓位数量（术语表中一台 AGV 8 个仓位是当前已知的典型值，但模拟器本身应支持配置任意数量，方便测试不同柜型）。详见 [[dr-004-configurable-slot-count|DR-004]]。
3. **协议层实现为 Modbus TCP Slave**：这是主系统 IO 模块对接代码实际使用的协议（见根目录 `requirement-documents/00-vision/vision-and-scope.md` 第 7 节"格口硬件控制"，IO 模块支持 Modbus TCP）。真实设备寄存器表已经提供，首批支持 `0x01/02/03/05/06/0F/10`，核心动态寄存器为 DO、DI、DO 工作模式和 DO 脉冲宽度；仓位到"模块实例 + 通道"的项目级映射继续通过配置文件或界面配置，不写死在代码里。详见 [[dr-005-modbus-protocol-fidelity|DR-005]]、[[dr-011-full-register-table-fidelity|DR-011]]。
4. **单实例对应单台 AGV**：一个模拟器进程实例模拟一台 AGV 的全部仓位；如需同时模拟多台 AGV，通过启动多个独立实例（各自不同端口/配置）实现，不在单个实例内部做多 AGV 建模。详见 [[dr-007-multi-agv-support|DR-007]]。
5. **业务场景覆盖**：模拟器需要能够支撑以下根目录 UC 涉及的仓位硬件状态变化（包括正常流程和异常分支），具体功能点见 [`01-requirements/`](../01-requirements/README.md)：
   - [UC-001 放入完工产品到仓位](../../../requirement-documents/03-use-cases/uc-001-load-completed-lot-into-slot.md)（含硬件相关异常：仓位不足；系统记录空闲但开门后实际有物，即"误放"；E4.1 关门后未检测到产品；开锁失败；长时间不关门的硬件条件）
   - [UC-002 确认任务完成](../../../requirement-documents/03-use-cases/uc-002-confirm-task-completion.md)（不直接操作仓位 IO；通过批量设置仓位实际光幕遮挡、由光幕 DI 推导待确认的占用组合）
   - [UC-005 取出仓位中存错的产品](../../../requirement-documents/03-use-cases/uc-005-retrieve-mis-stored-product-from-slot.md)（重新开锁开门、取出、状态回滚）
   - [UC-006 到站后取消运送任务](../../../requirement-documents/03-use-cases/uc-006-cancel-transport-task-upon-arrival.md)（本身不涉及仓位 IO；通过"全空闲" API 构造所有光幕无遮挡的硬件前置状态）
   - [UC-010 终点站取出产品存料](../../../requirement-documents/03-use-cases/uc-010-unload-completed-lot-at-destination-station.md)（模拟器通过 Modbus 开锁后自动弹门，并提供取出、关门、光幕变化及故障；按站点筛选仓位、任务/映射维护和确认完成由主系统负责）。详见 [[dr-003-first-batch-scenarios|DR-003]]
6. **自动化控制能力**：提供默认仅监听 `localhost` 的 HTTP/JSON API，供脚本驱动人工/环境动作、批量光幕设置、全空闲、完整 reset，以及故障注入和清除；不提供开锁 API。
7. **可视化面板（WPF）**：供开发自测/日常联调查看和操作仓位状态，并完整编辑 JSON 配置；配置经 JSON Schema 和语义校验后原子热重载。界面按可配置版面布局渲染，不追求美观度，仅内部使用。
8. **CI 接入能力（架构预留，当前不启用）**：核心逻辑（状态机、Modbus Slave、控制 API）需要能脱离 WPF 独立无界面运行，并具备状态重置、健康检查、确定性时序、结构化日志、干净的进程生命周期等能力，为后续把本模拟器接入主系统 CI 流水线（作为集成测试的"假硬件"）预留架构空间，避免以后返工。当前阶段不要求真正搭建 CI 流水线本身。详见 [[dr-008-ci-readiness|DR-008]]。
9. **可配置仓位版面布局**：仓位不是简单从上到下排列的单列列表，而是按任意数量的"面"分组（对应现场前侧/后侧等物理分组，两侧仓门开启方向相反），每个面各自是可配置的 X 列 Y 行统一基础网格；仓位可按矩形连续跨越多个基础格。WPF 面板把所有面并排同时展示，每个仓位只显示一个填满合并区域的状态卡片，不做切换视图。详见 [[fr-011-configurable-slot-layout|FR-011]]、[[dr-009-slot-layout-model|DR-009]]。
10. **寄存器表做成可配置模板**：真实 IO 模块的完整寄存器布局（不只是 DO/DI 状态，也包括模块信息、网络配置等寄存器）以模板配置的形式提供，不写死在代码里；模板声明的 DO/DI 数量是该型号模块的硬性上限。首个模板依据 [reference/C2000-A2-KDDA0A0-AD6_寄存器表.md](../reference/C2000-A2-KDDA0A0-AD6_寄存器表.md) 建立。详见 [[fr-013-configurable-register-table-template|FR-013]]、[[dr-011-full-register-table-fidelity|DR-011]]。
11. **多 IO 模块模拟支持**：一台 AGV 的仓位可能分布在多个物理 IO 模块上（单个模块 DO/DI 数量有限），模拟器需要能在一个实例内同时模拟多个独立的 IO 模块（各自独立的 Modbus TCP 服务端点）。详见 [[fr-014-multi-io-module-simulation|FR-014]]、[[dr-012-multi-io-module-support|DR-012]]。
12. **派生状态与确定性运行**：占用状态由光幕 DI 即时推导，不独立存储；配置给出 DO 默认模式/脉宽，运行时寄存器值优先，完整 reset 清理运行态、故障和计时器后恢复默认。业务超时由主系统判定，模拟器只提供硬件状态与故障刺激。

## 4. 范围之外 Out of Scope

明确排除，避免后续被误解为遗漏：

1. **不模拟 AGV 移动状态、不对接/模拟 RIOT**：AGV 是否在移动、移动安全联锁等逻辑由主系统软件层负责和测试，不属于本模拟器。
2. **不模拟 MES 接口**：[UC-007 从 MES 同步生成搬运任务](../../../requirement-documents/03-use-cases/uc-007-sync-transport-task-from-mes.md) 等 MES 交互逻辑不在本模拟器范围内。
3. **不支持单实例多 AGV 建模**：多台 AGV 场景通过多实例解决，见第 3 节第 4 点。
4. **不面向客户演示，当前不搭建正式 CI 流水线**：本模拟器当前只服务邵正宇、王昆两人的开发自测，不作为正式验收目标；但按第 3 节第 8 点保留架构上的 CI 接入能力，不是完全排除，是"现在不做，但不给以后设障碍"。
5. **不做用户权限、多人协作管理**：模拟器本身没有登录/权限体系。
6. **不模拟异常锁定、已禁用、任务或业务超时等业务态**：模拟器暴露锁状态 DI、光幕 DI 等硬件可观察量；门状态仅作内部操作顺序约束，占用状态由光幕 DI 推导。主系统在此基础上判定和维护的业务态（如 [UC-014](../../../requirement-documents/03-use-cases/uc-014-enable-disable-slot.md) 的"已禁用"、各业务 UC 的"异常锁定"及超时告警）完全由主系统负责。
