# DR-003 首批覆盖场景——所有多仓位相关 UC

## Decision 决策

第一批需要支持自动化测试的场景覆盖所有与仓位相关的 UC：UC-001（含异常分支）、UC-002、UC-005、UC-006、UC-010（含异常分支）。

> **更新说明（2026-07-10）**：UC-010（终点站取出产品存料）是在本决策最初确定时尚未写出的 UC，此前的覆盖范围列表遗漏了它；现补充纳入，由 [[fr-015-destination-station-unload-support|FR-015]] 承接，理由与其余 UC 一致——它同样直接操作仓位 IO（开锁、光幕核验），本决策"不单独按优先级砍量"的原则同样适用。

覆盖表示模拟器能够构造这些 UC 所需的**硬件可观察条件和人工物理动作**，不表示模拟器实现主系统业务：

1. UC-002 可通过 HTTP/JSON API 批量设置目标仓位的实际光幕遮挡，由光幕 DI 即时推导"已装载/已取出、等待确认"所需的占用组合；任务筛选、一次性确认和数据库更新仍由主系统负责。
2. UC-006 可通过"全空闲" API 一次性清除全部仓位遮挡，使所有光幕 DI 表示空闲；"任务名下是否有占用仓位"的关联核验与取消任务仍由主系统负责。
3. UC-010 中，模拟器只承接主系统通过 Modbus 开锁后，开门、取出、关门及光幕变化等硬件/人工侧动作。按目标站点筛选仓位、决定打开顺序、维护仓位—子批号映射、完成任务和 MES 交互均不属于模拟器职责。

术语统一如下：

- **放料/取出**：API 对仓位内实际遮挡施加的物理动作；占用状态由光幕 DI 推导，不另存一份状态。
- **误放**：仅指 UC-001 E2.2 的"系统记录为空闲但开门后实际有物"，可通过在未执行放料流程时设置光幕有遮挡构造。
- **存错产品/数量不符**：指 UC-001 E4.2，并转 UC-005；光幕只能表达有无，不能识别产品身份或数量，模拟器不负责判定。
- **UC-001 E4.1**：关门后光幕仍显示无遮挡，即"应有产品但未检测到"，不是"误放"也不是"残留"。

## Rationale 理由

用户明确"这要和多仓位相关的都要"，不单独按优先级砍量，因为这些场景本身数量不多、都与仓位硬件状态直接相关。UC-010 补充纳入后同样遵循这一原则。

用批量光幕设置和全空闲操作直接构造硬件前置状态，可以覆盖 UC-002/UC-006 的主系统判定分支，而不在模拟器中复制任务、站点、子批号等业务模型。

## Alternatives Considered 备选方案

曾考虑只优先支持 UC-001 正常流程，异常分支和 UC-005/UC-006 延后，用户否决，选择一次性全部覆盖。
