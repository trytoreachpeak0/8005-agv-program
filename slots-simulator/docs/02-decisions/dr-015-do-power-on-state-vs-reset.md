# DR-015 DO 上电状态寄存器与自动化测试状态重置接口的关系——两套独立机制

## Decision 决策

1. 寄存器表中"DO1～DO16 上电时的状态"（地址 116～131，见 [reference/C2000-A2-KDDA0A0-AD6_寄存器表.md](../reference/C2000-A2-KDDA0A0-AD6_寄存器表.md)）是真实设备本身具备的寄存器功能。模拟器按 [[fr-013-configurable-register-table-template|FR-013]]"完整还原寄存器表"的要求，必须支持对该寄存器组的正常读写行为（写入后能读回刚写入的值），但该寄存器组保存的值本身不驱动模拟器进程重启后的实际 DO 初始值，也不驱动 [[fr-010-automation-test-infrastructure|FR-010]] 完整 reset 恢复到的 DO 值。
2. 模拟器进程（重新）启动时的 DO 初始值，以及完整 reset（无需重启进程、一次性恢复全部仓位到初始状态）恢复到的 DO 值，统一按配置文件声明的初始空闲态执行（默认 DO=0），不读取、不依赖上电状态寄存器（116～131）当前保存的值。配置同时提供 DO 工作模式和脉冲宽度默认值；运行期间寄存器写入值优先，完整 reset 时恢复配置默认值。
3. 这是两套服务于不同目的、彼此独立的机制：
   - 上电状态寄存器是真实硬件协议面的一部分，模拟器保留其地址、权限和读写回读行为，使被测系统访问该寄存器组时不会遇到缺失地址；但本项目明确不模拟其对真实设备断电再上电的物理副作用，进程启动与测试 reset 始终使用可重复的配置基线。
   - FR-010 的状态重置是模拟器专门为自动化测试提供的"一键恢复到已知初始状态"能力，服务于测试用例之间的状态隔离，其结果必须是确定性的、不受被测系统之前任何寄存器写入历史的影响。
4. **完整 reset 的清理边界**：清除全部运行态，包括 DO/DI 派生状态、内部门操作状态、故障注入状态、模块断连/不响应状态、正在运行的脉冲与场景计时器；随后从当前有效配置重建默认状态。reset 不改写配置文件，也不把运行时寄存器修改持久化回配置。

## Rationale 理由

用户确认需要为寄存器表中的"DO 上电状态"寄存器与 FR-010 的"状态重置"接口之间的关系补一份说明，避免以后有人以为两者是同一回事、或模拟器重启/重置时应该读取这组寄存器来决定 DO 初始值。

这里选择"两者独立、状态重置/进程启动永远归零到配置里的空闲态，不受上电状态寄存器影响"的方案，是因为自动化测试场景最看重"结果可预测、不受历史写入影响"：如果状态重置或进程重启的结果依赖被测系统在上一次测试中写入的上电状态寄存器值，会引入测试用例之间的隐藏状态耦合——一次测试写入了非默认的上电状态值，可能导致下一次测试重置/重启后的初始状态与预期不符，这与 [[dr-008-ci-readiness|DR-008]]"确定性时序"的目标直接冲突。

## Alternatives Considered 备选方案

曾考虑让模拟器进程启动、或 FR-010 的状态重置接口读取上电状态寄存器当前保存的值来决定 DO 初始值，这样更贴近真实硬件"断电重启后 DO 恢复为设定的上电状态"的物理行为——但这会导致自动化测试的初始状态依赖上一次测试可能遗留的寄存器写入，产生跨测试用例的隐藏耦合，破坏测试结果的确定性，未采纳。
