# DR-013 门状态与占用状态均为派生状态

## Decision 决策

1. 仓位的"门状态"（开/关）不对应任何独立的 DI 寄存器点位。[[fr-001-configurable-slot-count-and-io-mapping|FR-001]] 定义的三类点位（开锁指令 DO、锁状态 DI、光幕 DI）已经完整覆盖真实硬件，不需要新增第 4 类点位。
2. 现场仓门本身没有独立的门磁/门位传感器；门是否打开，由锁的 DO（开锁指令）与 DI（锁状态反馈）推算得出，这一推算逻辑属于主系统软件层的判断，不是模拟器需要额外暴露的硬件信号。
3. [[fr-002-slot-state-machine-normal-flow|FR-002]] 中为了约束"开锁→开门→放料→关门"正常流程的先后顺序，模拟器内部可以维护一个"门是否已开"的业务状态字段，但这只是模拟器自身状态机迁移合法性检查用的内部概念，不对应、也不需要暴露为独立的 Modbus 寄存器。
4. 仓位"占用状态"也不独立存储：由光幕 DI 推导，`有遮挡`即"已占用"，`无遮挡`即"空闲"。放料/取出动作改变实际遮挡，光幕 DI 正常情况下随之变化，占用状态再由当前 DI 即时计算；故障注入导致光幕反馈脱钩时，对外可观察的占用状态仍以 DI 为准。
5. "实际遮挡"只用于模拟环境动作和传感器故障模型，不是主系统可读的另一份占用真值；reset、批量光幕设置和全空闲操作最终都通过统一更新光幕/遮挡模型得到占用结果，避免双份状态漂移。

## Rationale 理由

用户确认现场仓门没有单独传感器，门状态都是通过锁的 DO/DI 来判断的。这与最初对根目录 [UC-017 仓门开关状态识别测试](../../../requirement-documents/03-use-cases/uc-017-slot-door-state-detection-test.md) 的误读不同——该 UC 提到的"门状态 DI 信号"，其 Notes 部分本身也承认"具体来源于电子锁自带的开关反馈还是独立的门磁传感器"尚待与设备供应商确认；现在确认的结果是：没有独立传感器，该信号实际就是锁状态 DI 信号。因此 FR-001 不需要为"门状态"单独增加一类点位，FR-002 中的"门状态"应被理解为模拟器内部的流程排序概念，而不是独立硬件点位。

同理，主系统实际能读取的是光幕 DI，不存在另一条独立的"占用状态"硬件信号。把占用重复持久化会制造"DI 显示无遮挡但占用字段仍为已占用"的无效组合，因此统一派生。

## Alternatives Considered 备选方案

曾考虑在 FR-001 中新增"门状态（DI）"作为第 4 类可配置点位，与 UC-017 的描述对齐；因用户确认现场无独立门传感器，该方案会引入一个真实硬件不存在的寄存器点位，未采纳。
