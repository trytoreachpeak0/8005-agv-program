# DR-009 仓位版面布局模型——任意 N 个面、矩形跨格与并排展示

## Decision 决策

1. **泛化为任意数量的"面"**：不固定写死"前侧/后侧"两个面，配置里可以声明任意数量的面（每个面有名称、列数 X、行数 Y）。
2. **使用统一基础网格和连续矩形跨格**：每个面的基础格尺寸一致。仓位用左上角 `row`/`column` 加正整数 `rowSpan`/`columnSpan` 表示占用矩形，两个 span 默认均为 `1`。允许 `1×1`、`1×N`、`N×1`、`N×M`，不允许 L 形等不规则组合、绝对像素定位或仓位级单独旋转。
3. **跨格区域不得越界或重叠**：仓位矩形必须完全位于所属面内；同一面中任意两个仓位不得覆盖同一个基础格。空白基础格允许存在。
4. **各面并排同时展示，不做切换**：WPF 面板把所有面的网格同时摆在屏幕上（如左右两块），不提供 Tab/按钮切换单面查看的视图。每个仓位无论跨越多少格都只渲染一个状态卡片，并填满对应矩形区域。

## Rationale 理由

背景：现场多仓位 AGV 的仓位通常分为前侧、后侧两组，两侧仓门开启方向相反，操作员要绕到另一侧才能看到另一侧的仓位；每一侧内部可用 X 列 Y 行的基础网格描述，但实际仓位尺寸不完全相同，一个仓位可能连续占据多个基础格。

1. 泛化为 N 个面而不是固定前侧/后侧两个面，是为了与项目一贯的"不写死"风格保持一致（参考 [[dr-004-configurable-slot-count|DR-004]] 仓位数量可配置的同一思路）：以后如果出现三面、单面或其他命名的柜型，只需改配置，不需要改代码。
2. 在统一基础网格上增加矩形 span，既能表达不同尺寸仓位，又保持配置、碰撞校验和 WPF `Grid` 渲染简单明确。`rowSpan`/`columnSpan` 默认 `1`，使原有单格配置不需要迁移即可保持原语义。
3. 只支持连续矩形，是因为当前物理仓位可按矩形柜门理解；不规则形状和绝对像素定位会显著增加编辑、缩放、碰撞检测和测试成本，当前没有实际需求支撑这种复杂度。
4. 各面并排展示而不做切换，是因为本模拟器是开发自测工具（见 [[dr-006-users-and-automation-style|DR-006]]），不是真实操作员使用的 HMI，不需要模拟"人只能看到一面"的物理限制；两个面的网格直接摆在屏幕上更方便开发一次看全所有仓位状态，不必来回切换。

## Alternatives Considered 备选方案

- 曾考虑固定"前侧/后侧"两个面，做简单点，以后真出现别的布局再改——因与项目一贯的可配置风格不一致，未采纳。
- 曾考虑用 Tab/按钮切换单面显示，更贴近操作员实际视角、便于测试"当前只看得到这一面"相关的场景——因本模拟器面向开发自测而非真实操作员使用，一次看全更高效，未采纳。
- 曾考虑让仓位声明任意基础格集合，以支持 L 形等不规则区域——当前没有这种物理柜型需求，且会增加编辑与渲染复杂度，未采纳。
- 曾考虑使用绝对像素坐标和宽高表示不同尺寸仓位——难以随窗口缩放，也不利于 Schema 校验和自动化测试，未采纳。
- 曾考虑为每一行、每一列配置不同权重——当前统一基础格加 span 已能表达已知布局，先不引入额外自由度。
