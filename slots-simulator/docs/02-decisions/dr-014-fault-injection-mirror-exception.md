# DR-014 故障注入覆盖开锁弹门、重新闩锁、光幕反馈和模块通信

## Decision 决策

1. 正常路径下，开锁 DO 与锁状态 DI 是独立事实：有效开锁脉冲触发电磁铁拉下锁舌并由弹簧弹开仓门，锁 DI 变为未锁；DO 自动复位不改变打开仓门的锁 DI；人工关门并重新闩合后锁 DI 才恢复锁闭。
2. 模拟器支持以下可独立注入和清除的故障：
   - **开锁/弹门失败**：DO 脉冲和自动复位正常发生，但门未弹开、锁 DI 保持锁闭。
   - **闩锁失败**：控制 API 模拟关门后锁 DI 仍保持未锁，表示门未能重新闩合。
   - **光幕反馈故障**：光幕 DI 卡死或延迟，不随实际遮挡变化。
   - **模块通信故障**：按 IO 模块注入断连或不响应，其它模块继续运行。
3. 故障保持到控制 API 显式清除或完整 reset。清除后根据当前内部门状态、实际遮挡和 DO 状态重新计算可观察 DI，不保留陈旧反馈。
4. 开锁/弹门失败后，模拟器不自行再次触发 DO；是否重试由被测主系统决定，用于验证“结果未知先读状态、不得盲目重复脉冲”的规则。

## Rationale 理由

现场锁有弹簧弹门结构。锁 DI 只有在仓门实际关闭并重新闩合时才显示锁闭，因此旧的“DI 直接镜像 DO”模型会在脉冲复位时错误地宣称门已经锁好。故障模型应围绕可观察机构结果，而不是人为制造正常路径下不存在的 DO/DI 镜像关系。

多模块部署下，局部通信失败可能造成批量开锁部分成功。按模块注入断连和不响应，可以验证主系统分别记录成功、失败与未知仓位，并继续安全处理已经打开的仓门。

## Alternatives Considered 备选方案

- 让锁 DI 始终镜像 DO，仅在故障时脱钩（拒绝：正常脉冲复位后门仍开着，镜像模型本身即不符合硬件）。
- 只模拟笼统“开锁失败”（拒绝：无法分别验证弹门失败、关门后未闩合、光幕故障和局部模块通信故障）。
