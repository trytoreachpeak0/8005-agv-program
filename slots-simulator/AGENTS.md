## 项目目的

`slots-simulator` 用于模拟"多仓位 AGV"的仓位（格口）硬件部分，替代 Modbus Poll/Slave 这类通用调试工具，服务两个目标：

1. **可视化、直观**：以图形界面展示每个仓位的锁状态、门状态、光幕/物体检测状态，方便开发日常联调（仅供邵正宇、王昆两人自测使用，不面向客户演示）。
2. **自动化测试能力**：真实仓位硬件的开关门、放取物料依赖人工操作，效率低。本模拟器提供独立于 Modbus 协议的控制 API，供开发编写脚本以代码驱动仓位状态变化，让原本依赖人工的测试场景可以自动化、可重复执行（当前不要求接入正式 CI，脚本由开发自行运行）。

**完整项目文档见 [`docs/`](./docs/README.md)**，按 `00-vision`～`05-planning` 统一组织愿景、需求、决策、设计、测试和实施计划。本节只保留 Agent 工作所需摘要，详细内容以 `docs/` 为准。

## 架构设计要点（规划中，尚未实现）

1. **协议适配层**：实现 Modbus TCP Slave（对应 FR-005），支持 `0x01/02/03/05/06/0F/10`；DO、DI、DO 工作模式、DO 脉冲宽度是核心动态寄存器，`0x0F/0x10` 批量写原子。真实寄存器布局已在 `docs/reference/` 提供并按 FR-013 做成模板；仍需配置的是仓位到"模块实例 + 通道"的映射，不再描述为"点位表 TBD"。
2. **仓位状态机内核**：锁状态 DI 反映锁舌是否实际闩合，不镜像 DO；写开锁 DO 成功时弹簧自动弹门并使锁 DI 变为未锁，脉冲复位后仍保持未锁，直到人工关门并重新闩合。门状态只用于内部操作顺序，不对应独立寄存器；占用状态由光幕 DI 即时推导，不独立存储。放料/取出改变实际遮挡，故障注入可临时让反馈脱钩。**不建模 AGV 移动、任务、站点、MES、异常锁定或业务超时**，这些由主系统负责。UC-001 E4.1 是“关门后未检测到产品”，不是误放；“误放”特指空闲仓开门后实际有物，产品身份/数量错误则属于 UC-005 业务。
3. **自动化控制 API**：确定为 HTTP/JSON，默认仅监听 `localhost`，供脚本和 WPF 共用。API 代表人工/环境动作（关门、放料、取出、批量设置光幕遮挡、全空闲）、完整 reset、故障注入与清除；**不提供开锁或开门 API**，开锁并自动弹门必须由被测主系统通过 Modbus 写 DO。UC-002 用批量设置实际光幕遮挡构造，UC-006 用全空闲构造；UC-010 的站点筛选、任务/映射维护和确认完成不在模拟器内实现。
4. **WPF 面板**：作为 HTTP/JSON 控制 API 的可视化客户端，并提供模块模板/实例、仓位映射、布局、默认工作模式和脉宽等完整 JSON 配置编辑。配置必须先通过 JSON Schema、跨引用/资源边界语义校验及热重载预检，再以同一事务原子持久化和切换运行态；失败时磁盘与运行态都继续使用旧配置。WPF 不直接持有业务逻辑。
5. **单实例单 AGV**：一个进程实例只模拟一台 AGV 的仓位集合；同时模拟多台 AGV 通过启动多个独立实例（各自不同端口/配置）实现，不在单实例内做多 AGV 建模。
6. **项目分层要支持 Headless 运行（对应 FR-009/FR-010）**：核心逻辑（状态机、Modbus Slave、控制 API）放在不引用 WPF 的 Core 项目里；WPF 只是 Core 的一种可选客户端，不是启动入口。额外提供一个不带界面的 Host（如控制台程序）作为启动方式，供未来接入 CI 使用。参考分层：

   ```
   SlotsSimulator.Core   状态机 + Modbus Slave + 控制 API，不引用 WPF
   SlotsSimulator.Wpf    引用 Core，仅做可视化 + 手动操作
   SlotsSimulator.Host   引用 Core，控制台/无界面启动方式，供 CI/脚本使用
   ```

   Host 模式下还需支持：完整 reset、健康检查/就绪探针、结构化日志输出、正确响应终止信号。完整 reset 清运行态、故障和计时器并恢复配置默认值。业务超时由被测主系统计时和判定；模拟器只提供保持状态、模块不响应等刺激，不直接跳到业务超时态。当前不要求真正接入某个 CI 系统，但写代码时不要把这条路堵死。

7. **仓位配置模型分两个维度维护（对应 FR-001/FR-011）**：IO 点位映射（FR-001，协议地址）和版面布局（FR-011，面、左上角行列、`rowSpan`、`columnSpan`，presentation 层）是同一个仓位配置项下的不同字段，但关注点分离，互不耦合，方便各自独立演进。每个面使用统一基础格，仓位可连续矩形跨格且覆盖区域不得重叠；WPF 对每个仓位只渲染一个填满合并区域的卡片，所有面并排同时展示，不做切换视图。
8. **DO 运行参数与并发（对应 FR-012）**：配置提供每个 DO 的默认 Level/Pulse 模式与脉冲宽度，运行时 Modbus 寄存器值优先，完整 reset 恢复默认。Pulse 计时期间再次写 1 要从该次写入重启完整计时。同一仓位命令串行，不同仓位并行；故障注入是 DO/DI 镜像唯一例外。
9. **JSON+Schema 多模块配置（对应 FR-013/FR-014）**：完整寄存器布局以 JSON 模板配置提供；模块实例各自维护寄存器空间和 Modbus 端点，默认绑定 `localhost`。仓位引用"模块实例 + 通道号"，不能用裸地址。数量不设固定软件上限，但必须严格校验 ID/坐标唯一性、Schema、跨对象引用、地址/端口冲突、模板 DO/DI 容量及主机资源预算；任一失败则整体拒绝，不得部分加载。
10. **模块故障模型**：可指定模块注入"断连"或"保持连接但不响应"，其他模块不受影响；点位脱钩与模块故障都必须可显式清除，完整 reset 也会清除。恢复后按当前 DO/实际遮挡重建反馈，不沿用陈旧故障值。

架构与范围的详细依据见 [`docs/02-decisions/`](./docs/02-decisions/README.md)，实现级设计见 [`docs/03-design/`](./docs/03-design/architecture.md)。
