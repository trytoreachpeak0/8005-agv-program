# MesIngest Watch Variant A 完整双语与值语义

Status: done

## 2026-08-28 简体中文呈现修订

ADR-mes-0032 取代本规格中“简体中文界面保留原生英文标签”的旧例外。English 模式、语言切换、偏好持久化、状态保持、Variant A 布局和值语义仍保持；简体中文模式的产品名、系统名、领域类型、属性名、字段名、表头、筛选项、设置、通知、提示、复制列头和无障碍文本全部使用中文。只有运行时值保留原样，包括标识、稳定代码、工序类型值、制造执行系统原始值、时间、路径、命令、日志和 JSON 内容。已知代码在简体中文的普通 UI 中只显示中文含义，不在含义后附加括号原码或点号原码；原码只保留在明确的代码/原始证据字段、复制内容和未知码回退中。

简体中文规范词汇为：制造执行系统接入运维台、服务端、制造执行系统、调查窗口、需求系列、运输需求、需求系列标识、运输需求标识、工序类型、子批次、区域、设备、下一工序、来源时间、封装形式、通过、未通过、跟踪中、已归档。已知代码在普通 UI 中只显示中文含义；中文界面的语言选项显示为“简体中文”和“英语”。本修订不改变 Variant A 的主从布局、卡片层级、筛选、分页、值绑定或调查交互。

## Problem Statement

`MesIngest Watch` 当前生产界面以中文硬编码文案为主，同时混用 `Demand`、`Series`、状态码、字段名和中文解释。主窗口、资格审计、DemandSeries Inspector、设置、通知、Tooltip、复制结果和 UI Automation 分别自行拼接最终显示字符串，没有一个能够保证中文与英文语义一致的显示目录。使用者无法切换完整英文，也无法确认相同代码、状态和缺值在不同页面是否表达同一事实。

当前界面还存在“孤立值”问题：无表头 master-detail 条目、多值摘要、概览大号指标和详情证据中的数值、标识或状态，有时只能依靠位置、颜色、破折号或 Tooltip 猜测含义。特别是来源未提供、系统未知、不适用、尚未加载、查询成功但无结果和读取失败仍可能被同一个 `—`、空白区域或通用空态覆盖，导致使用者把源数据 NULL、等待加载、零结果和保留旧快照误认为同一状态。

用户已于 2026-08-27 选择 **Variant A — semantic workbench（语义分层工作台）** 作为双语与值语义呈现方向。Variant A 保留资格审计既有 master-detail 调查流程，以本地化含义作为主阅读层，并把协议码、标识和原始值保留为次要技术事实；字段名属于固定语义锚点，在简体中文模式使用中文。该选择固定信息结构和交互层级；throwaway 原型的假数据、评审条、变体切换器、Tag 字典和代码后置本地化遍历不能成为生产依赖。

生产实现必须同时满足 ADR-0031 的完整双语契约：首次启动固定使用简体中文；设置中可切换 English；所有已打开窗口即时一致更新；筛选、选择、滚动位置和 Inspector 调查上下文不丢失；全部页面及辅助表面完成后才可发布。只迁移资格审计或只翻译可见 XAML 会造成语言混杂版本，不是可交付结果。

## Solution

为生产 Watch 建立一个集中、强类型的双语文本目录和一个窗口生命周期内共享的显示语言状态。目录为每个语义键同时提供简体中文和英文，并负责已知状态、错误、操作、单位、相对时间、缺值以及未知动态码回退。主窗口、Inspector、设置、对话框、通知、Tooltip、复制说明和 UI Automation 都从同一目录投影文本，不再各自维护翻译字典或新增硬编码可见文案。

语言入口固定在“设置 → 显示与布局”；简体中文模式显示“简体中文”和“英语”，English 模式显示对应英文名称。没有已保存偏好时使用简体中文，不读取 Windows 显示语言决定初始值；保存后按当前 Windows 用户持久化。切换只重投影呈现，不重新解释规范代码、不改变 Host 请求、不清空本机状态，也不为切换本身触发一次数据刷新。

资格审计按已选 Variant A 重写为语义分层工作台：桌面宽度下左侧是有可见行内标签的运输需求主列表，右侧首先给出选中项的资格结论和规范阻断码，再以“当前唯一制造执行系统观测”“当前阻断条件”“外部可读资格”“缺值与查询语义”四个稳定区域解释事实、规则与结论。已知含义使用当前语言作为主层；运输需求标识、工序类型、子批次、区域、协议码、原始值和带偏移绝对时间仍可见且可复制，其中标签随语言变化、值保持原样。

全 Watch 采用“禁止孤立值”约束。每个值必须由可见字段标签、表头、卡片标题、单位或同级语义锚点解释；已有清晰表头时不重复标签。缺值和查询状态使用明确的语义类型而不是通用占位符；未知动态码显示本地化“未知”说明并附原始码。绝对时间统一为 `yyyy-MM-dd HH:mm:ss zzz`，相对时间只作为本地化次要说明；筛选和 Host 请求始终保存、发送规范代码。

开发可以内部按页面迁移，但发布门禁按一个整体版本验收：所有生产资源键有中英文、所有已知状态有双语含义、所有可见和可访问文本完成迁移、即时切换保持调查状态，并在相同数据、相同窗口尺寸下分别完成中文和英文的生产窗口视觉检查。Variant A 原型只作为比较权威，生产仍使用真实 ViewState、主题资源、响应式布局和 UI Automation。

## User Stories

### 语言默认值与本机偏好

1. 作为首次启动 Watch 的使用者，我希望界面默认使用简体中文，以便无需依赖 Windows 显示语言就能得到项目约定的初始体验。
2. 作为使用英文工作的开发人员，我希望在设置的“显示与布局”中选择 English，以便整个 Watch 使用一致英文呈现。
3. 作为使用中文工作的开发人员，我希望语言选项始终以 `简体中文` 自称显示，以便在英文界面中也能准确找到中文选项。
4. 作为使用英文工作的开发人员，我希望语言选项在简体中文界面显示为“英语”、在 English 界面显示为 `English`，以便固定界面文字不混杂语言。
5. 作为 Watch 使用者，我希望语言选择按当前 Windows 用户保存，以便下次启动恢复我的显示偏好。
6. 作为共享计算机的另一位使用者，我希望语言选择不写入 Host 配置或项目业务配置，以便不同 Windows 用户可以拥有独立偏好。
7. 作为 Watch 使用者，我希望旧版本偏好中没有语言字段时安全迁移为简体中文，以便升级不会损坏刷新间隔和窗口布局偏好。
8. 作为 Watch 使用者，我希望损坏或未知语言值安全回退为简体中文并保留可恢复启动，以便本机偏好错误不会阻止 Watch 打开。
9. 作为运维人员，我希望语言选择不改变 Host、MES、数据库、日志或 API 数据，以便显示偏好不会成为业务状态。
10. 作为 Watch 使用者，我希望重置显示偏好时语言按明确的简体中文默认值恢复，以便结果可预测。

### 即时切换与状态保持

11. 作为 Watch 使用者，我希望保存新语言后主窗口立即切换，以便不必重启应用。
12. 作为正在查看 Inspector 的使用者，我希望已打开 Inspector 与主窗口同时切换语言，以便两个窗口不会处于混合语言。
13. 作为正在处理对话框的使用者，我希望已打开的 ContentDialog 同步切换语言，以便确认动作和说明保持一致。
14. 作为正在查看通知的使用者，我希望当前 toast 的标题、说明、动作和关闭帮助同步切换语言，以便旧语言文案不会残留到期。
15. 作为 Watch 使用者，我希望语言切换保留当前导航页面，以便继续原来的工作。
16. 作为资格审计使用者，我希望语言切换保留已提交的资格、WorkType、原因、DemandId、SUBLOT 和 AREA 条件，以便查询上下文不丢失。
17. 作为需求系列使用者，我希望语言切换保留生命周期、当前出现状态、WorkType、SUBLOT、SeriesId、DemandId、AREA 和页码，以便无需重新建立调查范围。
18. 作为错误检索使用者，我希望语言切换保留分类、错误码、活动状态、时间窗口、SeriesId 和 DemandId 条件，以便不会扩大或改变检索。
19. 作为 AREA 筛选编辑者，我希望语言切换保留当前配置、未保存草稿、光标位置和冲突状态，以便文本编辑不会被打断。
20. 作为 Watch 使用者，我希望语言切换保留当前选中行和详情对象，以便不会自动选择另一项。
21. 作为查看长列表的使用者，我希望语言切换保留主列表和详情区域的滚动位置，以便不必重新寻找证据。
22. 作为 Inspector 使用者，我希望语言切换保留当前 Series、Demand、选中标签、事件过滤和调查上下文，以便原因分析连续。
23. 作为 Watch 使用者，我希望语言切换不发起额外 Host 查询，以便语言变化不会改变快照、触发加载态或制造网络故障。
24. 作为 Watch 使用者，我希望切换后规范代码和筛选值逐字保持不变，以便显示语言不会重新解释业务条件。
25. 作为 Watch 使用者，我希望切换后焦点仍停留在原来的可操作控件或语义等价控件，以便键盘流程不被重置。

### 完整双语覆盖

26. 作为 Watch 使用者，我希望标题栏、主导航、Host 页脚状态和页面标题全部使用当前语言，以便外壳没有语言混杂。
27. 作为概览使用者，我希望摘要卡、统计范围、更新时间、重点动态和下钻动作全部使用当前语言，以便指标可以独立理解。
28. 作为需求系列使用者，我希望筛选、列表、分页、生命周期说明、空态和打开 Inspector 动作全部使用当前语言，以便主调查流程完整。
29. 作为资格审计使用者，我希望筛选、分面、列表、详情、证据、分页和空态全部使用当前语言，以便不会在一次调查中来回解释术语。
30. 作为错误检索使用者，我希望分类、结果、证据、原始证据入口、失败状态和帮助全部使用当前语言，以便诊断表面完整。
31. 作为 AREA 筛选使用者，我希望配置列表、编辑器状态、文件动作、验证、应用状态和冲突选择全部使用当前语言，以便配置行为清晰。
32. 作为接入告警使用者，我希望活动异常、保护状态、证据标签、恢复状态和下钻动作全部使用当前语言，以便当前关注项可解释。
33. 作为设置使用者，我希望 Host 设置、显示与布局、刷新间隔、校验和保存结果全部使用当前语言，以便设置页没有残余硬编码。
34. 作为 Inspector 使用者，我希望标题栏、上下文、标签页、Demand 形成原因、MES 差异、事件和空态全部使用当前语言，以便独立窗口具备完整双语。
35. 作为 Watch 使用者，我希望 InfoBar、toast、ContentDialog、验证提示和恢复说明全部使用当前语言，以便反馈表面遵循同一术语。
36. 作为 Watch 使用者，我希望 Tooltip、上下文菜单和键盘帮助使用当前语言，以便辅助发现信息不会落在另一种语言。
37. 作为复制数据的使用者，我希望“含列名”复制中的说明性列头使用当前语言，以便粘贴结果可读。
38. 作为读取原始证据的开发人员，我希望 JSON、日志正文、API 字段和原始数据不被翻译，以便复制结果仍能与真实契约对照。
39. 作为屏幕阅读器使用者，我希望 Automation Name、HelpText、live region 和状态说明使用当前语言，以便视觉与无障碍语义一致。
40. 作为测试人员，我希望生产应用不存在只在某个深层状态才出现的单语言文案，以便完整双语不是首屏假象。

### Variant A 资格审计工作台

41. 作为资格审计使用者，我希望保留左侧主列表、右侧详情的调查结构，以便选择一个 TransportDemand 后在同一页面理解资格事实。
42. 作为资格审计使用者，我希望桌面宽度下主列表保持约 330 epx 的稳定阅读宽度，并与详情留出 12 epx 间距，以便信息层级与已选原型一致。
43. 作为资格审计使用者，我希望主列表每项都可见标出 Demand 标识、WorkType 和 SUBLOT，以便无表头条目不依赖字段位置。
44. 作为资格审计使用者，我希望主列表以本地化结论为主、规范阻断码为辅，以便快速扫描又能与 Host 契约核对。
45. 作为资格审计使用者，我希望当前选中项有非颜色专属的可见选择状态，以便高对比和色觉差异下仍能定位详情来源。
46. 作为资格审计使用者，我希望主列表底部明确显示当前范围、精确总数和分页动作，以便 `6 / 2,852` 之类的值不会孤立。
47. 作为资格审计使用者，我希望详情顶部首先说明选中 Demand 当前是否外部可读及原因，以便先得到结论再检查证据。
48. 作为资格审计使用者，我希望详情结论同时显示规范阻断码和相关原始字段，以便本地化说明不隐藏技术事实。
49. 作为资格审计使用者，我希望“当前唯一 MES 观测”区域显示 AREA、EQP、STEP、DATES、PACKAGE 和最近观测等可见标签，以便每个值都可解释。
50. 作为资格审计使用者，我希望来源 NULL 在原始值层显示为真实技术事实，并在主层解释为“来源未提供”，以便不被破折号掩盖。
51. 作为资格审计使用者，我希望“当前阻断条件”区域将本地化原因、稳定码和原始字段分层显示，以便原因可读又可检索。
52. 作为资格审计使用者，我希望“外部可读资格”区域逐项显示生命周期、唯一观测和必填字段检查，以便最终结论具有证据链。
53. 作为资格审计使用者，我希望失败检查与通过检查不仅用颜色区分，还使用文字、图标或明确状态，以便可访问。
54. 作为资格审计使用者，我希望“缺值与查询语义”区域解释六种不同状态，并突出当前适用状态，以便不会把 NULL、加载和失败混为一谈。
55. 作为资格审计使用者，我希望选中可读 Demand 时同一结构显示通过结论而不是换成另一套布局，以便比较不同资格状态。
56. 作为资格审计使用者，我希望选中 GONE、Series 已归档或 LongGoneButVisible Demand 时仍保留相同信息层级，以便生命周期与资格状态不混淆。
57. 作为资格审计使用者，我希望重复业务键或 SUBLOT 多 WorkType 等冲突展示全部阻断原因，而不是只保留主要原因，以便资格结论完整。
58. 作为资格审计使用者，我希望主要原因仍按 Host 稳定优先级展示，以便列表排序和摘要不会由 Watch 自行发明。
59. 作为资格审计使用者，我希望从详情进入所属需求系列时保留 SeriesId、DemandId 和来源审计上下文，以便后续 Inspector 调查可追溯。
60. 作为窄窗使用者，我希望 Variant A 在 720 epx 最小宽度下按生产响应式规则重排而不出现水平裁剪，以便固定桌面列宽不会破坏可用性。
61. 作为高 DPI 使用者，我希望 125% 和 150% 下标签、代码、时间、卡片和滚动区域完整可见，以便双语长度变化不会造成截断。
62. 作为 Watch 使用者，我希望英文长文案在同一语义区域换行或重排而不覆盖其他字段，以便 English 与中文拥有同等可用性。
63. 作为 Watch 使用者，我希望评审底栏、A/B/C 切换器、假状态摘要和原型语言按钮不进入生产页面，以便只保留真实功能。
64. 作为 Watch 使用者，我希望 Variant B 的字段账本和 Variant C 的叙事视图不取代已选工作台，以便实现不重新开放设计选择。

### 术语、代码与值语义

65. 作为中文使用者，我希望 UI 采用 `CONTEXT.md` 的规范中文概念，例如“需求系列”“运输需求”和“外部可读资格”，以便不会出现“Demand 世代”等混合复合词。
66. 作为需要对照代码的开发人员，我希望固定属性标签使用当前语言，而稳定标识值保持原样，以便界面一致且仍可直接检索日志和契约。
67. 作为简体中文使用者，我希望产品名、系统名、领域类型、属性名和源字段标签全部使用规范中文，以便界面不出现夹杂的英文固定文字。
68. 作为 Watch 使用者，我希望协议码、错误码、WorkType、配置键和稳定标识逐字保留，以便显示不会改变机器语义。
69. 作为 Watch 使用者，我希望每个已知协议码和错误码同时具有中文与英文说明，以便代码不是唯一可读信息。
70. 作为 Watch 使用者，我希望未知动态码显示本地化“未知代码”说明并附原始码，以便系统不隐藏新契约值。
71. 作为 Watch 使用者，我希望未知码不借用任何已知码的叙事、严重度或处置建议，以便不会生成错误解释。
72. 作为 Watch 使用者，我希望来源未提供与系统未知分别呈现，以便 MES NULL 不被误认为 Watch 不认识代码。
73. 作为 Watch 使用者，我希望不适用与来源未提供分别呈现，以便不参与某工序的字段不会被当作数据质量错误。
74. 作为 Watch 使用者，我希望尚未加载与查询成功但无结果分别呈现，以便等待详情时不会看到“0 条”。
75. 作为 Watch 使用者，我希望读取失败与查询成功但无结果分别呈现，以便网络或 Host 故障不会伪装成空数据。
76. 作为 Watch 使用者，我希望读取失败时明确标出保留的上次成功值及其时点，以便陈旧事实不会被误认为当前事实。
77. 作为 Watch 使用者，我希望空字符串、NULL、零行和未知码在投影层保持不同类型，以便后续页面不会再次把它们压成同一占位符。
78. 作为 Watch 使用者，我希望 Tooltip 只补充完整值或帮助，不承担唯一字段标签，以便关键信息始终可见。
79. 作为 Watch 使用者，我希望多值身份摘要按完整字段换行而不是逐字符截断，以便 DemandId、SUBLOT 和 WorkType 不失去配对关系。
80. 作为 Watch 使用者，我希望必要截断同时提供完整 Tooltip 和复制操作，以便技术事实仍可获得。

### 时间、数量、筛选与复制

81. 作为 Watch 使用者，我希望所有绝对时间显示为 `yyyy-MM-dd HH:mm:ss zzz`，以便时区偏移始终明确。
82. 作为 Watch 使用者，我希望切换语言不会改变同一个绝对时刻或移除偏移，以便中文与英文证据可直接比较。
83. 作为 Watch 使用者，我希望“18 秒前”等相对时间按当前语言变化且只作为次要说明，以便不会取代可审计绝对时间。
84. 作为 Watch 使用者，我希望概览大号数量带有当前语言的单位，以便数值不是孤立指标。
85. 作为 Watch 使用者，我希望概览指标的次要说明交代 AREA 范围、投影提交或 CatalogRevision 等时点，以便统计口径可见。
86. 作为筛选使用者，我希望筛选项显示本地化含义和规范代码，以便既能理解又能精确选择。
87. 作为筛选使用者，我希望应用条件时发送给 Host 的始终是规范代码，以便语言切换不改变查询结果。
88. 作为筛选使用者，我希望保存于当前 ViewState 的始终是规范代码，以便重新投影语言无需重新解析显示文本。
89. 作为复制单元格的使用者，我希望标识、代码、原始值和时间保持可机器对照的格式，以便粘贴到诊断工具后不丢真。
90. 作为复制整行的使用者，我希望说明性列头跟随当前语言，而值和稳定码保持原样，以便复制结果兼顾可读性与准确性。
91. 作为复制原始证据的使用者，我希望原始 JSON 或日志正文不发生本地化，以便证据仍能用于契约调试。
92. 作为 Watch 使用者，我希望数量格式与当前显示语言一致，但 DemandId、版本、哈希和修订号不做文化相关转换，以便格式化边界明确。

### Inspector、通知与无障碍

93. 作为 Inspector 使用者，我希望已知 Demand 形成原因显示本地化含义并保留内部原因码，以便原因可读又可核对。
94. 作为 Inspector 使用者，我希望首次观察、归档前消失后再现和归档后再次出现各自显示原因特定证据，以便本地化不会把不同形成机制压成通用说明。
95. 作为 Inspector 使用者，我希望未知或格式错误的形成原因使用中性本地化回退并保留原始码，以便不会借用其他原因的证据叙事。
96. 作为 Inspector 使用者，我希望切换语言后当前 Demand、原因事实、MES 对比和事件筛选保持不变，以便独立窗口调查连续。
97. 作为通知使用者，我希望 toast 的严重度、标题、说明、动作和关闭名称来自同一双语目录，以便通知与页面术语一致。
98. 作为通知使用者，我希望切换语言不会把持续故障当作新事件重新播报，以便纯呈现变化不会制造重复告警。
99. 作为屏幕阅读器使用者，我希望每个字段值的 Automation Name 包含当前语言的字段语义和必要原始值，以便不依赖视觉位置理解。
100. 作为屏幕阅读器使用者，我希望状态变化的 live region 在当前语言下只播报一次，以便切换和重绘不会形成重复朗读。
101. 作为键盘使用者，我希望语言选择、筛选、列表、详情、复制和 Inspector 动作保持可达且焦点顺序稳定，以便双语重排不破坏操作路径。
102. 作为高对比度使用者，我希望选中、通过、阻断、未知和失败都通过文字或图标表达，以便颜色被系统替换后仍可理解。
103. 作为低视力使用者，我希望中英文在浅色、深色、非活动和高对比状态下保持至少 4.5:1 的文字对比度，以便语义层级可辨认。
104. 作为发布负责人，我希望只有中英文资源、状态保持、UIA 和双语视觉检查全部通过后才发布，以便不会交付部分双语版本。

## Implementation Decisions

### 设计权威与生产边界

- ADR-0031 是完整双语、默认语言、术语、缺值、时间、筛选、复制和发布门禁的语义权威。2026-08-27 选中的 Variant A 是资格审计页面布局与信息层级的设计权威。若原型演示文案与 ADR 或仓库领域词汇表冲突，以 ADR 和领域词汇表为准；不得借此改变 Variant A 的结构。
- Variant A 只决定呈现结构，不改变 ExternalReadabilityAudit、ReadabilityAuditSnapshot、ExternalReadabilityState、ReadabilityBlocker、LeadReadabilityBlocker、AREA 范围、分页、排序或刷新语义。
- 生产代码不得引用 FluentPrototype，也不得复制其假数据、评审底栏、A/B/C 切换、Tag 字符串字典、视觉树遍历本地化或原型专用词汇。Variant B 与 C 只保留为被拒绝的对照证据。
- Inspector 的 Demand 形成原因呈现继续以已验证的 Variant E 原型结构为权威：本地化原因是主层，内部原因码是次要事实，原因特定证据随所选 Demand 更新；本 spec 只补齐其完整双语与未知码契约，不重开 Inspector 布局选择。

### 集中、强类型的双语目录

- 建立一个生产级 `WatchTextCatalog` 概念及其强类型访问接口，覆盖简体中文和英文。调用方引用语义键或强类型格式化方法，不能用任意字符串键查询，也不能在页面内维护字典。
- 每个资源条目必须同时具备简体中文和英文。资源完整性门禁枚举全部强类型键，拒绝缺少任一语言、空字符串、重复语义键或使用键名本身作为发布回退。
- 目录分离“固定 UI 文本”“带参数的格式化文本”“已知领域码说明”“缺值/查询状态说明”和“未知动态码回退”，避免调用方用字符串拼接重建语法。
- 已知状态、生命周期、资格码、阻断码、形成原因、接入关注类型、保护状态、错误类别和操作结果都由集中目录给出当前语言含义；原始码由独立字段保留。
- 生产 XAML 和 C# 不再新增硬编码可见文案。现有可见文案在迁移时全部进入目录或变为不可翻译的明确技术常量；测试数据和原始 Host 内容不属于 UI 资源。

### 运行时语言状态与持久化

- 定义仅包含 `SimplifiedChinese` 与 `English` 的强类型显示语言。它是 Watch 本机呈现状态，不等同于进程业务文化、Host 文化或 Windows 显示语言。
- Watch 应用组合根拥有唯一语言状态，并把同一个可观察状态提供给主工作区窗口、Inspector 协调器、通知协调器、对话框和 presentation 投影。新打开窗口直接继承当前值。
- 语言写入现有按用户保存的显示偏好文档。偏好 schema 升级必须保留刷新间隔、导航开合、主窗口布局和 Inspector 布局；没有语言字段的旧文档迁移为简体中文，而不是整份回退并丢失其它有效值。
- 设置中的选择保存成功后立即提交语言状态。保存失败时保留当前运行时语言并显示当前语言的失败反馈，不能呈现“界面已切换但偏好未保存”的模糊状态。
- 语言提交只触发文本和格式化结果的重新投影，不调用 Host、不更换 ViewState、不重建筛选条件、不改变导航或选择，也不把现有通知重新登记为新事件。
- 使用 `zh-CN` 与 `en-US` 作为 UI 数量和说明性文本的格式文化；标识、代码、原始值、URI、哈希、版本及 Host 查询参数继续使用不变文化或原始字符串。

### 值语义模型

- presentation 层不再用 `—` 同时表示多种事实。引入强类型显示值语义，至少区分：有值、来源未提供、系统未知、不适用、尚未加载、查询成功但无结果、读取失败。
- “来源未提供”只用于成功读取的源字段为 NULL 或明确未提供；“系统未知”用于未知动态码或当前系统无法解释的值；“不适用”用于该字段按工序或状态不参与。
- “尚未加载”只用于请求未开始或详情仍在加载；“查询成功但无结果”只用于成功提交且精确零命中；“读取失败”必须携带失败事实，并在保留旧值时同时携带最后成功时点。
- 空字符串、NULL、零行、取消和失败在 ViewState 到 presentation 的边界保持不同类型。页面模板只负责渲染类型，不根据最终字符串猜测语义。
- 已知动态码显示当前语言含义与原始码；未知动态码显示当前语言的中性回退与原始码，不继承已知码的描述、严重度、下一步或证据模板。
- Tooltip 可以补充帮助和完整被截断值，但可见字段标签、表头、卡片标题或单位必须承担主要语义锚点。

### 全 Watch 文本迁移

- 迁移范围包含标题栏、NavigationView、Host 页脚、概览、需求系列、资格审计、错误检索、AREA 筛选、接入告警、设置、Inspector、InfoBar、toast、ContentDialog、字段校验、空态、加载态、失败态、Tooltip、上下文菜单、复制列头、UI Automation Name/HelpText 和 live region。
- presentation 模块应输出结构化语义、规范码、原始值和可格式化参数，而不是永久保存某种语言的最终句子。窗口根据当前语言投影，确保同一 ViewState 可无数据刷新地切换。
- 简体中文模式中的产品名、系统名、领域类型、属性名和源字段标签全部使用规范中文；English 模式使用对应英文。标识、代码、原始值、JSON、日志和命令保持原样，不创建中英混合复合词。
- 概览数值由卡片标题和单位解释，并显示 AREA 范围、投影提交、CatalogRevision 或数据时点等必要范围。无表头条目和身份摘要使用行内标签；有清晰表头的 DataGrid 不重复每格标签。
- 绝对时间统一通过共享时间显示服务格式化为 `yyyy-MM-dd HH:mm:ss zzz`。相对时间由目录按当前语言格式化，只能作为带绝对时间的次要说明。
- 复制单元格和原始值保持技术事实；复制整行含列头时列头使用当前语言。JSON、日志正文、API 字段、原始证据、配置键和代码不得翻译。

### Inspector 原因呈现

- Inspector 继续显示选中 Demand 的本地化形成原因、原始 TransitionReason、前驱 Demand、生命周期边界、原因特定形成事实、MES 标量差异与相关事件。
- `FIRST_OBSERVED`、`PREARCHIVE_REAPPEARANCE`、`POSTARCHIVE_REAPPEARANCE` 等已知原因分别拥有完整中英文含义和事实模板。原因切换只重投影当前已加载快照，不修改或伪造证据。
- 未知或格式错误原因使用中性“其他/未知形成原因”说明并显示原始码；形成事实只显示真实通用证据，不借用任何已知原因模板。
- 主窗口语言切换事件更新已打开 Inspector 的标题、标签页、原因、事实标签、帮助与 UIA，同时保持窗口位置、当前 Series、当前 Demand、所选标签和事件过滤。

### 可访问性、响应式与 Fluent 规则

- 所有可见状态同时由文字和必要图标表达，颜色只作辅助。Automation Name 与 HelpText 使用当前语言，并包含足以解释值的字段语义；AutomationId 保持稳定，不随语言变化。
- 语言切换不主动抢焦点。原焦点控件仍存在时保留焦点；响应式重排替换控件时落到语义等价控件。Tab 顺序、键盘选择、复制和 Inspector 打开行为保持现有契约。
- 中文和英文都使用 WPF UI 动态主题资源、既有字体回退和 8/12/16/24 间距节奏。不得为英文单独硬编码颜色或另建平行页面。
- 主窗口最低 720 epx 宽；在桌面态复现 Variant A 的列结构，在内容碰撞前切换为可滚动或纵向重排的紧凑结构。125%/150% DPI、浅色、深色、非活动和高对比状态都必须保持标签、代码、按钮和焦点框可见。
- Variant A 的 1440×900 中文和同状态英文截图是本地原型比较基准，不是生产视觉批准。生产必须在同一真实数据语义、同一窗口尺寸和可比选择/滚动状态下重新捕获并由用户审阅。

### 发布门禁

- 可以按模块在开发分支迁移，但不得发布部分双语状态。完成定义是全部生产页面、Inspector、设置、通知、复制说明和无障碍文本同时支持中英文，且不再存在无语义归属的可见值。
- 自动门禁必须验证每个资源键中英文齐全、已知动态码双语齐全、未知码保留原值、六种值语义可区分、绝对时间保留偏移、生产 XAML/C# 没有新增硬编码可见文案。
- 行为门禁必须验证语言切换不改变页面、筛选、选择、页码、滚动位置、Inspector 上下文、通知故障周期或 Host 请求次数。
- 视觉门禁必须分别覆盖简体中文和英文的相同数据状态，至少包含概览、资格审计 Variant A、需求系列与 Inspector、错误检索、AREA 编辑/冲突、接入告警、设置、通知及窄窗状态。

## Testing Decisions

好测试只断言使用者可观察的行为：给定同一个真实 ViewState、Host 假实现、本机偏好和已打开窗口，选择语言后屏幕、复制结果与 UI Automation 显示什么，以及页面、筛选、选择、滚动和调查上下文是否保持。测试不绑定资源文件存储格式、私有字典、具体 binding 类型或内部事件名称，也不通过私有字段证明界面已经翻译。

### 主测试 seam —— 生产应用组合与真实窗口

采用一个最高层主 seam：通过生产应用组合创建真实 `WatchWorkspaceWindow`，注入现有 fake Host client、临时按用户偏好路径和可控时间，驱动真实设置语言选择、导航、筛选、选择、分页、复制、通知和 Inspector。测试从生产控件、ViewState、剪贴板投影和 UI Automation 观察结果，并记录 fake client 的请求以证明切换没有额外读取或条件变化。

同一个 seam 必须覆盖：

- 没有偏好时简体中文启动，保存 English 后重启恢复，旧偏好迁移时保留刷新与窗口布局。
- 主窗口六个页面、Host 页脚、设置、通知、对话框和已打开 Inspector 同步切换，没有混合语言残留。
- 切换前后 ActivePage、所有已提交筛选、页码、选中身份、主/详情滚动位置、焦点、AREA 草稿、Inspector Demand/标签/事件过滤保持一致。
- 切换不增加 Host 请求，不改变规范筛选代码，不创建新通知事件，不重复 live-region 播报。
- 资格审计真实 `READABLE`、`NOT_READABLE`、GONE、Series 归档、LongGoneButVisible、重复业务键和缺字段数据按 Variant A 结构呈现。
- 来源未提供、系统未知、不适用、尚未加载、成功零结果和读取失败分别进入不同可见状态；失败保留旧值时同时显示最后成功时点。
- 已知阻断码和形成原因在两种语言下显示相应含义与相同原始码；未知码使用中性回退且不借用已知叙事。
- 绝对时间在两种语言下保留同一时刻与偏移；相对时间和数量单位切换；标识、代码、JSON 和原始证据逐字不变。

### 资源发布契约检查

资源目录本身增加一个窄的发布契约检查：通过其公开强类型键清单验证每个键都具有中文和英文、格式参数一致、已知码目录完整且未知码回退保留原值。该检查不另建页面测试接口，也不替代真实窗口 seam；它用于捕获只有深层或异常状态才引用的缺失资源。
