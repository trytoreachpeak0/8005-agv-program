# MesIngest.Watch Variant A 独立 Fluent 通知卡片

Status: ready-for-agent

## Problem Statement

`MesIngest.Watch` 当前把加载、空结果、选择清除、持续故障、设置操作结果和 AREA 文件冲突等不同性质的反馈混放在各页 `InfoBar`、内联面板和状态文本中。部分反馈会占据页面布局行，自动刷新或故障状态变化时可能插入、移除或撑高内容，导致操作员正在查看的表格和详情区发生位移；同一持续故障也缺少统一的首次通知、后续收敛、恢复和跨刷新去重语义。

这种呈现还没有形成窗口级生命周期：页面切换时哪些反馈应结束、Host 故障是否跨页保留、窗口最小化期间是否排队、三条以上如何取舍、鼠标与键盘交互时是否暂停倒计时，都由各页自行决定。结果是相同严重度的事件在不同页面可能得到完全不同的视觉重量和可访问性行为。

用户已于 2026-08-26 选择原型 **Variant A — 独立 Fluent toast cards** 作为通知呈现方向。生产窗口需要按该原型的结构和交互层级重写，并接入真实 `MesIngest.Watch` 状态、服务、导航、计时与 UI Automation；原型项目、假数据、场景按钮和变体切换器不得进入生产依赖。

## Solution

在主 `MesIngest.Watch` 工作区窗口建立一个窗口拥有的、非布局参与的通知覆盖层。覆盖层位于内容区域右上方、集成标题栏和页面标题上下文之下，桌面宽度约 380 epx，最多显示三张独立 Fluent 卡片；窄窗时改为带安全边距的顶部单列。卡片按最新活动在前显示，同源事件合并，溢出时按错误、警告、成功/信息的优先级保留更重要事件。

通知只承载短暂且可操作的反馈：用户操作结果、刷新导致的选择清除、新持续故障的首次出现，以及恢复。正常初始加载与自动刷新开始/成功保持静默，只更新固定的进度与新鲜度区域。持续故障在首次 toast 后收敛到受影响页面标题旁的稳定状态，显示最高严重度、当前数量和详情入口；关闭 toast 不得清除该状态。

成功和信息卡片显示 3 秒，警告显示 5 秒，操作失败或新持续故障首次通知显示 8 秒。鼠标悬停或键盘焦点位于通知栈中时暂停倒计时。标准动态约为 180 ms 的透明度加 8–12 epx 垂直位移，Windows 减少动态时移除位移动画。

空结果、未选择、详情结论和字段校验继续在稳定内容区域中呈现，不转成 toast。全 AREA 范围确认与 AREA 并发写入冲突改用真正覆盖内容的 WPF UI `ContentDialog`；冲突未解决时自动保存继续暂停。后台或最小化期间不发送 Windows 系统通知，也不在恢复前台后重播过期的成功或恢复消息。

## User Stories

### 窗口级呈现

1. 作为 Watch 使用者，我希望通知覆盖在页面内容之上而不参与页面测量，以便通知出现或消失时表格、分页和详情区不发生位移。
2. 作为 Watch 使用者，我希望桌面宽度下通知固定出现在内容区域右上方，以便我在任何主页面都能用一致的位置发现反馈。
3. 作为 Watch 使用者，我希望通知位于标题栏和页面标题上下文之下，以便不遮挡窗口拖拽区、标题、Host 状态和标题栏按钮。
4. 作为 Watch 使用者，我希望每条通知是独立卡片，而不是一个不断增长的活动面板，以便每个事件的严重度、动作和关闭行为都清晰独立。
5. 作为 Watch 使用者，我希望通知栈最多同时显示三张卡片，以便它不会长期遮挡主要运营数据。
6. 作为 Watch 使用者，我希望最新发生或最新合并的事件排在最上方，以便最相关的变化最先进入视线。
7. 作为 Watch 使用者，我希望错误和警告在溢出时优先于成功与信息保留，以便低优先级结果不会挤掉仍需处理的问题。
8. 作为 Watch 使用者，我希望每张卡片显示可见严重度文字、Fluent 图标和窄色条，以便状态含义不依赖颜色。
9. 作为 Watch 使用者，我希望卡片包含简短标题、受控长度的说明、可选动作、出现次数和剩余时间，以便无需打开详情就能判断下一步。
10. 作为 Watch 使用者，我希望每张卡片都可以单独关闭，以便我能清理已读反馈而不影响其他事件。
11. 作为 Watch 使用者，我希望没有通知时覆盖层完全不占页面空间，以便页面保持原有布局。
12. 作为 Watch 使用者，我希望生产窗口不出现原型场景按钮、A/B/C 切换器或“当前原型状态”等评审元素，以便界面只保留真实业务功能。

### 触发与静默刷新

13. 作为 Watch 使用者，我希望正常初始加载不弹 toast，以便进入页面时不会被预期行为打扰。
14. 作为 Watch 使用者，我希望自动刷新开始时不弹 toast，以便高频轮询不会形成通知噪声。
15. 作为 Watch 使用者，我希望自动刷新成功时只更新固定的新鲜度和后台轮询状态，以便页面不重排也不反复播报。
16. 作为 Watch 使用者，我希望保存或应用 AREA 配置后收到一条简洁成功通知，以便知道显式操作已完成。
17. 作为 Watch 使用者，我希望应用 Host 设置、保存本机偏好或恢复默认设置后收到对应结果，以便显式操作有明确闭环。
18. 作为 Watch 使用者，我希望查询、排序、分页等本身已经通过结果和新鲜度表达成功的动作保持安静，以便通知只用于没有更稳定结果的必要反馈。
19. 作为 Watch 使用者，我希望用户操作失败时收到包含下一步动作的错误通知，以便可以进入设置、重试或查看详情。
20. 作为 Watch 使用者，我希望刷新清除了我正在查看的选择时收到一次信息通知，以便理解详情为何消失。
21. 作为 Watch 使用者，我希望空结果在数据区域内稳定呈现而不是弹 toast，以便空数据不会被误解成短暂事件。
22. 作为 Watch 使用者，我希望未选择详情、字段校验和只读结论留在各自稳定区域，以便操作上下文始终可见。
23. 作为 Watch 使用者，我希望长异常、凭据、完整 URL 和调用栈不出现在 toast 中，以便敏感或难读信息只通过受控详情查看。
24. 作为 Watch 使用者，我希望同一刷新周期产生的多个等价反馈只形成一个通知，以便渲染和事件订阅不会造成重复。

### 持续故障、合并与恢复

25. 作为 Watch 使用者，我希望一个新持续故障第一次出现时收到一次 toast，以便及时发现新的运营问题。
26. 作为 Watch 使用者，我希望同一活动故障在后续自动刷新中不重复创建 toast，也不重复进行 UIA 播报，以便轮询不会制造告警风暴。
27. 作为 Watch 使用者，我希望同源事件合并到现有卡片并增加“已合并 N 次”，以便知道问题仍在发生而通知栈不膨胀。
28. 作为 Watch 使用者，我希望同源事件再次发生时卡片回到栈顶并延长到该严重度应有的剩余时间，以便最新活动仍然可见。
29. 作为 Watch 使用者，我希望持续故障的稳定状态显示在受影响页面标题旁，以便首条 toast 消失后问题仍可发现。
30. 作为 Watch 使用者，我希望页面标题状态显示最高严重度和当前故障数量，以便一眼判断该页风险。
31. 作为 Watch 使用者，我希望页面标题状态提供可访问的详情动作，以便直接进入对应筛选、证据或设置。
32. 作为 Watch 使用者，我希望关闭持续故障的首次 toast 不会清除页面标题状态，以便“已读”不被误解为“已恢复”。
33. 作为 Watch 使用者，我希望故障真正恢复时稳定状态被清除并出现一条 3 秒恢复通知，以便知道系统状态已经改变。
34. 作为 Watch 使用者，我希望恢复后的同一来源将来形成新的故障事件时可以再次通知一次，以便新的故障周期不会被旧去重记录吞掉。
35. 作为 Watch 使用者，我希望 Host 连接或契约故障继续由导航页脚表示全局状态，并在首次出现时得到一条全局 toast，以便跨页面都能发现。
36. 作为 Watch 使用者，我希望 Host 故障通知的动作进入连接设置或详情，而不是把错误全文塞进卡片，以便能直接处理根因。

### 生命周期与窗口状态

37. 作为 Watch 使用者，我希望离开页面时该页所属的短暂通知立即结束，以便旧页面结果不会污染新页面。
38. 作为 Watch 使用者，我希望全局 Host 故障通知可以跨页面保留，以便导航不会隐藏全局问题。
39. 作为 Watch 使用者，我希望页面切换不会让已经收敛的持续故障丢失，以便返回页面时稳定状态仍反映真实活动故障。
40. 作为 Watch 使用者，我希望窗口最小化或处于后台时不产生 Windows 系统通知，以便 Watch 保持本地只读运营客户端的边界。
41. 作为 Watch 使用者，我希望恢复前台时不重播后台期间已经过期的成功或恢复通知，以便不会把旧结果误认为刚发生。
42. 作为 Watch 使用者，我希望后台期间首次出现且返回时仍活动的故障最多摘要一次，以便重要问题不会完全漏掉又不会成批回放。
43. 作为 Watch 使用者，我希望关闭窗口时通知计时器、事件订阅和动作回调一并释放，以便不会在窗口生命周期结束后继续更新 UI。

### 交互与可访问性

44. 作为键盘使用者，我希望 toast 不主动抢走当前焦点，以便输入、筛选或查看表格时不被打断。
45. 作为键盘使用者，我希望通过正常 Tab 顺序到达通知动作和关闭按钮，以便不使用鼠标也能处理反馈。
46. 作为键盘使用者，我希望每个图标按钮都有稳定自动化名称、工具提示和可见焦点状态，以便动作可发现且可操作。
47. 作为 Watch 使用者，我希望鼠标停在通知栈上时所有可见卡片暂停自动关闭，以便有足够时间阅读和点击。
48. 作为键盘使用者，我希望焦点位于通知栈内时所有可见卡片暂停自动关闭，以便卡片不会在操作过程中消失。
49. 作为 Watch 使用者，我希望离开通知栈后倒计时从剩余时间继续，而不是重新开始，以便生命周期可预测。
50. 作为屏幕阅读器使用者，我希望新通知只礼貌播报一次，以便倒计时变化、重新渲染或故障重复轮询不会重复朗读整张卡片。
51. 作为屏幕阅读器使用者，我希望严重度、标题、说明、合并次数、动作和关闭按钮都有明确语义，以便不依赖视觉布局理解通知。
52. 作为高对比度使用者，我希望卡片仍通过边界、文字和系统语义资源表达分组及严重度，以便自定义颜色被系统替换后仍然可读。
53. 作为低视力使用者，我希望正文和操作文字满足至少 4.5:1 对比度且控件不小于 32×32 epx，以便可辨认和可点击。

### 响应式、主题与动态

54. 作为桌面宽度使用者，我希望通知栈约 380 epx 宽并与页面右侧 24 epx 外边距对齐，以便文字可读且与现有布局节奏一致。
55. 作为窄窗使用者，我希望在布局即将与页面标题或导航冲突时通知改为顶部单列，以便卡片不被裁剪也不覆盖导航栏。
56. 作为最小宽度使用者，我希望单列通知保留紧凑导航后的左侧安全边距和右侧 12 epx 边距，以便 720 epx 窗口仍可操作。
57. 作为高 DPI 使用者，我希望 125% 和 150% 缩放下文字换行、动作、关闭按钮和焦点框完整可见，以便缩放不会造成裁剪。
58. 作为 Watch 使用者，我希望标准动态使用约 180 ms 的淡入/淡出与 8–12 epx 垂直位移，以便状态变化可感知但不拖沓。
59. 作为启用 Windows 减少动态的使用者，我希望通知取消位移与栈移动动画，只保留直接切换或淡入淡出，以便尊重系统偏好。
60. 作为 Watch 使用者，我希望栈内卡片新增、合并、关闭和溢出时平滑重排，以便能跟踪哪张卡发生了变化。
61. 作为浅色、深色或非活动窗口使用者，我希望卡片使用 WPF UI 主题资源而不是原型硬编码颜色，以便视觉与系统主题一致。

### 阻塞选择与稳定状态

62. 作为 Watch 使用者，我希望切换到全 AREA 范围这类需要明确选择的操作使用覆盖式 `ContentDialog`，以便确认不会挤压页面内容。
63. 作为 AREA 配置编辑者，我希望并发写入冲突使用真实 `ContentDialog` 提供“覆盖并保存”“重新载入文件”“稍后处理”，以便选择明确且与普通通知区分。
64. 作为 AREA 配置编辑者，我希望关闭冲突对话框不会丢弃草稿，并让自动保存继续保持暂停，以便冲突不会被静默绕过。
65. 作为 AREA 配置编辑者，我希望解决冲突后自动保存按选择恢复，并通过稳定编辑状态或必要的简洁操作结果确认完成，以便知道冲突生命周期已结束。

## Implementation Decisions

### 原型权威与生产边界

- 2026-08-26 选中的 Variant A 是布局和交互层级的设计权威。生产实现必须复现其窗口层级、卡片结构、尺寸、间距、状态与交互，不能以“符合文字契约”为由重新设计另一种通知表面。
- 生产代码不得引用 FluentPrototype 项目，也不得复制假数据、场景按钮、A/B/C 变体切换、评审底栏或原型专用词汇。Variant B 与 C 仅作为被拒绝对比保留。
- 主工作区窗口是本 spec 的生产宿主。它继续使用一个 `FluentWindow`、一个集成 `TitleBar` 和一个 `NavigationView`；通知覆盖层是该窗口根视觉树的高层 sibling，不插入任一页面的行定义。

### 原型到生产的具体映射

| 原型结构 | 生产映射 |
| --- | --- |
| 窗口根 Grid 中 ZIndex 20 的 `ToastOverlay` | 主工作区窗口拥有的单一通知 host，位于所有主页面之上、`ContentDialog` 之下 |
| 桌面宽 380、右 24、上方约 92 epx | 使用命名尺寸/间距资源对齐真实页面标题上下文；不得用屏幕绝对坐标定位 |
| 窄窗 Stretch、左 60、右 12 | 紧凑导航 48 epx 加 12 epx 安全间距，最低支持 720 epx 窗宽 |
| Variant A 的 4/44/*/40 四列卡片 | 4 epx 严重度轨、44 epx 图标区、弹性正文区、40 epx 关闭区 |
| 1 epx 边框、8 epx 圆角、卡片间 8 epx | 使用生产 Fluent/Watch token 和动态主题资源表达同一几何层级 |
| 严重度+倒计时、标题、说明、动作+次数 | 绑定真实通知项；无动作时不保留空按钮，但其余信息层级不变 |
| Variant A `ItemsControl` | 绑定窗口级最多三项的可观察展示快照，最新活动项在前 |
| 原型 `ContentDialogHost` ZIndex 40 | 生产 WPF UI `ContentDialog` 覆盖通知和页面，阻塞选择期间遵循现有窗口焦点规则 |

### 窗口级通知协调器

- 新增一个窗口级通知协调模块，由 `WatchV2ApplicationComposition` 或主窗口构造过程创建并随窗口释放。主窗口只负责把协调器的展示快照渲染为 Variant A 卡片，不让各页面直接维护各自的 toast 集合。
- 协调器接收语义事件，而不是 WPF 控件或任意字符串。每个事件至少具有稳定来源键、页面或全局作用域、严重度、标题、短说明、可选动作、是否属于持续故障、创建时间和显示期限。
- 稳定来源键由事件类别、作用域和真实业务身份组成，例如 Host 契约、某错误类别或某用户操作；不得把每次轮询时间或随机标识放进来源键，否则无法合并。
- 计时统一使用应用现有可注入 `TimeProvider`，不新增依赖真实 `DispatcherTimer` 的业务状态机。UI 线程调度只负责把已决定的快照应用到控件。
- 协调器保存的是窗口生命周期内的瞬时反馈与“本故障周期是否已通知”状态，不写磁盘、不成为审计日志，也不复制 Host 业务状态。

### 事件分类

| 事件 | 呈现决定 |
| --- | --- |
| 初始加载、自动刷新开始、自动刷新成功 | 不创建 toast；更新固定进度/新鲜度 |
| 用户显式保存、应用、恢复默认设置成功 | 3 秒成功 toast；若结果已由稳定内容完整表达，可保持静默 |
| 用户显式操作失败 | 8 秒错误 toast，必要时包含详情或设置动作 |
| 查询、排序、分页成功 | 默认由数据结果和新鲜度表达，不生成“已应用查询”布局行 |
| 刷新使当前选择消失 | 一次 3 秒信息 toast，同时稳定详情区进入未选择状态 |
| 新持续故障首次出现 | 一次 8 秒 toast，同时更新页面标题稳定故障状态 |
| 同一持续故障继续存在 | 不创建、不重播；仅更新稳定状态和必要的合并次数 |
| 持续故障恢复 | 清除稳定状态并显示一次 3 秒恢复 toast |
| 空结果、无选择、详情结论、字段校验 | 留在稳定内容区域，不进入通知协调器 |
| 全 AREA 范围确认、AREA 并发写冲突 | 使用 `ContentDialog`，不使用 toast 代替用户选择 |

### 合并、排序与溢出

- 同一来源已有卡片时不新增第四张卡，而是增加出现次数、更新文案到最新真实状态、把剩余时间提升到“当前剩余时间”和该严重度默认时长中的较大值，并移到栈顶。
- 展示顺序按最近创建或最近合并的活动时间倒序。最多展示三项。
- 第四项到来时，先比较严重度保留优先级：错误高于警告，警告高于成功与信息；同一优先级丢弃最旧项。低优先级新项可能在加入后立即被丢弃。
- 被丢弃或手动关闭的错误/警告卡片不得清除对应稳定故障状态。没有稳定状态承接的用户操作失败在被溢出前应优先于成功/信息保留。
- 不建立隐藏的无限通知队列。过期或被溢出的低优先级结果不在后续重播。

### 持续故障与页面标题状态

- 真实工作区状态与刷新提交结果是持续故障的权威来源；通知协调器只比较故障身份的新增、持续和恢复，不推断业务状态。
- 每个受影响主页面提供一个与页标题同一布局行的稳定故障区域。没有故障时该区域不创建额外页面行；有故障时显示最高严重度图标、严重度文字、当前数量和详情动作。
- 已经具备标题状态 pill 的页面复用该视觉模式；其他页面补齐同级结构，而不是保留会开合的故障 `InfoBar` 行。
- Host 连接与契约状态继续由 `NavigationView` 页脚作为全局稳定状态。首次全局故障可产生 toast，动作进入设置；切页不得清除该全局故障周期。
- 故障从活动变为恢复时清除其“本周期已通知”记录。之后同一来源再次进入活动态属于新故障周期，可以再次通知一次。

### 页面与窗口生命周期

- 主窗口导航完成时，协调器移除离开页面的所有页面级 toast；全局 toast 和真实持续故障状态不受影响。
- 页面级事件不得在其页面不可见时排队等待用户返回。用户返回页面时根据当前稳定状态呈现故障摘要，不重播旧成功或恢复。
- 窗口最小化或非前台期间禁止桥接 Windows Notification、任务栏 toast 或系统通知。成功、信息和恢复事件到期后直接消失。
- 后台首次出现且返回前台时仍活动的故障可生成一次当前摘要；已经恢复的故障不回放。该摘要仍使用同一来源键，避免激活窗口多次时重复。
- 主窗口关闭时取消计时、动作和事件订阅；已经排队到 Dispatcher 的渲染回调必须在检查窗口已释放后退出。

### 卡片交互与内容约束

- 每张卡片使用严重度文字、Fluent `SymbolIcon`、语义状态画刷和 4 epx 状态轨；错误、警告、成功、信息不得只靠颜色区分。
- 关闭按钮为至少 32×32 epx 的透明 Fluent 按钮，带“关闭通知”工具提示、稳定 UIA 名称和可见焦点。关闭只移除该卡片。
- 可选动作使用透明或次要外观，不使用表示持续选中的 accent fill。动作由真实导航或命令服务提供，执行后按该操作结果决定关闭、更新或保留卡片。
- 标题与说明必须是面向操作员的简短中文；生产标识、告警码和 schema 名按真实形式保留。异常全文、凭据、完整 URL 和 stack trace 只进入已有详情表面或受控日志。
- 倒计时向上取整显示剩余秒数，但其每秒变化不得触发整个卡片的 live-region 重播。出现次数只在合并后显示“已合并 N 次”，首次显示“首次出现”。

### 计时、焦点、UIA 与动态

- 成功、信息和恢复默认 3 秒；警告 5 秒；用户操作失败和持续故障首次通知 8 秒。
- 鼠标进入整个通知 host 或键盘焦点进入任一卡片时暂停所有可见卡片的倒计时；鼠标和焦点都离开后从剩余时间继续。
- 新卡片不得调用 `Focus`，不得改变当前表格、编辑器或页面命令焦点。通知动作和关闭按钮仍进入正常 Tab 顺序。
- 新事件只通过一个 `Polite` live region 播报一次。合并、倒计时、主题切换和同一故障的刷新渲染不得再次播报；恢复属于新的语义事件，可单独播报。
- 标准动态使用约 180 ms 的透明度和 8–12 epx 垂直位移；新增、移除和栈变动平滑过渡。Windows 减少动态为权威设置，开启时移除位移和栈移动，仅允许直接切换或透明度变化。

### 响应式、主题与对话框

- 桌面态使用约 380 epx 宽度、右侧 24 epx 页面外边距。窄态触发点以真实内容碰撞为准，并必须覆盖原型的 760×820 状态和产品 720 epx 最小宽度；窄态左侧安全间距为紧凑导航宽度加 12 epx，右侧 12 epx。
- 所有尺寸、圆角、状态色、背景、边框和文字使用生产 token 或 WPF UI 动态主题资源。原型中的静态画刷名只能作为语义参考，不能直接成为生产依赖。
- `ContentDialog` 的层级高于通知 host。打开对话框时页面兄弟内容被正确禁用，焦点进入对话框；关闭后按既有规则恢复到调用按钮或合理的后续控件。
- AREA 并发写冲突保留既有业务语义：覆盖并保存或重新载入会解除暂停；稍后处理保留草稿并继续暂停自动保存。此次只改变为真实覆盖式对话框，不重写指纹、冲突检测或快照语义。
- 全 AREA 范围确认由内联确认面板迁移到 `ContentDialog`，确认与取消仍调用既有查询语义；取消不得改变当前查询或选择。

### 既有 `InfoBar` 的迁移原则

- 不按控件类型批量删除 `InfoBar`。先按外部行为分类：稳定空态、未选择、详情结论、字段验证和目录监视降级可继续使用稳定内容表面；短暂用户操作结果迁移到 toast；持续故障迁移到页标题状态；阻塞选择迁移到 `ContentDialog`。
- 迁移后，正常自动刷新不得再使任何 `Auto` 高度状态行开合。保留的稳定 `InfoBar` 必须属于内容本身，而不是轮询反馈。
- 现有 presentation 模块继续负责真实页面文案和严重度；窗口级协调器消费其语义结果，不复制查询、Host 或 AREA 业务判断。

## Testing Decisions

好测试只断言使用者可观察的行为：给定真实窗口状态、语义事件、时间推进、导航和窗口激活状态，屏幕上出现哪些卡片、稳定故障状态与对话框，以及 UIA 对外暴露什么。测试不绑定内部集合类型、计时实现、动画对象名称或私有去重容器。

### 主测试 seam —— 生产工作区窗口

采用一个最高层主 seam：构造真实 `WatchWorkspaceWindow`，注入现有 fake Host client 与可控 `TimeProvider`，通过真实页面命令、刷新提交、导航和窗口状态驱动反馈，然后检查生产通知 host、页面标题状态、`ContentDialog` 和 UI Automation。通知协调器可以是独立内部模块，但默认不为其建立第二套与窗口行为重复的测试接口。

必须覆盖：

- 初始加载及自动刷新开始/成功完全静默，固定新鲜度更新且页面测量不变。
- 用户操作成功、警告、失败与恢复使用 3/5/8 秒规则；时间由 fake clock 推进，测试中不得真实等待。
- 同源事件合并、次数更新、回到栈顶、期限延长、最多三条、严重度优先和同级最旧淘汰。
- 新持续故障只播报一次，重复刷新不新增、不重播；关闭卡片不清除标题状态；恢复清除状态；新故障周期可再次通知。
- 页面级 toast 在导航时结束，全局 Host 故障跨页保留；返回页面不回放旧成功或恢复。
- 刷新清除选择时出现一次信息 toast，同时详情区进入稳定未选择状态且不自动选择另一项。
- 最小化/后台无系统通知、无旧成功/恢复回放；仍活动故障返回前台最多摘要一次。
- 鼠标和键盘焦点暂停计时，全部离开后继续；卡片不抢焦点，动作与关闭可通过键盘到达。
- `Polite` UIA 只对新语义事件触发一次；倒计时、合并重绘和自动刷新不重复朗读。
- 桌面与窄态的 host 对齐、宽度、安全边距、Z 顺序和不遮挡标题栏/导航；减少动态时没有位移。
- 全 AREA 范围确认和 AREA 写冲突使用真实 `ContentDialog`；未解决冲突保持自动保存暂停并保留草稿。
- 高对比、浅色、深色和非活动状态不依赖颜色表达严重度，32×32 控件目标和焦点视觉保持完整。
