# 受控工厂试运行交接清单

这是未来执行时使用的清单，不代表其中任何一项当前已经完成。

## P0 — 冻结候选与责任

- [ ] 不可修改的 FactoryPilotConfigurationSnapshot 绑定精确 ControlServer／OnboardHmi commit 与制品哈希、复合 ProtocolReleaseIdentity、两个 FakePeerIdentity、runner／向量身份及 G0～G3 证据。
- [ ] 绑定部署／环境、MesIngest 只读契约／HistoryEpoch、RIoT API／环境／车辆绑定、精确 Map 及不同的取货／关卡站点、路线证据、八仓配置指纹和电量阈值。
- [ ] 绑定目标硬件分辨率／缩放／触摸／扫码枪／键盘、时间／证据存储、保留能力、真实物料适用性和不含秘密的凭证引用。
- [ ] 为每项权威取得具名人员的真实确认。AI、占位符和口头集体同意均无效。

## P1 — 离线与跨仓库门禁

- [ ] 精确且获得真实批准的 release 通过 G0 和 G1。
- [ ] 两个仓库分别通过 G2，包括真实组件＋本仓 Fake，以及作为被测对象的 Fake。
- [ ] 精确真实构建在 W2G-IS-00～07 上通过 G3；不存在未关闭的 FAIL／INCONCLUSIVE。

## P2 — 静态环境与只读检查

- [ ] 只读检查 MesIngest 契约、容量、凭证和 HistoryEpoch；不得写 MES，也不得伪造生产 Demand。
- [ ] 只读检查 RIoT build／API、绑定、Map／站点、RouteCost 和未结订单；不得通过下发车辆命令来证明静态事实。
- [ ] 检查八仓、管理员、日志保留、时间和证据存储。

## P3 — 目标硬件与维护资格

- [ ] A 方案“旅程导引台”的生产映射已经由真实车载端开发者评审。
- [ ] 所有 UI 状态均无裁切／重叠；安全、断联／readiness、UNKNOWN、当前引导和急停信息无需危险滚动即可看见。
- [ ] 已测试触摸目标／动作及相邻禁用动作；正常主动作保持唯一，急停在视觉和空间上明显分离。
- [ ] 扫码结束符／焦点／连续输入／非法输入和键盘备用入口均恰好产生一次提交。
- [ ] 在记录下来的代表性距离与光照条件下通过可读性检查。
- [ ] 在停车并完成物理隔离的条件下，完成全部八仓 IO／锁／光幕／输出语义和可检测物料约束的资格确认。

## P4 — 空车、不开仓彩排

- [ ] 隔离的目标 HMI harness 重放旅程、断联、UNKNOWN 和恢复状态。
- [ ] 使用已批准的 RIoT 调试方法，验证精确空车路线、站点、IDLE 和停车证据。
- [ ] 不打开仓门、不注入虚构 MesIngest 事实，也不使用未经批准的直接车辆控制。

## P5 — 即时继续／停止判断

- [ ] 在声明的短时间窗口内重新验证每个快照新鲜度／身份字段。
- [ ] 选择一个真实、完整的 WIRE_TO_GATE 候选，且不存在活动／已抑制／已完成重复项。
- [ ] 证明 ExpectedBasketCount 为 1～8、适用仓位容量充足、人员和物料已就绪。
- [ ] 只有全部门禁通过后，用户才能授权开始；该授权不能覆盖安全门禁。

## P6 — 一次受控真实物料旅程

- [ ] 以空车开始；全部仓位均为 EMPTY／锁闭／输出复位；没有未结订单；连接已恢复且 VehicleBusinessReadiness 成立。
- [ ] 恰好执行一次最终重读与受理；依次完成 `TO_PICKUP` 和可信取货到站。
- [ ] 只扫描一次，完成被冻结的完整多仓装货并通过新鲜发车检查。
- [ ] 依次完成 `TO_GATE`、可信关卡到站和自动完整卸货。
- [ ] 原子提交本地完成；不等待、不读取也不写入 PDA／MES。

## P7 — 对账、清场与封存证据

- [ ] 全部仓位为空／锁闭／输出复位；Guard 和操作均已结清；两段 RIoT 移动及调用各有一个可解释结果。
- [ ] 恰好一个本地成功和 TransportDemandCompletion；车辆状态可完整解释。
- [ ] 在新的 FactoryPilotRunIdentity 下生成完整的 `run-manifest.json`、`timeline.ndjson`、`assertions.json`、带哈希的 `artifacts/` 和 `cleanup.json`。
- [ ] 已解决试运行决策中的十项不变量全部通过，包括 UI／输入可用性、可追踪性和零禁止副作用。

## 停止与清场规则

任何 FAIL／INCONCLUSIVE 都必须停止后续阶段。必须阻止新 Demand、下一段移动和尚未发送的开锁组；保留全部原始身份／绑定；保持或停车并证明车辆状态；SafelyFinishActiveUnlockSet 不得扩张；对账未知结果；只允许四条已批准的恢复路径。只有人员、货物、订单、Guard、逐仓物理／业务事实、输出及车辆隔离／readiness 全部明确后，才能关闭清场。红色运行证据永久保留；任何修改都必须创建新的 snapshot／runId，并从最早受影响阶段重新开始。

一次 PASS 只适用于该精确候选和配置，不构成 release 批准。
