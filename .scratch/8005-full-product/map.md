# 8005 完整产品实施范围与顺序路线图

## Destination

形成一份经用户批准的《8005 完整产品实施范围与顺序规格》，覆盖 `requirements/baselines/current-requirements-v1.0.0.md` 全部 348 条需求，逐条给出实施批次归属与批次间依赖，并固定全量切片家族编号、协议 v2 的冻结面与完整产品的验收边界与证据要求。本图只产决策，不产代码。

## Notes

- **只做决策，不产代码。**批次 1 及其后的实施属于随后的实施图，不属于本图。本图不写代码、不改 v1.0.0 基线、不动 `requirements/current-baseline.md` 指针、不替 Kun Wang 决定车载端实现、不代签任何 protocol release。
- **批准人是用户一人。**范围与顺序、切片家族、协议 v2 冻结面与验收边界全部由用户单独批准。协议 v2 相关票据落定并推送后按 `8005-agv-protocol` 的 notify-after-change 规则开 issue @`SocialKKKK` 通知，通知不是前置门禁，本图不因等待对方评审而挂起。MVP 那张图留下的「车载端开发同事未评审、未批准」在本图同样成立，须在规格中如实记录，不得表述为已获双方同意。
- **零遗漏口径是全部 348 条。**最终规格必须对 348 条逐条给出一行，MVP 已覆盖的 186 条（直接必须 85 + 交互／安全依赖 101）标注为批次 0 并指向 MVP 剖面证据，真正新排期的是 162 条。不允许「只排非 MVP 部分」的口径。
- **MVP 是软前置。**本图假定 WIRE_TO_GATE MVP 会通过现场验收，批次 0 直接引用已批准的 MVP 规格；MVP 的收尾、P0～P7 试运行进度与 `8005-agv-control-server/docs/defects/` 当前 5 个未闭合缺陷不进入本图票据，也不构成本图票据的阻塞。
- **MesIngest 的 100 条不在本图。**见 Out of scope。本图只在最终规格中保留一行指针，不核对、不重排、不为其分配批次。
- **用户倾向不做运行期权限管理（2026-09-03）。**这是 standing preference，不是已定决议——最终由票 05 落定。三点事实约束它：其一，权限**骨架已在批次 0**，不归本图排期（`REQ-0250` 三种访问身份、`REQ-0251`／`REQ-0336` 两级管理员、`REQ-0252` 一人一号单会话、`REQ-0253` 异常处置权限随角色授予、`REQ-0255` 管理员操作不可改写审计、`REQ-0276` 基础密码格式、`REQ-0278`／`REQ-0279` 会话不超时、`REQ-0226`／`REQ-0235` 维护开门与故障处置身份验证），本图不得重开这些。其二，本图实际可调的权限条目只有 10 条：`REQ-0236`、`REQ-0254`、`REQ-0311`、`REQ-0256`、`REQ-0273`、`REQ-0274`、`REQ-0275`、`REQ-0277`、`REQ-0280`、`REQ-0339`；砍掉它们等于账号与密码继续靠部署时预置配置管理，运行期改不了。其三，其中两条有跨簇耦合，不得单独砍：`REQ-0311`（恢复权限只属系统管理员）是 AGV 归档恢复的安全前提，`REQ-0339`（敏感生效动作要求新鲜二次认证）是配置激活与回滚（`REQ-0266`／`REQ-0346`）的安全前提——留其一砍其二会造成有审计无二次确认。票 05 须连同这两簇的去留一并判，不得只看权限一簇。
- **「不做」在本图只有两种合法形态：延后，或本图范围外。**v1.0.0 的 348 条 Lifecycle 全部 `active`，本图不改基线，因此任何范围收窄都不得表述为需求作废或废弃。票 09 负责区分二者，票 10 负责在规格中如实表述。
- **顺序粒度到批次与切片编号，不到逐切片证据清单。**本图产出 N 个实施批次、批次间依赖，以及全量切片家族的编号体系与它同 `W2G-IS-00`～`07` 的关系（沿用／替换／并存）。逐切片的验收证据清单属于实施图。
- **重构类与增量类不混排。**单车→多车并发、人工充电→充电桩调度、单 Map→跨地图要重做 ControlServer 的选择与分配核心，属重构；账号／配置／报表治理面属增量。两类归属与排序规则由票 02 判定，后续票据在该规则内工作，不各自重做一次判断。
- **协议 v2 一次冻结。**消息面、错误码、交付类别、测试向量范围与同 v1 的版本关系在票 06 一并定完。逐条加需求逐次发 release 会反复作废两端 G2 证据，本图不接受分批冻结。
- **现场物理前提已具备。**第二台 AGV 与已登记的 8005 项目独占充电桩现场都有，因此多车调度与自动充电两簇可以排进带现场验收出口条件的批次，不必降级为「仅双 Fake 联调」。注意 `remote-ops/onboard-hmi/config/` 目前只有 `agv01` 的现场配置，新增车辆的现场值填写属实施图。
- **日历约束：用户要求一周内完成「规格 + 批次 1 落地」。**本图目标在 2～3 天内走完全部票据，把余下日历留给实施图。顺序按依赖与风险排，不按日历倒推；宁可单票更重，不要更多轮次。
- 跨端决策须遵守 `8005-agv-program/CONTEXT.md` 与 `docs/adr/cross/` 中已接受的权威边界，特别是 NDJSON ProtocolEnvelope、精确 ProtocolVersion、消息交付类别、RecoveryHandshake、车载 IO 独占权威、服务端任务/仓位集决策权与车载物理执行权，以及 ADR-0056 的 .NET 工具链基线。
- `8005-agv-onboard-hmi` 与 `slots-simulator` 对 agent 只读：可读、可开 issue 与 PR，不得改内容。本图不受此限，因为它不产代码。
- 需要产品判断或最终批准的票据使用 `grilling` 与 `domain-modeling`；任何新领域词一旦定案立即写回 `8005-agv-program/CONTEXT.md`。
- **本图的全部工作在 worktree 内进行（2026-09-03 用户指示）。**分支 `wayfinder/8005-full-product`，路径 `8005-agv-program/.claude/worktrees/full-product-map`，基于 `main` 的 `10ac49b4`。后续会话先切进去再动手，不在 `main` 的工作树上改地图产物或证据。该目录已进 `8005-agv-program/.gitignore`，`main` 侧看不到它。
