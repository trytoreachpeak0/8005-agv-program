三点解读：

1. **18 张里绝大多数不属于 8005。**`华士老厂`／`华士新厂`／`尊阳电镀线`／`新潮尊阳测试`
   是别的厂区或项目。RIoT 是多项目共用平台，地图总数不等于 8005 的作业面。
2. **平台上确实存在真正的多图部署形态。**`华士新厂南侧1楼电梯`（floor 1）、
   `华士新厂南侧2楼电梯`（floor 2）、`二楼连廊`（floor 2）是电梯 + 连廊跨楼层的组合，
   这正是「一端在 A 图、另一端在 B 图」的典型拓扑。**它属于别人的现场**，但证明能力上
   RIoT 支持这种布置。
3. **同一物理区域重新测绘会产生新 mapId。**`尊阳电镀线`(6)/`尊阳电镀线opt`(14)、
   `新基测试2`(27)/`新基测试2opt`(28)、`ZY_WB_Map`(19)/`ZY_WB_MapF`(25) 三对都是同区域
   的不同版本。这是**换图迁移**，与跨图运输是两件事，`REQ-0341` 已经规定了它的行为
   （换 mapId 则原绑定立即失效，禁止按名称自动重绑），且属批次 0。

## 事实 2：8005 的产品配置钉在单张地图 mapId 25

来源：`8005-agv-control-server/src/ControlServer.Host/appsettings.json:51`

```json
"mapId": 25,
"mapIdentity": "老厂前线new",
"gateStationId": "关卡",
"gateStationRiotId": 210,
"dispatchZone": "MAP-25-WIRE_TO_GATE",
"allowedDispatchZones": ["MAP-25-WIRE_TO_GATE"]
```

`mapId` 是标量不是数组，`dispatchZone` 的命名本身把 25 编了进去。2026-07-20 的 RIoT 快照
里 mapId 25 名为 `ZY_WB_MapF`，配置里的业务名是 `老厂前线new`——同一张图的两个名字，
或期间改过名。

## 事实 3：mapId 25 有 206 个站，恰好是 205 机台 + 1 关卡

来源：`8005-agv-control-server/evidence/g3/20260827-map25-dynamic-gates-refresh/result.json`
与 `evidence/g3/20260827-local-upgrade-readonly-preflight/readonly-preflight-result.json`，
两份数值一致（全仓证据中该组计数出现 3 次，无第二个取值）：

```json
"map25": {
  "mapId": 25,
  "stationCount": 206,
  "areaNamedMachineStationCount": 205,
  "exactGateBinding": true,
  "nScopedAreaCount": 11,
  "uniqueAreaEqpCount": 11,
  "conflictingAreaEqpCount": 0

```

`205 + 1 = 206`。**按 AREA 命名解析出的机台站加上关卡，正好占满整张图，没有给充电桩、
等待点或暂存位留下位置。**这是从计数推出的，不是直接观测到充电桩缺席，须向用户确认；
但方向很清楚：截至 2026-08-27，mapId 25 上看不到充电桩站点。

## 事实 4：充电簇把桩的身份绑到「地图 + 站点」，却没有一条要求桩与车同图

`REQ-0171` 规定「8005 独占充电桩名册」以 RIoT **地图 + 站点**标识固定身份；
`REQ-0170` 的候选链是「该车允许集合 → 排除失败与暂停 → 保留 **RIoT 当前地图**中身份有效、
状态可确认且空闲的站点」。这里的「RIoT 当前地图」按 `BR-007` 的措辞是**当前目录快照**，
不是「车辆所在的那张图」。`REQ-0178`／`REQ-0179`／`REQ-0180` 的「地图等待点集合」同样
只说地图，不说是哪张。

对比之下，运输侧的三条把边界钉死了：`REQ-0191`（DispatchZone 单图）、`REQ-0192`（车辆
必须实际位于任务所属 Map 才进候选）、`REQ-0193`（固定站点不得跨图，禁止跨 Map 运输）。

**结论：跨图约束只覆盖运输，不覆盖充电与等待点。**若充电桩被测绘进另一张图，候选链不会
拒绝它，会下发一条 RIoT 执行不了的移动。这是票 11 原文没有问到的缺口。

## 事实 5：三个不同概念一直被「跨地图」一个词裹着

| 概念 | 含义 | 基线现状 |
| --- | --- | --- |
| **跨 Map 运输** | 搬运任务两端落在不同 Map | `REQ-0193` 明文禁止 |
| **车辆跨图移动** | 车辆物理上从 A 图开到 B 图（电梯、连廊） | 基线未规定；`REQ-0192` 只管派车候选 |
| **换图迁移** | 同一物理区域重测绘 → 新 mapId | `REQ-0341` 已规定，属批次 0 |

precontext 与票 02 说的「单 Map→跨地图」是第一项。第二项是充电与等待点的真实风险面。
第三项已解决，不该再算作重构。
