# 决定自动充电桩调度与充电失败治理的范围

Type: grilling
Status: open
Blocked by: 02

## Question

在票 02 定下的分类与排序规则内，决定完整产品把自动充电从 MVP 的「人工充电保持」推进到什么程度，以及充电失败治理面做到哪一档。

MVP 的边界是：低电量只进入具名管理员重新投运的人工充电保持，不建自动充电、不建充电排队、不做备用桩改派。完整产品要拆掉这个边界，涉及的条目至少包括 `REQ-0170`～`REQ-0180`（`ChargeHangReassign` 与普通待充共用候选链、独占资格由受控名册授予、充电失败车辆不取得独立优先级、成功预占后不可抢占、「已确认充不上」的严格系统事实、一般充电异常不得误触发暂停、系统事实不完整时只有 R-11 可补充现场确认、确认后以不可变幂等事件暂停该桩、清桩闭环、清桩的两种完成证明、人工清桩不自动恢复或阻断车辆）与 `REQ-0283`～`REQ-0288`（充电建单不建专属重试制度、原桩追加重试为 0、已确认中断与无进展的双向临时隔离、中断结果与根因归属分离、车辆失联按观测来源分开、待维修充电桩用分配暂停而非删除身份）。

本簇 `FP-C1` 共 **17 条**。其中 `REQ-0287` 与 `REQ-0288` 是票 01 从治理面移入的——两条的标题字面像车辆观测与车辆维修，正文却都在充电语境内：`REQ-0287` 规定 `ChargingRIoTVehicleObservationLoss` 保持原桩预占且不盲发停止／重启／移动命令，`REQ-0288` 规定用 `ChargingStationAllocationHold` 让待维修**充电桩**退出运行时候选、同时保留 `ProjectExclusiveChargingStationRegistry` 中的稳定身份。理由见 [票 01 决议](01-answer.md)。本票须一并决定这两条的范围，不得当作票 05 的治理条目略过。

现场物理前提已具备：第二台 AGV 与已登记的 8005 项目独占充电桩都有，因此本簇可以排进带现场验收出口条件的批次。

须回答：

1. 自动充电周期的完整边界：从 `MandatoryChargeEntryThreshold` 触发、待充电排队、选桩、`ChargingStationExclusiveReservation` 原子预占、RIoT 建单、物理充电、`ChargingCompletionThreshold` 到离桩与释放预占，哪些环节在完整产品里全量实现，哪些仍保留人工介入。特别是达到完成电量本身不证明订单收敛、不证明离桩、不足以释放预占这一约束怎么落到实现要求上。
2. 待充电排队与普通搬运派车的关系：充电改派车辆与普通待充车辆进入同一排队集合并按当前电量排序、「刚发生充电失败」不产生独立优先级——这条规则同票 03 的 Demand 选择顺序共享同一分配核心吗，还是两套独立的选择器？若共享，两者的排序键如何合并；若独立，抢占同一台车时谁优先。
3. 充电失败的判定与清桩闭环：`ConfirmedChargingInterruption` 的严格系统事实构成、`ChargingObservationUnknown` 期间保持预占且不盲发命令、确认后暂停该桩全部新分配、清桩的两种完成证明、人工清桩不自动恢复车辆——这一整套在完整产品里是一次做完，还是可以拆出一个更小的可验收子集。
4. 备用桩改派（`ChargeHangReassign`）：改派前须 CANCEL 旧 HANG、候选先排除刚失败站点再按 RIoT 当前地图过滤、任一资格状态未知即 fail-closed 排除——这一档进本期还是延后。若进，与票 03 的多车分配核心的耦合点在哪。
5. `ProjectExclusiveChargingStationRegistry` 的落地形态：名册的登记、批准与变更记录需要配置 UI 吗，还是像 MVP 那样接受受控预置配置？若需要 UI，它属票 05 的治理面增量还是本票。
6. `REQ-0175`（一般充电异常不得误触发暂停）与 `REQ-0176`（系统事实不完整时只有 R-11 可补充现场确认）对现场角色与权限的要求，同票 05 的账号权限治理面的交接点在哪。

### 已知边界

- 本票不改协议消息面，充电带来的消息面变化由票 06 一次冻结；本票只输出「哪些充电业务能力必须由协议承载」。
- 本票不决定批次归属与顺序，那是票 09。
- 本票不决定车载端实现方式；车载端归 Kun Wang，仓库只读。
- 电量策略的具体数值（`MandatoryChargeEntryThreshold`、`ChargingCompletionThreshold`、任务后余量）是投运前须以现场证据批准的现场配置，需求基线不写死数值。本票只决定能力范围与批准流程归属，不定数值。
