# 18 — 轨 B 出口证据：合成 3 车 L2，CI 三连绿

**做什么：** 把批次 2 轨 B 的四条能力放到 L2 上一起跑，产出出口证据。这是**轨 B 的出口**，
规格 8.3 逐字要求的四项都要有证据。

四项出口（规格 8.3 批次 2 轨 B 行）：

1. **L1 ＋ 合成 3 车 L2 绿**——新场景在 CI 上**连续三次通过**。三连跑的纪律沿用黄金渲染机
   的既定标准：L2 涉及跨进程时序，一次通过区分不了「正确」与「这次恰好排上了」。
2. **RIoT 白名单架构测试绿**（票 08）。
3. **引擎快照双周期刷新与陈旧态 fail-closed 有 L2 证据**——三种陈旧触发各取一次证据。
4. **命令面在 L2 上证明「该调用时调用了、参数正确、只调一次」**——三条断言，缺一不可。
   「只调一次」尤其重要：急停重试与对账很容易变成重复发令。

证据形状沿用既有 L2：`SUMMARY.md` ＋ `assertions.json` ＋ `timeline.jsonl` ＋ `logs/`
＋ `snapshots/`，落在 `evidence/l2/<日期>-<场景>-<序号>/`。

**`assertions.json` 的 `identity` 块在完整产品下加两项**（规格 8.4）：
`protocolReleaseIdentity`（v2 三元组）与 `batchId`。前者使 L2 证据能像 G2 一样按协议换代
作废，后者使证据能回答「这是哪个批次的出口证据」。**本票是这两项的落地点。**

四条证据纪律照旧：`-EvidenceRoot` 必须是不存在的目录；**红的证据不允许被绿的重跑覆盖**；
跑失败时 stage root 不删；**证据目录只增不改**。
