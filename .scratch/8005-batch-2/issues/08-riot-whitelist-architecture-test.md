# 08 — RIoT 白名单架构测试

**做什么：** 给 RIoT 调用白名单装上第一道机器守卫。当前白名单是纯文档——编译期、运行期、
测试期三处都没有守卫，任何人加一个 `.Raw` 调用都不会有人发现。这张票让 CI 上一条测试
持续证明两件事：

1. **`src/` 下 `.Raw` 零命中**——产品代码不得绕过具名 Facade。
2. **实际调用集合 ⊆ 获批清单**——服务端调用的 RIoT 端点，每一个都在白名单文档里。

**不挂任何簇，也不挂 `FP-C4`。** 规格第 3.3 节第 8 项明确要求：挂上去的话，`FP-C4` 一延后，
整个 RIoT 调用面的守卫跟着延后。它是横切守卫，独立存在。

清单来源是票 02 产出的产品文档，不是 scratch 票据。清单更新时测试跟着更新，两者的
一致性是这条测试的主要维护成本，接受它。

**前置：** 票 02（白名单成为产品文档，测试才有可引的清单来源）。
