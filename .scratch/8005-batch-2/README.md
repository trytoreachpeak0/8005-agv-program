## 冲突边界（并行前提，不可违反）

| 文件／区域 | 独占者 | 其余票的约束 |
| --- | --- | --- |
| 派车主循环（候选发现与准入段） | **票 05** | 只加判据文件 ＋ 注册表一行，不重构 |
| `ControlServerDbContext`、Migrations | **票 06** | 零 migration |
| `Ports.cs` | **票 06** | 票 05 的新接口放独立新文件 |
| `tools/` 合成装置 | **票 03** | 不动 `src/`、`tests/` 产品代码 |
| `riot-sdk` | **票 07** | 服务端只消费，不改 SDK |

**两个 prefactor（票 05、票 06）存在的唯一理由是消除并行冲突。** 实测热点：EF 模型快照是
单文件，两条能力轨各加一个 migration 必然冲突；派车引擎的候选发现与准入段被 B2、引擎、
`FP-C13`、`REQ-0207` 四方争抢。不集中处理就没有并行。

## 两条排期提示

- **轨 A 的重证（票 17）建议放在一个连续窗口内跑完**，窗口内轨 B 暂缓合并——G2 与 G3 证据
  绑定精确 commit，边跑边合会让证据的 commit 绑定不断变化。或等票 09～13 合完再跑。
- **票 19 不由批次 2 自己决定何时开工**——W1 窗口的门槛是批次 3 代码就绪。批次 2 的其余
  全部工作都不占现场窗口，不要因为这张票把整个批次 2 挂起。

## 出口

批次 2 完成 = **轨 A 出口（票 17）＋ 轨 B 出口（票 18）都达成**。两轨出口独立，轨 B 不阻塞
轨 A，但两轨都完成才算批次 2 完成（规格 8.3）。票 19 的现场演练随 W1 窗口补齐。
