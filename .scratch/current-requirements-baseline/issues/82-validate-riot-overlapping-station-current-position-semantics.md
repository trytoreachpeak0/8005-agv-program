# 验证 RIoT 重叠站点的车辆当前位置身份语义

Type: task
Status: resolved
Blocked by: 36, 37

External blocker: 尚未取得在隔离测试地图创建两个同坐标站点身份的明确授权，也未指定本次试验可控车辆与安全恢复责任人。

## Question

在不修改生产地图、不影响生产车辆的受控测试环境中，为同一坐标建立两个不同 RIoT 站点身份，并分别把它们作为移动订单目标，从不同进站路径让测试车辆到达重叠位置；连续读取 `GET /api/task/vehicles` 的 `currentMap + currentPosition` 及可用的底层只读位置证据，验证 RIoT 在目标站点不同、创建顺序不同、到达方向不同、订单结束及车辆静止后究竟返回哪个站点 ID，结果是否确定、稳定且可绑定到目标站点。

验证必须记录环境、RIoT build、地图版本或哈希、两个站点 ID 与坐标、车辆与订单身份、请求时间和原始响应，并回答：

- 单值 `currentPosition` 能否可靠区分同坐标的等待、业务或充电站点身份；
- 它表示订单目标、RIoT 选中的当前站点、任一重合站点，还是在不同时间可能变化；
- 8005 能否仅凭该字段证明角色特定的到达和占用；若不能，还需要订单目标、位姿、到达事件或其它什么已验证证据；
- 在证据不足时，当前基线应禁止重叠角色站点、允许但对角色识别 fail-closed，还是要求一个站点承载多个 8005 角色。

若没有安全测试环境、创建重叠站点的授权或可控测试车辆，则不得在生产环境试验；应把缺失条件和精确测试清单作为结果记录，保持依赖票据未决。

## Answer

用户于 2026-08-24 明确指示本项试验不再执行并取消。该受控行为验证因此退出本次“当前需求基线恢复与版本化治理”路线，不再等待测试环境、站点变更授权、车辆或安全恢复责任人，也不进入地图的“Decisions so far”。本次取消没有产生任何 RIoT 外部调用、地图或站点变更，也没有形成关于重叠坐标下 `currentPosition` 身份语义的新证据。

取消试验不等于证明该字段可靠或不可靠。后续“决定空闲返回、停靠点资格与调度竞争边界”必须在证据缺口明确保留的前提下自行封闭产品规则：不得把单值 `currentPosition` 当作同坐标多角色站点的可靠身份或角色到达证明，除非以后在新的、有独立授权的工作中取得可核查证据。
