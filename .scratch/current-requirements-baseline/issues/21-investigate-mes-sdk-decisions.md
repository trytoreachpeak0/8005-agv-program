# 调查 MES 与 SDK 架构决定

Type: research
Status: resolved
Blocked by: 11

## Question

对无损清单 R09 批次中的 MES/SDK ADR 与索引，逐份核实来源、决定主体、版本与历史、批准证据、批准范围及当前适用性；哪些内容可能表达需求约束，哪些纯属本地图目的地之外的设计选择？

## Answer

完整调查见 [R09 MES 与 SDK 架构决定调查](../evidence/investigations/R09-mes-sdk-decisions.md)。固定清单中的 18/18 份材料均已核实且 SHA-256 零漂移：7 个 ADR 明显包含须回到需求基线核实的业务或外部约束，5 个混合本地设计与待核实约束，5 个主要是地图目的地之外的本地设计选择，另有 1 个索引。17 个 ADR 虽均标为 `accepted`，但 0/18 具备本次基线要求的决定人、日期、授权范围和版本绑定。

调度异常恢复、充电改派、MES 幂等/GONE/抑制、完整快照、客户 SQL/DDL 边界、生产鉴权、可再派条件和产品能力范围须按报告中的原子指针回到业务、客户 IT、安全或外部接口审查；技术栈、SDK seam、双语言交付、错误模型和生成工具等本地选择不直接进入需求基线，除非已有外部承诺。Git 作者、ADR `accepted`、实现与测试一致性只能证明工程历史或当前护栏，不能替代业务批准。
