# 决定工厂 MES 验证的批准与完整性证据门槛

Type: grilling
Status: resolved
Blocked by: 23

## Question

工厂 MES 只读实验由谁、在什么范围内可以自行授权执行；要把查询契约、业务筛选、PACKAGE 容量、性能阈值或工厂验收结论纳入当前需求基线，必须保存哪些具名批准、SQL/来源文件 SHA-256、环境身份、run 记录和传输完整性证据，7 月 16 日与 7 月 27 日两套规则由哪一版本正式替代？

## Answer

用户于 2026-08-03 逐项确认以下规则：

1. **只读实验可自行执行，不设逐次审批。** 工厂 IT 提供的数据库账号实际权限较高，因此账号权限不能被解释为项目的授权范围。具名执行人可无需另行申请，通过项目受控 runner 运行已登记的 SELECT；项目自行把实际使用边界收紧为只读白名单，禁止手工任意 SQL、DDL、DML 及未登记的高负载扫描。
2. **run 只是限定环境的参考观察，不是正式验证证据。** 它可用于排查问题、了解当时数据形态和性能量级，但不代表正式验收、客户批准或长期性能保证，也不能单独推动任何规则进入当前需求基线。
3. **run 只保留最低参考记录。** 记录执行人、时间、环境名称或数据库实例标识、已登记的查询 ID、成功/失败与关键结果摘要；必要时可保存脱敏原始输出。不要求 SQL 哈希、来源文件哈希、传输哈希、完整性清单或正式批准字段。引用 run 时必须同时限定其运行时间和环境，不得外推。
4. **查询契约、业务筛选与 PACKAGE 容量按需求本身准入。** 进入当前需求基线时不要求工厂 run；必须锁定具体来源版本（例如 Git 提交＋文件路径，或等价版本记录）和适用范围，再由用户作为当前基线最终批准人逐项具名批准。
5. **性能阈值只能由明确需求批准产生。** “平均不超过 5 秒、最大不超过 10 秒”等阈值只有在用户明确批准为需求后才能进入基线。某次 run 达标只是参考观察，不能反向创造阈值。
6. **工厂 run 不产生长期验收结论。** 可以把“某查询在某时某环境运行成功”保留为历史事实，但不得写成长期有效的“工厂验收通过”。
7. **本决定正式替代两套旧规则的冲突部分。** 2026-07-16 规则中“每次先取得客户批准并保存所有 SHA-256”不再适用；2026-07-27 规则中“执行人可运行登记查询”继续适用，但必须受上述只读白名单边界限制。两份原始文档保持不变，以本票作为冲突部分的治理替代记录，不改写历史证据。
