# 决定当前 MES 只读与卸货、完工回写边界

Type: grilling
Status: resolved
Blocked by: 55

## Question

面对跨批次冲突 `CF-R01-002`：8005 当前版本是否严格只读访问 MES、禁止系统执行任何完工/卸货回写；若是，卸货或搬运完成后由 OP/PDA/其它既有流程承担哪些后续动作，系统只提示、审计还是等待其结果；若允许某类回写，则触发条件、责任系统、接口/数据契约、授权、失败与结果未知处置是什么；哪些内容属于当前基线，哪些仅是未来重新评审的范围外能力？

## Answer

用户于 2026-08-04 逐项确认以下边界：

- 当前 8005 范围内所有组成部分严格只读访问 MES；不得执行完工、卸货、过站、入库或其它 MES 写操作，也不得通过工作流或外部调用代替现场流程推动 MES 状态变化。
- 8005 的物理卸货与搬运结果只形成其本地业务终态和正常审计事实；本地完成不等同于 MES 完成，也不以任何 MES 写回或状态变化作为完成条件。
- 正常卸货后所需的 MES 入站、过站、接收或其它状态变化，由目的站对应的现场责任人通过既有 PDA/MES 流程承担；责任随目的站业务角色确定，不固定归属于 AGV 装货操作员，8005 不代办或接管。
- 物理卸货完成并满足安全结束条件后，8005 立即结束本地任务并释放车辆；不等待现场 PDA/MES 操作，不等待、轮询或验证 MES 状态变化，也不以之后只读观察到的 MES 变化回溯改变本地卸货终态。
- 8005 不显示 MES 后续操作提醒、不要求提醒确认，也不建立 MES 后续待办、完成状态、未确认告警或专门审计事件；只保留自身物理卸货、本地任务终态和车辆释放的正常业务审计。
- MES 写回能力不属于当前基线。未来若要引入，必须作为新能力重新评审，并取得版本绑定的接口与数据契约、授权、幂等、失败和结果未知处置批准；不得复用当前查询权限先实现后补评审。

因此 `CF-R01-002` 采用“当前严格只读、现场既有流程独立负责、8005 无提示且不等待”的一侧；早期简易需求中的“系统回写 MES 或提示 OP/PDA”不进入当前基线，保留为冲突历史证据。
