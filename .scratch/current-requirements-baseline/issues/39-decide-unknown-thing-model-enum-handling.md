# 决定未知物模型枚举值的项目处理规则

Type: grilling
Status: resolved
Blocked by: 38

## Question

在可核查物模型证据明确已知与未知边界后，8005 对未知、缺号或未说明的枚举值应采取透传、记录、告警、拒绝业务判断或失败中的哪些规则；哪些字段允许兼容未知值，哪些安全或业务路径必须阻断，以及批准结果如何绑定到物模型版本和适用系统范围？

## Answer

8005 将 RIoT 属性或服务结果中未经已批准物模型版本及适用范围定义的原始值统一视为 `UnrecognizedThingModelValue`：保留字段名、原始值、车辆、时间、调用或消息来源、环境、build、物模型文件哈希及关联业务编号，但不得按缺号补义、映射为邻近或默认枚举、丢弃原值，或用黑盒观察替代权威语义。入站未知值可以保存、诊断展示和作为证据传递，但不得复制到新的建单、移动、路径、急停或其它控制调用；出站参数若为缺号、保留值、未经批准枚举或 `pathType=-1 / UNRECOGNIZED`，必须在调用前明确拒绝并记录本地契约校验失败。

处理采用“最小范围阻断，安全不可证明时升级整车业务阻断”。`batteryState`、`movementState.state`、`pathType` 与 `avoidPolicy` 仅用于观察展示时可以携带未知标记继续显示；一旦其语义参与发车、路径、订单或状态对账，就阻断对应决定。`lastErrorCode`、`hardwareErrorCode` 与 `faultCodesList` 无法证明不影响安全时，车辆不得取得 `VehicleBusinessReadiness`。未知服务 `result.code` 使本次调用结果保持未知并阻断依赖成功结论的后续动作，不自动推定整车故障；只有未知值导致仓门、移动、急停或车辆安全状态无法证明时，才升级为整车停止接收新业务并进入人工恢复。`multiLoadState` 不属于 8005 消费范围，明确排除，而不是作为待支持未知字段。

每个未知值在首次出现、原值变化和恢复为已知状态时形成记录；持续重复时聚合保留首次、最近一次、出现次数和受影响路径，允许限频避免刷屏。只影响观察展示的未知值产生普通告警；造成调用结果未知、业务动作阻断或安全状态不可证明的值立即产生高优先级告警。恢复事件不自动补充未知语义。

上述防御性规则长期适用于 `RIOT-8005-RUNTIME` 的全部 8005 AGV。任何“值已知”的映射必须绑定明确的 `productKey`、物模型文件哈希或版本、RIoT 环境与 build、适用车型及固件范围；升级其中任一边界后，未被证据明确覆盖的新增值自动回到未知。300C 与 300E 的行为兼容假设不能补齐未知枚举语义。只有取得版本绑定证据并由当前基线最终批准人再次明确批准，未知值才能升级为已知映射。
