# 建立 R06–R10 文档级证据分类账

Type: task
Status: resolved
Blocked by: 18, 19, 20, 21, 22

## Question

依据已完成的 R06–R10 调查报告、无损清单和既定权威证据规则，为这些批次中的每份材料建立统一的文档级分类记录：固定路径与哈希、材料角色、来源类型、当前适用范围、历史/派生关系、批准四要素状态、可否进入原子需求提取，以及必须保留的证据或冲突指针；如何明确隔离测试草案、ADR/设计决定、模拟器规划和第三方资料，做到零漏项且不从设计或实现反推需求？

## Answer

已把 R06–R10 的逐件调查结论归一到统一的[文档级证据分类账说明](../evidence/document-classification/README.md)，规范化主数据为 [R06–R10 TSV 分类账](../evidence/document-classification/R06-R10-document-evidence-ledger.tsv)，并提供公式驱动的 [XLSX 审阅副本](../../../outputs/019fc6a3-e36c-7b63-ad6e-0e8d07af8ade/R06-R10-document-evidence-ledger.xlsx)及[重建/核验脚本](../evidence/document-classification/build-and-verify-r06-r10-ledger.ps1)。

分类账以无损清单中 R06–R10 的 201 个固定路径为全集，逐条固定完整 SHA-256、字节数、清单原始 Git 状态、勘误覆盖后的有效 Git 状态和材料角色，再记录文档分类、来源类型、当前适用性、历史/派生关系、批准四要素、原子提取路由以及证据/冲突指针。覆盖为 R06 65、R07 15、R08 57、R09 18、R10 46；重建和独立 `-VerifyOnly` 均验证 201/201、零漏项、零重复、零当前哈希漂移，并正确应用 R10 两条 Unicode 路径 Git 状态勘误。

批准边界保持失败式隔离：201 份材料都没有同时建立具名批准人、日期、范围与版本绑定，四要素字段全部为 `not-found`，`document_approval_state` 全部为 `not-approved-by-this-classification`；核验脚本会在分类过程擅自升级批准时失败。候选提取路由共 101 份：R06 52、R07 2、R08 19、R09 12、R10 16；这只代表可以进入后续原子拆分、追源、冲突裁决和显式批准，不代表已经是需求或当前基线条目。

隔离规则已按材料性质固化。R06 的测试草案不充当执行证据，其中 4 份上游漂移旧稿在重写或绑定旧版之前保持阻塞；R08/R09 的业务、领域、物理或外部约束候选必须先与 ADR/本地设计拆分，纯设计决定不作为需求提取；R10 只把模拟器自身 `SIM-REQ` 作为模拟器范围候选，设计、测试计划、实施计划、索引和主系统线索不从规划文本反推主系统需求。用户已排除的厂商 PDF 与派生寄存器表仅保留路径、哈希、勘误后状态和来源关系，2 份纯供应商记录明确不进入提取或继续适用性调查。

XLSX 的 `Summary` 公式读回为总记录 201、未由分类批准 201、候选路由 101、漂移阻塞 4、供应商排除 2；`Ledger` 提供冻结表头、筛选和状态着色。落盘文件重新导入后公式错误扫描为零，并完成两张工作表的视觉检查。此票没有改变业务领域词汇或决定，因此未修改根 `CONTEXT.md`；原子需求级票据仍等待 R11–R13 分类账及总账合并完成后按实际分组从地图雾区毕业。
