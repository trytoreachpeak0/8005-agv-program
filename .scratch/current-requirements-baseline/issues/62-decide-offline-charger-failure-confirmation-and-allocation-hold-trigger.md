# 决定无联网充电桩的充电失败确认与暂停触发边界

Type: grilling
Status: resolved
Blocked by: 59

## Question

在 8005 充电桩不联网、系统无法直接读取故障或健康状态的前提下，哪些可观测车辆、订单、到站和充电结果事实，或哪一级现场人员的明确确认，才能构成一次“确认的充不上”并触发对全部 8005 车辆的充电桩暂停分配；如何排除尚未到桩的导航不可达、车辆状态不可执行、订单异常与结果未知，避免把一切充电类 OrderHang 都误记为充电桩事件；触发、人工恢复和重新参与选桩分别必须保留哪些身份、时间、充电桩、车辆、订单、理由与现场处置审计证据？

## Comments

- 2026-08-05：用户批准严格事实组合可由系统自动形成“已确认充不上”：8005 充电订单的车辆、订单、预占和目标充电桩身份必须一致，车辆已到精确的 `RIoT 地图 + 站点`并执行开始充电，RIoT 完成内部重试后开始充电动作返回经验证失败码（当前证据为 `407802`）且订单最终进入 `HANG`，全程没有 `batteryState=CHARGING` 或成功结果，所有事实新鲜、连续且无未知或冲突。单独 `HANG`、超时、未到桩、导航不可达、车辆不可执行、自由文本提示或结果未知均不能触发充电桩暂停分配。
- 2026-08-05：用户批准人工补充确认只能由 R-11 设备/电气维护人员或被明确授予等效维护权限的人员以个人身份提交；确认具体车辆在具体充电桩实际尝试开始充电但充电未建立，不要求归责于车辆或充电桩。普通生产操作员只能报告或申请检查，不能触发全车暂停分配；人工确认不能覆盖车辆、订单、预占或充电桩身份冲突。
- 2026-08-05：用户批准每次暂停触发形成不可变、幂等的审计证据包：记录唯一暂停事件及触发来源，充电桩 `RIoT 地图 + 站点标识`、名册记录与版本，AGV、预占与 RIoT 订单身份，到桩/开始充电/失败/最终 `HANG`/确认/暂停生效时间，原始位置、订单、动作结果和电池状态及证据引用，RIoT build/契约版本，以及人工确认时的确认人、角色、认证时间和现场处置说明。理由固定为“已确认充不上”且根因保持 `UNKNOWN`，作用域为全部 8005 车辆，并记录变更前后状态；同一事件重复提交只返回原暂停结果。
- 2026-08-05：用户批准解除暂停不需要额外的 R-13 或生产主管复核，但必须由 R-11 设备/电气维护人员或等效授权人员以个人身份提交现场恢复确认；它绑定原暂停事件、充电桩身份和当前名册版本，记录检查结果、处置措施、确认人和确认时间，明确声明允许重新参与分配而不声称已取得健康遥测。服务端只有在该暂停仍是最新有效代次、没有更新失败事件且充电桩仍在有效名册时才解除；普通操作员、R-13 管理员、定时任务或换车试桩均不能替代此确认，重复提交幂等，结果未知时继续暂停。
- 2026-08-05：用户批准解除暂停只恢复“可参与资格评估”，不直接标记桩位空闲、不自动分配任何车辆也不自动重试原订单。下次正常调度仍须重新核验名册、车辆允许集合、RIoT 地图与站点、物理占用、本地预占和数据新鲜度，任一状态未知都 fail-closed；只有原子预占成功后才能建单。原失败车辆与其他车辆使用同一电量队列，无特殊优先级也不永久排除；重新入选审计引用恢复确认 ID、名册版本、资格快照和新预占 ID。
- 2026-08-05：用户纠正失败后的物理收敛：取消充电订单时车辆可能仍停在充电桩位置，因此不能把订单取消终态当作桩位已腾空；失败车辆必须移动到等待点，不再占据充电桩。等待点身份、选择门禁、移动失败及预占释放时点待后续逐项确定。
- 2026-08-05：用户进一步确认不建立每个充电桩专属的失败撤离等待点；车辆正常任务完成、正常充电完成或充电失败后都前往地图上的等待点，复用同一地图级待命去向。地图等待点是单点还是可分配集合、多车竞争及不可用时的处理待后续明确。
- 2026-08-05：用户批准将地图等待点建模为受控集合，即使当前每张地图只有一个等待点也保持集合语义；正常任务完成、充电完成和充电失败共用同一分配流程。多车同时返回时必须原子预占等待点；只选择当前地图中身份有效、路线可达且未被占用或预占的点。唯一等待点不可用时车辆继续原地排队并告警，不临时猜测其它站点。
- 2026-08-05：用户批准失败撤桩的资源交接顺序：先使原充电桩暂停对全部 8005 车辆生效，再原子预占当前地图的合格等待点，然后取消旧充电 `HANG` 订单并确认终态，重新核验车辆可移动、路线可达和正常派车安全门禁后，建立前往已预占等待点的移动订单。只有新订单确认成功、车辆当前站点确认已到等待点且不再位于原充电桩，才释放原充电桩预占；其暂停仍保留。撤桩中车辆短暂同时持有原充电桩与目标等待点预占；无合格等待点、车辆不可安全移动，或取消/移动结果未知时，保持原状态、对账并告警转人工，不强制发车或提前释放任一资源。
- 2026-08-05：用户指出上述撤桩顺序仍有闭环缺口：车辆可能因长期避障或其它原因无法到达等待点，不能因此永久占有充电桩与等待点资源；必须提供可审计的人工处置路径。后续方案需将“充电桩已安全腾空”与“故障车辆已到正常等待点并恢复业务就绪”分成两个独立闭环。
- 2026-08-05：用户批准简化为单一“清桩中”状态，并以两种可替代证明之一完成：系统确认车辆已到地图等待点，或授权现场人员确认车辆已移至安全位置、原桩已腾空并已置于不能继续自动执行旧订单的维护/禁止派车状态。清桩完成后释放原充电桩预占，但充电桩继续暂停等待 R-11 恢复；人工处置车辆继续禁止派车，直至位置、未结订单、移动安全和业务就绪对账完成；未使用的等待点预占只有在确认车辆不会继续前往后才释放。人工记录最少保留确认人、时间、车辆、充电桩、车辆最终位置与旧订单处置状态；旧订单仍可能继续执行时不能完成清桩。
- 2026-08-05：用户批准建立独立“人工清桩”权限，初始授予 R-13 AGV 运维/调度管理员与 R-11 设备/电气维护人员，任一具备权限者均可以个人身份单独提交，不需要双人审批。实际移车可由其它人员协助但须记录处置人，最终确认人必须拥有该权限；普通生产操作员只能报告、协助或请求处置。该权限只能确认原桩已腾空且车辆不会继续旧订单，不能解除充电桩暂停或恢复故障车辆派车；充电桩恢复仍只接受 R-11 恢复确认。
- 2026-08-05：用户批准去掉“清桩后旧订单可能再把车送回原桩”的后置分支；旧充电订单必须在清桩前确认取消终态，取消结果未知时继续对账且不完成清桩。清桩完成后释放原充电桩预占，充电桩仍等待 R-11 恢复，车辆按自身事实独立恢复。
- 2026-08-05：用户批准修正“人工清桩一律要求车辆维护/禁止派车”的过度保守规则。人工清桩只确认原桩已腾空；若车辆已移到地图等待点，且系统可完整核验位置有效、旧订单已终结、车辆状态正常并通过常规派车检查，则不需要进入禁止派车。只有人工推车/拖车/断电移车影响未收敛，或位置、定位、订单、运动或安全状态任一未知时，才禁止派车直至对账完成。

## Answer

用户于 2026-08-05 逐项批准以下结论：

1. **“已确认充不上”可由严格系统事实自动形成。** 车辆、订单、预占和目标充电桩身份必须一致；车辆已到精确的 `RIoT 地图 + 站点`并执行开始充电；RIoT 完成内部重试后返回已经目标 build/契约验证的失败码（当前证据为 `407802`）且订单最终进入 `HANG`；全程无 `batteryState=CHARGING` 或成功结果，所有事实新鲜、连续且无冲突。该事实不对车辆或充电桩归责。
2. **一般充电类异常不得误触发暂停。** 单独 `HANG`、超时、未到桩、导航不可达、车辆不可执行、自由文本失败提示、订单异常或结果未知都不足以确认充不上，必须保持原事实并进入对应异常分支。
3. **系统事实不完整时，只有 R-11 可补充现场确认。** R-11 或等效维护权限人员可以个人身份确认具体车辆已在具体充电桩实际尝试开始充电但充电未建立；普通生产操作员只能报告或申请检查，人工不能覆盖身份冲突。
4. **确认后立即以不可变、幂等事件暂停该桩的全部 8005 分配。** 事件记录唯一 ID 和触发来源，充电桩 `RIoT 地图 + 站点`、名册记录与版本，AGV、预占和订单身份，到桩/开始充电/失败/最终 `HANG`/确认/暂停时间，原始位置、订单、动作结果和电池状态及证据引用，RIoT build/契约版本，以及人工确认的个人身份、角色、认证时间和现场处置。理由固定为已确认充不上，根因保持 `UNKNOWN`。
5. **失败后进入单一“清桩中”闭环。** 旧充电订单必须在清桩前确认取消终态，取消结果未知时继续对账而不完成清桩。正常任务完成、充电完成和充电失败共用地图等待点集合；即使当前只有一个点也按集合建模，只选当前地图上身份有效、路线可达且未被占用或预占的点，多车原子预占；无合格点时原地排队并告警，不猜测其它站点。
6. **清桩有两种可替代的完成证明。** 系统确认车辆已到地图等待点，或取得人工清桩确认：车辆已移至安全位置且原桩已腾空。“人工清桩”权限初始授予 R-11 与 R-13，任一具备权限者均可以个人身份单独提交；协助者另行记录，普通操作员不可确认。记录至少包含确认人、时间、车辆、充电桩、车辆最终位置和旧订单处置状态。
7. **人工清桩不自动恢复或阻断车辆。** 若车辆已到地图等待点，且位置有效、旧订单已终结、车辆状态正常并通过常规派车检查，不需要进入维护/禁止派车。只有人工推车、拖车、断电移车影响未收敛，或位置、定位、订单、运动、安全状态任一未知时，才禁止派车直至对账完成。
8. **清桩后充电桩与车辆独立恢复。** 清桩完成后释放原充电桩预占，充电桩继续暂停；未使用的等待点预占只在确认车辆不会继续前往后释放。充电桩恢复只接受 R-11 或等效维护权限人员的个人恢复确认，绑定原暂停事件、充电桩身份与当前名册版本，记录检查结果、处置措施、确认人和时间；它不等待原车恢复。车辆按自身事实恢复，不会自动解除充电桩暂停。
9. **解除充电桩暂停只恢复正常选桩资格评估。** 不直接标记桩位空闲、不自动重试原订单或分配车辆。下次正常调度重新核验名册、车辆允许集合、RIoT 地图与站点、物理占用、本地预占和数据新鲜度，任一未知都 fail-closed；只有原子预占成功后才能建单。原失败车辆无特殊优先级也不永久排除，与其它车辆使用同一电量队列；入选审计引用恢复确认 ID、名册版本、资格快照和新预占 ID。

以上结论将无联网充电桩的失败事实、全车暂停、物理清桩、充电桩恢复和车辆恢复分离，既不把一般 OrderHang 误当充电桩事件，也不让无法到达等待点的车辆永久锁住充电桩资源。
