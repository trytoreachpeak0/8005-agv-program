# 建立 R01–R05 文档级证据分类账

Type: task
Status: resolved
Blocked by: 13, 14, 15, 16, 17

## Question

依据已完成的 R01–R05 调查报告、无损清单和既定权威证据规则，为这些批次中的每份材料建立统一的文档级分类记录：固定路径与哈希、材料角色、来源类型、当前适用范围、历史/派生关系、批准四要素状态、可否进入原子需求提取，以及必须保留的证据或冲突指针；如何做到零漏项且不把文档级分类误当作原子需求批准？

## Answer

已建立统一的 [R01–R05 文档级证据分类账](../evidence/document-classification/README.md)，主数据为 [TSV 分类账](../evidence/document-classification/R01-R05-document-evidence-ledger.tsv)，并提供可筛选的 [XLSX 审阅副本](../evidence/document-classification/R01-R05-document-evidence-ledger.xlsx)及[重建/核验脚本](../evidence/document-classification/build-and-verify-r01-r05-ledger.ps1)。

分类账以无损清单中 R01–R05 的 202 个固定路径为全集，逐条固定完整 SHA-256、字节数、清单原始快照 Git 状态、勘误覆盖后的有效 Git 状态和清单材料角色，再把对应调查报告中的文档级结论归一为来源类型、当前适用性、历史/派生关系、批准四要素、原子提取路由及证据/冲突指针。覆盖结果为 R01 19 条、R02 27 条、R03 48 条、R04 41 条、R05 67 条；重建与独立 `-VerifyOnly` 均验证 202/202、零漏项、零重复、零当前哈希漂移，并保留“修正初始快照的 Git 状态分类”的覆盖层而不重写原清单。

批准隔离边界已固化为数据约束：现有 R01–R05 证据没有任何文档同时建立具名批准人、日期、范围和版本绑定，所以四要素字段全部保持 `not-found`，`document_approval_state` 全部保持 `not-approved-by-this-classification`；核验脚本在任何记录被分类过程升级为批准时直接失败。该状态只表示本轮证据不能批准，不表示内容错误、永久否决或已经废弃。

原子提取采用单独路由，不与批准状态复用：26 份模板、索引、空白、迁移或追踪材料明确不从该文档本身提取；其余 176 份仅进入后续原子拆分、证据复核、冲突裁决和显式批准路径，其中混合内部设计、接口或安全主张的材料必须先拆分批准范围。R01 的内部待办材料按事项拆分后追证，但“建议动作”不得直接变成客户需求。

XLSX 审阅副本包含 `Summary` 与 `Ledger` 两张表，已读回核验批次计数、批准隔离公式和关键行，并完成视觉检查；未发现公式错误或截断关键摘要。此票未改变业务领域模型，因此无需修改根 `CONTEXT.md`。
