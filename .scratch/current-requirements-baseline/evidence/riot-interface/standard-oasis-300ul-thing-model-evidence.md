## 当前内容能确认的缺口

对现存 TSL 的机械复核与问题清单一致，并进一步固定了数量边界：

- `batteryState` 只定义 `0,2,3`；值 `1` 的是否保留、是否可达和语义未知。
- `movementState.state` 只定义 `0,2,3,4,5,6,7,8`；值 `1` 的是否保留、是否可达和语义未知。
- `movementState.paths[].avoidPolicy` 只定义 `0,1,2,16`；值 `3–15` 的是否保留、是否可达和语义未知。
- `movementState.paths[].pathType` 只定义 `0–4`；`moveFollowPath.paths[].pathType` 另定义 `-1: UNRECOGNIZED`。文件只能证明两处不一致，不能证明应把 `-1` 补到属性侧、从服务侧移除或两处本来就有不同语义。
- `multiLoadState`、`lastErrorCode`、`hardwareErrorCode` 是无语义映射的 `int`，`faultCodesList` 是无语义映射的 `int[]`。
- 37 个服务中有 36 个服务的 `outputData.result.code` 是无取值说明的裸 `int`；`loadConfig` 不采用该统一 `result.code` 结构。任何 code 的成功/失败含义、重试性、安全后果和适用服务范围都未知。

“已在 TSL 中列出某个枚举键和值名”只证明该文件中的静态映射，不单独证明现场可达性、状态迁移、跨 build 稳定性或 8005 业务含义。
