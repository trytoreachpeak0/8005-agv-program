# 发布明文传输版本并写入已知限制

Type: task
Mode: HITL
Status: open
Blocked by: 10

## Question

验收通过后，在 `8005-agv-control-server` 发布本轮候选，并把明文传输的代价原样登记。

发布内容：

- annotated tag 绑票 08 候选对应的服务端 commit，显式使用 **40 位完整 SHA**（票 28 的教训：用
  `HEAD` 或分支名会在 owner 恰好推了新 commit 时错标目标）；
- 资产为完整候选上传，沿用 0.1.1 的三资产形态；
- 发布说明中的已知限制，**措辞不得淡化**：
  1. 车载凭据 `credentialProof` 以明文经网络传输，抓包即可永久冒充车载端下发仓门 IO 命令；
  2. `motionState` 等安全闸门输入经明文传输后可被篡改，票 14／本轮票 10 证过的「移动中拦、停稳
     放行」在不可信网络下不再成立；
  3. 适用前提是受控的工厂内网；离开该前提不得使用本版本；
  4. 沿用 0.1.1 中仍然成立的其余已知限制（真实八仓 IO 与车载目标终端硬件资格等）。

约束：

- **只在服务端仓建 tag／release**。不得为凑齐三仓写入只读的车载端仓——车载端的版本引用归其 owner，
  agent 不得代建（票 28 的先例是由用户执行）；
- 协议仓不动，`protocol-v0.1.1` 保持原状；
- 上传前不得修改包内任何文件；如需更正，写在**包外**的 Release 说明里（票 12／15 的先例：包内手册
  在全量哈希内，改它要重建候选）。

判据必须是回读取证而非上传返回码：远程资产**下回来重算**哈希应全部 MATCH（红侧翻一字符应
MISMATCH）；tag 对象 peel 出的 commit 与候选 manifest 记录逐字一致；线上说明正文与本地副本在同一
归一化下 VERBATIM MATCH。注意 `gh --jq` 的输出在 PowerShell 里会被拆成数组而非字符串，逐字比对前
先落盘再 `Get-Content -Raw`，否则会假红（票 29 踩过）。

Mode 为 HITL：发布是对外动作，需用户明确授权后执行。
