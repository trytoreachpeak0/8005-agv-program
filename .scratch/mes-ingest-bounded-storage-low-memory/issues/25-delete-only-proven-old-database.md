# 25 — 只删除已证明的精确旧库

**What to build:** 在 MesIngestCutoverRun 的全部同窗门禁通过后，使用仅本次运行有效的临时权限自动删除精确旧库，并在成功、失败或异常结束后撤销权限。

**Blocked by:** 23 — 播种墓碑并运行无删除切换门禁.

**Status:** ready-for-agent

- [ ] 删除能力只存在于一次性 CutoverRunId 运行，日常 Host、Watch 和 reference consumer 永远不拥有或调用该能力。
- [ ] 删除前重新验证全部门禁仍属于当前运行，旧库显式名称、schema/contract、文件目录、连接状态和新库排除条件仍成立。
- [ ] 不允许通配、名称前缀、自动猜测、系统库、新库或无法解析文件目录的目标。
- [ ] 临时提升权限在成功、门禁失败、删除失败、取消和异常退出后都被撤销并留下审计。
- [ ] 任一检查或删除失败时不后台重试，保留能够保留的新旧数据库，只有新的明确运行才能再次尝试。
- [ ] 所有目标身份和门禁拒绝分支先通过无删库 dry-run/策略测试证明；不为每个拒绝条件创建并真实删除数据库。
- [ ] 真实删除只在隔离实例运行一个完整成功路径和一个删除失败/权限撤销路径，其余失败矩阵复用 Ticket 23 证据。
- [ ] 删除成功证据在数据库外和 Windows 事件日志中完整存在，且不声称有备份或回滚路径。
- [ ] 复用 Ticket 23 的 CutoverRun、身份解析、证据和现有 cutover SQL 工具，不建设通用数据库管理框架。
- [ ] 开发期运行聚焦拒删/权限/证据测试，关闭时运行一次真实 SQL Server Tier 1；正常验证目标在 60 分钟内完成并保持 Failed: 0、Skipped: 0。
