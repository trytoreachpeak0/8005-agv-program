## 2026-08-09 UI 与验收重建决定

用户拒绝当前生产 UI，并要求正式窗口对齐已经选择的 Prototype D/E 设计，同时先证明 Ticket 01–10 的行为没有被视觉重做破坏，再重建 Ticket 11、12、13。

本轮重建以 [map.md](map.md) 为执行入口。产品与领域行为仍以原 V2 规格为权威；以下内容成为附加的生产视觉契约：

- 顶部全局工具栏、左侧导航、独立筛选侧栏、主结果区和底部状态栏的层级须与 D/E 设计一致；
- Demand → Alerts 与 Alert → Demands 使用可解释的关系卡片，明确区分精确 DemandId、业务键、任务类型和全局范围；
- 中文用于导航、动作、解释和运维结论，英文用于实体名、字段名、枚举、TASK_TYPE 和 Alert code，不使用中英斜杠标题；
- 参考图的假数据和硬编码不是生产逻辑。生产实现必须保留 Ticket 01–10 的查询、分页、刷新、取消、详情、复制、可访问性和 Host 会话行为；
- 新 UI 未通过 Ticket 01–10 回归和用户视觉确认前，不得生成批准基线、恢复 Ticket 12 或进入发布打包。
