# AREA 筛选页实时同步与显示范围快照

Status: ready-for-agent

## Problem Statement

`AREA 筛选` 页当前把纵向空间花在了四行不产生信息的界面元素上：顶部重复陈述「当前应用了哪个配置、有几个 AREA、什么时候应用的」的横幅（这些左侧列表里都有）、编辑器上方的「AREA（每行一个）」标签栏、「磁盘版本未变化 / 从磁盘加载 / 保存并应用范围」一行，以及底部的「放弃修改 / 保存」一行。真正需要空间的 AREA 内容编辑器被挤到只剩四百像素高。

同时这一页假设自己是配置文件的唯一修改者。用户用记事本或其他编辑器改同一个 TXT、或者往配置目录里放一个新文件，Watch 都察觉不到，必须手工点「重新加载」或「从磁盘加载」。而这两个按钮的存在本身又占掉一行。

针对单个配置文件的命令（另存为、重命名、删除）挂在右侧编辑器的标题行，针对配置集合的命令（新建、应用全部）挂在左侧列表卡片，用户要在两栏之间来回找。

## Solution

这一页改为**编辑器与磁盘持续双向同步**，界面只保留承载信息的部分。

- 删除上述四行界面元素，腾出的纵向空间归编辑器。被删元素承载的信息合并进保留下来的行：有效 AREA 数量进文件标题行，格式要求进文件路径那一行，同步时刻进编辑器底部状态条。
- 编辑器内容在停止输入后自动写盘，不再需要「保存」；`Ctrl+S` 保留为立即写盘的显式动作。
- 监视整个配置目录：别的程序改了文件，编辑器自动更新且保持光标位置；目录里新增或删除了配置文件，列表自动反映。「重新加载」「从磁盘加载」随之删除。
- 所有针对配置文件的命令收进左侧「筛选配置」卡片：新建与打开配置文件夹在卡片标题行，另存为/重命名/删除在列表项右键菜单，应用是卡片底部的主按钮。

**显示范围的语义保持不变且被明确下来**：范围来自用户按下「应用」那一刻的 AREA 内容快照，不跟随文件。文件后来被改坏、被改成别的内容、甚至被删除，当前显示范围都不受影响，直到用户显式重新应用。当文件内容与快照不一致时，界面明确提示「待重新应用」。

这条语义让实时同步与显示范围彻底解耦：编辑器随时跟磁盘同步，而 `DemandSeries` 与 `资格审计` 两个页面的筛选范围只在用户主动应用时才改变。

## User Stories

### 布局与信息密度

1. 作为 Watch 使用者，我希望页面顶部不再有显示范围横幅，以便纵向空间留给 AREA 内容，而当前应用的是哪个配置在左侧列表里本来就看得到。
2. 作为 Watch 使用者，我希望编辑器上方不再有「AREA（每行一个）」这一栏，以便一屏能看到更多 AREA 行。
3. 作为 Watch 使用者，我希望有效 AREA 数量显示在文件标题行，以便这个信息不占用独立的一行。
4. 作为 Watch 使用者，我希望 AREA 的格式要求随文件路径一起显示，以便需要时看得到、不需要时不占空间。
5. 作为 Watch 使用者，我希望新建、打开配置文件夹、另存为、重命名、删除、应用全部集中在左侧「筛选配置」卡片，以便我在一个地方管理配置。
6. 作为 Watch 使用者，我希望另存为/重命名/删除通过在列表项上右键触发，以便命令的作用对象始终明确。
7. 作为 Watch 使用者，我希望「全部 AREA（不筛选）」是列表的常驻首项，以便它和其他配置共用同一套选中与应用的操作方式。

### 自动落盘

8. 作为 Watch 使用者，我希望编辑器里的修改在我停止输入后自动写入磁盘，以便我不需要记得按保存。
9. 作为 Watch 使用者，我希望页面上不再有「保存」和「放弃修改」按钮，以便那一行的空间归编辑器。
10. 作为 Watch 使用者，我希望仍然可以按 `Ctrl+S` 立即写盘，以便在不放心自动保存时有一个明确动作。
11. 作为 Watch 使用者，我希望切换配置、切换页面、窗口关闭前未落盘的内容被强制写入，以便我的修改不会因为离开而丢失。

### 文件与目录的实时同步

12. 作为 Watch 使用者，我希望别人用其他编辑器改了我正在查看的配置文件时编辑器内容自动更新，以便我看到的永远是文件的当前内容。
13. 作为 Watch 使用者，我希望自动更新时光标位置、选中范围和滚动位置保持不变，以便我不会因为别人保存了文件而丢失编辑位置。
14. 作为 Watch 使用者，我希望页面上不再有「重新加载」和「从磁盘加载」按钮，以便我不需要主动去同步。
15. 作为 Watch 使用者，我希望配置目录里新出现的 TXT 自动进入列表，以便我不需要重启或手动刷新。
16. 作为 Watch 使用者，我希望目录里被删除或改名的配置自动从列表消失或改名，以便列表始终反映目录真实内容。
17. 作为 Watch 使用者，我希望列表自动更新时当前选中的配置不被改变、焦点不被抢走，以便我正在做的事不被打断。
18. 作为 Watch 使用者，我希望编辑器伴生的临时文件不出现在配置列表里，以便列表只显示真正的配置。
19. 作为 Watch 使用者，我希望一次性拷入多个配置文件时列表一次性刷新，以便界面不会连续抖动。

### 并发修改

20. 作为 Watch 使用者，我希望我正在输入的同时别人也改了同一个文件时我的输入不被静默覆盖，以便我不会丢失刚打的内容。
21. 作为 Watch 使用者，我希望同样情况下别人的修改也不被静默覆盖，以便两边的工作都不会无声消失。
22. 作为 Watch 使用者，我希望真正发生冲突时看到一个明确的二选一，以便由我决定保留哪一份。
23. 作为 Watch 使用者，我希望冲突提示出现期间自动落盘暂停，以便提示不会被随后的自动写盘绕过。
24. 作为 Watch 使用者，我希望别人保存文件的动作不会让这个配置在列表里闪烁或短暂消失，以便列表保持稳定。
25. 作为 Watch 使用者，我希望我正在编辑的文件被外部删除时已输入的内容仍留在编辑器里，以便我可以另存为新文件而不是从头再来。
26. 作为 Watch 使用者，我希望文件被外部改名时编辑器跟随到新名字，以便我不会看到「文件已删除」的误报。

### 显示范围与快照

27. 作为 Watch 使用者，我希望显示范围来自我应用配置那一刻的内容快照，以便配置文件后来被改坏或删除都不影响我正在看的数据。
28. 作为 Watch 使用者，我希望编辑配置文件不会立即改变显示范围，以便我打字打到一半时两个数据页不会跟着抖动。
29. 作为 Watch 使用者，我希望当前应用的配置内容与快照不一致时界面明确提示「待重新应用」，以便我知道看到的范围和文件当前内容不是一回事。
30. 作为 Watch 使用者，我希望这种情况下应用按钮变成「重新应用」且可点，以便我一眼知道下一步动作。
31. 作为 Watch 使用者，我希望只改注释或空行不会被提示「待重新应用」，以便我不被没有实际影响的变化打扰。
32. 作为 Watch 使用者，我希望内容非法的配置不能被应用，以便非法内容不会变成显示范围。
33. 作为 Watch 使用者，我希望配置非法时当前显示范围保持不变，以便我不会因为编辑到一半就丢失正在使用的筛选。
34. 作为 Watch 使用者，我希望非法状态在编辑器底部、文件标题行和左侧列表项上都有提示，以便我在页面任何位置都能发现问题。
35. 作为 Watch 使用者，我希望「当前应用」和「文件非法」两个状态能同时显示，以便我不会因为文件出错就看不出它仍是正在生效的那一个。
36. 作为 Watch 使用者，我希望删除当前应用的配置后显示范围仍然保持，以便我不会突然从筛选后的少数 AREA 跳到全厂数据。
37. 作为 Watch 使用者，我希望删除后列表里仍能看到这个配置名并标明范围仍生效，以便我知道当前范围的来源。
38. 作为 Watch 使用者，我希望放开筛选必须显式应用「全部 AREA」，以便放开筛选永远是有意的动作。

### 降级与首次使用

39. 作为 Watch 使用者，我希望配置目录不可监视时界面明确告知，以便我不会误以为列表是最新的。
40. 作为 Watch 使用者，我希望首次使用时配置目录自动创建，以便我不需要手工准备目录。

## Implementation Decisions

### 复用既有机制，不重造

存储模块 `WatchAreaFilterProfileStore` 已经具备本特性所需的三项基础设施，一律复用：

- **乐观并发**：`Save` 接受 `expectedFingerprint`，`Rename` 与 `Delete` 接受 `expectedSourceFingerprint`。`Fingerprint` 由文件最后写入时刻的 ticks 与内容 SHA-256 组合而成。这就是冲突检测的依据，**不新增 baseline 机制**。
- **跨进程事务锁**：目录内的锁文件，所有读写操作都在锁内进行。多实例并发已被覆盖，**不新增锁**。
- **可注入时钟**：`TimeProvider` 已是构造参数，去抖与延迟确认直接用它。

`AtomicWriteText`（临时文件 + 替换）与删除时的墓碑机制维持原样。

### 新增：目录事件源

`WatchAreaFilterProfileStore` 增加**第四个可选构造参数**——配置目录事件源，与既有的 `deleteProfileFile`、`timeProvider` 注入模式一致。默认实现是包装 `FileSystemWatcher` 的薄适配层；测试传入手动驱动的实现。

Watcher 的生命周期归 store 管理，不归界面层。store 对外暴露的是**已解释的目录变更**，不是原始文件系统事件。

### 事件解释规则

原始文件系统事件不能直接当作语义使用。主流编辑器（记事本、VS Code、Vim）保存文件都是「写临时文件再替换或改名」，本项目自身的原子写入也是。因此：

| 规则 | 内容 |
| --- | --- |
| 去抖 | 同一路径的连续事件在一个短窗口内合并为一次 |
| 删除延迟确认 | `Deleted` 事件不立即视为删除；延迟确认后文件仍不存在才判定为真删除，期间同名文件重新出现则视为内容更新 |
| 改名跟随 | `Renamed` 视为改名而非删除；正在编辑的文件跟随到新名字 |
| 自身写入抑制 | 落盘时记录路径与指纹，命中的事件丢弃。不做抑制会导致「落盘 → 事件 → 重载 → 光标跳回开头」 |
| 伴生文件过滤 | 只接受扩展名为 TXT 且文件名不以点开头的项。`FileSystemWatcher` 的扩展名过滤会匹配 8.3 短名，因此回调内必须二次校验 |
| 溢出兜底 | 订阅 `Error` 事件；触发时全量重扫目录并重建 watcher |
| 读取重试 | 文件可能正被外部写入，读取失败按退避重试若干次后才报错 |
| 线程 | 事件在线程池线程触发，界面更新前必须切回 UI 线程 |
| 目录失效 | 目录被删除或改名时停止 watcher 并定时重建，界面显示降级提示 |

### 编辑器同步模型

参照 VS Code 的 `afterDelay` 自动保存档位。内部脏标记保留——删除的是按钮，不是状态机。

| 磁盘变化 | 编辑器缓冲 | 行为 |
| --- | --- | --- |
| 有 | 干净 | 静默重载，保持光标、选区、滚动位置 |
| 有 | 脏 | 保留本地输入；落盘时指纹不匹配则提示冲突 |
| 有 | 内容与缓冲逐字节相同 | 不动，避免光标无谓跳动 |
| 无 | 任意 | 无操作 |

自动落盘把「脏窗口」压缩到一秒量级，因此第二行是罕见回退路径，界面上不为它预留视觉重量，但必须实现——省略等同于静默吞掉他人修改。

冲突提示只给「保留我的修改」与「使用磁盘版本」两项，不做三路合并；AREA 文件规模不足以让合并产生价值。提示显示期间暂停自动落盘。

正在编辑的文件被外部删除时，若缓冲是脏的，**不得清空编辑器**：内容留在原地，转为未命名草稿并提供另存为入口。

### 显示范围快照

显示范围的权威来源是已应用配置的 AREA 快照，不是 TXT 文件的当前内容。这一语义在存储模块中已经成立（活动标记持久化了配置名与 AREA 列表），本特性将其明确为契约并补上界面表达。

- 文件内容变化——无论来自本页编辑器还是外部程序——永远不自动改变显示范围
- 只有应用动作才把解析结果写入快照
- 快照不依赖文件存在或合法，进程重启后仍然有效
- 漂移判定比较**解析后的 AREA 序列**而非原始文本，因此仅修改注释或空行不算漂移

由此不需要「上一次有效范围」这类内存态，也不需要非法时的范围回退逻辑；非法只影响能否应用。

**应用按钮五态**（由原型确定，选中项为对象）：

| 选中项 | 文件校验 | 内容 vs 快照 | 按钮 |
| --- | --- | --- | --- |
| 非当前应用 | 有效 | — | 应用此配置（主按钮，可点） |
| 非当前应用 | 非法 | — | 应用此配置（禁用） |
| 当前应用 | 有效 | 一致 | 已应用（禁用） |
| 当前应用 | 有效 | 已漂移 | 重新应用（主按钮，可点） |
| 当前应用 | 非法 | 已漂移 | 重新应用（禁用），底部状态条说明原因 |
| 当前应用 | 文件已删除 | — | 重新应用（禁用），范围仍生效 |

「当前应用」与「文件非法」是两个正交维度，列表项上并存显示：徽标保留给「当前应用」，非法与漂移信息走该行副标题。

### 行为变更：删除当前应用的配置

现有实现中，通过界面删除当前应用的配置会清空活动标记，显示范围回退到全部 AREA；而外部删除不走该路径，快照会保留。两者不一致。

**本特性统一为保留快照**。删除后列表保留一个提示项，显示配置名与「文件已删除 · 范围仍生效」，并提供以同名另存为的恢复入口。要放开筛选必须显式应用「全部 AREA（不筛选）」。

这是本 spec 唯一一处改变既有业务语义的地方，理由是避免显示范围在用户无预期的情况下放开到全厂数据。已经用户确认。

### 界面布局

采用原型变体 D（主从两栏，命令归左栏）。左栏固定宽度不足以平铺全部文件命令，因此另存为/重命名/删除走列表项右键菜单，删除与重命名沿用既有的确认流程，只是触发入口移到左栏。

## Testing Decisions

好测试只断言外部可观察的行为：给定目录状态与事件序列，模块对外呈现什么。不断言去抖定时器、事件抑制表这类内部结构。

### Seam 1 —— 存储模块（主）

`WatchAreaFilterProfileStore`，构造时传入隔离的临时目录、`FakeTimeProvider` 与手动驱动的事件源。

覆盖：事件解释规则全部条目、编辑器同步三态、指纹冲突、删除延迟确认、改名跟随、伴生文件过滤、快照语义、漂移判定、删除后快照保留。

推动时钟由 `FakeTimeProvider` 完成，**测试中不出现真实等待**。这一点是硬性要求：去抖与延迟确认都是时间相关行为，用真实 sleep 会让 tier 1 变慢且不稳定。

先例：该测试类现有用例已经是「真实临时目录 + 真实文件系统 + 注入时钟」的形态，本特性沿用同一形态，只增加事件源注入。

### Seam 2 —— 界面组合

`WatchV2ApplicationComposition`，在 tier 1 内不启动真实窗口即可断言控件的存在性、类型与自动化名称。

覆盖：被删除的四行元素确实不存在、命令迁移到左栏后的控件结构、应用按钮五态、非法与漂移的提示文案、删除后的提示项、光标与滚动位置的保持。

先例：生产外壳测试类已在用同一模式断言控件结构。

随本特性删除的按钮在现有测试中有若干处断言引用，需同步调整，不得以跳过测试的方式绕过。

### 不测

包装 `FileSystemWatcher` 的适配层不单测。真实 watcher 的怪癖（短名匹配、内部缓冲区溢出）由「扩展名二次校验」与「`Error` 全量重扫」两条防御性规则兜底，其正确性在事件解释层验证。

## Out of Scope

- **金机视觉验证**。本 spec 只做到 tier 1 通过；黄金渲染机预览与基线批准另行安排，且必须由用户审阅最终真实窗口预览后才能进行。
- **三路合并**。冲突只给二选一。
- **网络共享目录或跨机器同步**。配置目录是本机当前用户的本地路径。
- `DemandSeries`、`资格审计` 两个数据页自身的改动。它们消费显示范围，本 spec 不改变它们的呈现。
- 外部资格、`CatalogRevision`、`Dispatch` 范围。Watch 本就不涉及这些，本 spec 不改变该边界。
- 多实例之间的完整协调。活动标记被其他进程修改时刷新界面状态属于范围内，但不引入实例间的主动通知机制。

## Further Notes

### 原型证据

界面方案由 WPF 原型项目内的三个变体对比得出，可通过其页面与变体参数切换，并附带有效/非法两种场景。变体 D 已选中，E 与 F 作为落选对比保留在原型项目内，选中结论记录在该项目的 README 中——这与该项目对既往变体的处理方式一致。

E 落选是因为顶部芯片条对非法配置没有任何标记，用户视线在编辑器内时无法察觉；F 落选是因为其内联编辑器比被替换的布局还矮，与腾出纵向空间的目标相悖。

### 与初版 ticket 的关系

本 spec 取代了先前手写的同名 issue 文件，该文件实为 spec 形态而被误置于 issues 目录。其全部内容已吸收，包括冲突矩阵与待确认项的结论。

### 待 `/to-tickets` 决定的切分
