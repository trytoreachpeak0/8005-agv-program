# 项目文件与文件夹命名规范

> 适用范围：本项目（8005 多仓位 AGV）根目录下所有新建的文件夹与文件。
> 目标：① 在 Windows 与 Linux 上都能安全使用、无冲突；② 全项目命名风格统一、可预测；③ 一眼就能看懂内容，方便搜索和引用。
> 说明：本规范只约束**以后新建**的文件/文件夹，不要求立刻重命名历史文件，但建议后续整理时逐步向本规范靠拢。

---

## 1. 四条基本原则

1. **跨平台安全**：同一份命名规则，在 Windows 和 Linux 上表现完全一致，不出现"在我电脑上能打开，同步到同事电脑就报错/变乱码"的问题。
2. **只用一种分隔风格**：整个项目统一使用"短横线分隔"（kebab-case），不要有的文件用下划线、有的用空格、有的用驼峰。
3. **小写优先**：不依赖大小写区分文件，因为 Windows/macOS 默认不区分大小写，而 Linux 区分——同一批文件在不同系统下会出现"看似一样，其实冲突/找不到"的问题。
4. **见名知意**：命名要能反映内容（做什么用的/关于什么），不要用 `新建文件夹`、`最终版`、`v2改` 这类无信息量的名字。

---

## 2. 两个系统的"硬性红线"（必须遵守）

综合 Windows 与 Linux 的限制，取两者交集之外的"最安全子集"：

### 2.1 禁止使用的字符

不要在文件名/文件夹名中使用以下字符（即使 Linux 允许，也统一禁止，保证两边一致）：

```
\  /  :  *  ?  "  <  >  |
```

以及所有不可见控制字符（如 Tab）。

- `/` 在 Linux 是路径分隔符，`\` 在 Windows 是路径分隔符，两者都**绝对不能**出现在文件名本身里。
- `: * ? " < > |` 这些字符在 Windows 上直接会被拒绝创建，Linux 虽然允许，但为了统一，也不要用。

### 2.2 不要用空格，改用短横线 `-`

Windows/Linux 都"允许"文件名里有空格，但空格会带来实际麻烦：

- 命令行/脚本里引用带空格的路径必须加引号，极易出错（本项目里 `requirement documents` 这个文件夹名就属于这种情况，以后新建时应改为 `requirement-documents`）。
- 复制到网址、Markdown 链接里，空格会被转义成 `%20`，很难看也容易出 bug。
- Git、CI 工具、部分命令行工具对带空格的路径支持不稳定。

**统一结论：不用空格，多个单词之间一律用短横线 `-` 连接。**

### 2.3 结尾不能是空格或点号

Windows 规定文件名/文件夹名**不能以空格或点号 `.` 结尾**（即使你在资源管理器里手动打了，系统也会自动去掉或报错）。新建时注意别手滑多打空格。

### 2.4 不要使用 Windows 保留设备名

以下名称在 Windows 上是系统保留字，**不区分大小写、不管有没有扩展名都不能用**作为文件名或文件夹名：

```
CON, PRN, AUX, NUL,
COM0, COM1 ~ COM9,
LPT0, LPT1 ~ LPT9
```

例如 `con.md`、`COM1.json`、`NUL` 文件夹都是非法的，即使在 Linux 上创建了，同步到 Windows 后会打不开/报错。

### 2.5 大小写：全部使用小写

- Windows/macOS 文件系统默认**不区分大小写**（`Report.md` 和 `report.md` 会被当成同一个文件）。
- Linux 文件系统**严格区分大小写**（`Report.md` 和 `report.md` 是两个不同文件）。
- 后果：如果团队里有人在 Windows 上建了 `Report.md`，又有人在 Linux 上建了 `report.md`，两边各自以为文件不同，一同步到同一个系统就会互相覆盖或冲突。

**统一结论：文件名、文件夹名全部使用小写字母。** 需要突出的词，用短横线分隔而不是靠大写区分（例如用 `agv-task-flow.md`，不用 `AGVTaskFlow.md`）。

> 例外：`README.md`、`LICENSE`、`CHANGELOG.md` 这类国际社区公认的"全大写/首字母大写"约定文件名可以保留原样，不必强行改成小写。

### 2.6 长度限制

- Windows 传统限制路径总长度 260 个字符（新版本可开启长路径支持，但不要依赖这个设置）。
- Linux（ext4 等）单个文件名限制 255 **字节**，而不是 255 个字符——一个中文字符在 UTF-8 下占 3 字节，也就是中文文件名超过约 80 个汉字就可能超限。
- **建议**：单个文件/文件夹名尽量控制在 30 个字符（约 15 个汉字）以内，整条路径尽量不超过 120 个字符，避免出现同步、压缩、备份工具报"路径过长"的问题。

## 3. 分隔符规则（核心问题：多个单词之间到底用什么分隔）

**统一规则：全项目使用短横线 `-` 分隔（kebab-case，短横线命名法）。**

理由（参考 GitHub、npm、主流开源项目及 Web 标准的通行做法）：

| 分隔方式 | 示例 | 是否推荐 | 原因 |
| --- | --- | --- | --- |
| 短横线 `kebab-case` | `agv-task-flow.md` | ✅ 推荐，统一使用 | URL/命令行友好，不需转义；跨平台不区分大小写也不会冲突；GitHub、GitLab、npm 包、Docker 镜像、绝大多数开源项目的默认约定 |
| 下划线 `snake_case` | `agv_task_flow.md` | ⚠️ 仅限特定场景 | 只在"文件名必须直接作为代码标识符/数据库标识符"时使用，例如 Python 模块名（`.py`）、SQL 建表脚本对应的表名字段名习惯。本项目目前没有需要直接 import 的源码文件，因此**统一不用下划线**，减少两套规则并存的心智负担 |
| 空格 | `agv 任务流程.md` | ❌ 禁止 | 命令行需转义、URL 会变成 `%20`、部分工具处理不稳定 |
| 驼峰 `camelCase` / `PascalCase` | `agvTaskFlow.md` | ❌ 不用于文件名 | 在大小写不敏感的 Windows 上和全小写名字容易混淆；只在代码内部变量名/类名里使用，不用于文件系统层面命名 |

> 简单记忙法：**文件夹和文件名，永远只用"小写字母/数字 + 短横线"**。如果以后项目引入了 Python、JS 等真正的程序源码，源码文件遵循对应语言生态的社区惯例（Python 用 `snake_case.py`，React 组件用 `PascalCase.tsx`），但那属于"代码规范"范畴，与本文档讨论的"文档/资料类文件命名"分开处理。

## 4. 中文与英文命名的处理

本项目文档以中文业务语义为主，允许中文命名，但要注意统一：

1. **纯中文标题**：语义完整的中文短语可以直接作为文件名，不必强行翻译成英文或在中文之间插入短横线。
   例：`焊线氮气柜送关卡任务说明.md` ✅
2. **中文 + 英文/数字混合**：中英文之间、中文与数字之间用短横线分隔，不要用空格或直接贴在一起。
   例：`rcs-接口清单.md`、`sql-脚本-送烘箱.sql`（不要写成 `rcs接口清单.md` 或 `rcs 接口清单.md`）
3. **不使用全角标点**：文件名中不要出现中文标点，如 `，。《》：？！、（）`，一律使用英文半角的 `-`、`_`（如需要）、`.`、`()`。
4. **同一类文件统一语言**：同一目录下同一类文件尽量统一用中文或统一用英文，不要一半中文一半英文（如同目录下既有 `装片完工送烘箱.sql` 又有 `wire-bonding-finish.sql`），便于排序和检索。
5. 涉及跨团队协作、未来可能给国际供应商（如 RIOT/斯坦德等设备厂商）看的技术接口类文档，建议优先使用英文短横线命名，检索和引用更方便。

## 5. 日期与版本号

- 日期一律使用 **ISO 8601** 格式：`YYYY-MM-DD`，例如 `2026-07-07`。
  - 不要用 `07-07-2026`、`26-7-7`、`0707` 这类格式，前者容易中美日期顺序混淆，后者无法正确排序。
  - 需要用到日期的文件，日期放在文件名**开头**，方便按文件名排序即按时间排序：`2026-07-07-需求评审纪要.md`。
- 版本号统一使用 `v` + 数字，短横线连接：`agv-interface-spec-v1.2.md`。
  - 不要用"最终版""终极版""改到不能再改版"这类无法排序、无法比较新旧的描述。

## 6. 常见文件类型命名建议（结合本项目现状）

| 类型 | 建议命名方式 | 示例 |
| --- | --- | --- |
| 需求/说明类 Markdown | 中文语义短语，或"编号-中文标题" | `01-vision-scope.md`、`简易需求文档.md` |
| 接口/协议类 JSON、SQL、TSL | 全英文短横线，体现来源系统与用途 | `riot-swagger-device.json`、`sql-send-to-oven.sql` |
| 按业务场景归类的旧程序脚本 | "动作-对象"结构，短横线分隔 | `get-eqp-list-by-material.sql` |
| 图片/截图 | 内容 + 日期（如需要），短横线分隔 | `agv-cabin-layout-2026-07-07.png` |
| 会议纪要/评审记录 | 日期在前 + 主题 | `2026-07-07-需求评审纪要.md` |
| 说明性 README | 固定使用大写 `README.md` | `README.md` |

## 7. 文件夹层级命名建议

- 顶层文件夹按"业务模块"划分，用简短英文小写单词：`mes`、`rcs`、`requirements`（替代现有的 `requirement documents`，去掉空格）。
- 子文件夹按"功能/场景"划分，中文或英文短横线均可，但同级目录尽量统一语言风格。
- 避免超过 4~5 层的深层嵌套，层级越深，路径越容易超长、越不好维护。

## 8. 速查表（Cheat Sheet）

| 规则 | 要求 |
| --- | --- |
| 分隔符 | 统一用短横线 `-`，禁止空格、下划线、驼峰 |
| 大小写 | 全部小写（`README.md` 等国际通用文件名除外）|
| 禁止字符 | `\ / : * ? " < > \|` 及控制字符一律不用 |
| 禁止结尾 | 不以空格或 `.` 结尾 |
| 禁止名称 | `CON PRN AUX NUL COM0-9 LPT0-9`（不分大小写）|
| 日期格式 | `YYYY-MM-DD`，放在文件名开头 |
| 版本号 | `v1.0`、`v1.2` 这类可比较、可排序的格式 |
| 长度 | 单个名字建议 ≤30 字符，整条路径建议 ≤120 字符 |
| 语言混排 | 中英文/中文数字之间用短横线分隔，不加空格 |
| 语义 | 名字要说明"内容是什么"，不用"新建文件夹""最终版"等无意义词 |
