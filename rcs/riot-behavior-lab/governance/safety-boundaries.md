# 安全边界

> 本文件长期有效，不随任何一轮验证变化。新开一轮之前必须重读一次；[`experiments/catalog.md`](../experiments/catalog.md) 里的每条实验卡都必须遵守这里的规则。

现场只有**一台**可用于验证的测试车（key 见 [`environment.local.json`](../environment.local.json)），其余车辆正在正常运行。任何一轮测试都必须收敛到这一台车，不能影响其它车。

## 硬性规则

1. **写操作必须显式带测试车的 key**（`appointVehicleKey` / path 上的 `deviceKey` / `vehicleKey`），禁止「让系统随便派车」。
2. **不用「全部车辆 / 批量 / 全部地图」类写接口**（例如批量重启 SROS、清空全部设备、删除地图等）。
3. **不碰地图编辑删除、系统级配置、全局交管清理**等会影响其他车或整场的接口。
4. 只读接口可以查全局列表（设备列表、地图列表），但后续写操作仍只针对本车、本车当前地图上的安全站点。
5. 执行过程中每一步的真实请求参数与返回摘要，必须记入当轮 `evidence/rounds/<该轮>/execution-log.md`，不能只在聊天里口头说一下。

## 反例执行时的额外注意

[`experiments/catalog.md`](../experiments/catalog.md) 里部分卡片（尤其 E1、H1、H2）设计了“故意传一个不存在/不合法的 key”的反例，用来验证系统在异常输入下**是否仍然遵守上面第 1 条**（不会被系统“兜底”派给/影响别的车）。这类反例本身预期是**失败**、不产生真实副作用，风险很低——但如果实测发现系统真的把操作影响到了测试车之外的其它车/订单，这是**严重发现**，必须：

1. 立刻停止当前测试序列，不再继续按原计划往下走。
2. 若已造成实际影响（例如误禁用了别的车），优先用对应的恢复接口（如 `enable`）尽快恢复。
3. 按 [`README.md`](../README.md) §6 走人工干预流程，把发现完整记入当轮 `execution-log.md`，不要只当成一条“失败的测试”记完就过。

## 与人工干预的关系

安全边界是“能不能做”的红线；[`README.md`](../README.md) §6 的人工干预协议是“AI 做不到/做了不安全时怎么交接给人”的流程。两者配合：任何一步如果无法在遵守上面硬性规则的前提下用 API 完成，应该走人工干预，而不是放宽安全边界去“想办法把它做完”。

## 与接口研究范围的关系

安全边界回答「能不能调」；[`catalog/api-research-scope.md`](../catalog/api-research-scope.md) 回答「值不值得研究」。允许调用不等于需要研究；本轮实验应优先落在研究范围中的「现在就需要进行研究」。
