# Round 42（2026-08-04）— 全车快照的充电桩占用与目标监控能力

## 问题

- `GET /api/task/vehicles` 是否以少量有界请求覆盖同一 RIoT 环境内全部车辆，而不是只返回 8005 已登记车辆？
- `currentPosition` 能否与独立地图站点元数据共同证明车辆当前位于充电桩？
- `taskType=CHARGE`、`endStationNo` 与 `orderTaskId` 能否证明车辆正在前往充电桩，任务终结后这些字段何时清除？
- 分页参数是否真实生效；在代表性车辆规模和低频轮询下，响应大小、延迟与失败率如何？

## 环境与证据边界

- 用户于 2026-08-04 明确指示：`RIOT-8005-RUNTIME` 当前不可达，本轮改用 `RIOT-CROSS-PROJECT-TEST`。
- 本轮目标固定为 `http://172.10.1.72:8888`、build `2.2.0.30`；脚本发现 base URL 不符即停止。
- 8005 受控 OpenAPI 快照来自 `v2.2.0.14`，声明相同的 `GET /api/task/vehicles` 路径与车辆卡片字段。本轮只能形成测试环境代理证据，不得表述为 `RIOT-8005-RUNTIME v2.2.0.14` 的实测事实。
- CallApiKey 只从忽略版本控制的 `environment.local.json` 读取；证据中不保存密码、token 或可复用凭据。

## 批准范围

- 仅执行 GET：build、全车 key、车辆快照以及两张已有地图的站点元数据。
- 不建单、不取消订单、不指定充电、不改变车辆启用、急停、定位、地图、站点或任何业务状态。
- 不为了制造 `CHARGE` 样本干预其它项目车辆；只观察自然存在的占用、在途、终结与未知状态。

## 步骤

1. 记录 build 和 `getAllVehicleKeys` 参考集合。
2. 对车辆快照执行默认参数、`pageSize=1` 的相邻页、`pageSize=5` 的相邻页和 `pageSize=100` 的单页探针，核对分页是否生效及是否存在总数/游标元数据。
3. 读取 `ZY_WB_Map`（mapId 19）与 `尊阳电镀线opt`（mapId 14）的站点元数据，独立识别当前充电站点。
4. 每 5 秒执行一次 `pageNum=1&pageSize=100` 全车快照，共 24 次、最长约 2 分钟；串行且同一时刻最多一个请求。
5. 汇总车辆覆盖、非 8005 车辆、充电占用、`CHARGE` 在途、任务字段清除、未知状态、响应字节数、延迟和失败率。

## 判定门槛

- **覆盖**：快照车辆 key 集合必须与独立的 `getAllVehicleKeys` 相等；缺失、重复或分页结果无法无歧义合并即失败。
- **占用**：只有 `currentMap + currentPosition` 命中独立站点元数据中的充电站点，且同时有 `batteryState=CHARGING` 或现场对照，才视为已观察到占用。
- **在途**：只有自然样本同时给出非空 `orderTaskId`、`taskType=CHARGE` 和能解析为候选充电桩的 `endStationNo`，才视为已观察到前往目标。
- **终结清除**：同一车辆的同一任务必须从非空任务字段过渡到终态对照并清除；本轮没有自然过渡就保留未知。
- **未知**：断线、定位错误、字段缺失、接口失败、覆盖不一致和短暂矛盾一律 fail-closed，不沿用上一轮快照冒充当前状态。
- **负载**：本轮只测客户端可见的大小、延迟与失败率；没有 RIoT 服务端资源指标时不得声称已证明无服务端资源影响。

## 停止条件

- build/base URL 不符、任一请求方法不是 GET、鉴权失败、连续 3 次请求失败或出现无法解释的业务状态副作用时立即停止。
- 脚本不自动扩大地图、车辆或接口范围。
