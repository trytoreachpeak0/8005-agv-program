# 未决问题与验证优先级

这里记录“需要回答的问题”，实验目录记录“怎样获取证据”。问题得到足够证据后，将结论迁入 `knowledge/`，不要直接删除历史问题。

状态取值：`OPEN` / `TESTING` / `SUPPORTED` / `REFUTED` / `BLOCKED`。

## P0：最小业务闭环

### Q-001 创建移动任务应使用哪个 API 面

- 状态：`OPEN`
- 已知：Task 模块存在 `POST /api/task/v1/order`；Order 模块也存在多种建单接口。
- 未知：哪个接口适合本项目“指定车辆、仅给目的站”的移动任务，二者是否创建同一类订单。
- 需要证据：同一安全场景下的请求/响应、生成标识、队列变化和后续查询入口。

### Q-002 如何可靠判断已经到达目标站

- 状态：`OPEN`
- 候选观测：`orderState`、`missionState`、`procState`、车辆当前站点、`movementState`。
- 风险：把“订单成功”“车辆停止”“进入目标站”错误地当作同一事件。
- 需要证据：建单至完成的统一时间轴，以及现场到站时刻的人工作业标记。

### Q-003 多个状态面如何关联

- 状态：`OPEN`
- 需要同时观测：订单、mission、调度进程、车辆、设备物模型。
- 需要证据：至少一次完整成功轨迹和一次取消或中断轨迹。

### Q-004 `upperId` 是否具有幂等或唯一约束

- 状态：`OPEN`
- 需要证据：首次提交、响应丢失后查询、相同 `upperId` 重复提交，以及不同接口面的表现。

### Q-005 队列“0 或 1”如何判断

- 状态：`OPEN`
- 需要证据：建单前、排队、执行、完成和取消后的车辆任务信息及订单查询。

## P1：异常与恢复

### Q-006 cancel、interrupt、pause 和 hang 的真实差异

- 状态：`OPEN`
- 需要证据：各命令的前置状态、响应、状态转移、可恢复命令和最终善后状态。

### Q-007 RIoT 通用成功与错误判定规则

- 状态：`TESTING`
- 已观测：登录错误密码返回 HTTP 200、业务 `code=2009`。
- 未知：其他模块是否统一采用相同约定，成功码是否始终为 `0`。

## P2：多仓位与物模型

### Q-008 `multiLoadState` 的实际取值与变化条件

- 状态：`BLOCKED`
- 原因：物模型仅声明裸整数，没有取值说明。
- 解锁条件：厂商文档，或可以安全控制各仓位动作并同步采集状态的实验环境。

### Q-009 动作服务返回 `code` 的含义

- 状态：`BLOCKED`
- 原因：物模型中多个服务返回裸整数，当前禁止业务依赖。
- 解锁条件：厂商返回码文档，或足够的正反例观测。
