# 实验执行器边界

当前目录先定义执行器必须遵守的输入、输出和安全约束。没有满足这些约束前，不把临时 HTTP 脚本当作正式执行器。

## 输入

- 实验编号和场景。
- `environment.local.json` 中的现场连接信息。
- 本轮目录及本轮已批准的写操作范围。
- 实验需要的动态参数，例如测试车、地图、起点、终点和已有订单。

## 输出

每次调用至少产生：

- UTC 或带时区的时间戳。
- 实验编号、场景和步骤编号。
- HTTP 方法、脱敏 URL、脱敏请求头和完整脱敏请求体。
- HTTP 状态、耗时和完整脱敏响应体。
- 业务 `code`、`message` 和解析结果，但摘要不能替代完整响应。
- 关联标识：`upperId`、`orderId`、`orderKey`、`deviceKey`、`mapId`、`stationId`。

状态实验还必须输出统一采样记录：

```json
{
  "at": "2026-07-15T13:00:00+08:00",
  "event": "poll",
  "correlation": {
    "upperId": "...",
    "orderId": "...",
    "vehicleAlias": "test-vehicle-1"
  },
  "observations": {
    "orderState": null,
    "missionState": null,
    "procState": null,
    "vehicleState": null,
    "currentStation": null,
    "sysState": null,
    "movementState": null
  }
}
```

字段不存在时使用 `null`，不要省略；接口请求失败时单独记录错误，不沿用上一次状态冒充当前值。

## 安全要求

- 默认只允许只读实验；写实验必须在本轮计划中明确批准。
- 所有车辆写操作必须显式限定测试车。
- 执行前自动检查测试车身份、连接状态、当前订单和目的站。
- 请求或响应落盘前自动清除密码、token 和可复用凭据。
- 发生未授权车辆变化、未知副作用或收尾失败时立即停止后续写操作。
- 执行器不得自动扩大实验范围，也不得自动选择“任意可用车辆”。

## 实现顺序

1. 只读探针：鉴权、设备、车辆、地图、站点。
2. 通用脱敏与原始响应落盘。
3. 多接口状态采样器。
4. 单车建单与善后操作。
5. 实验结果校验和轮次差异比较。
